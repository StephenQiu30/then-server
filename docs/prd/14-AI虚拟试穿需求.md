# AI 虚拟试穿需求

## 状态与上位需求

- 状态：`approved_with_gates`，需求边界已批准，2026-08-30；生产启用受门禁。
- 上位需求：[`10-OOTD产品需求.md`](10-OOTD产品需求.md)。本文细化其中“用户主动发起的单件静态 AI 试穿”，不改变本地衣橱、结构化推荐、单品拼图、保存和反馈必须独立可用的要求。
- 共用任务契约：静态生成继承 [`17-云端生成与任务管理需求.md`](17-云端生成与任务管理需求.md) 的任务身份、幂等、状态、取消、迟到结果、配额和删除语义；本文只增加静态输入、质量、真实性和生产门禁。
- 启用语义：本文批准受控静态试穿的产品范围、用户承诺和验收方向，不等于批准任何供应商处理真实用户照片。隔离 POC、生产候选盲测、供应商准入、生产地域、逐次隐私同意、质量、安全、成本、性能、删除验收与灰度止损规则全部通过，并由生产 feature flag 明确开启后，才可向对应地区和版本的真实用户开放。
- 关闭语义：门禁未通过、开关关闭或运行中触发止损条件时，产品只展示结构化穿搭和单品拼图；不得出现不可用入口、自动跨境回退或暗中创建生成任务。

## 背景与问题

结构化推荐可以回答“这几件是否适合当前场景”，但用户仍可能难以想象某一件衣物放到自己身上的整体效果。通用 AI 换装工具通常把生成当作主结果，容易产生三个问题：生成失败会阻断决策、用户误以为结果代表真实尺码或合身度、人物与衣物照片在缺少明确同意和删除证据时被扩大处理。

本能力需要成为推荐后的可选视觉增强：用户先拥有一套可以直接保存的真实衣橱方案，再主动选择其中一件受支持衣物生成本人静态预览。无论是否登录、同意、联网或生成成功，核心 OOTD 决策都必须继续成立。

## 目标用户

- 年满 18 周岁、已在产品中确认一套穿搭，并希望进一步判断整体视觉感受的用户。
- 愿意在看到处理方、地域、用途、保留期和删除方式后，主动上传本人照片完成一次生成的用户。
- 希望得到快速视觉参考，但不把产品当作尺码、量体、商品质量或身体评价工具的用户。
- 不愿上传人物照片的用户仍属于完整产品用户，只是不使用本增强能力。

## 产品目标

1. 用户在结构化穿搭已经可用的前提下，明确选择一件衣物发起一次静态预览。
2. 在提交前让用户理解支持类别、视觉模拟限制、实际处理方、地域、保留期和删除方式，并自由拒绝。
3. 生成过程可离开、可恢复、可取消；任何失败都保留原穿搭和单品拼图。
4. 只向用户展示通过身份、衣物、肢体和内容安全质量门的结果。
5. 用户可以核对、保留、重试、报告异常或删除结果，并能删除其全部派生资产。
6. 先用授权 POC 判断候选能力是否值得生产化，再以生产候选盲测、供应商/法务证据和灰度止损门禁决定是否按地区和版本小流量开放。

## 非目标

- 不提供真实尺码、量体、版型、颜色、材质、垂坠、舒适度或合身保证。
- 不提供身体评价、“显瘦”、身材修饰、吸引力评分或医学判断。
- 不支持他人、名人、未成年人或来源不明的人物照片，不提供换脸或通用图片编辑。
- 首个生产候选不支持多件同时替换、顺序叠穿、外套、鞋、包、帽子、首饰、透明材质或复杂配饰。
- 不在推荐结果出现、页面预加载、滚动浏览、后台定时或批量操作时自动生成。
- 不将三套推荐自动全部生成，不以增加生成次数作为产品目标。
- 不将生产人物照片、衣物照片、结果或反馈用于训练、微调或供应商产品改进。
- 不在本需求中批准动态预览、视频试穿、实时 AR、真实 3D 或自托管模型生产化。
- 首发不提供试穿结果的下载、导出、系统分享、社交分享或公开链接。

## 功能范围

### 生产候选范围

- 入口只出现在用户已经选中的穿搭详情中，且单品拼图始终先显示。
- 一次只允许替换一件上衣、下装或连衣裙；具体开放类别按 POC 结果分别启用，不能用一个类别的通过结论覆盖其他类别。
- 人物输入为用户已确认、满足生成质量要求的本人数字形象；衣物输入为用户拥有且具备清晰单件图的对应衣物。
- 在第一次云端生成前完成账号认证；拒绝登录不影响本地衣橱、推荐、拼图、保存和反馈。
- 提交前展示本次视觉模拟说明和逐次第三方处理同意。
- 生成期间展示真实、非百分比阶段，允许离开页面、取消或稍后查看。
- 完成后支持“原始单品 / AI 预览”切换、局部查看、保留、重新生成、异常反馈和删除；保留只改变媒体生命周期，不自动成为推荐偏好。
- 不合格或不安全结果不展示，自动回退到原穿搭与单品拼图。
- 用户删除人物、衣物、试穿结果、关联穿搭或账号时，相关派生结果进入统一删除流程。

### POC 范围

- POC 只使用取得明确授权的测试人物与衣物，不使用未同意的生产照片或真实用户数据夹具。
- 使用同一组输入对候选供应商进行可比测试，分别记录类别覆盖、身份保持、衣物关键特征、严重伪影、失败率、端到端延迟、单次成本、处理地域、最长保留期和删除结果。
- 中国大陆与海外 POC 分开批准测试数据和处理路径；海外质量基准不能自动成为大陆生产回退方案。
- POC 可以比较托管供应商或经完整许可证审查的候选能力，但不构成供应商采购、生产准入或自托管建设批准。

## 核心用户故事

- 作为用户，我可以先看到不依赖 AI 的完整穿搭，再决定是否预览其中一件衣物上身。
- 作为用户，我可以在提交前知道哪些照片会被谁、在哪个地域、为何处理以及保存多久。
- 作为用户，我可以拒绝人物照片上传，并继续完成推荐、调整、保存和反馈。
- 作为用户，我可以知道当前衣物为什么暂不支持试穿，并选择补拍、换一件或继续使用拼图。
- 作为用户，我可以在生成过程中离开 App，回来后看到真实状态，而不必一直停留在前台。
- 作为用户，我可以请求取消，并区分“正在取消”和“供应商及派生资产已清理”。
- 作为用户，我只会看到通过安全与质量检查的结果；结果不合格时，我的原穿搭不会丢失。
- 作为用户，我可以比较衣物原图和 AI 结果，报告人物或衣物变化，并删除不想保留的结果。
- 作为用户，我可以理解预览只是视觉模拟，不会被引导相信它代表真实尺码或身体事实。

## 业务规则

1. **`TRYON-RULE-001`** 只有用户明确选中的当前穿搭可以发起试穿；穿搭在提交前发生变化时，必须重新确认目标衣物。
2. **`TRYON-RULE-002`** 每次生成只能由用户明确点击触发。页面曝光、查看推荐、保存穿搭或历史复用都不能隐式触发或计费。
3. **`TRYON-RULE-003`** 用户首次选择人物照片或首次发起含人物生成前，必须完成当前政策版本的“本人且年满 18 周岁”声明；登录或账号认证不能替代年龄声明，政策版本变化后必须重新确认。检测或人工报告为不允许来源时，不进入生成。
4. **`TRYON-RULE-004`** 人物和衣物都必须达到当前类别的输入要求。仅可用于衣橱展示的图片仍能参与推荐，但不能冒充可生成素材。
5. **`TRYON-RULE-005`** 首个候选一次只替换一件上衣、下装或连衣裙；未通过独立门禁的类别不得在界面中承诺。
6. **`TRYON-RULE-006`** 本次同意必须具体到处理目的、实际处理方、地域、输入、最长保留期和删除方式。拒绝或关闭同意时不创建外部任务。
7. **`TRYON-RULE-007`** 不允许因某地区没有合规供应商而自动把人物照片传到其他地区。
8. **`TRYON-RULE-008`** 生产数据固定不得用于训练。未来任何训练用途都必须另立需求并取得与试穿服务分离、可撤回的明确同意。
9. **`TRYON-RULE-009`** AI 结果是独立的视觉模拟，不得覆盖人物、衣物属性、穿搭组成、推荐依据或实际穿着事实。
10. **`TRYON-RULE-010`** 生成成功只表示结果通过系统最低质量门，不表示用户喜欢、保存或实际穿着；用户主动选择“保留”只记录媒体保留意图，不进入推荐学习。
11. **`TRYON-RULE-011`** 重试必须由用户主动发起或属于明确告知的短暂故障恢复；不得用后台无限重试制造重复处理和重复成本。
12. **`TRYON-RULE-012`** 用户请求取消后应立即回到原穿搭。若供应商无法即时停止，应诚实显示“正在停止并清理”，不能宣称已经删除。
13. **`TRYON-RULE-013`** 删除源人物、衣物或结果时，依赖的裁剪、生成图、缩略图、缓存、供应商副本和后续动态预览都必须进入同一删除范围；删除完成前结果不可继续访问。
14. **`TRYON-RULE-014`** 所有结果页固定展示视觉模拟及非尺码声明，不得使用“真实上身”“准确合身”“尺码适配”等表述。
15. **`TRYON-RULE-015`** 配额或成本限制只可在用户发起时清楚说明，不得用制造焦虑的倒计时、隐性扣减或模糊失败消耗额度。
16. **`TRYON-RULE-016`** 只有用户在与媒体保留分离的反馈动作中明确提交、且之后可撤回的结构化反馈，才可进入推荐学习；查看、缩放、保留、删除、重试和异常举报都不能被推断为穿搭偏好。

## 用户可见状态与失败恢复

| 状态 | 用户看到 | 可恢复动作 |
| --- | --- | --- |
| 功能未启用 | 结构化穿搭和单品拼图，不出现不可用生成承诺 | 继续调整、保存或反馈。 |
| 未选择穿搭 | 先选择一套方案的提示 | 返回推荐并确认方案。 |
| 人物素材不足 | 说明单人、构图、光线或遮挡问题 | 换图、补拍或使用风格化模板形象/拼图。 |
| 衣物素材不足 | 说明该单品需要更清晰的平铺、衣架或商品图 | 补拍、换一件或继续保存。 |
| 等待同意 | 展示处理方、地域、目的、保留期和删除方式 | 同意后继续，拒绝则回到拼图。 |
| 排队或生成中 | “检查照片”“生成预览”“检查结果”等真实阶段，不显示伪造百分比 | 离开页面、取消或稍后回来。 |
| 后台处理中 | 原穿搭仍可编辑和保存，任务入口保留状态 | 返回查看或请求取消。 |
| 已完成 | AI 标识、非尺码声明、原始单品对比和结果操作 | 保留、重试、报告或删除。 |
| 结果未过质量或安全门 | 不展示问题图，说明本次预览不可用且原穿搭仍在 | 换图、换衣物、稍后重试或只用拼图。 |
| 地域不可用 | “当前地区暂不支持 AI 预览” | 继续使用本地核心；不得跨境自动回退。 |
| 网络或供应商暂时失败 | 原穿搭和当前选择完整保留 | 稍后重试；重试不能重复扣减。 |
| 离线 | 可继续编辑、保存和记录；不自动上传待处理照片 | 联网后重新确认处理信息和同意。 |
| 正在取消 | 已回到原穿搭，同时说明外部处理可能仍在停止 | 查看清理状态，不重复创建同一任务。 |
| 正在删除 | 结果立即不可见，显示删除处理状态 | 等待完成；部分失败自动重试并提供支持入口。 |

无论哪种失败，都不得更改用户已经确认的衣橱、穿搭、计划或实际穿着记录。

## 成功指标及防误导指标

### 成功指标

- 有资格且看到入口的用户中，主动发起试穿的比例。
- 发起后获得可展示结果的比例，以及按类别统计的失败率。
- 端到端 p50/p95 延迟和等待中离开、取消、放弃的比例。
- 用户主动保留结果、返回修改单品和报告异常的比例。
- 结果页完成“原始单品 / AI 预览”核对的比例。
- 身份、衣物、肢体和内容安全质量拒绝率及严重异常漏放率。
- 单次成功结果成本、重复任务阻止率、取消后额外处理量。
- 删除按时完成率、超时数、供应商删除失败数和资产复活事件数。
- 拒绝云端处理后仍完成结构化穿搭保存的比例。

### 防误导指标

- 试穿生成、查看、停留、缩放、保留、删除和重试必须与“实际穿着”“推荐成功”和独立反馈分开统计；首发没有分享或导出转化口径。
- 不得把生成成功率通过隐藏质量拒绝、自动重试、重复生成或降低安全门来提升。
- 不得把同意率通过默认勾选、合并目的、阻断本地核心或暗示性文案来提升。
- 不得以人物更瘦、更白、更年轻或更符合单一审美作为质量分数或优化目标。
- 质量看板必须分别呈现身份保持、衣物保真、严重伪影和用户举报，不能只报告整体满意度。
- 成本指标不得替代用户价值和安全指标；超过成本上限时应关闭或限流，而不是降低隐私与质量门。

## 依赖与风险

### 依赖

- 已批准且可独立工作的数字形象、衣物录入、结构化推荐和穿搭保存流程。
- 可验证人物与衣物输入质量的采集和补拍路径。
- Sign in with Apple、明确同意、区域策略、受控媒体处理、异步任务恢复和完整删除能力。
- 候选供应商的商业许可、模型与辅助组件许可证、子处理方、处理地域、训练禁用、最长保留期、取消和删除证明。
- 授权且具有代表性的 POC 数据集、双人盲评规则、内容安全响应和异常举报流程。
- 已批准的单次成本上限、日/月成本预算、配额策略和供应商容量保证。

### 风险

- 模型改变面部、发型、肤色、体型、姿态、Logo、文字、图案或服装轮廓。
- 出现不合理裸露、额外人物、肢体缺失或对特定肤色、体型和服饰的系统性偏差。
- 供应商地域、数据保留、训练用途、删除能力或模型生命周期与承诺不一致。
- 延迟、限流、价格或供应商中断导致用户等待和成本失控。
- 用户把生成结果当作尺码、颜色或商品真实效果，从而产生错误决策。
- 取消、重试、迟到结果和删除并发导致已拒绝资产重新出现。

## 发布门禁

静态 AI 试穿属于“受控静态试穿”发布层级。隔离 POC、生产候选盲测和真实流量灰度是三个独立决策点：前一阶段通过只允许进入下一阶段评审，不自动批准生产，也不能把授权测试集结论包装成真实用户表现。

### 通用产品与降级门槛

- 结构化推荐、单品拼图、保存和反馈在功能关闭、拒绝同意、离线及生成失败时均可完整完成。
- 入口只对用户主动选中的方案开放，一次只替换一个已通过类别门禁的单品。
- 所有用户可见状态、免责说明、取消、重试、报告和删除路径通过无障碍与本地化验收。
- 首发不出现下载、导出、系统分享、社交分享或公开链接入口。

### 隔离 POC 退出门槛

POC 只回答候选方案是否值得进入生产化评估，不批准供应商处理真实用户数据或开放真实流量。

- 使用至少 100 组明确授权的人物—衣物组合，覆盖不同肤色、体型、18 岁以上年龄段、发型、姿态、光照、纯色、条纹、格纹、Logo、文字、宽松和贴身服装。
- 在这组预先锁定的 POC 样本与评分表上，有效输入任务失败率不高于 3%，身份保持人工可接受率不低于 80%，衣物关键特征人工可接受率不低于 80%，严重肢体、裸露或额外人物伪影率不高于 5%。这些数值只是 POC 退出线，不是生产质量承诺。
- 跨用户访问、同意、地域和删除安全用例全部通过；任何未过内容安全或严重异常门的结果不得下发给测试人员。
- 每个准备继续评估的类别独立达到 POC 退出线；不得用上衣结果代表下装或连衣裙。
- 形成可复核的原始评分、失败分类、评审一致性、成本、延迟、地域、最长实际保留与删除证据；未知项明确记为未知。

### 生产候选盲测门槛

- 产品与质量负责人必须在盲测开始前锁定代表性分层、样本量、评分维度、双盲流程、评分者培训、分歧裁决、类别独立通过线和严重问题一票否决条件。
- 盲测使用生产候选模型、参数、区域、完整安全链和预期输入分布；不得复用调参样本作为唯一评价集，也不得只报告总体平均值。
- 身份保持、衣物关键特征、肢体/裸露/额外人物异常、肤色与体型分层差异、有效输入失败、端到端延迟和安全漏放均需分别出具证据。
- 生产样本量和数值阈值尚未由代表性数据证明时保持未决；未批准不得把 POC 数值直接复制为生产承诺，也不得批准生产执行计划或真实流量。

### 供应商、地域与隐私门槛

- 完成供应商及全部关键模型、辅助组件和子处理方的商业许可证审查；研究、非商业或许可证链不清晰的能力不得进入生产。
- 生产处理地域、数据出境边界、最长输入/输出保留期、训练禁用、取消与删除责任具有合同或同等可审计证据。
- 中国大陆用户只能路由到获准的大陆处理路径；没有合规路径时关闭能力，不得自动跨境。
- 每次生成前的处理信息与同意可追溯、可撤回；删除人物、衣物、结果或账号的端到端演练通过。
- App Store 隐私标签、隐私政策、服务协议和内容安全处置流程完成评审。

### 成本、性能与配额门槛

- 端到端 p50/p95、排队时长、供应商超时和最低支持设备资源预算必须用生产候选链路实测，并低于商业与体验评审批准的硬上限。
- 单次任务、单个可展示结果、重试和取消后的成本必须有真实报价与测量证据，并低于商业评审批准的硬上限。
- 配额授予、查询、预占、成功结算、失败释放、取消与迟到结果的结算语义在真实链路完成幂等验收。
- 已定义供应商限流、超时、迟到结果、取消和大面积故障时的用户降级与成本止损规则。

### 灰度与止损门槛

- 功能默认关闭；按环境、App 版本、地域、类别和供应商策略逐步开启，并支持立即关闭且不影响本地核心。
- 客户端入口和服务端真实处理能力必须同时受控；任一侧关闭时不能创建外部任务。
- 仅在前述生产候选门禁全部关闭后，先向内部授权账号开放，再按已批准比例向真实用户灰度；每一阶段达到预先定义的最小观察量与观察窗口后才能扩大。
- 严重安全内容漏放、跨用户访问、未授权跨境、训练承诺变化、删除失败或资产复活为立即止损事件。
- 质量、成本、配额异常、p95 延迟或用户举报持续越过已批准阈值时暂停扩量并回退单品拼图；不得静默降低门槛或切换到未批准供应商。
