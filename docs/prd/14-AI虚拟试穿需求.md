# AI 虚拟试穿与完整 Look 生成需求

更新：2026-09-22，需求 `approved_with_gates`，实施 `pending`。用户已授权采用完整图优先、按需静态 GLB 的低成本路线；生产照片、供应商和真实生成尚未通过。本文件承接图片与其模型派生，设计见 [Design 07](../design/07-AI虚拟试穿设计.md)，执行 [14-01](../plan/14-01-完整穿搭图与按需三维生成执行计划.md)。

## 用户价值与范围

用户以预设人物或本人照片，加明确选中的衣物图片生成一张完整穿搭图；核对并保留后可主动生成整套立体展示。无需先有身体网格或单件三维服装。图片成功后即可保存/日期/收藏/主动分享；GLB 失败不回滚图片。

首个候选使用最多四张参考图的图片编辑能力，先测一个人物加至多三项服装参考。实际可开放类别由授权数据质量验证决定；API 接受四图不等于任意四类都保真。超数量/不支持类别必须明确提示，不静默去掉鞋、衣服或自动改为多轮高费用请求。多件能力不合格则保留失败结论，不能把单件演示认领完整 Look 完成。

## 需求与用户规则

| ID | 规则 |
| --- | --- |
| `TRYON-REQ-001` | 主动视觉增强，推荐/结构化保存不依赖生成；没有隐式计费 |
| `TRYON-REQ-002` | 人物与衣物输入合格；本人照片限本人且 18+，内置授权虚构成人参考不要求声明为本人 |
| `TRYON-REQ-003` | 当次同意、真实任务状态、离开恢复、取消/重试、核对结果与失败回退 |
| `TRYON-REQ-004` | AI 图/模型不证明尺码、面料、背面真实性或实际穿着，不改写衣物/推荐事实 |
| `TRYON-REQ-005` | 处理方、地域、留存透明，生产不训练；源/结果的派生删除可恢复 |
| `TRYON-REQ-006` | 授权 POC、质量/费用/延迟、供应商权利、照片处理与独立开关通过后启用 |
| `TRYON-REQ-007` | 后续视频派生仍需独立用途和准入，不能复用静态生成同意 |
| `TRYON-REQ-008` | 完整 Look 图绑定人物和多件选衣快照；先验证支持集，图 ready 即可使用，不等模型 |
| `TRYON-REQ-009` | 模型只由显式按钮创建，绑定已确认图片的 owner/Look/revision/hash/模型参数；同版本任务/有效模型去重复用 |
| `TRYON-REQ-010` | 新选衣产生新图版本；旧 GLB 不覆盖当前版本，取消/删除后的迟到结果只清理；不自动重试不确定已计费的提交 |

### 稳定业务规则

1. **`TRYON-RULE-001`** 只有用户明确选中的当前穿搭可以发起试穿；穿搭在提交前发生变化时，必须重新确认目标衣物。
2. **`TRYON-RULE-002`** 每次生成只能由用户明确点击触发。页面曝光、查看推荐、保存穿搭或历史复用都不能隐式触发或计费。
3. **`TRYON-RULE-003`** 用户首次选择人物照片或首次发起含本人照片生成前，必须完成当前政策版本的“本人且年满 18 周岁”声明；登录或账号认证不能替代年龄声明，政策版本变化后必须重新确认。检测或人工报告为不允许来源时，不进入生成。
4. **`TRYON-RULE-004`** 人物和衣物都必须达到当前类别的输入要求。仅可用于衣橱展示的图片仍能参与推荐，但不能冒充可生成素材。
5. **`TRYON-RULE-005`** 原单件 POC 范围由 TRYON-REQ-008 的完整 Look 支持集替代；多件、鞋、外套等必须逐类验证，输入超限时明确拒绝，不静默丢弃衣物。
6. **`TRYON-RULE-006`** 本次同意必须具体到处理目的、实际处理方、地域、输入、最长保留期和删除方式。拒绝或关闭同意时不创建外部任务；撤回 `generation_input` 同意时，在同一事务内撤销该同意下所有素材关联任务的结果访问并建立清理记录。可确认尚未提交且没有活动租约的任务立即转为已取消并释放预留额度；可能已发送给外部的任务保留取消/对账事实，不宣称外部已停止或删除，迟到结果不得发布且必须进入清理。
7. **`TRYON-RULE-007`** 不允许因某地区没有合规供应商而自动把人物照片传到其他地区。
8. **`TRYON-RULE-008`** 生产数据固定不得用于训练。未来任何训练用途都必须另立需求并取得与试穿服务分离、可撤回的明确同意。
9. **`TRYON-RULE-009`** AI 结果是独立的视觉模拟，不得覆盖人物、衣物属性、穿搭组成、推荐依据或实际穿着事实。
10. **`TRYON-RULE-010`** 生成成功只表示结果通过系统最低质量门，不表示用户喜欢、保存或实际穿着；用户主动选择“保留”只记录媒体保留意图，不进入推荐学习。
11. **`TRYON-RULE-011`** 重试必须由用户主动发起或属于明确告知的短暂故障恢复；不得用后台无限重试制造重复处理和重复成本。
12. **`TRYON-RULE-012`** 用户请求取消后应立即回到原穿搭。若供应商无法即时停止，应诚实显示“正在停止并清理”，不能宣称已经删除。
13. **`TRYON-RULE-013`** 删除源人物、衣物或结果时，依赖的裁剪、生成图、缩略图、缓存、供应商副本和后续动态预览都必须进入同一删除范围；删除完成前结果不可继续访问。
14. **`TRYON-RULE-014`** 所有结果页固定展示视觉模拟及非尺码声明，不得使用“真实上身”“准确合身”“尺码适配”等表述。
15. **`TRYON-RULE-015`** 配额或成本限制只可在用户发起时清楚说明，不得用制造焦虑的倒计时、隐性扣减或模糊失败消耗额度。
16. **`TRYON-RULE-016`** 只有用户在与媒体保留分离的反馈动作中明确提交、且之后可撤回的结构化反馈，才可进入推荐学习；查看、缩放、保留、删除、重试和异常举报都不能被推断为穿搭偏好。

## 状态与恢复

图片与模型各自显示“排队、生成中、检查中、已就绪、失败、已取消”；任务未接纳不显示已开始。用户可离开 App，返回从持久任务恢复；前台轮询有退避，页面离开停止 UI 轮询不取消后台任务。失败保留草稿和已确认图片，主动重试才产生新的允许尝试。

已确认图生成模型前展示实际用途和费用；图片同意不自动覆盖模型供应商。如果后台提交超时、是否计费未知，则进入核对状态并查询已有任务，不直接重提。模型完成后只关联其原图片版本，不强制切走用户的新草稿。

## 质量与费用验收

先验证单套代表，再用至少 12 组授权输入覆盖单件/多件、浅深色、图案、裙装/鞋和错误输入。记录所有尝试、失败、严重问题、时延和实际费用。人物身份/肤色明显变化、服装丢失、图案错误、肢体异常、意外裸露或关键辅助器具消失均单列，不用成功 HTTP 或精选样图代替质量。

调用报价与放大系数见 Design 20，不能把 $0.35 理论一次成功报价作为每个用户结果的保证。费用上限、尝试上限与提交前说明进入执行计划；没有具体测试账号/额度和用途许可，不发起计费验证。

## 删除、输出与发布

删除图覆盖其 GLB/缩略图/缓存/供应商副本；只删模型可保留图；删源人物/衣物图按血缘处理而不抹除独立衣物或穿着记录。先拒绝访问，再异步清理，失败可重试，不能复活。图片系统分享按 AVATAR-REQ-044；不导出原始本人照片或自动创建公开链接，外部已分享副本不能声称被远程删除。

开发 POC 采用本地 `fixture` 图片替身和 `img2threejs` 三维流水线；本地 Codex CLI 只能作为受控编排器，不能替代实际图片 Provider。托管转换器、远端 GLB 插件或其他云 Provider 的服务授权、数据地域/留存/删除和输入/输出权利分别核实。生产启用需照片质量门、真实任务全链路、实际账单对账、最低设备与关闭演练通过；内部合成素材 POC 不构成真实用户准入。

## 验收映射

REQ-001～007 延续 TRYON-ACC-001～008；单件专用假设按当前支持集修订。新增 REQ-008 → TRYON-ACC-011，REQ-009/010 → TRYON-ACC-012，任务共同约束 → CLOUD-ACC-012。11-05 验证模型展示，14-01 验证真实生成；各自均未完成。

## 功能性需求拆解与完成条件

| 用户动作 / 需求 | 输入、前置与正常结果 | 必须覆盖的异常和验收断言 |
| --- | --- | --- |
| 选择生成内容 / REQ-002/008 | 一个人物参考加 1～3 件当前支持衣物图；逐件可见来源和类别；冻结所选衣物/人物的版本与摘要 | 0 件、超 3 件、缺人物、图损坏、不支持类别、无使用权、跨账号或输入已删均不提交；允许只存草稿，不静默少一件生成 |
| 确认图片生成 / REQ-001/003/005 | 认证有效，展示目的、实际供应商/地域/留存、输入缩略图、预计消耗与失败/取消规则；用户确认后提交当前不可变输入 | 关闭/拒绝不上传、不占额度；确认后输入/供应商/同意政策改变需重新确认；余额/并发/预算不足显示具体原因并保留草稿 |
| 等待与恢复 / REQ-003 | 接纳后保存稳定 job ID；离开页面或杀 App 后从服务端恢复阶段；允许查看其他 Look | 创建响应丢失用同一幂等键找回；401 重新认证同一账号后恢复，换账号不展示旧任务；429 尊重恢复时间；未接纳不画虚假百分比 |
| 核对完整图片 / REQ-004/008 | 已收取净化且过最低安全门的图展示“待确认”；用户查看每件衣物并选择保留或放弃；保留后可日期/收藏保存 | HTTP 成功不直接算质量通过；严重异常不交付；用户不保留不是偏好反馈；图片失败仍可编辑/保存草稿，无模型也可完成图片旅程 |
| 生成或查看模型 / REQ-009 | 已确认图、独立模型用途/费用；有任务则恢复、有有效模型则直接查看，只有缺少有效任务/产物且明确同意时才新建 | 页面曝光、保留图片、点击已缓存模型产生外部计费 POST 为 0；模型失败留图片；缓存下载坏包重新获取已有对象，不自动重新生成 |
| 再改衣物 / REQ-008/010 | 从已存 Look 新建内容版本 B，改衣后先生成 B 图，再主动生成 B 模型 | A 的图/模型/任务只归 A；迟到 A 不改变当前 B；选择旧版必须标出旧版；日期/收藏更改不创建新图任务 |
| 取消/重试/删除 / REQ-003/005/010 | 取消先关闭展示与后续提交，外部任务允许停止则停止，无法停止则继续对账和清理；已知失败后用户可按规则发起新尝试 | 不确定是否受理不盲重发；取消不承诺退款；删除源后所有可达派生物不可访问，重启/迟到回调继续清理；只删模型不删图片 |

图和模型各自用服务端状态映射 UI：`未提交→排队→生成中→检查中→待确认/就绪`；失败可有限重试。`核对任务状态` 与 `停止并清理` 是真实可持续状态，不能被客户端计时器改为失败/成功。外部 provider 状态名不直接进入用户文案。

## 质量支持集与 POC 判定

这是准入实验规格，不能作为实际生成能力的声明。先固定输入集、评分表和费用上限，再调用；不能看到结果后改标准。首个代表 Look 合格后执行不少于 12 组输入，建议 9 组合法输入（单件/两件/三件各至少 3 组）和 3 组本地拒绝输入（超限、无权/已删、损坏/不支持）。真实本人照片只在其独立准入通过后加入，虚构人物测试不代替真实人群测试。

| 检查维度 | 检查方式 | Go / No-go |
| --- | --- | --- |
| 输入完整性 | 提交快照与出图逐件对照，记录类别、颜色、主要款式/图案和未选区域 | 每个准备开放的组合至少 3 个独立合法输入通过；若样本覆盖不足继续补测或不开放该组合，不能由其他类别平均分抵扣 |
| 人物与内容安全 | 两名评审独立查看正面图，分歧复核；真实人物另检身份/肤色/辅助器具与宗教服饰 | 明显身份改变、肢体异常、衣物丢失或意外裸露的产物不交付；已选定正式资产严重缺陷为 0；发生严重失败须留记录并解决后才进入下一阶段 |
| 视觉可用性 | 人物/服装保持、整体画面、细节伪影分别按 1～5 分（1 不可用，3 明显错误，4 可保留小瑕疵，5 满足预期）评分 | 选定用于集成的图各项 ≥4，不能以均分掩盖一个维度不合格；公开生产的总体合格率阈值在扩大测试前另行固定 |
| 整套 GLB | 对通过图片做正/侧/背及连续观察，记录面数/纹理/字节、图片对应性、最低真机表现 | 单样本满足 AVATAR-ACC-029 和 NFR-002/003；图合格而 GLB 不合格只允许图片路径，不能宣称完整三维已通过 |
| 费用与延迟 | 逐尝试记 provider/model/参数、提交次数、受理 ID、阶段时间、计费及保留/丢弃原因 | POC 默认最多 2 次计费尝试/样本且总预算硬封顶，具体金额未批准不调用；达到上限停止，不补隐藏重试；如报告百分位须同时给样本数 |
| 错误输入 | 本地和服务端均校验上表三种拒绝输入 | 外部提交数为 0、提示可恢复、草稿仍在；不能只测 API happy path |

POC 的“9 组合法输入”只是最小覆盖起点；一个组合若未达到独立通过样本要求，应扩测试而非宣称全类别支持。质量、实际费用与延迟分别记录，不设虚假的固定完成秒数；更广泛人群的安全、公平性和真实供应商删除仍属于生产验收。

## 非功能性需求与范围验收

引用 `OOTD-NFR-001～013`：本片重点为任务可靠性（008）、预算（009）、权限/删除（006/007）、可观测性（011）与异步接纳响应（013）；模型性能由 11-05 的同一 renderer 验证。TRYON-ACC-011/012 必须同时提供 UI、持久任务、私有文件、供应商调用/账单四类证据，不能单凭一张成功截图退出。

生产配置必须有用户并发上限、每任务尝试上限、图片/模型日额度、项目货币预算、任务超时、收取限制与删除最大保留期。数值随已批准账号和供应商合同固定，未配置则对应云入口不可接纳任务；不在 PRD 写入密钥或用无限值占位。
