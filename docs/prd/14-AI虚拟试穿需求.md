# AI 虚拟试穿与完整 Look 生成需求

更新：2026-09-30。按本轮用户授权修订为个人自用的 Woo 式本人虚拟人偶生成需求；真实输入、供应商质量、费用与设备验收待验证。依据与候选选择见 [Design 29](../design/29-Woo虚拟人偶与自用成本决策.md)。当前推荐供应商是待测候选，不是已准入服务或 Woo 内部算法的结论。旧实现、fixture 与技术测试不证明本版人物目标通过。

## 用户价值与当前范围

首版先以本人照片建立已确认人偶参考，再用当日整套穿搭照片或明确选中的衣物图生成 **半写实、明显虚拟的人偶 Look 图片**。本人核对特征、衣物与风格并确认后，可以保存日期/收藏或主动生成该图对应的完整静态 GLB。图片独立可用，模型失败不回滚图片。

本人参考决定可辨识特征，风格参考决定表现方式，Look 输入决定当天衣物，显示设置决定相机和光线；四者不能混为一个可变提示词。生成式参考不保证跨套脸部硬锁、同一头部网格或拓扑一致。首版不进行参数化人体、即时服装网格替换、骨骼动作、眼球动作或视频生成。

两类来源明确分开：真实穿搭记录尽量保留原有衣物与身形，仅风格化；尝试新搭配使用衣物参考生成视觉模拟，不自动登记实际穿着，也不证明真实合身。当前不要求公共后端、账号认证、多人数据隔离、社区或订阅系统；本地单用户任务与密钥也不能因此省略用途、隐私和费用控制。

## 输入与功能流程

| 流程 | 输入与确认 | 正常结果 | 拒绝、失败与恢复 |
| --- | --- | --- | --- |
| 建立人偶参考 | 有效本人照片、Woo 风格参考/规则；推荐清晰正脸与全身，检查遮脸/缺脚/模糊/多人 | 少量参考候选 → 本人确认 → 独立 AvatarReference 与 StyleProfile 版本 | 不满意不设为默认；保留实验费用；真实侧背与生成侧背标记不同；单照片效果待验证 |
| 每日真实穿搭 | 当天全身穿搭照 + 已确认本人/风格参考；保留原单品、身形和真实记录来源 | 风格化 Look 图待确认；确认后可保存日期/收藏，或选生成立体 | 衣物/脸变化可放弃、改输入或在限次内主动重做；错误不覆盖已有记录 |
| 尝试新搭配 | 本人/风格参考 + 每件明确选中的衣物图，展示类别和输入数量 | 新 Look 图待确认；标为尝试搭配 | 超参考数量、不支持类别或已删来源本地提示；不静默删鞋包、不自动分多轮增加费用 |
| 提交图片 | 展示不可变输入、目的、供应商、估算费用、尝试余量及保留/删除条件，本人明确继续 | 持久化请求记录后提交；接纳后记录供应商任务 ID | 拒绝/取消不提交；预算不足保留草稿；发送后丢响应转提交未知，不把本地请求 ID 当供应商幂等保证 |
| 核对图片 | 成功下载且过文件/最低内容检查 | 待确认 → 本人核对 → 确认时间与图摘要；满意结果本地保存 | HTTP 成功不等于满意；换脸、缺衣、严重肢体异常或意外裸露不能成为满意输入 |
| 按需三维 | 已确认图、独立模型用途与费用；同图已有任务/有效资产先复用 | 生成完整带纹理静态 GLB → 下载校验 → 本人检查正/侧/背 → 满意资产保存 | 失败保留图片；坏下载重取已有对象，不直接新生成；严重融合/缺失不作为满意模型 |
| 换输入或记录日期 | 日期/收藏改元数据；衣物、本人/风格参考变化建新内容版本 B | B 先生成图，再可选生成 B 模型；A 可明确作为历史查看 | A 迟到不覆盖 B；只改日期不计费；旧模型不能与新单品标签混标 |
| 取消/删除 | 选择停止当前尝试、删除结果或源参考，说明对象范围 | 本地隐藏/停止后续提交；可停止外部任务则调用；不可停止则对账并清理 | 不承诺供应商即时停止/退款；源删除沿血缘阻止发布，重启或迟到结果继续清理 |

Tripo seedream 编辑当前最多四张参考图；“人偶 + 上衣 + 下装 + 鞋”已占四张。本人/风格双参考若均需要上传也占端点额度，不得把四张衣物与人物图另行叠加。组合参考板、分步骤编辑或替换模型是待测试方案，不保证一次完整保真，也不静默启用额外计费步骤。[官方图像编辑](https://developers.tripo3d.ai/en/docs/generation-image-to-image)

## 状态与持久化

图片与模型独立保存：未提交 → 提交中 → 已接纳/等待 → 生成中 → 下载检查 → 图片待确认或模型待核对 → 满意/已保存。提交未知、失败、取消核对、结果过期、待清理为可恢复状态；未接纳不显示已开始，不用计时器伪造进度或百分比。

请求记录先落本地，冻结 Look/本人参考/风格版本、输入摘要、供应商与模型/参数、估算费用及尝试序号；接纳后追加供应商任务 ID。离开页面暂停 UI 轮询不代表外部任务已取消。返回读取持久记录，已知任务进行状态查询，未知提交先核对，不自动新建。

结果 URL 可能短期过期：BFL 官方结果链接仅有效十分钟，其他端点按实际文档和测试记录。及时下载到受保护临时区、校验类型/完整性/摘要，再原子发布文件引用；只有完整本地文件与元数据成功保存才标离线可用。长期关闭 App 后能否取回结果需端点验证；无法取回明确过期，保留费用与源图，重做必须再次主动确认。[BFL 结果获取](https://docs.bfl.ai/flux_2/flux2_image_editing)

生成任务只关联原输入版本，不因晚返回切换当前 Look 或覆盖更晚确认结果。删除或本机已确认取消当前任务后阻止发布并处理迟到对象；仅撤回未来用途不自动清除已有或在途结果，取消/删除另行选择。缓存删除、满意资产删除和源参考删除分开；图片主动分享与私人备份按 PRD 11 的 `AVATAR-REQ-044`，外部导出副本由本人管理。

## 候选、成本与预算规则

本表只定义候选用途与配置。单价、计费依据及价格核对日期集中维护于 [Design 29 §4](../design/29-Woo虚拟人偶与自用成本决策.md#4-api-选择先把接入与现金成本一起算)；个人用量、安装固定成本与预算算例见 [§6](../design/29-Woo虚拟人偶与自用成本决策.md#6-个人使用的成本预算)，POC 消耗上限与满意成本口径见 [§9](../design/29-Woo虚拟人偶与自用成本决策.md#9-先验证人物和满意成本再扩大实现)。这些是研究快照，不是固定单价、实测账单、满意率或已验收承诺。提交前按实际账号、端点、分辨率、附加项与当时价格显示估算，并随尝试保留价格快照。

| 候选 | 研究用途 | 配置与能力边界 |
| --- | --- | --- |
| Tripo seedream_v5 | 风格化多参考图片基线 | 最多四张参考图；本人/风格与衣物输入共享额度，效果待验证 |
| Tripo H3.1 标准纹理 | 整套静态 GLB 基线 | 标准带纹理配置，不重复购买基础纹理，不默认附加处理 |
| Tripo P1 标准纹理 | 少量质量/移动性能对照 | 标准纹理配置；低面数不等于 Woo 风格或更低满意成本 |
| BFL FLUX.2 klein 4B 编辑 | 图片成本/质量对照 | 本档多参考上限四张，记录实际输出分辨率，效果待测 |
| FASHN | 特定衣物替换实验 | 不作为所有 Woo 人偶的默认生成器；如启用需固定版本与配置另测 |

预算包括图片、三维、成功但不满意的重做、附加处理与人工修复；安装签名、已有设备和资产制作时间作为固定/人工成本单独记录。计费及失败/取消规则以 Design 29 §4 的原始依据和实际任务记录核对；成功但不满意不能当作免费失败，本地取消按钮不等同供应商退款。

- 图片和模型分别设付费尝试上限；达到上限暂停，先检查输入或候选，不无限重做。
- 同套已有满意图/GLB，直接加载；改日期、收藏、旋转和重新打开不提交。
- 新请求要同时满足本月用量上限与当阶段尝试上限；展示估算和实际扣费差异，未知扣费保留待核对，不记为零。
- 默认标准纹理及静态 GLB，不自动购买绑定/动画/高清/分件/转换。供应商切换、附加项或多轮编辑前重新显示费用。
- 缓存和费用记录可导出；清缓存不删除已保留资产，也不因为缓存缺失自动再生成。

## 五套本人质量与费用 POC

这是待执行实验规格。文档更新不授权上传照片或计费调用；使用本人照片、实际 API Key、试验输入、云用途和具体消耗上限应在实验前明确。首轮用量预算建议与算例统一见 [Design 29 §9](../design/29-Woo虚拟人偶与自用成本决策.md#9-先验证人物和满意成本再扩大实现)，不是最低充值额或已经批准扣费。

先做一套，再用五套本人典型穿搭覆盖简单衣物、外套、长裙/宽裤、图案、鞋包/眼镜。固定确认的人物与风格版本，对照：A 原穿搭直接三维；B 先风格化 Look 图再三维。A 若没有稳定目标风格不能仅因“不像照片”通过；若 B 更符合目标，主线采用 B。

每套两路合计最多两次 H 三维，图片最多两次，另做少量 P1 对照；例如 A/B 各留一次 H。本人参考、附加项和额外重做纳入已明确的实验预算。若需要增加任何路径的次数，先调整清楚上限与预算，不隐藏增加实验次数；金额与分配算例以 Design 29 §9 为准。

| 维度 | 通过断言与失败处理 |
| --- | --- |
| 目标风格 | 本人确认 Woo 式虚拟人偶感，比例/造型/材质相符；默认二次元或真人照片皮肤不是替代通过 |
| 本人特征与跨套 | 认得出本人，五套像同一个虚拟人物；明显换脸留失败记录，改输入/候选，不无限补抽 |
| 衣物 | 核心颜色、轮廓、领口/袖长、裤裙型、鞋包/眼镜保留；不能为美观换掉核心单品 |
| 真三维 | 连续旋转，检查正面/45°/背面、头发/肢体/鞋包；严重融合或缺失不得保留为满意模型；背面推测可见 |
| 费用与满意率 | 所有付费尝试、保留/丢弃原因和人工修复均登记；按 Design 29 §9 的满意每套成本口径报告，零保留时报告失败而非给零成本 |
| 保存与复用 | 满意文件本地保存后重启、断网仍能查看；反复打开不提交生成；坏下载/过期有可恢复说明 |
| 本机展示 | 记录设备、面数/纹理/字节、缓存呈现、帧率、切换与持续旋转；约三秒/30fps 仅初始目标，待实际设备测量 |
| 错误与恢复 | 多人/损坏/缺关键输入/超参考数在提交前提示；提交未知、过期、低存储、取消/删除迟到均不覆盖原记录或重复计费 |

五套不证明所有品类或所有人物都支持，当前个人自用不设公共人群公平性/十二组生产样本为首版硬门槛。供应商最低内容质量与私人处理/删除能力仍须核验。质量、费用、延迟和设备证据分别报告，技术 fixture、CLI 编排或合成 GLB 只可证明其测试范围。

若持续无法保持同一虚拟人物，先停当前候选，再评估固定人偶方案。VRM/three-vrm 不是通用服装自动适配系统，Blender/MPFB/VRoid 属可选制作工具；先比较一个固定人偶与三件衣物的实际人工投入，不能只因已有资产组合零 API 费就称总成本更低。
