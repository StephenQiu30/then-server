# 数字形象与照片采集需求

更新：2026-09-15。产品能力固定，状态分别由 Plan/Acceptance 维护。

## 首版眨眼与视线跟随

`AVATAR-REQ-038`：用户确认首版在既有微动之外增加眨眼与轻微视线跟随。角色就绪且舞台可见时，可观察自然闭眼/睁眼和受限眼球方向变化；无交互后平滑回到默认视线。拖动旋转优先，换装不得重置人物身份或造成脸部跳变。Reduce Motion 开启、舞台不可见或角色切换时停止装饰性眼部动态，保留直接操作。脸部效果必须由真实眼睑/眼球数据支持；现有工程模型缺失这些数据时，验收保持未通过，不能用整体缩放或旋转冒充。挥手、行走和实时布料未在本轮增加为首版必需。

用户已授权确定格式：采用 Three.js + 标准 GLB；允许评估付费授权资产，但具体采购先确认预算。本次规格依据见 [开源研究与选型](../design/threejs-avatar-research.md)，验收归 `AVATAR-ACC-027`。`AVATAR-REQ-035` 的“当前工程增量不伪造表情”继续有效，但不再被解读为完整首版排除眨眼和视线跟随。

## 人物制作约束与选型稳定性

`AVATAR-REQ-036`：开发团队使用无需 Blender 制作、修复或导出的资产交付方式；正式资产不以 `.blend` 为必要输入。必须能追溯来源、许可、版本与原始交付包，并重复取得/导入验证。三套人物、内置换装和真实三维交互目标保留，不能因资产困难擅自改为纯图片产品。

`AVATAR-REQ-037`：人物技术按 [Design 01 的 AVATAR-BASELINE-01](../design/01-技术选型.md#人物技术冻结与变更规则) 执行。运行时已确定为 Three.js；具体生产资产来源尚待代表包验证，未通过前不得宣称已完成生产选型。替换已确认路线先记录需求与实测依据，再按变更 SOP 同步设计、计划及验收。

## 背景与问题

数字形象可以帮助用户直观比较穿搭，但强制上传人物照片会显著增加首次使用成本和隐私顾虑。照片质量不足、多人入镜、元数据泄露、生成失真和删除不完整，也可能让视觉增强变成核心体验的阻碍。

产品需要同时服务两类用户：不愿提供照片的用户必须获得完整穿搭能力；主动选择照片的用户则需要清楚知道照片为什么被使用、在哪里处理、保留多久以及如何删除。数字形象只能是表达与预览工具，不能被包装成身体测量或真实试衣事实。

## 目标用户

- 希望用虚拟形象比较穿搭的 iPhone 用户；无照片本地使用不要求年龄声明，人物照片路径限成年本人。
- 不愿上传人物照片，但仍希望使用衣橱、推荐、保存和穿搭记录的用户。
- 愿意主动选择一张本人照片，同时关注隐私、失真与删除能力的用户。
- 使用轮椅、辅助器具、宗教服饰或具有不同身体表达，需要受到平等、中性对待的用户。

## 产品目标

1. 用户零照片、零自有衣物、不登录且设备离线时，直接使用真实三维模板、内置服装完成编辑、换装、观察和 Look 保存恢复；静态图/拼图只作用户选择或故障/无障碍替代，不抵扣三维交付。
2. 用户主动使用照片时，以一张本人全身照作为最小输入；自拍仅作为用户主动选择的相似度增强，不是必填项。
3. 在用户确认前说明照片可选、本人且 18+、处理用途、处理位置、保留方式、删除入口和视觉能力边界。
4. 对模糊、多人、遮挡、异常格式和设备能力不足提供中性、可恢复的建议，不评价用户身体或外貌。
5. 用户可以切回无照片模式，并能看到照片及相关派生视觉资产真实的删除进度和失败状态。
6. 人物照片不参与穿搭推荐资格、过滤或排序，照片缺失不会减少推荐数量或功能。
7. 用户首次选择人物照片或发起含人物的生成前，必须声明照片是本人且本人年满 18 周岁；账号认证不能替代该声明，声明策略版本变化后必须重新确认。

## 非目标

- 不做量体、尺码预测、真实合身、面料物理、颜色还原或身体健康判断。
- 不做人脸识别、身份认证、跨照片人物搜索或长期保存人脸、身体特征。
- 不自动美颜、瘦身、增高、换脸、改变肤色、年龄或性别表达。
- 不接受未成年人、他人、名人、网图或来源不明的人物照片。
- 不要求侧面、背面、多角度、视频、贴身衣着、内衣或暴露身体。
- 不扫描完整照片图库，不自动导入最近照片，不读取照片地点或人物关系。
- 不默认同步人物照片或数字形象，不把用户素材用于训练、广告、画像或模型评测。
- 本功能不负责静态 AI 试穿、动态预览、社交分享或公开链接。
- 首发不提供人物照片、数字形象、试穿或动态生成媒体的下载、导出或系统分享。

## 功能范围

### 首发必备能力

- 默认显示内置有效造型和真实三维人物；至少提供两件几何不同的上装可更换。允许用户停用形象改用原生静态/单品界面，但默认不能以拼图代替真实模型。
- 外观选项以有效资产清单为准；有限体型同时作用于身体和服装，越界或未支持组合明确拒绝，不暗改体型或衣物。
- 独立编辑草稿支持撤销、取消、恢复默认和保存；水平拖动及原生正侧背控件仅改变视角，保存 Look 与切换历史造型分开。无操作时不持续播放或绘制。
- 首次进入不请求相册或相机权限，不以照片设置阻断衣橱、推荐、保存和历史。
- 用户可主动选择形象风格和表现选项；系统不得从姓名、照片或历史行为推断人口属性。
- 每个视觉预览附近持续展示“仅为视觉示意，不代表真实尺码、合身、垂坠、透明度或颜色”的说明。
- 停用形象只停止显示；删除才清除私人外观及派生预览。两种操作都保留真实衣物、结构化搭配、实际记录和反馈；删除后历史角色区域显示已删除，可用独立服装示意/文字，不能从旧快照复原私人参数。
- 无网络时可创建、修改、保存和删除模板角色与 Look；保存固定资产版本、参数和日期/原时区，重启恢复一致；不能访问的云端照片项目不得阻断主路径。

### 首发条件能力：本人照片本地准备

只有照片处理、生命周期、隐私和真机质量门槛全部通过后才启用；未通过时不展示不可用入口。

- 在打开系统照片选择界面前展示用途说明，并要求用户确认照片是本人且本人已年满 18 周岁；该声明只门禁人物照片和含人物生成，不影响本地无照片核心。
- 用户一次只主动选择一张全身照；取消选择时保留原有形象和页面上下文。
- 在本机完成必要的安全检查与元数据移除，展示处理后的照片供用户最终确认。
- 质量不足时只给出一个最主要、可操作的技术原因，并提供“换一张”与“使用风格化形象”。
- 自拍仅在用户主动选择增强脸部相似度时出现；跳过自拍不影响继续使用。
- 默认提供一次性使用；是否允许长期保存在本机，须先明确保留期限、删除和备份边界。
- 离线时，已在设备上可读取的照片仍可完成本地准备；依赖云下载的项目不可用时允许换图、稍后重试或使用模板。
- 若用户希望同一张本人 OOTD 同时用于人物参考和衣物拆分，界面必须分别说明两个目的并让用户逐项选择；只选择衣物拆分时，不得创建可复用人物形象或保留人物源图。

### 后续或独立条件能力

- 系统相机拍摄入口。
- 照片参考的长期本机复用。
- 照片离机生成、静态 AI 试穿和动态预览。
- 人物照片或生成结果的跨设备同步、导出与分享。

这些能力必须分别满足对应 PRD、同意、供应商、隐私、删除和质量门槛；本地保存同意不能自动扩展为云端上传或同步同意。

## 核心用户故事

- 作为新用户，我可以不提供照片或真实衣物，直接用内置目录在三维人物上换装，不被劝说先上传。
- 作为离线用户，我可以设置风格化形象并完成衣橱、推荐和保存穿搭。
- 作为愿意个性化的用户，我可以先了解照片用途和删除规则，再决定是否选择照片。
- 作为用户，我只需要选择一张本人全身照；不提供自拍也不会被阻止。
- 作为照片不符合当前能力的用户，我能获得中性、具体的改进建议，也能立即回到无照片路径。
- 作为重视隐私的用户，我可以选择一次性使用，且完成、取消或失败后不留下可复用副本。
- 作为用户，我可以更换、停用或删除数字形象，并清楚知道哪些内容删除、哪些衣橱与历史事实保留。
- 作为使用辅助技术的用户，我能读到状态、原因、操作和视觉边界，不依赖颜色或动画理解流程。

## 业务规则

| 需求 ID | 规则 |
| --- | --- |
| `AVATAR-REQ-001` | 照片永远可选；无照片路径不得减少推荐、保存或历史能力。 |
| `AVATAR-REQ-002` | 人物照片仅限年满 18 周岁的用户上传本人照片；未确认时不得进入选图或生成流程。 |
| `AVATAR-REQ-003` | 一张全身照是最小照片输入，自拍只能是用户主动选择的可选增强。 |
| `AVATAR-REQ-004` | 照片使用前必须让用户看见用途、处理位置、保留方式、删除路径和无照片替代方案。 |
| `AVATAR-REQ-005` | 照片离开设备前必须移除位置、拍摄设备、原文件名和其他非必要元数据；未经单独同意不得离机。 |
| `AVATAR-REQ-006` | 多人或可能包含未同意第三方的照片不得通过自动裁剪继续处理。 |
| `AVATAR-REQ-007` | 照片检查只判断当前视觉流程是否可用，不输出身体、年龄、性别、种族、吸引力或健康评价。 |
| `AVATAR-REQ-008` | 人物照片、外貌信息和照片是否存在不得成为推荐过滤、排序或资格信号。 |
| `AVATAR-REQ-009` | 本机复用、单次云生成、跨设备同步和训练是不同目的，必须分别说明和同意；生产数据不得用于训练。 |
| `AVATAR-REQ-010` | 取消、失败、过期和删除都必须覆盖当前用途产生的照片副本与派生视觉资产，不得用“已提交删除”冒充“已删除”。 |
| `AVATAR-REQ-011` | 删除数字形象不删除衣物、结构化搭配、实际穿着和反馈；历史移除私人外观参数/引用/预览，角色显示已删除，可显示独立服装示意；不得据旧快照重建被删外观。 |
| `AVATAR-REQ-012` | 任何视觉结果都必须明确说明其不代表真实尺码、合身、垂坠、透明度或颜色。 |
| `AVATAR-REQ-013` | 本地无照片核心不要求年龄声明；首次选择人物照片或发起含人物生成前确认本人且 18+，账号认证不等于年龄证明，声明策略版本变化后必须重新确认。 |
| `AVATAR-REQ-014` | 同一 OOTD 用于人物参考与衣物拆分属于两个目的；用户逐项选择，未选择人物参考时不得保留可复用人物源图或创建照片形象。 |
| `AVATAR-REQ-015` | OOTD 照片处理默认只向衣橱交付待确认衣物草稿和组合草稿，不自动创建 `OutfitPlan` 或 `WearEvent`。 |
| `AVATAR-REQ-016` | 首发不提供人物或生成媒体下载、导出、社交分享和公开链接。 |

## 用户可见状态与失败恢复

| 状态或失败 | 用户看到 | 恢复路径 |
| --- | --- | --- |
| 首次进入/加载 | 默认人物与搭配正在本地准备，不索取照片 | 真实加载失败给出原因和重试/静态操作，不伪造 AI 进度。 |
| 三维就绪 | 当前真实模型、已应用造型与观察控制 | 选衣、编辑、观察、保存；照片为独立可选入口。 |
| 编辑草稿 | 草稿与已应用状态可区分 | 撤销、取消或保存；非法参数/组合定位问题，保留上一有效造型。 |
| 渲染失败 | 新预览未应用，不把旧图标为新结果 | 重试或原生静态操作；合法结构化配置仍可保存，旧 revision 不作新封面。 |
| 保存失败 | 草稿保留，尚未保存 | 重试或取消，不以预览 ACK 代替事务成功。 |
| 角色已删除 | 历史中角色已删除、独立服装与真实记录保留 | 可主动创建默认角色，禁止旧回调或历史参数自动复活。 |
| 等待用户确认 | 处理后预览、一次性/本机复用范围和删除说明 | 确认、换图、移除自拍或返回模板。 |
| 本地检查中 | 有限步骤、可取消说明 | 取消并清理本次临时内容；保留原形象。 |
| 建议更换 | 一个中性技术原因 | 换一张或使用模板，不允许无说明死循环。 |
| 照片项目离线不可读 | 明确说明所选项目当前无法读取 | 选择本机照片、稍后重试或使用模板。 |
| 设备能力不支持 | 当前照片能力不可用，不暗示用户身体有问题 | 使用模板或拼图，核心流程继续。 |
| 存储不足或流程中断 | 本次设置未完成，旧形象未被覆盖 | 清理空间后重试；下次启动可重新开始。 |
| 删除中 | 形象和照片立即隐藏，明确仍在清理 | 等待或离开页面，系统继续受控处理。 |
| 删除失败 | 媒体保持隐藏，显示尚未完全删除 | 重试或进入支持路径；不得恢复旧预览。 |

## 成功指标及防误导指标

### 成功指标

- 零账号/照片/自有衣物用户完成“内置选衣—真实换装—观察—保存—重启恢复”的比例；照片权限弹窗和网络请求为零。
- 真实衣橱用户完成推荐和保存的比例单独统计，不把模板造型当作已拥有衣物。
- 从进入数字形象页到无照片模式就绪的中位时间。
- 主动进入照片流程后的用途说明理解率、完成率和主动退出率。
- 合格照片首次通过率、可恢复失败后的重试成功率。
- 一次性照片在成功、失败、取消与中断后的清理完成率。
- 删除请求完成率、超时数、失败重试成功率和资产复活事件数。
- VoiceOver、最大辅助字号和 Reduce Motion 下的核心流程完成率。

### 防误导与护栏指标

- 无照片用户的推荐数量、保存成功率不得低于照片用户的等价结构化路径。
- 首次进入 OOTD 的照片或相机权限弹窗触发率必须为零。
- 不把打开照片说明页、查看预览或点击试穿计为实际穿着或推荐成功。
- 不通过默认勾选长期保存、捆绑同意、重复弹窗或隐藏跳过入口提高照片转化率。
- 严重失真、意外裸露、肤色改变、辅助器具或宗教服饰被擦除必须单独统计，并作为关闭能力的依据。
- 删除只有在所有已承诺范围完成后才计为成功。

## 依赖与风险

- 无照片模板和单品拼图需要与衣橱、推荐、穿搭记录保持一致降级。
- 照片质量门槛可能对不同肤色、体型、身高、残障、辅助器具、宗教服饰和性别表达产生差异失败率。
- 系统照片项目可能位于云端，断网时无法读取；不能因此请求更宽图库权限。
- 图片损坏、超大文件、低存储和 App 中断可能留下临时内容，需要验证完整清理。
- 长期本机复用会扩大敏感数据保留，需要先确定期限、备份排除和撤回体验。
- 任何离机处理都会引入供应商地域、保留、训练、子处理者和删除证明风险。
- 视觉结果可能造成身份、身体、肤色、衣物细节或辅助器具失真，必须保留安全回退和关闭能力。

## 发布门禁

### 风格化无照片能力

- 新安装、无照片、无自有衣物、无登录、无网络且不授予新权限时，完成内置选衣、真实几何换装、正侧背/水平观察、Look 保存及重启恢复。
- 正式人物/服装三视图、全部发布组合与体型采样通过视觉及基础遮蔽验收；仅颜色变化、胶囊占位、图片或 360 视频均不算真实资产完成。
- 草稿/已应用/已保存状态一致；非法资产、迟到 revision、渲染进程终止和保存/删除中断可恢复，不复活私人外观；覆盖 AVATAR-ACC-010～018。
- 自动待机只在角色可见且 Reduce Motion 关闭时连续绘制；页面隐藏、销毁或 Reduce Motion 开启时停止装饰性动画帧。最低硬件性能/热/内存门禁与模拟器功能验证分开记录；模型格式通过不代表画质或性能通过。
- 所有模板选择由用户主动完成，不存在人口属性自动推断。
- 视觉边界说明和关键操作通过本地化、Dynamic Type、VoiceOver 与 Reduce Motion 验收。
- 删除或停用形象不会破坏衣橱、搭配和历史事实。

### 本人照片能力

以下任一项未通过时，照片个性化必须默认关闭，但无照片能力可独立发布：

- 本人且 18+ 的确认发生在系统选图前，且没有未成年人或他人照片通路。
- 本地无照片路径不显示年龄确认；人物声明策略版本改变后，新的选图或含人物生成会重新确认，登录状态不会被当作年龄证据。
- 多人、模糊、遮挡、异常格式和低能力设备均有中性、可恢复的本地路径。
- 元数据移除、一次性生命周期、异常启动清理和删除链具备自动化与最低支持真机证据。
- 不同用户群体的失败率和严重失真经过授权测试；发现意外裸露或重大偏差时能够远程关闭入口。
- 实际权限、数据流、保留和删除行为与用户说明、隐私政策和商店披露一致。
- 云端能力只有在其独立供应商、同意、地域、删除和内容安全门槛通过后才能启用。

| ID | 当前需求 |

| `AVATAR-REQ-017` | 无人物照片、无账号且断网时，可从内置模板调整外观与有限体型，查看三维角色；无需输入真实身体尺寸或推断个人属性。 |
