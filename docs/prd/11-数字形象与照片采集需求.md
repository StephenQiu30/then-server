# 数字形象与照片采集需求

更新：2026-09-30。需求方向按本轮用户授权修订；实现、本人照片质量、真实费用及真机验收均待验证。依据为本轮独立公开调研《Woo 虚拟人偶：成本与技术选型修订（V2）》与当前会话，仓库决策入口见 [Design 29](../design/29-Woo虚拟人偶与自用成本决策.md)，不以既有代码、设计或旧计划反推需求。

## 当前人物合同

产品为本人个人自用工具，不公开上线。目标是以本人为参考的 **Woo 式半写实三维人偶**：接近本人的正常身体比例，保留脸型、眉眼关系、发型/发色、肤色、眼镜与体形等可辨识特征；造型与表面适度简化，明显具有虚拟人偶和雕塑感。真人照片质感、皮肤毛孔、默认大头 Q 版和日系大眼均不是默认目标。

当前主线为：本人照片 → 确认本人虚拟形象参考 → 按固定风格生成每日 Look 图片 → 本人确认 → 按需生成完整静态 GLB → 本地保存、连续旋转和复用。人物参考首先是图片参考，不冒充参数化三维身体。每套 GLB 是该套穿搭的完整静态实体；新衣物组合先产生新图片，随后可另生成模型。

首版不要求三个人物、六套正式资产或所有造型随安装包交付。没有本人参考或生成结果时，今日页提供建立形象、导入照片和查看已有记录的真实空态，不用虚构人偶冒充本人。衣物、日期和搭配草稿仍可保存；尚未生成视觉结果不能标成已生成 Look。质量准入采用第一个本人样本与五套本人穿搭 POC，当前未通过。

## 现行需求与验收断言

以下需求为当前产品合同。旧验收编号与旧计划只保留历史追踪，不能证明本版已实现或已验收。

| ID | 规则 | 可观察验收断言 |
| --- | --- | --- |
| `AVATAR-REQ-001` | 不选人物照片时仍可管理衣物、保存结构化搭配草稿和查看已有记录；本人形象生成需要合格输入 | 拒绝照片权限不阻断上述旅程；没有结果不展示虚假成功 |
| `AVATAR-REQ-004` | 处理前可看见目的、处理位置、保留、删除与不生成替代路径 | 本机准备、图片生成与模型生成分别说明，不用照片选取授权所有云用途 |
| `AVATAR-REQ-005` | 上传前移除位置、设备、原文件名等非必要元数据；未经明确选择云用途不得离机 | 本地导入无外部提交；上传的是已确认且净化的当前输入 |
| `AVATAR-REQ-006` | 多人、第三方或来源不明照片提示重新选择，不自动裁剪为本人继续生成 | 拒绝时保留草稿，外部生成提交为零 |

| `AVATAR-REQ-009` | 本地复用、云生成、同步与训练是不同目的；首版不引入跨设备同步或训练 | 云入口显示实际供应商与输入；不自动上传历史或用于训练 |
| `AVATAR-REQ-010` | 取消、失败、过期和删除按对象范围清理临时副本；完成状态必须有真实依据 | 本地清理失败可恢复；外部尚未确认删除时不宣称已删除 |

| `AVATAR-REQ-015` | 照片导入与视觉生成不自动登记实际穿着或确认计划 | 保存媒体与“实际穿过”是独立动作 |
| `AVATAR-REQ-032` | 首版采用本地随包脚本的 Three.js / GLTFLoader 展示校验后的 GLB；原生页面管理状态 | 不加载远程执行脚本；图片不能抵扣真实 GLB 连续观察 |
| `AVATAR-REQ-034` | 静态舞台按交互需要重绘；不可见、后台停止绘制，退出释放资源；辅助功能可完成核心观察 | 后台不持续绘制；VoiceOver、最大字号、Reduce Motion 可用角度/缩放/复位控件完成查看 |
| `AVATAR-REQ-035` | 首版不宣称眼球、眨眼、表情、骨骼动作、布料模拟或即时衣物网格替换 | 用户文案和验收不将整套模型切换称为实时换衣 |
| `AVATAR-REQ-036` | 首版不依赖 Blender；可选修模另记人工时间与费用，来源、许可、版本和文件摘要可追溯 | 所选产物具有来源记录；免费工具不被描述为零总成本 |
| `AVATAR-REQ-041` | Look 内容版本与日期、收藏等记录元数据分离；草稿可保存和恢复 | 改日期、收藏或取消编辑不触发生成；保存失败不丢草稿 |
| `AVATAR-REQ-042` | GLB 只关联同一已确认图版本；校验后原子发布，可连续旋转、有界缩放和复位 | 错图、坏包、迟到回调不覆盖当前造型；重看已有有效模型不生成 |
| `AVATAR-REQ-043` | 图片可独立保存，只有明确选择“生成立体”才创建模型任务 | 等待或模型失败保留图片与日期；旧模型不贴新衣物标签 |
| `AVATAR-REQ-044` | 已确认图片可主动保存或系统分享；私人备份导出与对外图片分享分开 | 不自动公开链接；分享图净化；私人备份可含本人主动选定的原照、满意图、GLB 与元数据，说明外部副本不受 App 删除控制 |
| `AVATAR-REQ-045` | 本人 Woo 式虚拟人偶是首版人物目标；无公共账号、社区、订阅或多人预设硬门槛 | 空态到首个本人 Look 的旅程不依赖登录或购买预设包 |
| `AVATAR-REQ-046` | `AvatarReference` 与 `StyleProfile` 分别版本化，Look 冻结两者版本 | 修改风格或重新建立本人参考不覆盖旧 Look；不能只存一份可变“人物设置” |
| `AVATAR-REQ-047` | 建立形象选择有效本人照片，推荐清晰正脸与完整全身；实际数量服从已验证端点和质量要求 | 提示缺脚/遮脸/模糊；单图是否足够不预先保证；补充自拍/真实侧背由本人选择 |
| `AVATAR-REQ-048` | 先查看并确认本人虚拟形象参考，再用于 Look；真实侧背输入与 AI 补出的侧背分开标记 | 未确认参考不自动作为默认人物；可保留/放弃/另建版本；推测视角不标为实拍 |
| `AVATAR-REQ-049` | 真实每日穿搭和尝试新搭配分开标记；内容版本冻结人物、风格、衣物或整套照片的来源摘要 | AI 尝试不自动变实际穿着；旧图、模型与新输入不能混标 |
| `AVATAR-REQ-050` | 生成式参考不保证身份硬锁、相同三维头部或相同拓扑 | 本人核对跨套特征；明显换脸不得以“风格化”解释；失败进入改输入或模型的有限实验 |
| `AVATAR-REQ-051` | 满意图片/GLB、任务和费用持久到本地；媒体文件与元数据分开，支持私人备份 | 已下载满意资产离线与重启可用；仅保存远端任务 ID/URL 不算资产已保存 |
| `AVATAR-REQ-052` | 文件先完整下载、校验，再发布引用；显示就绪与保存成功是不同事实 | 中断、低存储、解码错误不留下成功引用；恢复不重复提交生成 |
| `AVATAR-REQ-053` | 更换当前参考是保留历史版本；删除参考是明确的血缘删除动作 | 两个操作入口与影响不同；删除范围含私人衍生资产，但不清除独立事实 |
| `AVATAR-REQ-054` | 本人决定是否接受云处理；实际处理方、保留与删除能力未知时不可宣称已核验 | 本地准备仍可完成；未授权云用途不提交；API Key 不进入图片、分享文件、日志或预览脚本 |
| `AVATAR-REQ-055` | 所有生成由显式动作触发，记录图/模型各自尝试次数和费用，已有同套满意资产优先复用 | 打开、旋转、改日期、收藏及同套复用产生新的计费提交为零；成本规则见 PRD 14 |
| `AVATAR-REQ-056` | 一套本人可旋转结果后，以同一确认参考版本验五套典型穿搭的质量、费用和本机展示 | 五套 POC 尚未完成；精选图、合成包或历史技术测试不抵扣本人验收 |

## 功能流程与失败恢复

| 操作 | 输入与正常结果 | 失败/取消及持久化 |
| --- | --- | --- |
| 建立本人参考 | 选本人正脸/全身 → 本地质量检查与用途确认 → 生成少量人偶候选 → 本人核对并确认 | 不满意只保存实验结果和费用；不将候选自动设为本人。取消保留已有满意参考，临时输入按保留策略清理 |
| 设定风格 | 保存已确认人偶图、比例、材质简化与构图规则为风格版本 | 改风格新建版本；旧 Look 保留其原风格，不重做所有历史 |
| 记录每日 Look | 当天全身照 + 本人/风格参考 → Look 图 → 确认 → 日期、来源类型和收藏保存 | 出图失败仍可存搭配草稿；图片不满意不自动转三维；日期/收藏修改不重新生成 |
| 尝试搭配 | 本人/风格参考 + 明确衣物图 → 新 Look 图 → 确认后可选三维 | 超端点参考图上限或未验证类别明确提示，不静默丢单品；流程与状态见 PRD 14 |
| 查看立体 | 已确认图 → 主动请求模型，或加载该图已有校验 GLB → 正面/拖动/缩放/复位 | 模型等待、下载失败或坏模型显示原因并保留图片；重试已有下载与新计费生成分开 |
| 保存/恢复 | 写入文件后保存稳定 Look ID、内容版本和元数据；重新启动找回当前版本 | 保存失败保留草稿；未完成下载显示未保存/待恢复，不能提示离线可用 |
| 删除/备份 | 明确选择仅删模型、删 Look 或删本人来源；可主动导出私人备份 | 先隐藏再清理；低存储/失败可恢复；外部已导出副本由本人管理，不声称远程撤回 |

### 数据不变量

- `AvatarReference` 冻结本人源照片、已确认人偶参考、真实/生成视角标识及确认时间；`StyleProfile` 冻结风格参考与规则。二者独立 ID、版本和摘要。
- `LookRevision` 冻结上述版本、真实穿搭/尝试搭配类型、输入摘要、衣物快照、确认图片与确认时间；日期/收藏不改变内容身份。
- `RenderAsset` 只归属指定 Look 图版本与摘要，记录供应商/模型/参数、可获得的版本或 seed、文件摘要及校验状态；固定 seed 不等于身份硬锁。
- `GenerationJob` 和 `CostRecord` 记录每次请求、供应商任务 ID、输入版本、提交已知/未知、阶段、过期及估算/实际扣费。未核验供应商幂等能力时不假定可重发。
- 停止未来云用途、取消当前任务、删除源参考或结果是分别选择的动作；仅停止未来用途不自动取消在途任务或清除已有媒体，已确认的取消与删除才触发各自范围的阻止发布/清理。
- 文件与数据库原子性、待清理标记和资源释放要有可恢复行为；具体存储实现由本版设计确定，旧数据库方案不构成此需求的前置。

## 本人 POC 与当前验收

以简单衣物、外套、长裙/宽裤、图案、鞋包/眼镜等五套本人穿搭测试同一参考版本。逐套确认 Woo 人偶感、可辨识本人特征、跨套稳定、衣物颜色/轮廓/单品、正侧背连续观察、严重融合/缺失及实际愿意保留的结果。严重换脸、缺衣、肢体异常或鞋包明显融合的结果不得作为满意资产。

同时记录所有图片/模型付费尝试、放弃原因、人工修复时间、资产体积与实际本机表现；HTTP 成功不等于满意。首个样本和五套 POC 均为待做实验，不是正式资产已通过。文档修订不授权上传本人照片或立即计费；实验需本人明确云用途、API Key、输入和预算。

已保存满意文件重启后离线打开、连续切换 30 次、旋转 5 分钟及后台/退出释放为本机验证旅程。缓存呈现约 3 秒、拖动至少 30fps 是待具体设备验证的初始目标，不能宣称已有最低设备通过。输入、云处理接受度和实际手机仍须在实验前确定。
