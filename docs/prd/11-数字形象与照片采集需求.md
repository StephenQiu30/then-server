# 数字形象与照片采集需求

更新：2026-09-22，需求 `approved`；新路线实施 `pending`。按照用户本轮授权，以完整 Look 图片和整套静态 GLB 替代旧独立三视图及模块人物首版要求。照片本地准备的已验证行为继续有效，生产入口仍受原门禁。

## 当前人物合同

三套自有/授权可爱成人预设、每人物两套完整 Look；先一个代表样本，再扩内容。每人物至少一套图片/GLB 随包。零账号、零照片、零用户衣物、断网可选择完整 Look、旋转/缩放/复位并保存恢复。内置选择不发生生成费用；任意新组合另走 PRD 14。

模型为固定姿势整套实体，不要求单件衣物可拆卸、同骨架、体型编辑或眼部动作。Three.js 保留真实连续观察，图片是先显示内容与故障回退；图片和视频不能抵扣 GLB 交互验收。

## 本人照片规则

一张本人全身照为最小可选输入；自拍增强和长期复用均非首片必填。系统 picker 只读取用户选定项，端侧检查、净化与确认后才可进入单独获准的云用途。无照片和衣橱/记录路径不能被阻断。内置虚构成人预设是产品授权素材，不要求用户声称预设是本人；个人照片规则只适用于真实人物来源。

| `AVATAR-REQ-014` | 同一 OOTD 用于人物参考与衣物拆分属于两个目的；用户逐项选择，未选择人物参考时不得保留可复用人物源图或创建照片形象。 |
| `AVATAR-REQ-015` | OOTD 照片处理默认只向衣橱交付待确认衣物草稿和组合草稿，不自动创建 `OutfitPlan` 或 `WearEvent`。 |

本机准备、图片生成与模型生成是不同目的。不得用一次照片准备同意授权所有后续处理；同一 OOTD 若用于人物参考和衣物拆分，用户分别选择。只拆衣物时不留可复用人物参考。输入质量与临时清理细则见 [Design 04](../design/04-数字形象与照片采集设计.md)，既有 11-01 继续按原测试边界推进。

## 用户可见状态

默认图片、模型加载、三维就绪、编辑草稿、图片生成、模型生成、保存中/失败、媒体已删除分别表达。没有新的可用模型时继续显示当前图片及原因；旧版本只作为历史查看。应用场景成功与数据库保存成功分开，未 ready 不提示已经显示新造型。

VoiceOver、最大字号、Reduce Motion 与减少透明度必须完成同等核心旅程。直接观察可通过原生角度/缩放/复位控件操作，不要求复杂手势。每类视觉持续可见“AI/模板视觉示意，非尺码或真实合身”说明。

## 发布门禁

正式六套完整 Look 的画风/衣物/脸部、连续观察、来源和静态 GLB 预算通过；本地保存/重启/删除、坏包/迟到回调和最低真机通过。图片生成/3D 生成各自完成供应商、同意、数据地域、质量、费用与删除验收；本地包不等待未启用的云能力。照片真实人群质量、公平性与设备门禁仍按 11-01/Acceptance 11，不能由合成资产替代。

### 数据与显示不变量

- `Look` 是用户保存实体；`LookRevision` 冻结人物来源、衣物参考快照、图片身份；`modelAssetID` 只能关联同一图片摘要。表/属性的最终名字由实际 GRDB 切片决定，此处是业务含义。
- 本地 ID 不要求云账号；以后上传只登记本地与云实体映射，不自动上传全部历史。账号切换不能把前一账号的任务/私人媒体映射给后一账号。
- 今日选中版本、编辑草稿、数据库已保存版本和 renderer 当前版本分别可查。模型加载 ACK 只影响显示；保存结果只影响持久化；两者不能互相代替。
- 文件先在受保护临时区完整写入并校验，再原子发布引用；数据库失败留下可回收文件，不能留下指向半个模型的成功记录。无账号内置母版按引用使用，删除用户记录不能破坏母版。
- “重置视角”仅调整相机；“切回默认”仅改变当前选择；“删除记录”是独立确认动作。上述操作不得共用一个含糊的“重置”入口。
