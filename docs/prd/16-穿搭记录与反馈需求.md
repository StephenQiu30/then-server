# 穿搭记录与反馈需求

更新：2026-09-30。状态：current_personal_use_scope；首版为单人本地“今日 / 衣橱 / 穿搭簿”，不公开上线。上位需求：[10-OOTD产品需求](10-OOTD产品需求.md)，研究依据：[29-Woo虚拟人偶与自用成本决策](../design/29-Woo虚拟人偶与自用成本决策.md)。需求修订不证明 App、供应商或真机验收已通过。

## 对象与事实边界

| 对象 | 表示什么 | 不自动表示什么 |
| --- | --- | --- |
| Look | 整套造型的稳定身份、标题和收藏，包含一个或多个内容版本 | 某天实际穿过或生成输入发生变化。 |
| LookRevision | 冻结的本人参考及风格版本、当天照片或手工选衣快照、已确认图片及可空静态 GLB；标明“真实穿搭照片”或“尝试搭配”来源 | 真实拥有、计划、实际穿着、推荐偏好或服装合身。 |
| 日期条目 / DateEntry | 穿搭簿中原本地日期/时区、当日备注与确定 LookRevision 的引用；同一 Look 可有多个日期条目 | 实际穿过。改日期不改变输入和模型。 |
| OutfitPlan | 本人明确“计划穿”的今日或未来组合及当时快照 | WearEvent。 |
| WearEvent | 本人确认当天/过去本地日期并点击“实际穿了”的完整或部分事实 | 自动满意反馈、推荐偏好或自动待洗。 |
| Feedback | 对一个仍有效 WearEvent 的可选感受/备注，明确提交、可编辑删除 | 新的一次穿着或已启用学习。 |

同一满意整套 Look 跨日期直接复用本地图片和 GLB，不重新付费。改变衣物、本人参考、风格或源图才形成新的生成输入与版本；日期、当日备注、收藏、标题、浏览和旋转本身不触发生成。收藏/标题属于 Look，当日备注属于 DateEntry，计划、实际和私人日记各自保存自己的日期/原时区。首版模型是整套静态人偶，复用不等于固定人体即时换衣。

## 当前可追踪需求

| ID | 当前行为 |
| --- | --- |
| OUTFIT-REQ-001 | 计划与实际分开；明确保存计划才创建 OutfitPlan，计划到期也不自动创建 WearEvent。 |
| OUTFIT-REQ-002 | 支持按计划、换了几件、穿了别套、最后没穿、无计划补录和部分记录；未知衣物不补造，计划与实际差异保留。 |
| OUTFIT-REQ-003 | 穿后反馈可跳过、纠正、删除，空值是未回答。首版支持本人主动简短感受/备注；四维结构化反馈及推荐证据学习不作为核心保存前置。 |
| OUTFIT-REQ-004 | 衣物当前状态与历史分离；如记录待洗等变更，必须本人逐件确认，与实际记录共同成功或共同失败；不默认勾选。 |
| OUTFIT-REQ-005 | 穿搭簿有日期时间线、月历、收藏和详情，支持编辑删除及再次应用；复用历史前说明当前衣物差异，不直接新增实际穿着。 |
| OUTFIT-REQ-006 | 本地无账号、离线可保存、查看、修改、删除、复用与反馈；已有媒体从本地文件读取，无图时文字历史仍可用。 |
| OUTFIT-REQ-007 | 导入、保存 Look、生成、浏览、收藏、下载/分享均不能增加实际穿着或偏好；事实确认是独立动作。 |
| OUTFIT-REQ-008 | 私人照片/形象、衣物、Look、日期条目、计划、实际和反馈分别说明删除影响；删除后不让任务/快照恢复已删私有数据，统计按剩余事实重算。 |
| OUTFIT-REQ-009 | Look 独立保存本人/风格参考版本、输入快照、已确认图片和可空 GLB；允许先保存无模型结果/有效草稿，图片和模型归同一版本，不借用其他版本封面。 |
| OUTFIT-REQ-016 | 日期条目保存稳定 ID、原本地日期/时区和确定的 LookRevision 引用。同日可多套，同一 Look 可跨日期引用；历史编辑当前选择不会倒灌已存版本。 |
| OUTFIT-REQ-017 | 复用同一满意资产、关联新日期、收藏和旋转不调用供应商；重新生成须明确选择新输入/参数并确认费用，不能因打开页面而付费。 |
| OUTFIT-REQ-018 | 每个在途任务固定 Look ID/revision、源图内容、本人/风格版本及任务身份。晚结果只归原版本；原对象已删或输入被撤销时不复活，不覆盖另一日期或当前新 Look。 |

反馈可以只是本地回看信息，当前不启用自动偏好学习。高级天气算法和推荐延期见 [13-穿搭推荐需求](13-穿搭推荐需求.md)。私人日记/月历关系见 [19-每日记录与穿搭社区需求](19-每日记录与穿搭社区需求.md)，社区及账号平台不属于本轮。

## 用户流程

| 流程 | 正常完成 | 取消 / 失败 / 恢复 |
| --- | --- | --- |
| 保存今日 Look | 当天照片或手工选衣 → 看源图与人偶结果、确认/标记来源 → 选日期 → 保存 LookRevision 与日期条目；GLB 可空 | 不满意可保留草稿/源图再做；模型失败不影响已存图和日期；取消不新增，保存失败保留输入。 |
| 保存/编辑计划 | 从当前组合或历史选择 → 明确“计划穿” → 确认日期、衣物快照 → 保存 | 当前衣物已改/删或不可用时显示差异并重新确认；取消不创建实际；取消/删除计划保留独立实际记录。 |
| 确认实际穿着 | 本人选择今天/过去日期 → “按计划 / 换件 / 别套 / 无计划” → 复核实际单品和完整度 → 明确“实际穿了” → 保存 | 未来日期不能记为实际；部分记录合法；相似同日记录先提示检查，本人确认后允许真实多次穿着。 |
| 最后没穿 | 对计划明确选择未穿，可选原因 | 不创建 WearEvent，不自动给整套衣物负面偏好，不要求填反馈。 |
| 反馈 | 实际穿着保存后可填简短感受/备注或跳过 | 跳过不创建空反馈；取消不变更；编辑删除不重复计数，实际已删时拒绝保存反馈。 |
| 日期回看 / 收藏 | 时间线或月历进入详情 → 查看当时版本、来源和事实标签 → 收藏/取消 | 无图用文字，坏 GLB 保留图；收藏不生成，不创建计划或实际。 |
| 再次应用 | 选满意历史 Look → 复用本地结果 → 关联新日期；如需计划另点“计划穿” | 仅日期变化不重做；原衣物当前不可用时提示。只有本人改变造型并确认新生成才可能收费。 |
| 编辑 / 删除 | 修改 DateEntry 日期/当日备注或 Look 标题/收藏只更新对应元数据；改造型保留旧版本并新建输入；删除前列受影响对象 | 取消不变更；冲突留草稿；只删一个日期条目不删除其他条目引用的资产，不误删独立实际/反馈。 |

真实穿搭照片的来源标签只说明素材，不代替“实际穿了”确认。照片未对应衣橱稳定单品时，不从 AI 外观猜出衣物身份和穿着次数；可保存 Look 或部分实际记录。

## 持久化、版本和费用

本地分别保存 Look 稳定 ID 与元数据、LookRevision 内容快照和媒体引用、DateEntry 日期/原时区/当日备注与版本引用；计划、实际和私人日记另存各自事实。生成任务只引用 LookRevision 与固定输入。共享满意资产不因多个日期复制生成，一条日期删除不误删其他有效引用。

字段与文件必须保持可恢复的一致性：新文件准备好才提交可读元数据，失败留旧版本；中断后无半条记录和无效新封面。明确保存命令具有本地稳定身份，重复点击/重试不生成重复 Look/计划/实际；真正同日多次穿着需本人明确第二次保存。不可将 WebView 渲染成功当作持久化成功。

旧版本保持可回看，当前草稿独立。在途任务结果标明所属版本并由本人确认；编辑参考/选衣后旧结果不得自动晋升为新版本。请求发送后响应丢失显示“提交结果未知”，先核对任务，不自动付费重发；供应商结果下载完成并保存本地后才承诺离线查看。结果过期/丢失如实显示，不用旧图替代本次成功。

只删除渲染缓存不会删除满意模型。删除整个 Look/本人参考则展示直接派生媒体和所有日期引用影响；独立计划/实际文字事实按本人确认保留脱敏占位或删除，已删私有媒体拒绝被旧任务/缓存重新关联。任务、费用记录与隐私清理策略跟随 PRD11/14，不承诺云副本已经删除。

## 待验收标准与追溯

- 本人完成“照片/手工选衣 → 确认图片 → 保存日期/收藏 → 重启离线回看 → 编辑删除”；模型尚无或失败不阻断。
- 保存/生成/收藏/关联日期均不创建 WearEvent；按计划、换件、别套、无计划和部分实际只有明确确认后计数，未穿不计。
- 同套满意模型跨日期直接复用，浏览、旋转和收藏零供应商请求；新造型费用需明确确认。
- 修改衣物、参考或风格创建新输入，旧历史不倒灌；交叉顺序/迟到结果、删除时在途返回不能串 Look、日期或版本。
- 单条日期删除、仅图/模型删除、整套删除及形象删除均符合影响说明；共享文件不误删，已删内容不复活。
- 反馈可跳过、编辑撤回，删除实际时清除相应反馈与计数；不自动推断偏好或状态。
- 真实本地保存失败/存储不足/进程中断/重复命令不产生半条或重复事实；跨时区和午夜不改原日期。
- 最大辅助字号、VoiceOver、无图片及减少动态效果下能完成主要动作，状态标签不只靠颜色。
