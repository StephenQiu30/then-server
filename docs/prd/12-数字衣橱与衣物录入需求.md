# 数字衣橱与衣物录入需求

更新：2026-09-30。状态：current_personal_use_scope；需求已按本轮用户决定修订，新增链路待实现与验收。本次文档变更不认领旧代码、接口或测试已经满足新范围。

上位需求：[10-OOTD产品需求](10-OOTD产品需求.md)。研究依据：[29-Woo虚拟人偶与自用成本决策](../design/29-Woo虚拟人偶与自用成本决策.md)。首版供本人自用，不公开上线，一级入口为“今日 / 衣橱 / 穿搭簿”。

## 目标与范围

衣橱用于保存本人真实拥有的衣物照片和手工类别，逐件积累即可使用；不要求一次录满衣柜。首版提供相机/系统选图、无图手工新增、分类浏览与简单搜索、编辑、换图、删图、删除及手工选衣。名称与类别由本人确认，图片可空；扩展属性、自动识别、推荐天气算法和同步均不是保存前提。

衣橱条目是二维照片与元数据。今日可使用本人当天全身穿搭照片，或手工选择衣物形成尝试搭配。本人参考、风格参考及 Look 的生成由 [11-数字形象与照片采集需求](11-数字形象与照片采集需求.md)、[14-AI虚拟试穿需求](14-AI虚拟试穿需求.md) 定义。首版不为每件衣服创建三维服装；整套静态 GLB 属于某个 Look 版本，不能表述为可即时换装的独立衣物资产。

零衣物时显示“拍摄今天的穿搭 / 添加第一件衣物”，仍可从全身照片创建 Look。内置目录、随包完整人偶、品牌素材库及零录入即时换衣不再是首版门槛。若后来采用参考素材，须标明来源，不能自动记为本人拥有。

## 用户流程

| 流程 | 输入与正常完成 | 取消、失败及恢复 |
| --- | --- | --- |
| 拍单件 / 系统选图 | 明确单件用途 → 本人拍摄或选择图片 → 本机预览/裁剪 → 手工名称与类别 → 确认保存 → 衣橱出现稳定条目 | 拒绝权限、取消选图或解码失败不新建；可换图或无图保存。不会要求全图库授权。 |
| 无图新增 | 输入名称、类别、确认状态 → 保存 | 未确认或取消不写；未知扩展属性不补值；保存失败保留输入。 |
| 当天全身穿搭 | 从今日进入 → 检查脸、头脚及主要衣物完整 → 交给本人 Look 流程 | 多人、遮脸、缺脚或严重模糊提示重拍/换图；不自动创建多件衣物，不冒充已核验的穿着事实。 |
| 浏览与选衣 | 分类网格/简单搜索 → 查看名称、照片与状态 → 加入托盘 → 可替换/移除 → 复核后继续 | 空衣橱或无图不是错误；不完整组合可存文字草稿。需要图像的生成资格不足时说明具体项，不伪造合成。 |
| 修改 / 换图 | 从稳定 ID 读取当前 revision → 本人修改 → 保存新 revision | 图片处理或写入失败保留旧图、旧字段；取消回到原值；照片按原比例展示。 |
| 只删照片 | 预览直接依赖影响 → 确认 → 隐藏并清理 → 文字衣物保留 | 清理失败可重试；不显示假完成，不清空独立历史事实。 |
| 删除衣物 | 展示 Look、计划及实际记录引用 → 选择保留“已删除单品”历史占位或删除明确列出的关联内容 → 确认 | 取消不变更；影响列表过期时重新确认；不可误删仍被其他条目引用的共享媒体。 |

单件衣物可由本人手工裁剪主要单品；不把前景掩膜叫作自动衣物分割。商品截图先手工去除地址、订单及无关人物；专门商品导入、自动净化和批量拆分不在首版。本人的整套照片可以作为 Look 输入，不必先拆成衣橱条目。

## 本地持久化与任务边界

衣物元数据存本地库，媒体存沙盒文件，稳定引用与内容版本共同记录。文件准备完成后才提交可读元数据；失败与中断不得留下“保存成功但找不到新图”的条目，临时文件可恢复清理，已有媒体不被提前覆盖。未保存草稿与已保存条目分开，退出时说明未保存，重启可恢复的草稿标明身份。

提交生成前再次复核选衣 ID、revision 和图片，变动时保留选择并要求本人决定。冻结后更新托盘、改日期或编辑衣物不改写在途任务输入；晚到结果按原 Look 版本回收，不能覆盖当前另一套搭配。提交结果未知时不自动重发，费用和恢复规则归 PRD14/17，研究报价归 Design29。

离线可维护衣橱、手工草稿与已有 Look。新云生成需要网络，但不能阻断基础管理；恢复网络不自动上传本地记录。不承诺同步、系统相册原件永久可用或供应商 URL 永久有效。

## 待验收标准与追溯

- 在无账号、无网络、拒绝相机/完整图库权限时，能完成无图新增、分类浏览、选衣、编辑与删除；不依赖推荐服务。
- 拍摄/导入一件衣物，手工确认后保存，关闭重开条目与文件一致；换图失败不丢旧图，重复点击或重试只产生一次明确保存。
- 从衣橱手工选择搭配，未点生成不请求供应商；四参考上限、不合格/缺图、版本变更均有可恢复说明，不能静默漏衣。
- 改名、换图、归档或删除后，已有历史保持当时快照；只删图、删条目及删关联历史的影响符合本人选择，无旧缓存/任务复活。
- 存储不足、写入失败、进程中断与离线均无半保存；图片缺失时文字路径仍完整。
- 最大辅助字号、VoiceOver、仅文字状态及减少动态效果下可完成核心旅程；类别、状态和错误不只靠颜色表达。
- 当天全身输入不自动产生拥有或实际穿着；同套满意资产复用不请求生成、不增加生成费。

功能验收入口保留 [12-数字衣橱与衣物录入验收](../acceptance/12-数字衣橱与衣物录入验收.md)，其中 WARDROBE-ACC-020/021 的选衣/快照关系需按本轮范围重验；旧结果仅证明原测范围。新增需求从 WARDROBE-REQ-038 递增，本轮未新增/完成执行切片，也未宣布任何验收通过。编码前须更新对应 Design/Plan/Acceptance 的覆盖和证据，旧 Web/云合同不能替代本地 App 验收。
