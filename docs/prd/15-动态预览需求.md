# 动态预览需求

更新：2026-09-30。动态生成与动作能力 **deferred**；静态立体观察 **scope_confirmed**，实现、本人模型质量与设备验收仍待验证。本轮用户目标为个人自用的 Woo 式本人虚拟人偶；首版用完整静态 GLB 的本地连续旋转满足立体观察，不购买视频、自动绑定或动作服务。旧 pending/blocked/技术测试状态不改为通过。依据见 [Design 29](../design/29-Woo虚拟人偶与自用成本决策.md)。

## 当前静态观察合同

静态模型旋转是相机/观察交互，不等于人物转身动画。今日或详情首先显示已确认 Look 图片，有同版本校验 GLB 时可主动查看正面、拖动旋转、有界缩放与复位；无模型、加载/校验失败继续使用图片并明确原因。图片或 MP4 均不抵扣可连续观察的真三维验收。

首版不要求走路、眨眼、眼球注视、表情、骨骼动作、发丝物理、布料模拟、即时替换服装网格或 5–10 秒 MP4；这些不是当前模型采购、完整人物结果或个人使用门槛。Woo 演示中的 Create 360° 不证明其内部格式或动作实现，本项目不据按钮名称增加视频需求。

| 新需求 ID | 当前规则与验收断言 |
| --- | --- |
| `MOTION-REQ-008` | 静态 GLB 观察归 PRD 11/14；主动查看、旋转、缩放、复位不提交图片/模型/视频生成，不产生额外推理费 |
| `MOTION-REQ-009` | 前后台、不可见暂停绘制，退出释放资源，按交互需要重绘；Reduce Motion 与辅助控件仍能完成观察，不需要持续待机动画 |
| `MOTION-REQ-010` | 首版不创建视频或动画资产/任务；整套静态模型切换不宣称骨骼换装、真人运动、眼球动作或真实背面 |
| `MOTION-REQ-011` | 动态能力只有本人另行明确需要、预算与质量收益可验证时才重新准入，不作为当前静态人物 POC 完成条件 |
| `MOTION-REQ-012` | 未来视频/动作分别定义输入、费用、供应商、状态、有效期、保存和删除合同；既有图片或模型用途不自动授权新的处理 |

## 首版流程与恢复

1. 当前已确认图显示“图片”；该版本具有已下载、校验 GLB 才提供现有模型查看，不显示假三维成功。
2. 打开立体先查询同版本满意本地资产，加载完成后显示就绪；重看只读文件，不重新生成。缺资产时主动“生成立体”转 PRD 14 的独立用途、预算与任务流程。
3. 可从正面连续观察正侧背并复位；地面、比例和构图一致，背面标为模型推测。静态姿态不需要骨骼或视频。
4. 加载坏包、低存储、解码错误或版本迟到时保留图和日期记录；重取已有文件与新计费生成分开，不自动隐藏重做。
5. 离开、后台、重启后可恢复 Look 选择与已保存资产；视角重置不删除结果，删除源/资产后的迟到加载不得复活。

五套本人模型的静态质量与费用 POC、离线恢复与实际设备性能见 PRD 11/14，当前均待验证。旧播放器、合成资产或 renderer 技术结果不能证明本轮本人造型、跨套稳定和满意成本通过。

## 后续能力登记

原编号永久保留，不删除、不复用。下表是延期原则，并非已批准首版供应商、采购或具体视频时长承诺；重新启动时按当时用途与成本另立输入及验收。

| 原需求 ID | 延期保留的语义 |
| --- | --- |
| `MOTION-REQ-001` | 从仍有效且本人确认的静态来源主动触发，不能因浏览/保存隐式生成 |
| `MOTION-REQ-002` | 原 turntableVideo/MP4 方案仅历史候选；未来实际结果类型明确标记，不称为 mesh、交互三维或真实背面 |
| `MOTION-REQ-003` | 如以后做视频，保留静态回退、播放/暂停、前后台与 Reduce Motion 合同；首版不要求播放器 |
| `MOTION-REQ-004` | 新处理方、用途、地域、输入、留存与费用独立明确，不复用静态同意 |
| `MOTION-REQ-005` | 原视频/poster/缓存/中间物/供应商副本的血缘删除原则保留，受控与外部导出副本分开 |
| `MOTION-REQ-006` | 质量、实际费用、时延、私人处理、本机恢复与删除证据齐备后才考虑启用；公开发布流程不作为个人首版前置 |
| `MOTION-REQ-007` | 动态观看、保留、导出和分享仍不等于实际穿着或偏好学习信号 |
