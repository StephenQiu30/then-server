# 动态预览需求

当前范围：2026-09-22 按低成本路线调整为 **deferred**。现行首版用静态 GLB 本地旋转满足立体观察，不调用 AI 视频；本文件只约束后续独立视频能力，既有 pending/blocked 场景不改为通过。Woo 的 Create 360° 按钮不能证明其内部产物格式，下述 MP4 是本项目的后续设计。

## 状态与上位需求

需求 approved_with_gates，实施 pending。更新：2026-09-15。后续能力保留独立 Create 360° 视频；当前未接入供应商或生成链路。上位 [PRD 10](10-OOTD产品需求.md)，设计 [Design 08](../design/08-动态预览设计.md)，验收 [Acceptance 15](../acceptance/15-动态预览验收.md)。

## 当前固定需求

用户从已确认且仍有效的静态结果主动生成 5–10 秒 MP4，以原生播放器观看。支持真实任务恢复、取消、重试、保存、下载、系统分享和删除；各能力按隐私/成本/质量门禁启用。视频与 Three.js/GLB 真 3D 是两种独立结果，均属于完整产品目标。

| 需求 ID | 当前合同 |
| --- | --- |
| `MOTION-REQ-001` | 只从用户已确认且仍有效的静态结果主动创建，不因页面曝光或保存自动生成 |
| `MOTION-REQ-002` | 结果类型是 `turntableVideo`/MP4，清楚说明 AI 生成，不标记为 mesh、可交互 3D 或真实背面 |
| `MOTION-REQ-003` | 静态结果先显示；原生播放器支持播放/暂停、前后台恢复、失败回退和 Reduce Motion 不自动播放 |
| `MOTION-REQ-004` | 动态 Provider、地域、输入、保留和删除取得独立当次同意 |
| `MOTION-REQ-005` | 删除覆盖视频、poster、manifest、设备缓存、对象存储、中间物和供应商副本 |
| `MOTION-REQ-006` | 质量、成本、延迟、内容安全、隐私、最低真机、恢复和独立开关全部通过后才能开放 |
| `MOTION-REQ-007` | 生成、观看、下载或分享都不是实际穿着或偏好事实 |

## 用户流程与失败恢复

1. 已确认的静态结果显示可用性；资格、同意、配额或供应商门禁不满足时说明原因，保留静态路径。
2. 用户查看当前用途、处理方/地域、费用和删除说明，独立同意后提交；以稳定任务 ID 恢复，不因重启重复计费。
3. 展示排队、处理、审核、可用、失败或取消中的真实状态，不做假进度；用户可离开、取消或稍后重试。
4. 通过质量检查的 MP4 原子发布，静态图先出现；视频可播放/暂停，后台暂停，Reduce Motion 不自动播放。
5. 明确展示生成视角的推测性；没有约定转身覆盖就不标记 Create 360° 成功。
6. 保存/下载/系统分享由用户主动触发，不自动建计划、记录实际穿着或偏好。导出副本不再受 App 删除控制，分享前说明。
7. 删除隐藏结果并清理全部受控副本；尚未物理完成就显示删除中/待重试，迟到结果不可复活。

## 业务规则与发布门禁

- 继承 PRD 17 的认证、owner、输入快照、幂等、取消、配额和删除规则，PRD 18 的目的隔离与撤回规则。
- 任务只引用已确认静态结果及明确版本；源失效或授权撤回后不可新建或重放旧结果。
- 动态生成与静态试穿使用独立同意、费用上限、开关和可用区域；Provider 候选能力不是生产承诺。
- 质量验收覆盖身份/衣物连续性、肢体缺陷、闪烁、裁切、声明的转身范围；延迟、成本、输出预算在授权 POC 后冻结，不虚构已测指标。
- 最低真机原生播放、弱网/坏文件/低存储、前后台、VoiceOver、减少动态、取消/删除竞态均须有证据。
- 不采集额外身体测量，不做尺码/合身/真实背面承诺；不增加帧序列拖拽 renderer 或多渲染器兼容层。

## 成功标准

验证用户能主动生成、离开恢复、播放、保留和删除一段合格视频，且静态/结构化穿搭始终独立可用。视频输出、下载或停留不作为实际穿着或偏好学习信号。所有发布门禁未关闭前，维持未开放状态。
