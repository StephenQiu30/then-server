# 产品需求文档

此目录存放产品需求文档。10 号文档维护 OOTD 产品总纲；11–19 号按“一个主要功能一份 PRD”维护用户价值、业务规则、可见状态、指标和发布门禁。PRD 不承担实现拆解；切片排入近期产品计划后、编码前，从已批准 PRD/design 创建一份同编号执行计划，在其中统一范围契约、任务与证据。

推荐模板：

```markdown
# 功能名称

## 状态
draft | approved | approved_with_gates | approved_principles | superseded

## 背景与问题

## 目标用户

## 产品目标

## 非目标

## 功能范围

## 用户故事

## 业务规则

## 用户可见状态与恢复

## 成功指标

## 依赖与风险

## 发布门禁

## 未决问题

## 追踪关系
```

PRD 描述用户价值和业务行为，不在其中锁定没有经过设计评审的实现细节。

`approved_with_gates` 表示需求边界已批准但生产启用仍受门禁；`approved_principles` 表示原则已批准、具体策略仍有阻断决策。两者都不得被实现或进度文档误写成“已上线”。

每份单功能 PRD 应为可独立追溯的业务规则或需求簇分配 `DOMAIN-REQ-NNN` 形式的稳定 ID。进入实现后，单切片执行计划声明覆盖哪些 ID，并由同一文件中的任务和证据反向追踪；已被引用的 ID 不因排序变化复用或重排。
