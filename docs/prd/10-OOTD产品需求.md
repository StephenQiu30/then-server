## 定位与用户任务

Then 是本人使用的每日穿搭工具：保存衣物和穿搭，以 Woo 式半写实三维人偶展示，按日期回看和复用。保留本人脸型、发型、肤色、眼镜和体形，同时有明确的虚拟人偶表达；不以真人扫描、皮肤毛孔、Q 版或默认二次元模板为目标。

核心任务为建立本人虚拟形象参考、记录当天穿搭/尝试衣物组合、确认图片后按需生成真实三维、本地保存复用、控制费用和导出备份。真实穿搭与尝试搭配分别标记；生成/保存/收藏不自动证明实际穿过，图和模型不保证尺寸、合身或未拍到的背面真实性。

## 当前开发范围：先验证人物与满意成本

首轮使用本人 5 套有代表性的穿搭，建立一个确认的本人/风格参考版本，对比原照片直接转三维与先生成 Woo 式人偶图再转三维。每套两条路径合计的 H 三维尝试建议最多 2 次，图片建议最多 2 次；实际付费前配置并确认消耗上限，P1 仅少量对照。

保留原图、不可变输入、生成图、可打开的真实 GLB、参数、耗时、实际扣费和本人评价。至少一套满意成果能连续旋转、保存与重启恢复，才证明最小闭环；五套成功/失败分别报告，单样本不代表跨套一致性或所有衣物通过。

建设顺序：人物实验 → 最小生成/展示/保存闭环 → 衣橱与日期回看 → 日常使用验证。高级推荐、动作、实时换衣、账号和同步不作为前置。没有实际证据的供应商、真机、费用与备份恢复保持待验。

## 完整产品批准主路径

1. 拍摄/导入本人正脸和完整全身照片，查看遮脸、缺脚、多人、模糊等提示；取消不创建任务。
2. 建立并确认虚拟人偶参考，保存独立本人参考与风格版本。
3. 输入当天整套穿搭或支持的衣物组合；显示输入、模型能力、预估费用和可用预算。
4. 本人主动生成人偶 Look 图片，核对特征、衣物和风格；满意图可独立保存。
5. 点击生成立体才创建模型任务；结果绑定已确认图片的不可变版本。
6. GLB 下载/校验/本地保存后可正面查看、连续旋转、有界缩放与复位。
7. 保存日期/收藏、复用同套；无网和重启可开。失败/过期/坏模型不破坏确认图片与已有记录。

参考图片不等于可换衣参数化人体；每套是独立完整静态模型，不承诺同一网格即时换衣或跨套脸型绝对一致。更换本人/风格参考只影响新版本，不覆盖历史成果。视频、几个角度图、封面或 HTTP 成功不代替真实三维。

## 页面与自用范围

一级导航为**今日 / 衣橱 / 穿搭簿**；我的形象和预算/API 设置有明确入口。相机/导入是新建动作，首版没有注册、登录、发现、订阅或公开发布流程。

| 页面 | 输入与动作 | 必须处理的状态 |
| --- | --- | --- |
| 今日 | 当前日期、满意 Look、关联衣物；新建/生成立体 | 空记录、图有模型无、离线、缺文件、失败 |
| 我的形象 | 本人照片、人偶参考、风格版本；确认/更换 | 权限拒绝、缺输入、不合格、取消、旧 Look 保留 |
| 拍照/导入 | 全身构图、相机/相册、原照与处理预览 | 多人、遮脸、缺脚、方向/模糊、云照片未下载 |
| 衣橱/选衣 | 分类、图片、手工属性与组合 | 无图、分类错、同类替换、超参考数量/类别 |
| Look 图片 | 原输入与结果对照；保存/手动重做 | 风格不符、换脸、改体形、衣物失真；不自动付费 |
| 任务 | 阶段、尝试、预估费用、预算、恢复 | 排队/执行/下载、提交未知、取消待核实、失败/过期 |
| 立体 | 正面、拖动、缩放、复位 | 坏包、资源不足、后台暂停、返回释放资源 |
| 穿搭簿 | 日期、真实/尝试分类、收藏、复用、改删 | 补记、共用模型、无图、删除影响、历史版本 |
| 设置 | Key、消费、限制、文件管理、导出 | 无 Key/预算、余额不足、缓存清理、满意资产保护 |

空/错状态提供实际下一步；等待不能展示虚假成功。日常页面不暴露无决策价值的供应商实现字段。

## 数据与事实边界

| 概念 | 保存要点 |
| --- | --- |

## 非目标与技术边界

首版不做真人扫描/量体/合身预测、布料仿真、实时 AR、即时独立服装替换、骨骼/眼部/视频、商城/广告/订阅、公开社区和通用工作流平台。

以 iPhone 为待确认目标：SwiftUI + SwiftData + 沙盒文件，Vision/Core Image，URLSession + Keychain，WKWebView + Three.js/GLTFLoader。先测 Tripo 图片编辑/H 标准三维，少量 P1/FLUX 对照；它们是候选，不是 Woo 实现结论。[技术与启用边界](../design/01-技术选型.md)

不预建公共后端、服务端数据库/队列和 GPU 平台。本文未删除或迁移既有工程；最低系统、依赖版本、数据迁移与实际接入在实施任务验证。

## 成本要求

金额与算式统一维护在[成本决策](../design/29-Woo虚拟人偶与自用成本决策.md#6-个人使用的成本预算)，记录报价日期/币种/模型/参数/不包含项；示例不是订阅、已批准预算或合格保证。

- 图片满意后才转三维，默认标准纹理，附加质量主动选择。
- Key、余额、预算/尝试上限不足时不接纳；预估、预留、实际与未知分开。
- 未核实费用继续占预算；不把未知当零，不静默重做、续费或切换付费供应商。
- 成功但不满意的产物也纳入费用；取消本地等待不自动意味着供应商取消/退款。
- 已有同套资产展示无重复调用；文件增长、备份、重签和人工适配也是成本。
- 固定人偶方案要算首次/新增衣物/维护，不能因其组合 API 费为零就判最便宜。
