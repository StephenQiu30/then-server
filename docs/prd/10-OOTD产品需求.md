# OOTD 产品需求

更新：2026-09-22。设计与需求 `approved`；新 Look 路线尚未实现。用户已授权以调研结果全面替换旧设计，现行主线是**完整穿搭图优先、整套静态 GLB 按需生成、版本缓存复用**。架构见 [Design 20](../design/20-OOTD完整产品能力与阶段架构设计.md)，实际完成情况见 [Plan 10](../plan/10-OOTD产品实施计划.md)。

## 定位与用户任务

于是是一款以数字衣橱、穿搭展示、每日决策与记录为核心的产品。新用户先用内置完整 Look 获得可见价值，之后自愿录入真实衣物、生成新穿搭并记录复用。图片与模型只表达视觉效果，不保证真实尺码、合身、垂坠、颜色或背面真实性。

首要用户任务是“保存一套喜欢的穿搭”“尝试已有衣物的新组合”“回看今天实际穿了什么”。无需在首次使用前建完整衣柜、登录或上传本人照片。

## 当前批准主路径

1. 今日显示随包完整 Look，选择三套预设之一的完整造型，图片立即可见，已有 GLB 可连续旋转查看。
2. 保存日期/原时区、收藏与版本，退出重启后恢复；默认体验零账号、零上传、离线可用。
3. 用户从我的衣物或内置参考选衣，选择预设人物或自愿准备本人照片，主动生成完整穿搭图。
4. 图片就绪后可独立保存、核对或主动分享；点击“生成立体展示”才创建整套 GLB，已存在有效模型时直接查看。
5. 等待/失败保留图片和草稿；换衣创建新版本，旧模型不得冒充新结果；同版本重复访问复用已验证缓存。

内置内容先验证一个代表 Look，再扩三个人物各两套，共六套；各人物至少一个默认 Look 的图片和 GLB 随包。新组合的图片/模型生成需要网络，**不承诺离线任意换衣或同一人物上逐件即时换网格**。

## 页面与发布范围

一级导航为“今日、衣橱、穿搭簿”；账户从头像进入，照片是创建动作。社区客户端与治理就绪时增加“发现”。Web 首个业务切片继续注册、登录与本人账户，不提前建立其他空页面。

| 发布层级 | 退出条件 |
| --- | --- |
| 离线 Look | 正式完整资产、图片/GLB 切换、真实保存/恢复/删除、无障碍和最低真机通过；不等用户云生成 |
| 云图片与按需 3D | 供应商/地域/权利与删除合格，质量、费用、任务幂等/恢复和 App Client 通过；可分别关闭 |

### 后续主动同步合同

完整跨设备同步由 `BL-SYNC-01～04` 独立交付；当前首版离线 Look 与本地衣橱、推荐、记录不以同步为前置。以下固定后续用户主动启用时的行为；技术合同见 [17-39](../plan/17-39-主动同步合同执行计划.md)，已实现的本地服务端增量能力见 [17-40](../plan/17-40-服务端增量同步执行计划.md)，客户端与真实两设备验收仍待完成。

| ID | 要求 |
| --- | --- |
| `SYNC-REQ-001` | 用户按账号主动启用一组结构化同步范围：衣橱、计划、实际穿着/反馈和私人日记；本阶段不提供可造成游标缺口的逐领域开关。登录、云生成或分享不隐式上传访客、本机 Look 或媒体文件。尚无服务端 Look 时不显示 Look 已同步。 |
| `SYNC-REQ-002` | 本机访客事实保留原 owner；用户明确选择导入后才建立该账号下的 UUID 映射。不同账号的游标、草稿、媒体缓存和迟到响应互不复用；退出不删除未同步的本机事实。 |
| `SYNC-REQ-003` | 服务端给选定范围提供稳定增量游标和删除事件，重复拉取/提交不重复事实；删除优先于同 ID 的迟到创建或编辑，换账号和失效会话不能读旧账号变更。 |
| `SYNC-REQ-004` | 离线同一实体发生不同修改时保留待同步草稿，服务端 revision 冲突要求用户复核；不按设备时间自动覆盖。关联计划/实际/日记的服务端连带变更也必须到达另一设备。 |
| `SYNC-REQ-005` | 结构化同步不自动授权图片、人物源、完整 Look 图/GLB 或第三方生成。日记可含现有媒体引用，但若未独立启用媒体同步，客户端须显示真实不可用状态，不能称图片已跨设备恢复。 |

## 保留的日常业务合同

无图或单件图建档为近期路径；OOTD 自动拆分、批量整理、商品图专项导入为条件扩展。衣物 ID 不使用图片摘要或文件名，确认属性与历史快照分开，待洗/借出/归档默认不进入新推荐。推荐最多三套，不为凑数放宽硬约束；用户可锁件、换件，保存前复核状态与 revision。

Look、OutfitPlan、WearEvent、Feedback 和 Diary 分属不同事实。没有真实衣物也可保存内置 Look；没有计划也可记实际穿着；没有实际穿着也可写日记。生成图不反写衣物属性，不自动发帖。社区和账户已有后端开发结果继续保留，以对应 Acceptance 为准。

## 非目标与技术边界

首版不做量体、数字孪生、尺码预测、布料仿真、实时 AR、任意模型上传、商城/广告/订阅或通用工作流平台。高级角色需求延期，不能借生成失败自行扩大实现范围。

SwiftUI + Observation、GRDB、WKWebView + 锁版 Three.js/GLB；Go + Gin/Huma + GORM/PostgreSQL、Kafka/Outbox、Redis 现有用途、私有 MinIO。禁止 Blender；不新增 GPU 自部署服务。运行时 OpenAPI 唯一，具体版本归 Design 01。App 云 Client、生成 worker 与正式资产目前尚未交付。

## 成功指标与发布判断

主激活为首次会话持久保存 Look 的比例与耗时；回访观察每周再次保存或实际记录。分别统计衣物录入、图片可接受结果率、3D 主动生成率、每个保留结果成本、缓存复用、p50/p95 延迟和删除完成率。真实推荐另统计实际穿着与用户明确评价，不用视觉点击替代。

供应商授权/数据地域与删除、代表性质量、最低真机、App Store 披露和真实恢复证据缺失时，相应生产入口保持关闭。文档批准不包含购买额度、调用付费服务或发布上线的完成声明。
