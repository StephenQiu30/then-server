# 每日记录与穿搭社区需求

状态：`approved / staged implementation`，更新2026-09-22。用户已确认穿搭日记（含轻量生活记录）、首版图文社区（含基础互动）及后端设计方案；19-02～19-06 已有本地和远端后端验收。本轮将客户端流程拆解到19-07/08，App和frontend业务页面尚未实现。工程细则见 [Design 21](../design/21-后端产品边界与领域设计.md)、[Design 22](../design/22-后端数据库设计.md)、[Design 23](../design/23-后端接口设计.md)。

## 用户价值与角色

用户无需先上传衣物或创建真实穿着记录，即可写日记或分享穿搭灵感。私人记录服务于回顾生活，社区内容服务于主动表达和发现；发布必须由作者明确触发。

访客可浏览批准的公开资料和笔记；账号用户可记录和互动；moderator 处理内容审核/举报；admin 处理封禁/申诉与审核权限。运营人员不能无理由访问私人日记或人物采集原图。

## 明确不进入首版

短视频社区、私信、直播、商城、广告、复杂达人运营、全生活管理系统、用户任意模型上传和机器学习 Feed 排序。既有试穿视频/真 3D 产品目标仍保留，但不能据此提前开放社区视频上传或 AI 图片公开发布。

## 工程默认值与待决项

- 日记标题80、正文5,000、心情/场合各40、最多9图；帖子标题80、正文3,000、最多9图/5标签；评论为最多500的文本。字符计数按服务端运行时schema及其实际校验实现，不以UTF-8字节数冒充字符。以上已分别在19-03/04/05落地，当前事实见`diary_contract.go`、`community_contract.go`、`community_social_contract.go`；Client从运行时接口读取限制，不再把已实现值写成建议值。
- 第一版采用时间序发现流、一级回复、固定运营角色、人工内容审核和站内通知；不新增通用工作流引擎。
- 发布前仍需明确：运营地域/年龄准入、实际审核负责人和处理时限、举报审计/备份保留期限、邮件服务和真实媒体发布预算。这些不阻断完成需求文档，但不得在代码中假定已获得生产准入。
- 客户端需求/状态/实施步骤见[19-07 私人日记](../plan/19-07-私人日记与月历客户端执行计划.md)、[19-08 社区客户端](../plan/19-08-社区发现发布与治理客户端执行计划.md)，实现与真实界面验收仍pending；公开API不等于完整社区已交付。

## 功能流程与验收细则

| 功能 / 需求 | 前置、输入与正常流程 | 失败/取消/完成断言 |
| --- | --- | --- |
| 日记编辑 / REQ-001/002 | 当前账号；日期/原时区、可选图文与心情/场合；可无衣物/穿着关联；保存后有稳定ID和revision | 未来日记日期拒绝，同日可多条；文字/图片均空按实际API内容规则拒绝；跨账号关联拒绝；取消不写，409留草稿；重启读取一致 |
| 月历回看 / REQ-003 | 按原本地日期查询月份，计划/实际/日记分别展示，点击一天进入分组列表 | 无数据不是错误；错误可重试；不混算本地与账号未同步记录；日记或Look增加不改变实际穿着数；缺云Look/反馈统计不伪造关联/统计 |
| 普通图片 / REQ-011 | 系统选图→用途专属上传→净化/检查→固定版本→明确关联 | 取消/坏图/超数不发布；先存成功的正文与失败图片不得混成“全部保存成功”；确认前可移除失败项再保存；人物采集原图禁止直接作为公开图 |
| 私人内容导入 / REQ-004 | 主动选择来源，仅复制用户勾选字段到私人帖子草稿；再次核对公开预览 | 来源ID、未选图片、精确私人上下文不进入公开DTO；返回/取消不发布；删私人源不自动删除独立帖子，影响在确认页说明 |
| 送审/修改/撤回 / REQ-005 | 保存草稿→用户点送审→待审核→批准后公开；编辑新revision重新送审 | 待审不是已发布，拒绝可看原因并修改；旧批准版在新稿待审时保留；撤回/下架使公开访问失效，迟到审批不能复活 |
| 发现/搜索/主页 / REQ-006 | 访客看批准的公开范围；登录看关注；固定时间序游标/有限页长 | 同时间不漏/重；过滤条件改变丢弃旧游标；刷新复核下架/屏蔽，不展示私有或待审版本；不新建机器学习推荐 |
| 赞藏关/评论 / REQ-007/008 | 显式操作，重复意图幂等；评论和一级回复按审核状态显示 | 错误回滚乐观状态；无权限或原帖撤回拒绝；回复不能超过一级/跨帖；删除不泄漏旧正文；收藏列表本人可见且不通知作者 |
| 屏蔽/举报/申诉 / REQ-009/010 | 用户说明原因，运营按角色处理并记录目标版本与动作；封禁撤销访问 | 解除不恢复关注；普通用户不能看举报内部信息/审核或提权；并发屏蔽/评论不可绕过；申诉结果不自动重新发布旧内容 |
| 通知 / REQ-013 | 站内查看/标已读，点击前复核目标可见性 | 重投不重复通知；失效目标显示不可用而非缓存私有正文；收藏身份不入通知 |
| 账号/删除 / REQ-012/014 | 复用17-30；删除日记、帖子、账号分别说明影响；账号删除先失效访问再清副本 | 202不显示“所有副本已删除”；无权限/离线不宣称服务端操作完成；邮件/头像/会话列表不存在时不得放可点击假入口 |

所有修改以服务端revision/状态为准；画面中的“已保存/已公开/已处理”必须对应持久事实。错误页保留允许继续的草稿和恢复动作，不能只留一个短暂toast。首次社区发布前，用户必须看见实际公开的字段和图片。

## 权限和数据边界

| 角色 | 可以读取/操作 | 明确禁止 |
| --- | --- | --- |
| 访客 | 批准的公开帖子/主页/允许公开的评论 | 私人日记、作者草稿、待审/拒绝正文、收藏者、举报详情 |
| 作者账号 | 自己日记/草稿、本人通知与私藏、允许互动/发布/撤回 | 替换owner读别人媒体、以私人源URL直接发布、跳过审核 |
| moderator | 权限内待审/举报/内容处理 | 无理由读取私人日记、人物原始采集图，提升自身角色或账号封禁权限 |
| admin | 当前API授权的治理/封禁/申诉并留审计 | 绕过用途访问全部私人媒体；恢复账号时自动恢复旧公开内容 |

权限矩阵须由真实API验证，隐藏按钮不能代替服务端授权。日记链接Look属于可选关联；云实体尚未实现时不伪造ID。账号日历与本地时间线明确区分，完整同步/合并需单独验收。

已完成后端的COMMUNITY-ACC-001～011结果保留。新增COMMUNITY-ACC-012验App私人日记/月历完整旅程，COMMUNITY-ACC-013验App发布发现、匿名阅读与Web治理；生产再核对真实媒体、审核运营、邮件、地域、隐私与备份删除。没有可用审核/举报处理人员和界面，不开放公开投稿。
