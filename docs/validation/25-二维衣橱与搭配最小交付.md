# 二维衣橱与搭配最小交付

> 实现与验证记录，不构成需求或当前实施任务；当前范围见 [需求入口](../requirement/README.md)。

更新：2026-10-12（Asia/Shanghai）。本轮按用户最新要求交付 Web 二维衣橱、单件替换、计划和实穿统计。人物、动作和 3D 不参与这次验收。

后续状态：真实照片上传、补图和换图已在 [26-照片上传与补图](26-真实衣物照片上传最小交付.md) 接入；下文“未接入真实照片”保留为该轮交付时的历史边界。

## 可以实际操作的页面

| 页面        | 本轮实现                                                                                |
| ----------- | --------------------------------------------------------------------------------------- |
| `/wardrobe` | 单品图片卡片、类别/名称/状态筛选、添加与编辑、每件衣物今年的实穿次数、衣橱实穿汇总      |
| `/plans`    | 固定类别平铺预览、类别候选图、单件替换、移除、日期与场景、保存/调整计划、计划单品参考图 |
| `/wear`     | 从计划带入单品、核对后主动确认、无计划记录、部分记录、纠正/删除及统计刷新               |

开发页面当前在 `http://127.0.0.1:3100`；本轮实际使用 Go API 与独立 PostgreSQL 开发库 `then_wardrobe_2d`，没有修改其他项目数据库。预览使用合成示例账户，记录均为操作验证，不是用户真实穿着历史。

## 素材与最小实现

- 复用此前 Codex 生成并拆出的米白针织衫、海军蓝衬衫、炭灰长裤、蓝色牛仔裤和白色运动鞋，共五张图片；本轮没有追加生图。
- 正式页面读取 `frontend/public/wardrobe-samples/` 中的素材，不依赖 `.tmp`、实验页开关或供应商在线服务。鞋图保留原素材中的裤脚与背景，当前没有重新抠图或假称素材质量已完成精修。
- 图片选择以可选的 `sample_image` 标识随衣物保存到现有数据库记录；仅允许这五个内置标识，未开放任意图片 URL。卡片与选图均标明“示例”，不将其描述为实物照片。
- “添加五件示例衣物”须主动点击；每个账户内使用稳定 ID，重复请求不新增同一件衣物。普通新增衣物仍使用独立 ID；没有照片时显示占位，仍可选搭配和记录。
- 衣物图片关联经现有 Huma operation、GORM record、运行时 OpenAPI 和生成客户端贯通，没有新增图片生成平台、BFF 或依赖包。
- 点击单品只改变前端选择；同类替换保留其他类别的 ID 与 revision。连衣装与上下装互斥；本轮采用每类一件的固定布局，不引入拖拽画布或人物分层。
- 保存计划与确认实穿分别调用已有接口。实穿创建、纠正、删除和会影响历史的衣物删除均使统计缓存失效，重新读取服务端聚合结果。

## 已实际验证的核心链路

| 操作                             | 观察到的结果                                                       |
| -------------------------------- | ------------------------------------------------------------------ |
| 添加五件示例并刷新               | 五张图、名称、分类和图片关联均由真实 API 返回并保留                |
| 上衣分类 / 搜索“牛仔” / 待洗筛选 | 分别显示 2 件 / 1 件 / 0 件；无匹配时有空态                        |
| 针织衫＋牛仔裤＋运动鞋，改选衬衫 | 只改变上衣；下装与鞋保持不变；Enter 键同样可替换                   |
| 保存日期计划                     | 数据库出现 1 条计划，实穿天数、记录、单品使用仍全部为 0            |
| 从计划进入并主动确认实穿         | 统计成为 1 天、1 条记录、3 件穿过的单品；三件衣物各 1 次           |
| 将这条记录的上衣纠正为针织衫     | 衬衫回到 0 次、针织衫成为 1 次，下装与鞋仍为 1 次；总记录仍为 1 条 |
| 独立 API 夹具重复同一创建请求    | 实穿仍只计 1 条，不重复累加                                        |
| 独立 API 夹具纠正与删除          | 次数转移到实际选中的衣物；删除后天数/记录/使用清单重新成为 0       |

单件替换的一次浏览器“点击到读取页面状态”观察为 306 ms，包含自动化往返和状态读取，**不是渲染帧耗时、平均延迟或性能承诺**。当前不调用生成服务；首次展示仍可能等待本地图片加载。

浏览器检查了衣橱与搭配页的 320、390、768、834、1024、1440 px 宽度：没有页面横向溢出，衣橱五张图片均完成加载，搭配选择在调整宽度后保持。验证使用桌面浏览器视口，不能代替真实手机或 VoiceOver 验收。

## 统计范围与当前边界

- 汇总和单品次数使用现有 `/statistics/wear` 服务端聚合；当前页面明确显示“今年”，从当年 1 月 1 日至设备本地今天，不冒充历史累计。
- 实穿次数按有效事件计，天数按服务端现有日期口径计；查看、替换、保存计划均不增加次数。示例账户无记录表示未记录，不代表某件真实衣物从未穿过。
- 衣橱筛选针对**当前已加载**的活动衣物，页面显示已加载数量，分页提供继续加载；不是全库搜索或全库库存汇总。
- 计划图为当前仍可读取的单品参考图，历史身份/名称继续使用服务端快照；未增加历史图片快照。已清除的快照不补造图片。
- 当前选图仅支持这五张素材。真实衣物照片上传、抠图、归档入口、单品最近穿着及明细、跨年度统计和推荐结果图文化仍在后续队列。
