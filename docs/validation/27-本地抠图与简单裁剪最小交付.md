# 本地抠图与简单裁剪最小交付

> 实现与验证记录，不构成需求或当前实施任务；当前范围见 [需求入口](../requirement/README.md)。

更新：2026-10-12（Asia/Shanghai）。本轮在现有 Web 二维衣橱中完成照片整理，不增加人物、3D、视频或第三方付费图片服务。

## 使用方式与范围

在 `/wardrobe` 添加或编辑衣物，选择 JPG/PNG/WebP 照片后：

1. 点击“自动抠图”，在本机浏览器生成透明 PNG，并自动收紧透明留白。
2. 需要时展开“简单裁剪”，输入从上/右/下/左移除的百分比，点击“应用裁剪”。每边 0–45%，作用于当前展示图，不修改原文件。
3. 对照原图与当前展示图；可“查看原图”或“恢复原图”。处理结果为草稿，点击保存后才更新衣橱、搭配候选及计划参考图。
4. 原图单独关联；衣物 ID、计划/实穿历史和计数保持。取消编辑不会覆盖已保存的透明展示图。

原文件上限仍为 12 MB / 2400 万像素。展示衍生图最长边最多 2048 px；PNG 保留透明及半透明边缘。裁剪采用四边数值输入，不引入拖拽画布、手绘蒙版、复杂批处理或新的后台服务。

## 可落地的本地方案

采用 **U²-Net 小模型 U2netp + ONNX Runtime Web CPU WASM**。推理、蒙版合成、透明留白裁剪与手动裁剪均在浏览器本机完成；照片只在用户保存时进入已有本地私有媒体流程，没有发送给第三方推理 API。

- 模型来自 [rembg 官方发布](https://github.com/danielgatis/rembg/releases/download/v0.0.0/u2netp.onnx)，4,574,861 bytes，官方校验 MD5 `8e83ca70e441ab06c318d82300c84806`；[rembg 预处理/模型来源](https://github.com/danielgatis/rembg/blob/main/rembg/sessions/u2netp.py) 和 [U²-Net 原项目](https://github.com/xuebinqin/U-2-Net) 是依据。
- ONNX Runtime Web 固定为 npm `1.30.0`，CPU WASM 单线程，无额外 Python、CUDA 或 GPU 服务；[官方项目](https://github.com/microsoft/onnxruntime/tree/v1.30.0/js/web) 说明浏览器执行方式。
- 模型随前端本地静态资源提供；WASM/MJS 从锁定 npm 包在 predev/prebuild 自动复制，按需加载，不在打开衣橱时直接启动模型。推理会话在当前页面复用。
- U²-Net 仓库的 Apache-2.0 与 ORT 的 MIT 许可文本、来源说明保留在 `frontend/public/wardrobe-processing/`。运行时复制文件不重复提交；模型文件保留为实际运行资产。
- 模型只预测前景透明度，图像颜色与纹理来自输入照片，没有生成或改绘衣物。

这是一条小模型的最小实现，不保证所有复杂背景、细肩带、蕾丝或相近色衣物都能自动处理正确。当前通过的实拍样本为一件白色 T 恤；用户仍应检查边缘，必要时先裁剪或恢复原图。

## 原图保留与权限

原有通用媒体 Worker 会在 ready 后清理上传源。已修正为：**ready 的衣橱媒体保留原始上传字节**，其他用途仍沿用既有清理规则；媒体删除与账号删除仍执行清理。未引入新的永久公开桶。

衣物新增可选 `original_photo_media_id`，与展示用 `photo_media_id` 分开，通过同一事务、本人/用途/ready 校验和 revision 保存；省略原图字段的元信息编辑不会清除已有原图。HTTP 字段定义仍以 Huma/运行时 OpenAPI 为准，不建立第二份接口合同。

原图读取与展示图均需要本人会话并使用 `no-store`；前端认证图片禁用公共图片优化。PNG/WebP 只扩展衣橱用途，其他已有上传用途仍限 JPEG。原始照片可包含 EXIF 和内嵌 JPEG 缩略图；衣橱展示衍生图经过重新解码/编码，不带原始 EXIF。

**历史边界：**前一轮已经被旧 Worker 清理的原始上传版本无法恢复。对此接口明确返回 `X-Original-Source: normalized-legacy`，处理时显示提示，使用当时仍存在的净化图；新上传完整原文件返回 `raw`。本轮最终样本重新选择了原始实拍 JPEG，以真实原文件完成保存与校验，没有把历史净化图冒称恢复出的原文件。

本轮尚未新增孤立 ready 媒体的自动回收器，也没有历史图片版本管理；存储回收仍是后续独立切片。
