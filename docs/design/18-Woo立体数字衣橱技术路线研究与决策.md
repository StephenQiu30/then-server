## Woo 可核实的可见效果

来源为用户提供并实际查看的 [LerSent 原帖视频](https://x.com/LerSentAI/status/2090783821452943404)，作者描述“记录 OOTD、以立体形象展示”。2026-09-22 在浏览器查看约 55 秒片段；时间为观察定位，不是内部实现证据。

| 观察 | 可核实内容 | 不能据此推断 |
| --- | --- | --- |

| WOO-REF-02，约 16.5 秒 | 侧面人物与“随意拖动”的演示说明 | 使用 Tripo、Three.js 或某种特定格式 |

| WOO-REF-04，约 34 秒 | TOPS/OUTERWEAR/BOTTOMS/SHOES 衣物分类与选择 | 每件衣物都有独立三维资产 |
| WOO-REF-05，约 38 秒 | 照片选择流程 | 本人建模、量体或扫描 |

| WOO-REF-09 | 可用于对照页面层级和旅程 | 可复制其品牌、人物或服装资产的权利 |

因此我们的目标是复现可见价值：漂亮的全身穿搭、简单选衣、等待后得到新 Look、可旋转观察和日期记录。技术选择基于本项目的成本与质量，不宣称复原 Woo 私有实现。

## 路线比较与决定

| 方案 | 能得到什么 | 主要成本/缺口 | 本次取舍 |
| --- | --- | --- | --- |
| 透明人物图 + 视差 | 轻量空间感，几乎无三维运行成本 | 没有真实侧背几何，不满足连续立体观察 | 图片阶段与故障回退，不能充当 GLB 验收 |
| 分别生成正侧背图片 | 固定几个角度 | 角度一致性、全组合内容量；无法任意观察 | 旧 11-03 路线退役，不继续制作 24 套矩阵 |
| 完整图 → 静态 GLB | 真正连续旋转，可本地重复查看 | 背面推断、脸/细节可能失真，新衣需新版本 | **采用，Tripo H3.1 优先验证** |
| 模块人物 + 独立衣物 + 骨架 | 即时换衣与更复杂动作 | 同骨架/权重/遮蔽/眼部/跨组合适配成本 | 后续独立能力，退出首版前置 |
| AI 360 视频 | 自动播放的动态展示 | 额外调用、视频一致性与存储成本；不可任意视角 | deferred；静态 GLB 旋转不需要视频生成 |

首版衣橱保持二维。完整图按需生成，模型只为用户选中的图片版本生成，私有存储与缓存复用。内置完整 Look 在制作阶段生成并审核，默认三人物各至少一套离线可用；六套首批内容不等于已有合格资产。

## 验证依据与实际缺口

GitHub 核对 img2threejs 源码及 TripoSR；Context7 核对 Three.js GLTFLoader、场景和动画接口；Firecrawl 与官方网页核对 Tripo API/定价与服务条款。结论是静态 GLB 无须骨架即可通过 Three.js 旋转，Tripo 的云 API 与 TripoSR 不同。详细来源归 [Three.js 研究](threejs-avatar-research.md)，成本公式归 Design 20，不维护第二份报价。

当前 App 八个工程 GLB 不含贴图，validator 固定 rig 并拒绝 textures/images，Look 保存仍有内存态缺口；真实 Tripo 样本、生成 worker 和 App 云 Client 尚未交付。本次没有付费调用，不以文档或 API 能力证明视觉质量。

## 交付与退出

1. 用一套自有/授权人物完整图验证 GLB 正侧背、连续观察和最低设备预算；不合格先处理输入/模型参数。
2. 11-05 交付图片与 GLB 的整套切换、Look 持久保存/恢复/删除，再扩六套内容。
3. 14-01 验证人物+选衣图 → 完整图 → 主动生成模型，包含幂等、费用、取消/删除与版本绑定。
4. 模块换装、眼部和独立视频保留原需求 ID 的延期记录，不再阻止本路线首版；原工程测试的通过范围不扩大。

生产图片/模型的身份、衣物与安全质量、来源权利、照片处理地域、供应商删除、最低真机和端到端任务通过前，不开放真实用户云生成。内部内置资产制作与用户生成服务分别确认许可，付费套餐不自动证明可以转供终端生成。
