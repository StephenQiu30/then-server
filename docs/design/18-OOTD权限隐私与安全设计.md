## 目标与约束

### 目标

1. 将人物、面部、身体和穿衣照片及全部派生资产按高敏感数据管理。
2. 权限与同意按功能首次使用、处理目的和实际第三方逐次取得，拒绝后保留不依赖云 AI 的核心路径。
3. 只采集、上传、保留和披露完成用户当前动作所需的最少数据。
4. 使用版本化区域处理策略阻断未经批准的跨境、供应商和子处理方。
5. 通过私有对象存储、短时签名 URL、加密、严格 owner 授权和日志 allowlist 防止泄露。
6. 建立从源照片到 mask、裁剪、生成图、视频、帧、缓存和供应商任务的资产血缘，使删除可枚举、可验证、可重试。
7. 在供应商、API、异步队列、对象存储、客户端缓存和备份之间形成可测试的端到端删除契约。
8. 防止非自愿试穿、换脸、身体评价、训练复用和敏感遥测。

### 非目标

- 不定义或声称具体司法辖区下的最终法律基础；上线前必须由有资质人员完成评估。
- 不收集人脸识别模板、声纹、精确身体尺寸或健康属性。
- 不默认使用用户内容训练、微调、评测或改进自有/第三方模型。
- 不开放公共人物搜索、人脸匹配、换脸或他人照片试穿。
- 不默认创建公开分享链接或把生成结果写入系统相册。
- 不把精确位置、日历正文、联系人、交易信息与人物照片一同发送给 AI 供应商。
- 不因 AI 不可用而自动放宽地域、保留、加密或日志要求。

## 隐私原则

- 本地优先：输入质检、方向修正、EXIF/GPS 移除、缩略图和可行的初步人物 mask 优先在设备完成。
- 目的限定：推荐、静态试穿和动态预览是三个目的；不得用一个笼统同意覆盖所有未来处理。
- 最少披露：AI 供应商只接收本次任务所需的人物/衣物派生图和受控参数，不接收衣橱、账户、日历或自由文本全集。
- 最短保留：临时输入、失败输出、供应商结果和视频源各有明确 TTL；“可能以后有用”不是保留理由。
- 派生继承：裁剪、mask、embedding、生成图、视频和帧至少继承源资产最高敏感级别。
- 可撤回与可删除：撤回阻止新的处理；删除沿血缘处理已经产生的全部副本。
- 诚实表示：AI 输出明确标注为视觉模拟，不用于尺码、身体测量、健康、吸引力或身份判断。
- 无暗黑模式：不同意第三方处理不影响衣橱浏览、结构化推荐、单品拼图和穿搭记录。

## 数据分类

| 级别 | OOTD 数据 | 最低控制 |
| --- | --- | --- |
| 高敏感 | 含人物的原图、面部/身体裁剪、人物 mask、数字形象、静态试穿、生成视频、透明帧、可能重建人物外观的特征 | 本地预处理、TLS、私有存储、KMS/信封加密、严格 owner 授权、短 TTL、禁止日志、逐次第三方同意、血缘删除 |
| 敏感 | 单件衣物图、品牌/尺码/穿着频率、衣橱清单、穿搭记录、体感和场合反馈 | 目的限定、私有存储、owner 隔离、最少字段、删除与导出 |
| 敏感元数据 | Job ID、供应商、模型版本、区域策略、同意记录、媒体尺寸、失败类别、生成成本 | allowlist 日志、限期保留、访问审计、不得与公开标识拼接 |
| 一般配置 | 不含个人内容的模型能力表、受控类别和产品配置 | 完整性保护、版本管理 |

分类规则：

- 衣物图只要含身体、面部、纹身、家庭环境、票据、快递单或镜面反射，就升级为高敏感。
- 去脸不等于匿名；身体、发型、纹身、环境和服装组合仍可能识别个人。
- 视觉 embedding 可能保留可识别特征，按源资产级别处理；首版不得持久化人物/面部 embedding。
- manifest 本身不含图像正文，但能枚举高敏感帧，按高敏感访问策略保护。
- 媒体 hash 不得用于跨用户去重或关联；相同照片是否存在也是敏感信息。

## 权限与同意

### 系统权限矩阵

| 功能 | 系统能力 | 申请时机 | 拒绝后的替代路径 |
| --- | --- | --- | --- |
| 相册选取照片 | PhotosPicker | 用户主动选择“从相册选取”时；优先使用系统 picker，避免请求整个照片库 | 使用相机或手工创建无图衣物 |
| 相机拍摄 | Camera | 用户主动选择“拍摄”并看到用途说明后 | PhotosPicker、商品图或通用形象 |
| 写入相册 | Photos Add Only | 仅在用户主动选择“保存到相册”时 | 保留 App 私有存储或系统分享面板 |
| 通知 | UserNotifications | 用户主动要求生成完成提醒时 | 在 App 内恢复 Job 状态 |
| 定位 | 不作为 OOTD 图片处理前置权限 | 如未来天气推荐获独立批准，按对应功能申请 | 手工选择城市或天气条件 |

不得在首次启动批量请求相机、相册、通知或定位。权限用途说明、实际请求时机、隐私清单和产品行为必须一致。

### 第三方 AI 逐次同意

每一次静态试穿或动态预览提交第三方前，必须展示并记录本次处理：

- 功能目的和将生成的内容。
- 实际供应商及必要子处理方类别。
- 输入数据类别，例如人物图、衣物图或静态试穿图。
- 处理国家/地区和是否涉及跨境。
- 供应商最长输入、输出和请求元数据保留期。
- 是否用于训练；当前固定为“不用于训练”。
- 取消、撤回和删除方式。
- 拒绝后仍可使用的功能。

同意必须由用户在本次动作中主动确认，不能：

- 预勾选。
- 与服务条款、营销或分析同意捆绑。
- 用旧供应商或旧地域的同意覆盖新供应商、新区域或更长保留期。
- 用静态试穿同意自动覆盖图片转视频处理。
- 在离线队列数小时或数天后无条件复用已失效策略；提交前需再次校验同意与策略版本。

`ConsentRecord` 至少保存：

- `id`、`user_id`、`purpose`、`policy_version`。
- `provider_id`、处理地域、数据类别和最长保留期。
- 用户看到的文案版本和确认时间。
- 同意状态、撤回时间和来源设备。
- 不保存照片、签名 URL 或自由文本输入。

撤回只阻止新处理，不能伪称已经删除既有资产；既有资产应由单独删除请求处理。

## 地域、跨境与供应商准入

### ProcessingPolicy

所有外部处理都必须先解析版本化 `ProcessingPolicy`：

| 字段 | 说明 |
| --- | --- |
| `policy_id` / `version` | 可审计的不可变策略版本。 |
| `subject_region` | 适用用户或部署区域，不从精确位置推断。 |
| `storage_region` | 源与结果对象存储区域。 |
| `compute_region` | 自有计算区域。 |
| `allowed_provider` / `provider_region` | 获准供应商及处理区域。 |
| `data_categories` / `purposes` | 允许发送的数据与目的。 |
| `cross_border_status` | `not_applicable`、`approved` 或 `blocked`。 |
| `max_input_retention` / `max_output_retention` | 供应商保留上限。 |
| `training_allowed` | 生产固定为 `false`。 |
| `effective_at` / `expires_at` | 生效和重新评审时间。 |

要求：

- 中国大陆或其他受地域约束的部署默认不跨境回退；无法找到已批准同地域供应商时关闭 AI 生成。
- 不能仅依据供应商营销页面认定地域和删除能力；需 DPA、子处理方清单、服务条款和实际技术验证。
- 供应商改变模型、地域、保留期、子处理方、训练条款或所有权时，旧策略失效并阻断新任务，直到重新评审。
- 不通过 IP 或精确位置静默推断用户法律身份；账户/部署配置和用户明确选择的区域规则需由合规方案定义。
- 供应商输出若只能通过公共 CDN 获取，不满足私有访问和保留要求时不得进入生产。

### 供应商准入清单

1. 商业和模型许可证链完整，包括预处理、人体解析和辅助权重。
2. 明确输入、输出、URL、任务元数据和备份的保留期。
3. 默认不将客户内容用于训练或人工审阅；例外有明确开关和合同保证。
4. 支持删除或能证明 TTL 满足产品删除 SLA。
5. 声明处理地域和子处理方，且与 ProcessingPolicy 一致。
6. 提供 API 鉴权、回调签名、速率限制和安全事件通知。
7. 能通过授权测试集的质量、公平性和内容安全门。
8. 能在合同终止后导出必要审计元数据并删除客户内容。

## 照片与视频本地处理

上传前执行：

1. 解码并验证真实媒体类型、像素尺寸、方向、帧数和资源上限。
2. 拒绝截断文件、polyglot、超大像素、异常 ICC/EXIF、路径和容器攻击。
3. 按 EXIF 修正方向后重新编码到受控格式与色域。
4. 不复制 GPS、拍摄时间、设备、镜头、相册标识和不必要的元数据。
5. 按功能裁剪到最小必要区域和分辨率。
6. 在临时文件设置适当 Data Protection，并在成功、失败、取消和启动恢复时清理。
7. 本地预览和服务端资产使用不同 ID，避免把系统相册标识上传。

人物质量检查可以在本地运行。不得因为端侧算法失败而静默上传更大原图；用户应看到重试或明确同意的云端路径。

## 对象存储与传输

### 存储分区

已批准架构至少逻辑隔离：

- `raw-private`：用户确认上传的源资产，最严格角色访问。
- `derived-private`：裁剪、mask、试穿、视频和帧。
- `transient-private`：供应商输入/输出和未完成任务临时资产，强制 TTL。
- `share-private`：只有用户主动分享后才创建，仍使用到期 token，不允许公共 ACL。

不要求一定使用四个物理 bucket，但 IAM、KMS、生命周期和审计边界必须等价。

### 签名上传和读取

```text
客户端请求 upload intent
→ API 校验用户、目的、MIME、长度、数量和配额
→ 创建 pending MediaAsset
→ 返回 5–10 分钟、绑定方法/对象/headers 的签名上传凭据
→ 客户端从临时文件直接上传
→ complete 接口校验对象 HEAD、长度、MIME、hash 和 owner
→ 安全扫描/重新编码完成后资产才进入 ready
```

安全要求：

- bucket 全部关闭公共访问和 ACL；对象 key 使用不可猜测 ID，不含用户邮箱、文件名或业务正文。
- 签名 URL 是 bearer credential，TTL 取满足任务的最短时间，并限制 HTTP 方法、对象、内容长度和必要 headers。
- 完整 URL 及 query 禁止出现在日志、trace、分析、崩溃报告、数据库和队列消息中。
- 上传完成前资源不可被生成任务读取；未完成 upload intent 自动过期清理。
- 供应商拉取输入使用单独、短于用户读取 URL 的凭据；任务完成后立即撤销或等待极短 TTL 到期。
- 输出读取同样鉴权并签发短时凭据；客户端缓存不是公开分发渠道。
- 不进行跨用户内容寻址去重；每位用户拥有独立对象引用和删除边界。

### 加密和密钥

- 传输统一 TLS，拒绝降级和明文回调。
- 对象存储和数据库启用静态加密；高敏感对象使用 KMS 管理的密钥和受控服务角色。
- API Key、签名密钥、供应商凭据只存密钥管理服务，不进入 App、源码、镜像层和日志。
- 是否使用每用户 DEK、按域信封加密或密码学擦除，应在 POC 前完成威胁与运维评估；不能用未经验证的自制加密。
- 密钥轮换需保留版本并有恢复测试；删除密钥不能代替对象、供应商和缓存删除，除非批准的密码学擦除方案证明覆盖全部副本。

## 授权与隔离

- 每个业务查询和对象读取都从认证上下文取得 `user_id`，不得信任客户端提交的 owner。
- 所有媒体、Avatar、WardrobeItem、Outfit、Job、结果和删除请求都带 owner，并在 Repository 查询中限定。
- 生成任务只能引用同一 owner、状态允许且关系有效的资产。
- 不返回对象存储内部 key、供应商 job ID、内部血缘或其他用户资源是否存在。
- 管理和客服默认看不到图片；紧急访问采用单独角色、理由、时限、审批和审计，不提供长期万能链接。
- 分享使用独立、可撤销、到期的 ShareGrant；删除或撤销后立即失效，不能把内部资产 URL 当分享链接。
- 账号合并必须显式迁移 owner 与密钥边界，并有跨账号污染测试。

## 资产血缘与保留

### MediaAsset 与 MediaDerivation

每个资产至少保存：

- `id`、`user_id`、`kind`、`classification`。
- `object_reference` 的受控内部标识，不是可访问 URL。
- `state`、`retention_class`、`expires_at`、`deleted_at`。
- `mime`、尺寸、字节数和受控 hash。
- `processing_policy_id`、来源服务和创建任务。

派生关系使用显式 `MediaDerivation` 边：

- `derived_from`
- `thumbnail_of`
- `mask_of`
- `provider_input_for`
- `provider_output_of`
- `frame_of`
- `manifest_for`
- `cached_copy_of`
- `shared_copy_of`

删除从根资产遍历所有出边，且必须能从供应商任务反查输入、输出和子处理副本。不得只依赖文件名前缀或 bucket listing 推断关系。

### 候选保留类别

| 资产 | 候选最长保留 |
| --- | --- |
| 未完成上传 | 24 小时 |
| 本地和服务端预处理临时文件 | 当前任务；失败或启动恢复时立即清理 |
| 供应商短时输入 URL | 完成本次拉取所需的最短窗口，建议 5–10 分钟 |
| 失败/拒绝的生成输出 | 24 小时内自动清理，若能更短则更短 |
| 动态预览原始视频 | 帧打包和验证后尽快删除；长期保存需独立目的 |
| 用户明确保存的 Avatar、衣物和结果 | 至用户删除或账号删除 |
| 主动分享副本 | 明确 TTL，例如 7 或 30 天，并可随时撤销 |
| 无内容安全审计元数据 | 依法和运营需要的固定期限，建议 14–30 天后复评 |
| 备份 | 固定窗口内自然过期，候选上限 30–35 天 |

正式期限必须由 PRD、法律评审、供应商合同和灾备方案共同批准。

## 删除协议

### 删除覆盖范围

删除 Avatar、衣物、试穿结果、动态预览、穿搭或账号时，应根据语义覆盖：

- 源照片和标准化副本。
- 人物/衣物裁剪、mask、缩略图和 render input。
- 供应商输入 URL、任务、输入/输出、人工审核副本和请求历史中可删除内容。
- 静态试穿结果、质量检查派生数据和本地缓存。
- 图片转视频输出、原始视频、36–48 帧、poster、manifest 和 CDN 缓存。
- 未完成 Job、Outbox、队列消息、DLQ 和临时文件。
- 分享 grant、分享副本和系统后台下载。
- 可反向识别用户或源资产的 embedding。
- 备份中的副本按既定周期到期；恢复备份时重放 tombstone，防止已删数据复活。

如果 Outfit 或穿搭记录需要保留业务事实，应先在 PRD 中定义删除语义；不得为保留展示而继续引用已删除高敏感媒体。

### DeletionRequest 状态机

```text
requested
  → access_revoked
  → enumerating_lineage
  → deleting_primary
  → deleting_provider
  → purging_cache_and_queue
  → verifying
  → completed
```

异常状态：

- `retrying`：短暂错误，按退避策略继续。
- `attention_required`：达到重试上限或供应商无删除能力，触发安全/隐私告警。
- `completed_with_backup_expiry`：主系统已删，备份等待固定到期日；向用户准确说明，而不是宣称即时物理擦除全部备份。

约束：

- `access_revoked` 应在请求接受后立即完成；之后所有读取返回不存在或安全错误。
- 删除任务 at-least-once 执行并幂等；对象已不存在视为成功，但仍需验证血缘无可达副本。
- 部分删除失败不能重新开放其他已删资产。
- 删除完成记录只保留请求 ID、时间、类别、结果和不可逆用户引用；不保留媒体正文或对象 key。
- 新产生派生资产前必须检查根资产无活动删除 tombstone，防止删除与生成竞态。

### 候选 SLA

- 用户读取权限撤销：请求接受后 5 分钟内，目标为即时。
- 主数据库、对象存储、CDN/缓存和自有临时资产：24 小时内。
- 供应商副本：不晚于合同和产品承诺，且必须满足正式批准的删除 SLA。
- 备份：在公开说明的固定窗口内自然过期，候选不超过 30–35 天。

无法满足这些 SLA 的供应商或架构不得进入生产。

## API 与异步任务

以下是领域级安全契约。相关云能力进入 POC 或发布实施阶段时，必须先写入唯一 `backend/openapi.yaml` 并完成鉴权、授权、幂等、资源上限、删除和契约测试评审，不能从本文维护第二份接口契约：

- `POST /v1/consents`：记录具体目的、供应商、区域、数据类别和文案版本的主动同意。
- `GET /v1/consents/{consent_id}`：返回当前状态与撤回信息，不返回敏感输入。
- `POST /v1/consents/{consent_id}/withdraw`：阻止新的外部处理。
- `POST /v1/media/uploads`：创建受目的、MIME、大小和数量限制的上传 intent。
- `POST /v1/media/{media_id}/complete`：完成对象校验和安全处理。
- `GET /v1/media/{media_id}`：校验 owner 后返回短时读取信息。
- `DELETE /v1/media/{media_id}`：创建资产血缘删除请求。
- `POST /v1/deletion-requests`：删除 Avatar、衣物、生成结果、动态预览或账号范围数据。
- `GET /v1/deletion-requests/{request_id}`：返回阶段、目标范围和备份到期说明。
- `POST /v1/share-grants`、`DELETE /v1/share-grants/{id}`：只有分享需求获批后才可加入。

所有生成接口必须携带与实际目的、供应商和策略一致的 `consent_record_id`。服务端不能只相信该 ID 存在，还要验证 owner、状态、策略版本、时间和请求数据类别。

删除相关异步任务至少包括：

1. `enumerate_asset_lineage`
2. `cancel_generation_jobs`
3. `delete_primary_objects`
4. `delete_provider_artifacts`
5. `purge_cdn_and_device_grants`
6. `purge_queue_and_transient_assets`
7. `verify_no_reachable_assets`
8. `complete_deletion_request`

队列消息只包含内部 ID、操作和 trace context，不含图片、签名 URL、对象 key、提示词或供应商秘密。

## 日志、遥测与审计

只有对应云能力进入受控 POC 或发布实施阶段后才引入本节观测；门禁关闭的本地核心路径不发送生成遥测。

### 允许字段

- 路由模板、请求 ID、Job ID、资产类型、状态和稳定错误码。
- 处理策略 ID、供应商代号、模型版本、区域代号。
- 字节区间、格式、阶段耗时、重试次数和成本单位。
- 删除阶段、积压数量和最老请求年龄。

### 禁止字段

- 图片、视频、帧、mask、base64 和二进制片段。
- 完整 URL、query、对象 key、原始文件名和设备相册标识。
- EXIF/GPS、面部/身体特征、embedding 和人体质量分值正文。
- 用户提示、衣物描述、品牌/尺码/场合自由文本。
- 供应商原始请求/响应、API Key、签名和回调正文。
- 邮箱、姓名、电话号码、精确位置和可直接识别账户的信息。

日志库应使用字段 allowlist，在业务对象进入 logger 前完成脱敏；不能依赖下游平台事后过滤。访问审计独立保存管理员、操作、理由、范围和时间，不保存看到的内容。

## 威胁模型

| 威胁 | 场景 | 控制 |
| --- | --- | --- |
| IDOR/跨租户访问 | 替换媒体、Job、Outfit 或删除请求 ID 读取他人数据 | 从认证上下文取 owner；Repository 强制 user 过滤；对象读取二次授权；跨用户属性测试 |
| 签名 URL 泄露 | URL 进入日志、剪贴板、崩溃报告或第三方请求历史 | 极短 TTL、方法和对象绑定、禁止日志、单独供应商 URL、到期与撤销测试 |
| 公共对象误配置 | bucket/CDN ACL 使照片可匿名读取 | 阻断公共访问、IaC policy、持续配置扫描、匿名读取验收 |
| 恶意媒体 | polyglot、解码炸弹、畸形 ICC/EXIF、超大视频耗尽资源 | MIME sniff、像素/帧/时长/字节硬限、隔离解码、超时和资源配额 |
| 回调伪造和重放 | 攻击者伪造供应商完成事件替换结果 | HMAC/公钥签名、时间窗、nonce、provider job ID 和状态机校验 |
| 重复消息与重复计费 | 队列 at-least-once 或用户连点多次 | Idempotency-Key、输入快照哈希、provider job ID 持久化和唯一约束 |
| 删除竞态 | 删除进行中 worker 仍生成新派生资产 | 根资产 tombstone、创建前检查、Job 取消、删除后再次遍历验证 |
| 派生资产遗漏 | 只删原图，mask、视频、帧、缓存和供应商副本仍存在 | 显式 MediaDerivation、provider job 反查、删除遍历和孤儿扫描 |
| 备份复活 | 恢复旧备份重新出现已删资产 | 独立 tombstone 日志、恢复 runbook 强制重放、灾备演练 |
| 内部人员滥用 | 客服或工程人员直接浏览人物图 | 最小 IAM、默认无媒体权限、JIT 审批、理由、时限和审计 |
| 供应商训练复用 | 服务条款或配置允许用用户内容训练 | DPA、training=false 策略、配置验证、合同变更阻断 |
| 未经同意的他人照片 | 用户上传他人或未成年人的照片试穿 | 当前范围只允许年满 18 周岁的本人照片；端侧多人门禁、内容安全、举报删除与滥用限流共同控制，第三方或未成年人场景必须另立 PRD |
| 身体评价伤害 | 模型或文案进行显瘦、吸引力、缺陷判断 | 固定任务和文案；不收身体评价；不支持自由编辑 prompt |
| 视觉 embedding 重识别 | 人物特征长期保存或跨场景关联 | 首版不持久化人物 embedding；临时质量特征立即丢弃 |
| 分享链接扩散 | 用户误分享永久公开人物图 | 默认不分享、短 TTL、明确预览、随时撤销、禁索引和禁公共 ACL |
| 缓存残留 | 删除后设备、CDN 或 worker 临时目录仍可恢复 | 缓存索引纳入血缘、删除事件、启动清扫、受控目录、删除验收 |
| 提示和响应泄漏 | 自由文本带入供应商或日志 | 结构化枚举、服务端固定模板、供应商 DTO 不入日志 |

## 失败与降级方案

| 失败 | 安全行为和用户路径 |
| --- | --- |
| 相机/相册权限拒绝 | 不反复弹窗；提供另一输入方式、无图衣物或通用形象。 |
| 用户拒绝第三方 AI | 不上传；继续衣橱、推荐、单品拼图和记录。 |
| 无合规同地域供应商 | 明确当前地区不支持 AI，不自动跨境。 |
| 上传中断 | 保留本地临时文件到受控恢复窗口；过期或取消后清理。 |
| 媒体安全检查失败 | 不进入主存储 ready 状态；显示可理解的换图建议。 |
| 供应商隐私条款变化 | 立即阻断新任务；既有资产按原承诺保留或删除。 |
| KMS/鉴权不可用 | 关闭失败，不返回未加密或绕过授权的资产。 |
| 删除部分失败 | 继续禁止读取，状态显示处理中，重试并告警。 |
| 日志/遥测不可用 | 业务可按安全策略运行，但不得降级为控制台输出敏感正文。 |
| 对象存储或 CDN 异常 | 使用已授权本地缓存或静态占位，不切换公共 URL。 |
| 供应商无法删除 | 不得宣称完成；进入 `attention_required`，按合同和事件响应处理。 |

安全失败必须关闭失败；产品增强失败可以降级，但不得以降低隐私控制作为降级方式。

## 可观测性和安全运营

相关云能力上线后至少建立以下无敏感正文指标：

- 上传 intent 创建、完成、过期和孤儿数量。
- MIME/像素/内容安全拒绝率和资源耗尽阻断。
- 未授权/跨用户访问拒绝、签名 URL 过期和异常访问。
- ProcessingPolicy 阻断、跨境阻断、供应商条款过期数量。
- 同意、撤回及“不同意后仍完成基础流程”比例。
- 临时资产超期、Provider 删除失败、对象/数据库血缘不一致和孤儿资产数。
- DeletionRequest 各阶段 p50/p95/p99、最老年龄和 SLA 违约。
- 密钥轮换、IAM 变更、管理员媒体访问和分享撤销。
- 日志敏感字段扫描和隐私清单/第三方域名变化。

告警至少覆盖：

- 任何公共访问配置。
- 任何未经允许区域的外部请求。
- 删除请求接近或超过 SLA。
- 临时高敏感资产超过 TTL。
- 供应商删除连续失败或条款过期。
- 跨用户授权测试/运行时保护触发。
- 生产日志出现签名 URL、对象 key 或媒体特征模式。

安全事件响应需能按资产 ID、Job ID、供应商和策略版本定位受影响范围，而无需检索图片正文。

## 关键决策、替代方案与再评估触发器

### 逐次第三方同意而非一次总同意

- 选择：静态试穿和动态预览每次提交前确认实际处理方和策略。
- 原因：人物图片敏感，供应商、地域和保留期可能不同；逐次同意与用户当前动作一致。
- 替代：首次开启后永久同意所有生成；透明度不足，拒绝。
- 再评估：若同一供应商、目的、地域和保留策略长期稳定，可研究有限期“本会话记住”，但必须易见、可撤回且不能跨策略版本。

### 私有对象存储直传而非 API 中转

- 选择：受限制签名上传，API 保存元数据和授权。
- 原因：避免大文件占用 API，支持后台传输和独立生命周期。
- 替代：API 接收全部文件；实现简单但放大资源和临时文件风险。
- 再评估：若签名能力不能限制上传，或监管要求所有字节经专用检查网关，可引入受控媒体入口，但不允许公共存储。

### 不保存人物/面部 embedding

- 选择：身份质量特征只在受控内存中短暂存在。
- 原因：embedding 可能被重识别，会扩大生物特征和删除风险。
- 替代：长期身份模板；当前拒绝。
- 再评估：只有独立生物识别 PRD、法律基础、专用加密、访问和删除设计全部批准后才可讨论。

### 明确资产血缘而非前缀删除

- 选择：MediaAsset + MediaDerivation + provider job 关系。
- 原因：跨存储、供应商和缓存的派生关系不能靠文件名可靠恢复。
- 替代：按用户目录递归删除；容易漏删共享、任务和供应商副本。
- 再评估：无；任何新媒体处理都必须接入统一血缘。

### 默认不跨境回退

- 选择：无合规同地域能力时关闭 AI 增强。
- 原因：可用性不能自动扩大高敏感数据披露。
- 替代：根据延迟或价格自动路由全球供应商；当前拒绝。
- 再评估：特定跨境路径完成独立法律、同意、合同和技术评审后，以新 ProcessingPolicy 明确开放。

### 默认不用于训练

- 选择：生产处理 `training_allowed = false`。
- 原因：提供试穿服务不等于授权训练，且训练删除难度显著更高。
- 替代：在隐私政策中笼统包含模型改进；拒绝。
- 再评估：只有独立数据贡献计划、非诱导 opt-in、可撤回/删除方案、许可和偏差评估获批后另立文档。

## 可执行测试与验收

### 权限、同意和区域

1. UI 测试验证相机、相册、通知均只在对应用户动作后请求，拒绝后有完整替代路径。
2. 相同目的但供应商、地域、保留期或文案版本变化时，旧 ConsentRecord 不能提交新任务。
3. 撤回同意后新任务全部阻断，既有删除入口仍可用。
4. 不允许区域的任务在生成签名 URL 和调用供应商前被阻断；不得出现自动跨境请求。
5. 用户拒绝第三方处理后仍能完成衣橱录入、结构化推荐、单品拼图和保存。

### 媒体与对象存储

1. 使用含 GPS、设备、镜头、时间和自定义 EXIF 的夹具，验证上传派生图不包含这些字段。
2. 伪 MIME、polyglot、截断、超大像素、异常 ICC、超长视频和解码炸弹均关闭失败，且无残留临时文件。
3. 匿名、公网、跨用户和过期签名 URL 读取全部失败；方法、对象或 headers 改动后签名失效。
4. bucket、CDN 和对象 ACL 配置测试证明不存在公开读写。
5. 未 complete、未扫描或已删除的 MediaAsset 不能被生成任务引用。
6. 签名 URL、对象 key 和原始文件名不会进入数据库业务字段、队列消息、日志或崩溃报告。

### 授权与威胁

1. 对所有媒体、Avatar、WardrobeItem、Outfit、Job、结果和删除 API 运行跨用户 ID 替换测试。
2. Repository 属性测试证明 owner 条件不能由调用方省略。
3. 回调错误签名、过期时间、nonce 重放和错误 provider job ID 全部拒绝。
4. 重复请求、重复队列、worker 崩溃和回调重放不产生第二份业务效果或重复计费。
5. 管理员无审批不能读取媒体；JIT 访问在到期后失效并产生无正文审计。
6. 分享 grant 到期、撤销、资产删除和账号删除后立即不可访问。

### 删除与保留

1. 为每类源资产建立含裁剪、mask、试穿、视频、48 帧、manifest、缓存、分享和 Provider 副本的测试血缘。
2. 删除源资产后验证所有可达对象、数据库引用、队列/DLQ、CDN、客户端缓存和 Provider 副本均处理。
3. 在删除与生成并发、worker 中断、对象已不存在、Provider 超时和部分删除失败下重复执行，结果仍幂等且不恢复访问。
4. 每日孤儿扫描用合成遗漏证明能发现无血缘对象、无对象记录和超期临时资产。
5. 灾备恢复演练重放 tombstone，证明已删除高敏感数据不会因恢复旧备份重新可见。
6. 自动度量证明读取撤销 ≤5 分钟、自有主系统删除 ≤24 小时，备份和 Provider 符合最终批准期限。

### 日志、密钥和发布

1. 静态扫描和负向夹具阻断图片/base64、完整 URL、对象 key、EXIF、人物/衣物描述、API Key 和供应商响应进入生产遥测。
2. 运行时脱敏测试向每个稳定错误注入合成敏感字段，观测平台只收到 allowlist。
3. 密钥不在源码、客户端包、镜像层、CI 日志和配置导出中；轮换后旧新对象均可按策略读取或删除。
4. IaC 检查最小 IAM、公共访问阻断、生命周期、KMS 和审计配置。
5. 每个发布包重新生成并审核隐私清单、第三方域名、SDK 权限和数据用途；与实际网络抓包一致。
6. 供应商准入文档、DPA、地域、保留、训练和删除证明在有效期内；过期时部署门禁失败。

### 人工与真机验收

1. 用户在同意界面能回答“上传什么、给谁、在哪里处理、保留多久、如何删除、拒绝后还能做什么”。
2. VoiceOver 和最大 Dynamic Type 下，相机/相册用途、第三方同意、跨境说明、删除范围和备份期限均可读取和操作。
3. App 进入后台时高敏感页面使用隐私遮罩；任务切换缩略图不暴露人物和衣橱。
4. 设备离线、低存储、系统杀进程、账号退出和重新安装相关恢复/清理行为符合公开承诺。
5. 删除进行中时所有入口都不可重新读取旧内容；完成状态不早于端到端验证。
6. 法务、隐私、安全和产品共同签署数据清单、供应商、区域、同意文案、保留期限和事件响应方案。

任何一项跨用户访问、公开对象、未经同意/跨境处理、敏感日志、删除复活或供应商训练风险未关闭时，受影响的云端 OOTD 功能必须保持 feature flag 关闭，不得接入真实用户流量。
