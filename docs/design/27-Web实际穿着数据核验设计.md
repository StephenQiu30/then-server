# Web 实际穿着数据核验设计

状态：`approved`（2026-09-23，遵循用户指定的 `then-server` 后端和 Web 先行范围）。依据 [PRD 16](../prd/16-穿搭记录与反馈需求.md) `OUTFIT-REQ-013`～`015`、[Design 09](09-穿搭记录与反馈设计.md#账号实际穿着-api-基线) 与运行中 Go API `/openapi.json`；实施见 [17-33](../plan/17-33-Web实际穿着数据核验执行计划.md)。

`/wear` 是登录后的本人实际穿着核验页，避开后端 `/wear-events` 的同源代理路径。用户主动选择今天或过去的本地日期、完整或部分记录、真实衣物和来源；关联计划时选本人计划并明确按计划、换件或别套，页面提交所选计划当时的 revision。“按计划”要求完整的原计划衣物集合；计划快照已清除或实际选衣不同则改用换件来源。无计划来源不携带计划 ID。逐件不可穿与待洗确认默认关闭。创建 UUID 在结果不确定的重试中保持不变，编辑、删除使用 expected revision；冲突保留草稿并提供主动重载。

后端返回同日相似事件候选时，页面显示候选并要求用户再次主动确认；仅原样提交当前候选 ID/revision 集合。候选集合变化继续拒绝并重新确认。列表稳定分页，显示日期、来源、完整度、计划关联和服务端历史快照；`content=null` 显示已清除占位，不从当前衣橱倒灌。含清除占位的事件禁止直接编辑，保留历史或另建记录。删除须二次确认。

复用已有 PageShell、Field/Card/Alert/AlertDialog/NativeSelect、生成客户端与账户/衣橱/计划查询。交互组件归 `components/wear-event`，请求归 `hooks/wear-event`，纯校验与映射归 `lib/wear-event`。不新建 BFF、schema、通用状态框架。此页不实现 App 同步、离线记录、反馈、推荐学习、穿着次数聚合、日记或社区。

验收以隔离 PG/Redis、真实 Go API 和 Next.js 检查无计划及关联计划记录、重复确认、待洗原子结果、版本冲突、两账号隔离、删除后计划重算、401/网络恢复、移动布局和无障碍；公开入口继续受账号发布门禁约束。
