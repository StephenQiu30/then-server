# WebGPU 与 Three.js 展示评估

更新：2026-09-22。研究结论：**保留当前 WebGL2 + Three.js；WebGPU 为后续可选实验，不是首版依赖。** 产品按 [Design 20](20-OOTD完整产品能力与阶段架构设计.md) 使用整套静态 GLB，当前没有为了模块换装、眼部或布料引入新渲染后端的必要。

## 决策依据

图片转 GLB 解决资产输入，Three.js 负责场景与观察，WebGL2/WebGPU 是渲染后端。一个后端可用不等于人物好看；模型拓扑、贴图、轮廓、灯光和相机才是当前首要质量变量。静态 GLB 的旋转无需骨架或 WebGPU。

Three.js WebGPURenderer 与 WebGLRenderer 并非在所有材质、扩展和平台上无差别替换；以 [官方 WebGPU 文档](https://threejs.org/docs/#WebGPURenderer) 和项目固定版本实际行为为准。不能仅凭浏览器支持信息推断 App 的 WKWebView、GPU、系统策略和性能已经通过。

## 保留的历史证据

旧研究曾进行独立 WKWebView 能力探测和工程 GLB 检查。工程资源约 326 KiB、约 6,000 三角形，缺少生产贴图与真实头发等成本，因此不能据此推导生产模型性能或渲染后端优劣。此前要求的三人物×八组合、眨眼/注视和双后端发布矩阵不再作为首版退出条件，未运行的测试不改为 passed。

## 再评估触发条件

只有正式静态 Look 资产在 WebGL2 下出现可复现的画质或性能瓶颈，且优化面数、贴图、绘制与资源释放后仍不能满足目标，才启动独立后端实验。对照须使用同一 GLB/hash、相机、灯光、设备、系统、分辨率和交互脚本，记录首帧、持续拖动、内存、热状态、后台恢复和材质差异。

结论必须来自最低真机数据；迁移前同步 Design 01、实现计划和设备验收。当前无需安装新运行时、调整 minimum iOS 或维护双 renderer。
