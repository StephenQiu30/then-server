# 账号反馈与穿着统计设计

状态：`approved`；2026-09-23。承接 [16-03](../plan/16-03-结构化穿后反馈与证据重建执行计划.md) 的已验证本地语义和 [17-23](../plan/17-23-账号实际穿着API执行计划.md) 的账号实际事件。当前用户指定先在 `then-server` 实现后端，再做 Web 核验页；App 本地记录不会自动上传。

## 事实边界

- 一条现存、归属本人的 `WearEvent` 最多有一条反馈。跳过不写反馈；至少填写四维之一、一个问题标签或一段备注。四维分别为冷热、活动舒适、场合匹配、再穿意愿；取值沿用本地 16-03。问题标签最多五个且不能重复，备注去首尾空白后最多 240 字。标签与备注保留给本人查看，不作为偏好证据。
- `PUT /wear-events/{wear_event_id}/feedback` 完整保存或纠正反馈，带客户端稳定 `feedback_id`、每次命令的 `mutation_id` 和可空 `expected_revision`；首次创建时 revision 为空，纠正时为当前正整数。相同命令重试不重复加 revision；同 ID 不同内容、过期 revision 返回 409。`DELETE` 带三个标识及当前 revision，可重试；新命令可再次创建。
- 反馈和命令回执受 `(owner_id,event_id)` 外键约束。删除实际事件或账号时级联删除；衣物历史脱敏可保留反馈正文，但已脱敏单品不得再成为单品证据。跨账号的事件与反馈统一 404。
- `GET /statistics/wear?from=YYYY-MM-DD&to=YYYY-MM-DD` 只从本账号现存实际事件计算，闭区间最多 366 日。`wear_events` 是实际事件数，`wear_days` 是去重的本地日期数，`item_uses` 只含现存快照中有衣物 ID 的实际件次；无反馈也可有真实穿着统计。未上传的 App 本地事件不可混入。计划、日记、浏览、生成、点赞和反馈均不额外增加穿着次数。
- 反馈纠正/撤回不改变穿着次数；实际事件改期或删除时，统计与已有月历均从当前事实重算。账号 Web 客户端另在 17-35 消费本切片 API；云推荐证据、同步和生产发布另验，不建长期偏好缓存表。

## 实现位置与验证

`application/outfitfeedback` 管输入和命令，`adapter/postgres/outfit_feedback.go` 管事件行锁、反馈与回执事务及实时统计，`adapter/httpapi/outfit_feedback_{contract,routes,handlers}.go` 定义运行时 OpenAPI，bootstrap 显式组装。沿用现有 PostgreSQL、GORM、Gin/Huma、账号会话，不引入新服务或 SDK。隔离 PostgreSQL 测试验证重试/冲突、双账号、纠正/删除重算和级联；HTTP/OpenAPI 测试验证四个 operation。
