# Woo 虚拟人偶与自用成本决策

修订日期：2026-09-30（Asia/Shanghai）。产品范围：个人自用，不公开上线。人物目标：以本人为参考，保留脸型、发型和体形特征，生成 Woo 演示中那种半写实、明显虚拟的三维人偶。

本次调研从零开始，依据 Woo 演示及供应商、框架、开源项目的官方资料，不以 Then 现有文档或代码作为方案证据。用户已要求将结论纳入需求；当前行为合同见 [PRD 10](../prd/10-OOTD产品需求.md)，技术基线见 [Design 01](01-技术选型.md)。本文保存研究依据、候选比较与成本口径；未实施 App、上传私人照片、付费生成或安装模型。需求方向已确认，候选质量、设备与真实费用仍待验证。

## 1. 研究摘要

本轮比较了多参考风格化、整套图生三维、固定人偶/兼容衣物和本地模型的能力与总成本。当前选择及启用边界只在 [Design 01](01-技术选型.md) 维护，页面、数据与运行设计只在 [Design 03](03-OOTD产品总体设计.md) 维护；本文保留判断依据、候选差异、费用和实验方法。

研究建议为先固定本人及风格参考，确认完整人偶 Look 图后按需生成静态 GLB并复用。它以少量接入和资产制作投入取得本人三维效果，但不保证生成式身份硬锁或即时独立换衣。固定资产路线的价值与投入见第5节；模型/真实费用均未通过本人实验。

## 2. 人物风格：按 Woo 的效果定义

用户明确指定 Woo，因此不把“半写实”理解为任意卡通模板。以下是根据演示可见效果提出的美术要求，不是对 Woo 内部实现的逆向结论：

- 正常或接近本人身体比例，完整全身；不默认大头 Q 版或日系二次元大眼。
- 保留脸型轮廓、眉眼关系、发型/发色、肤色、眼镜等可辨识特征。
- 表面适度平滑，细节经过简化，具有三维雕塑和人偶感；不用照片皮肤纹理作为唯一目标。
- 衣物的颜色、轮廓、领口、袖长、裙/裤型、鞋包等是每日记录的核心，不能随意换成另一件。
- 单纯减少面数、加阴影或调粗糙度，不会自动得到符合目标的人物风格。造型必须从参考图和资产制作阶段控制。
- 正面作为默认视角，左右拖动旋转，复位；白灰背景、统一构图、柔和接触阴影。
- 首版采用静态姿态。走路、眨眼、发丝物理与布料模拟不是这轮人物目标的必要条件。

原帖演示展示了立体人物、拍摄全身、衣橱选衣、新 Look 图片，以及独立的 Create 360° 操作。宣传演示不能证明实际模型格式或算法。[Woo 原帖](https://x.com/LerSentAI/status/2090783821452943404)

### 本人参考和风格参考分别控制什么

- 本人参考：原始面部/全身照片，决定“这个人是谁”。
- 风格参考：确认满意的人偶图、材质方向、构图与简化规则，决定“以什么方式表现”。
- Look 输入：实际整套穿搭照片，或选中的衣物，决定“今天穿什么”。
- 显示设置：相机、光线、背景和尺度，决定“在 App 里怎样看”。

建立一组确认后的本人虚拟形象参考，比每次只输入“生成一个像我的人偶”更可控；但生成式参考并不等于身份硬锁定，也不保证三维拓扑一致。

实际拍到的穿搭与 AI 尝试的新搭配应分开标记。风格化的人偶也不是服装尺寸或真实合身程度的证明。

## 3. 当前推荐流程

### A. 先建立本人虚拟形象参考

选清晰正脸和完整全身照片，生成少量 Woo 式人偶图。由本人确认脸型、发型、体形和风格后，保存为 AvatarReference 的一个版本。

这一步首先得到参考图片，不应在数据里假装它已经是可随意换衣的参数化三维人体。真实侧背照片和 AI 补出的侧背参考也要区分。

### B. 真实每日穿搭记录

本人当天全身照片 + 已确认的人偶参考 → 风格化整套 Look 图片。

保持原有衣物和身形，仅改变表达风格；避免每次都从零重新设计本人。每天先保存图片与日期，只在本人选择“生成立体”时创建模型。

### C. 尝试新搭配

人偶参考 + 衣物图 → 新 Look 图片 → 确认 → 可选三维。

第一轮先测单件和简单组合。Tripo 的 seedream 图像编辑当前最多 4 张参考图，“人偶 + 上衣 + 下装 + 鞋”已经占满；包、外套等不能再无限堆图。服装参考板、分步骤编辑都是可实验办法，需要另外验证衣物和人物误差，不能直接承诺完整套装一次保真。[图像编辑接口](https://developers.tripo3d.ai/en/docs/generation-image-to-image)

### D. 满意图片转立体

输入已经确认的虚拟人物 Look 图片，生成带纹理静态 GLB。检查正面、45°、背面、头发、鞋包与衣物；只有通过的人偶才成为满意资产。

模型与其源图片绑定，不因任务晚返回覆盖另一个日期或另一套穿搭。模型生成失败时，已经保存的图片和记录仍然可用；图片本身不抵扣真实立体目标的验收。

### E. 本地复用

再次打开、旋转、改日期、收藏同一 Look，直接加载已保存文件。复用已经满意的相同整套造型无需再次生成；新造型仍需要新产物。

缓存标识至少包括：本人参考版本、风格版本、输入图片内容标识、模型/供应商、参数、可用的版本或 seed。固定 seed 也不能保证更换输入后人物身份绝对一致。

## 4. API 选择：先把接入与现金成本一起算

以下是 2026-09-30 查询官方页面的标价，不是实测费用或质量排名。

| 候选 | 本次用途 | 官方费用 | 本版优先级 |
| --- | --- | --- | --- |
| Tripo seedream_v5 图像编辑 | 风格化、多参考 Look 图片 | 5 credits，$0.05/输出 | 与三维共用一个账号和任务体系，先测 |
| Tripo H3.1 图生三维 | 整套静态 GLB，标准纹理 | 30 credits，$0.30/次 | 三维成本基线 |
| Tripo P1 图生三维 | 对照低面数拓扑、移动展示 | 标准纹理 50 credits，$0.50/次 | 少量质量/性能对照 |
| BFL FLUX.2 klein 4B 编辑 | 低单价的风格化对照 | 起 $0.014/图，随输出分辨率变化 | 质量通过且接入值得时再替换 |
| BFL FLUX.2 pro 编辑 | 低价候选质量不足时的对照 | 起 $0.045，受请求配置影响 | 不默认使用最高档 |
| FASHN v1.6 / Max | 特定衣物替换实验 | v1.6 $0.075/图；Max 按配置变化 | 不再作为所有虚拟人偶的默认生成器 |

价格依据：[Tripo 官方价格](https://developers.tripo3d.ai/en/pricing)、[P1 官方价格](https://developers.tripo3d.ai/en/models/p1)、[BFL 官方价格](https://docs.bfl.ai/quick_start/pricing)、[FASHN 官方价格](https://help.fashn.ai/plans-and-pricing/api-pricing)。

选择 seedream_v5 的理由是先降低接入和维护成本，不是已经证实它能最好地生成 Woo 人偶。它支持编辑、风格转移和多参考融合，但需要本人样本验证。FLUX.2 的 klein 可作低成本对照；其官方多参考上限也为 4，不能把其他 FLUX.2 档位的上限套过来。[Tripo 图像编辑](https://developers.tripo3d.ai/en/docs/generation-image-to-image)、[FLUX.2 能力与版本](https://docs.bfl.ai/flux_2/flux2_overview)

首版不同时接五个供应商。先用一个完整链路，记录满意结果成本；只有质量或费用数据说明收益时，再替换图片模型。

### 不应为名称或附加选项付费

- P1 的低面数不等于 Woo 的风格，也不代表更便宜。
- H 标准带纹理生成不需要再另付一遍基础纹理费。
- 更高清纹理、详细几何、smart low-poly、分件、格式转换和绑定可能额外计费；静态旋转首版不自动启用这些项目。
- 图生接口可提供 GLB，首版不先建立每次云端转换 USDZ 的步骤。
- 自动绑骨骼不提供可拆换的服装，也不解决穿模。

Tripo 的系统失败/取消任务不收费；返回成功但外观不满意的资产属于成功产物，重做需要计入预算。[官方计费](https://developers.tripo3d.ai/en/docs/billing)

### 照片处理边界

个人自用可以使用自己的 API Key；不需要建立公共生成服务。原照仍可能离开本机，虚拟化不会消除原始照片的隐私属性。使用 file_token 也只是不需要公开图片 URL，不等于本地处理。

若完全禁止云处理，再根据实际 GPU 选择本地推理。当前没有硬件信息，不能把“免费模型”算成零总成本。

## 5. 固定人偶 + 服装资产：什么时候值得做

固定三维人偶可以维持同一个头部和身体，已有兼容衣物组合不需要推理。它适合“同一个人即时换装”“骨骼动画”“跨套脸部绝对稳定”等更严格需求。

但它需要角色造型、独立服装、UV/贴图、绑定、体形适配、身体遮蔽和组合检查。现实衣物照片不会因为导入 VRM 就变成合适的三维衣服。

| 工具/资产路线 | 已核验能力 | 对当前目标的判断 |
| --- | --- | --- |
| Blender 定制 | 可人工控制脸、头发、体形、衣物、材质与骨架 | 风格控制强；初次制作与新增衣物成本需实测 |
| MPFB + Blender | 参数化人体、MHCLO 衣物加载/卸下与拟合 | 人体制作备选，不是自动 Woo 风格生成器 |
| VRoid Studio / Dress-up | 人物编辑，制作端服装适配，可导出组合 VRM1.0 | 默认美术方向与 Woo 有距离，不能直接作为最终风格 |
| three-vrm | 在 Three.js 中加载与运行 VRM 人物 | 渲染运行库；不负责现实服装建模或自动贴合 |

依据：[MPFB 资产装卸](https://github.com/makehumancommunity/mpfb2/blob/master/docs/ui/apply_assets/assetlibrary.md)、[VRoid Dress-up](https://vroid.pixiv.help/hc/en-us/articles/39512879834649-Introduction-to-VRoid-Studio-s-Dress-Up-Feature)、[three-vrm](https://github.com/pixiv/three-vrm/blob/dev/README.md)。

VRM 定义人形骨架、表情等角色扩展，不是通用服装尺寸与自动拟合标准。Three.js 可让蒙皮网格共享骨架，但衣物仍需正确的权重、绑定矩阵和体形适配。VRM 标准表情也不是本人脸型参数。[VRM1 规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/README.md)、[SkinnedMesh](https://threejs.org/docs/pages/SkinnedMesh.html)

### 怎样比较总成本

生成路线总成本：
新 Look 数量 ×（图片单价 × 图片付费尝试次数 + 三维单价 × 三维付费尝试次数）+ 修复时间。

固定资产路线总成本：
首次人偶制作 + 每件新增衣物制作/适配 + App 换装实现 + 组合维护；已有兼容资产组合的 API 费用为零。

不能只比较两个公式的最后一项。30 套/月、H 标准三维每套一次，基础三维费一年为 $108；平均两次为 $216。人工制作衣柜是否能节省总投入，必须用实际工时比较。

本版结论：先按套生成和复用；若跨套身份仍不满意，或即时换衣成为明确要求，再做“一个固定人偶 + 三件衣物”的小规模对照，而不是一开始建完整服装库。

这些工具的软件许可与输出资产许可也不同：MPFB 代码 GPL、内置资产 CC0；VRoid 预置资产与第三方服饰有各自条款。个人自用边界已核对，第三方资产不能一概当免费无条件素材。[MPFB 许可](https://github.com/makehumancommunity/mpfb2/blob/master/LICENSE.md)、[VRoid Guidelines](https://vroid.com/en/studio/guidelines)、[Blender 许可](https://www.blender.org/about/license/)

## 6. 个人使用的成本预算

### 按当前建议计算

统一假设图片每次 $0.05，H 标准三维每次 $0.30；“两次”指两次可计费产物，包括成功但不满意的重做。以下不含税费、附加选项、人工、已有设备费用与充值门槛。

| 使用方式 | 图片费用 | 三维费用 | 月度用量小计 |
| --- | --- | --- | --- |
| 30 套，每套图与模型各一次 | $1.50 | $9.00 | $10.50 |
| 30 套图各两次，仅 10 套做三维各两次 | $3.00 | $6.00 | $9.00 |
| 30 套图与三维都各两次 | $3.00 | $18.00 | $21.00 |
| 30 套各两次，但三维使用 P1 | $3.00 | $30.00 | $33.00 |

同一满意模型日后浏览、旋转和关联新日期不增加生成费。上述数量不代表每月保证得到 30 套合格人偶。

本地文件也会增长：若每个满意 GLB 假设为 20MB，每月新增 30 个约为 600MB，一年约 7.2GB，另加原照和结果图。20MB 是容量测算假设，实际需样本测量；先导出到自己的电脑备份，不默认购买云存储。删除缓存与删除满意资产必须分开。

换用 FLUX.2 klein 的公开起价，在每月 60 张图片的假设下，图片阶段理论最多省约 $2.16；真实分辨率、质量和重做会改变收益。相比之下，只将 10 套而非 30 套转三维，在上表假设下省 $12。两者算的是不同成本层次。

### 控制花费的产品规则

1. 先确认图片，再生成模型，避免把不满意的人脸或衣物带入三维。
2. 保存满意结果；同输入和同参数已有产物时直接复用。
3. 默认标准纹理，额外质量档位由本人主动选择。
4. 每套图片、三维分别设置重做上限，达到上限后暂停并检查输入或模型。
5. 记录预估费用与最终扣费；发生“提交结果未知”时不自动重发。
6. 改日期、收藏和旋转不触发生成。
7. 显示本月用量与设定上限，而不是引入订阅和支付系统。
8. 定期导出原图、满意图、GLB 和元数据；离线可查看已有结果。

### 不能漏掉的 iPhone 安装成本

自用 iOS 原生 App 可以通过免费的 Xcode Personal Team 安装，但官方说明其预置描述文件 7 天到期，需要重新构建并安装。长期使用要比较这份维护时间与付费开发者账号成本。[Apple 私人团队说明](https://developer.apple.com/cn/help/account/basics/about-your-developer-account)

Apple Developer Program 官方年费为 $99 或当地等值货币。它不是本次研究或原型实验的必买项；如果原生长期自用选择加入，须作为固定成本单独预算。已有会员时，不必为这个 App 再重复购买。[Apple 官方注册与会员费用](https://developer.apple.com/programs/enroll/)

若将 $99 年费均摊为 $8.25/月，上表 $9 / $21 的用量场景，连同这项固定费用分别是 $17.25 / $29.25/月。税费、实际当地收费和其他支出另计。这是成本分摊，不是 Apple 提供月付方案。

若明确要求零新增固定年费且不接受周期重装，应重新比较私人网页/PWA 或其他目标设备；网页仍有私有访问、浏览器持久存储和备份问题，不能只因没有签名费用就默认最适合。模型实验本身可先在电脑完成，不急于购买账号。

## 9. 先验证人物和满意成本，再扩大实现

### 第一轮样本

用自己的 5 套有代表性的穿搭：简单衣物、外套、长裙/宽裤、图案、鞋包/眼镜。建立一个确认的人偶参考版本，同一组输入比较两条路径：

1. 原穿搭照片直接生成三维，再统一显示。
2. 先转成 Woo 式人偶 Look 图片，再生成三维。

第一条用于检查能否省去图片阶段；不能只因为模型看起来“不像照片”就判定达到目标。若它缺乏稳定的人偶风格，采用第二条。

每套两条路径合计最多两次 H 三维，图片最多两次，并少量比较 P1；例如先为直接三维和风格化后三维各留一次 H。5 套图各两次、H 合计各两次、P1 各一次，按当前单价基本用量约 $6；若两条路径各做两次 H，则变为约 $9，已超出每套两条路径合计两次 H 的初始上限，不能自动执行。额外本人参考和重做另计。建议首轮设置 $10–15 的消耗上限，它不是已批准的付费额度、最低充值额、实测账单或质量保证；实际执行前由本人设定允许额度。

### 质量与成本同时验收

| 验收项 | 达标判断 |
| --- | --- |
| Woo 风格 | 本人确认有目标三维人偶感，造型、材质和比例一致 |
| 本人特征 | 脸型、发型、肤色、眼镜与体形认得出是自己；允许合理简化 |
| 跨套稳定 | 五套能看出同一个虚拟人物；明显换脸不能用“风格化”解释 |
| 衣物 | 核心颜色、轮廓和单品保持；不能为人物好看而换掉衣服 |
| 三维 | 可连续旋转，头发/肢体/鞋包不严重融合或缺失，侧背可接受 |
| 成本 | 记录全部可计费尝试与人工修复，计算实际愿意保留的每套成本 |
| 使用 | 满意文件保存后离线能开，重启不丢；浏览不再生成 |

“满意每套成本”=该批图片/模型所有付费产物、可选处理与修复成本 / 实际保留套数。不要把 HTTP 成功率当满意率。

### 真机展示

先用 WebGL2，统一比例和地面位置，按交互需要重绘，暂停不可见场景。无动画的静态人物不必持续渲染耗电。

初始参考目标：缓存模型呈现约 3 秒内，拖动至少 30fps，连续切换 30 次和旋转 5 分钟；这些待本人手机测试。模型文件大小不等于 GPU 内存：2048² RGBA 纹理解码约 16MiB，含完整 mipmap 约 21.3MiB，多材质会累加。面数、纹理和压缩都需兼顾人物与衣物质量。

如果两次生成仍不满意，先改输入或模型；若始终无法保持同一虚拟人物，再触发固定资产小实验。不要无上限重做，或先开发完整页面掩盖人物失败。
