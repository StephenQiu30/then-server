# 数字衣橱与虚拟试穿竞品研究

研究核验：2026-09-22。本文保存外部证据、当前项目审计与研究结论；产品目标及需求深化见 [Design 20](20-OOTD完整产品能力与阶段架构设计.md)，实施状态见 [Plan 10](../plan/10-OOTD产品实施计划.md)。本次是需求与设计调研，未实施 App 功能、调用付费生成、采购资产或开放真实用户照片。

## 研究结论

现行定位为：以好看的完整 Look 提供首次价值，用真实衣橱和穿着记录支持持续使用。**完整穿搭图 → 按需整套静态 GLB → Three.js 展示与复用**已由用户于 2026-09-22 授权写入当前设计；供应商、样本和代码实施仍未通过。

1. 当前关键缺口是合格完整人物图/静态 GLB、Look 持久化和真实云任务；模块服装、骨架和眼部不再作为首版资产前置。
2. 内置参考、用户拥有衣物、Look 图片和派生模型必须分离；生成结果不证明真实拥有或尺码合身。
3. SwiftUI/GRDB/Three.js/Go 单体与既有 Kafka/PostgreSQL/MinIO/Redis 可复用，无需为静态展示引入游戏引擎或 GPU 集群。
4. 图片、可交互 GLB 和视频按不同结果验证；视频延期，连续模型旋转无须额外 AI 视频调用。
5. 公开文档证明能力可进入验证，不证明人物/衣物保真、实际费用或删除准入；以下竞品与许可证据仍用于指导验证。
6. Tripo 云 API 不等同 TripoSR 或 img2threejs；优先验证其图片转 GLB，图片端先测 Seedream v5。高级绑骨/分割能力不代表自动得到兼容衣物。

详细取舍、当前成本公式和退出条件归 [Design 20](20-OOTD完整产品能力与阶段架构设计.md)，不再并列一套待批准主线。

## 三条视觉路线的取舍

| 路线 | 能解决的问题 | 不能自然解决的问题 | 实施建议 |
| --- | --- | --- | --- |
| 整套静态 GLB + Three.js | 连续旋转、缩放、本地离线复用 | 即时逐件换装、真实背面/尺码、自动保证画风 | 当前采用方向，先验证代表完整 Look 与持久化 |
| 本人照片 AI 试穿 | 本人身份下的服装视觉预览 | 稳定背面、准确面料/合身、每个未选区域不变、可编辑网格 | 先验证完整 Look 多参考支持集，单件作为对照；质量与本人照片准入分别验证 |
| 图片派生 360° 视频 | 更生动的展示和分享素材 | 用户自由改变视角、可替换网格、真实背面保证 | deferred，首版模型旋转无需该调用 |

三视图图片可以作为静态结果与降级资源；不能把三张图滑动或一段视频验收成连续 3D。当前完整图和静态 GLB 路线已取代旧 P1 独立三视图生产；11-03 退役不等于其原门禁通过。

Context7 查到的 [SkinnedMesh](https://threejs.org/docs/pages/SkinnedMesh.html) 与 [SkeletonUtils](https://threejs.org/docs/pages/module-SkeletonUtils.html) 支持绑定和克隆蒙皮模型；这要求资产骨架、bind pose、权重、空间及 morph 合同兼容。示例里的 `DetachedBindMode` 不能无条件应用到所有服装。`SkeletonUtils.clone` 仍会共享 geometry/material 引用，卸载一套 Look 时需要明确资源所有权，避免销毁另一套正在使用的资源。

[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) 的皮肤、形变与压缩扩展支持不自动包含解码器、正确材质或业务兼容性；需要压缩时随包锁定对应解码器并验证。当前没有必要提前加入所有压缩依赖。

[WebGPURenderer 官方说明](https://threejs.org/manual/en/webgpurenderer.html)包含 WebGL2 后端与 `forceWebGL`；它不等于旧 WebGLRenderer。当前 App 仍使用 WebGLRenderer。是否迁移依据 [独立评估](webgpu-avatar-assessment.md) 的代表资产/最低真机三路比较决定；本轮文档查询没有给出迁移收益证据。

| [阿里云 aitryon-plus](https://help.aliyun.com/zh/model-studio/aitryon-plus-api) | 文档限定华北 2 北京；人物和衣服需要可访问 HTTP(S) URL；支持上下装组合；单传一类可随机生成另一类 | [公开计费](https://help.aliyun.com/zh/model-studio/billing-for-outfitanyone)：基础版 0.20 元/张、Plus 0.50 元/张；Plus 文档约 90 秒，结果 URL 24 小时 | 若目标市场为中国大陆，可进入地域候选审查；不自动切换当前优先验证路线或用户处理地域，不把北京端点等同于完整数据驻留/删除承诺 |

**单件替换是最容易被低估的产品约束。** 阿里云明确说明只传上装可能随机生成下装，保留下装需要先获取对应衣物输入。由此可以直接推导：不能只传目标上衣便在 UI 承诺“其他衣物完全不变”。需要增加保留输入、验证未选区域、计入分割调用及延迟；当前 [PRD 14](../prd/14-AI虚拟试穿需求.md) 已采用完整 Look，仍须逐件核对支持集与用户选定内容，不得用随机补衣服抵扣输入保真。

**结果保留与删除需要分别核验。** [FASHN 隐私文档](https://docs.fashn.ai/api-overview/data-retention-privacy)说明标准 CDN 输出安排三天后到期，base64 输出可从状态端点取回最多 60 分钟，请求历史仍保存参数/输入 URL/状态等信息，并声明 Customer Content 不用于训练。链接过期、状态接口不可取回和“不训练”均不等于所有日志、缓存及备份已完成删除。Then 应及时收取结果到自己的私有对象存储，任务账本保存供应商请求 ID 和删除状态。

| 方案 | 当前一手证据 | 准入判断 |
| --- | --- | --- |
| [CatVTON](https://github.com/Zheng-Chong/CatVTON/blob/main/LICENSE) | 根 LICENSE 为 CC BY-NC-SA 4.0 | 研究候选；现有许可包含非商业限制，不作为商业发布默认依赖 |
| [IDM-VTON](https://github.com/yisol/IDM-VTON/blob/main/LICENSE.txt) | 根许可证为 CC BY-NC-SA 4.0；官方 README 包含额外预处理与模型依赖 | 同上；不能用 Gradio demo 可运行代替完整商业授权和部署评测 |
| [FASHN VTON v1.5](https://github.com/fashn-AI/fashn-vton-1.5) | 主仓库 Apache-2.0，公开推理代码/权重，支持人物和服装图 | 可做研究；默认整链暂不进入商业准入，原因如下 |

FASHN 的 [pipeline.py](https://github.com/fashn-AI/fashn-vton-1.5/blob/main/src/fashn_vton/pipeline.py) 导入 `FashnHumanParser`，构造时调用 `_setup_hp_model()`；[解析器 README](https://github.com/fashn-AI/fashn-human-parser#license) 明确继承 SegFormer 许可，而 [NVIDIA LICENSE 第 3.3 节](https://github.com/NVlabs/SegFormer/blob/master/LICENSE)限定研究/评估用途的非商业使用。**因此不能把默认推理链整体标成 Apache-2.0 可商用。** 此结论针对本轮查看的代码与声明，不对另有授权的 FASHN 商业 API 作相同推断。

后续如选择自托管，先关闭主模型、解析器、pose detector、权重、数据与输出权利的准入，再做 GPU 吞吐/显存/可用性测量。获得许可或更换解析器均可能改变质量，必须重新盲测。Go 继续作为产品服务；只有自托管被选中且需要部署时，才增加隔离 Python 推理进程，不提前创建空 AI 服务。

## 同输入评测与成本口径

当前优先验证 Seedream v5 完整图与 Tripo H3.1 静态 GLB，先单套代表，再至少 12 组授权图片输入；失败才对照专用 VTON。样本量与首片止损归 Design 20/14-01。进入生产前另扩代表性人群盲测，不能用少量合成成功推导生产质量。

以下维度适用于同输入对比，不意味着同时建设多个 Provider、恢复 11-03 或采用开源自部署。

样本覆盖：上装/下装/连衣裙，纯色/条纹/印花，长短袖与宽窄轮廓，发丝/手臂遮挡，不同肤色和身体轮廓，平铺和穿着商品图；不使用未授权用户照片。两个评审者不知道供应商名称，记录分歧并复核。

| 维度 | 必须记录 | 退出方式 |
| --- | --- | --- |
| 衣物保真 | 颜色、轮廓、图案、文字、衣领、袖长逐项 0/1/2 分 | 错款、明显图案/文字改变独立列为严重缺陷，不由美观分抵消 |
| 人物与未选区域 | 脸、肤色、手、背景、未选衣物变化 | 身份显著漂移或未选区域改变违反任务承诺时，拒绝展示/候选不通过 |
| 可用结果 | 技术成功、质量通过、用户主动保留分别计数 | HTTP 200/供应商 succeeded 不直接计产品成功 |
| 时延 | 上传、排队、推理、收取、校验与首屏展示分段 p50/p95 | 供应商标称时间不得直接作为全链路指标 |
| 费用 | 每次调用、成功输出、质量淘汰、重试、分割/视频/存储及流量 | 同模型/模式/输出数比较，完整 outfit 不能套单张单件价格 |
| 恢复/隐私 | 超时未明、重复回调、取消、撤回、删除和过期 URL | 任一重复扣配额、复活结果或越权读取即阻断对应发布 |

**可用结果成本 =（全部已计费输出 + 前后处理 + 基础设施分摊）/ 质量通过且可交付的结果数。** 技术失败不计费的供应商仍可能产生“技术成功但质量不可用”的费用。

示例仅作敏感性测算：FASHN v1.6 公开价格为 $0.075/张，若 100 张技术成功输出只有 70 张可用，则生成费用摊到每张可用结果约 $0.107；1,000 张可用结果约需 $107 生成费用，尚不含其他成本。阿里云 Plus 同口径为 0.50/0.70≈0.714 元/可用张，1,000 张约 714 元。70% 是假设，不是实测，两者也不因此具有相同质量。分币种展示，不做未核验汇率换算；不扣除免费额度。

## 用户研究与发布验证建议

技术调研不能替代需求验证。建议 8–12 名目标用户开展两轮任务观察，再邀请约 30 名愿意使用真实衣橱的用户做两周日记研究；均是待执行设计。

- 首次任务：零账号/零上传，选人—选衣—观察—保存—退出重进；观察是否理解“已应用”和“已保存”。
- 长期任务：只录入近期常穿单品，完成一次场景推荐、局部替换、计划、确认穿过和反馈；记录真实耗时及录入放弃原因。
- 可信度任务：混合展示模板 3D、本人 AI 图与视频，检查用户是否误以为支持合身或准确背面。
- 删除任务：删除一张照片或一个 Look，让用户预测受影响的记录，再核对实际系统结果。
- 评价重点：是否愿意第二天主动回来做同一任务、是否愿意逐步录入，以及哪些缺陷使其放弃；不将“觉得可爱”直接等同于日常使用价值。

[Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/)将 UGC 举报/屏蔽、账号删除与向第三方 AI 分享个人数据前的明确告知/许可列为相关要求。现有社区治理和隐私合同应延续到客户端。目标市场仍未确定，本报告不代替针对具体运营地域的数据处理与上线审查，也不默认跨地域切换供应商。
