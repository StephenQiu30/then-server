# 数字衣橱与虚拟试穿竞品研究

## 状态与结论

- 文档状态：`approved`，研究截止 2026-09-15。
- 研究范围：数字衣橱、AI 私人造型、照片虚拟试穿、虚拟人物、多视角媒体和真实 3D 内容平台。
- 证据原则：产品能力只引用官方站点、官方应用商店、官方开发文档或官方 GitHub；第三方评测只用于发现候选，不作为技术事实。
- 结论：市场不存在一套同时把“零录入即时换装、本人衣橱管理、照片级试穿、真实 3D、尺码预测、社交商城”都低成本做好的通用方案。成熟产品通常只选择其中一条主线，再把其他能力作为条件增强。
- 对于是的影响：保持 [Design 18](18-Woo立体数字衣橱技术路线研究与决策.md) 的多视角媒体 MVP，不恢复 Blender/GLB/Three.js。新增的竞争定位是“零上传立即可玩，结果可保存并逐步连接真实穿搭计划”。

本研究补充 Woo 单一参考，不推断任何竞品未公开的模型、服务端、数据库、渲染器或训练数据。

## 市场分层

| 市场层 | 用户购买的价值 | 常见输入 | 主要输出 | 代表产品 |
| --- | --- | --- | --- | --- |
| 数字衣橱与计划 | 管理已有衣物、减少每日决策、复盘利用率 | 单品照片、购买记录、穿搭记录 | 衣橱、拼贴 Look、日历、统计、建议 | Whering、Acloset、Indyx、Stylebook、Alta |
| 照片虚拟试穿 | 快速看到“我穿它可能怎样” | 本人照片、衣物/灵感图 | 生成图片，部分产品派生短视频 | Doppl、Doji、DRESSX、Perfect Corp |
| 电商虚拟造型 | 提升商品发现、组合购买和模特包容性 | 商家商品图、预设模特或顾客图 | Switch Model、Mix & Match、Try-On | Veesual、Google VTO、FASHN |
| 真实 3D 虚拟身份 | 长期虚拟身份、连续观察、动画和内容交易 | 自拍或角色编辑、适配的 3D 资产 | rigged avatar、服装资产、动画、创作者市场 | ZEPETO、Avaturn |
| 研究与开源模型 | 验证试穿、身份控制或生成方法 | 数据集、人物图、衣物图、pose/mask | 模型输出或研究 demo | OutfitAnyone、Kolors、OOTDiffusion、StableVITON、VITON-HD |

这些层不能用同一验收口径。图片试穿通过不代表尺码准确，短视频通过不代表存在 3D 网格，3D avatar 可旋转也不代表真实衣物垂坠可信。

## 数字衣橱与造型产品

| 产品 | 官方公开的核心能力 | 首次价值成本 | 可借鉴内容 | 不进入首版的内容 |
| --- | --- | --- | --- | --- |
| [Whering](https://whering.co.uk/) | 添加/管理衣物、搭配、计划、旅行打包、穿着洞察、朋友衣橱；官网称用户超过 1,000 万 | 需要添加或导入已有衣物 | 计划、统计、朋友协作均建立在稳定衣物事实之上 | 社交衣橱、关注关系、可持续评分 |
| [Acloset](https://www.acloset.app/) | 从照片或购买来源建立衣橱，AI 整理、每日推荐、天气、统计和虚拟试穿 | 仍需照片/购买数据，但自动识别降低录入负担 | 后续把建议、天气和统计连接到真实衣物 | 首版不做镜像自拍拆衣、商城导入和社区 |
| [Indyx](https://www.myindyx.com/) | 数字化衣橱、搭配、日历、打包、利用率，以及真人造型服务 | 自己录入、转发购买凭证或购买人工整理服务 | 清晰区分免费工具与高价值人工服务 | 真人造型师市场、转售和订阅体系 |
| [Stylebook](https://www.stylebookapp.com/features.html) | Looks、Closet、Packing Lists、Calendar、Style Stats、Shopping、图片导入和设备同步 | 手工建立衣橱 | 本地优先、拼贴、日历、穿着统计的长期价值明确 | 90 多项工具不整体复制；避免功能清单膨胀 |
| [Alta](https://www.altadaily.com/) | 数字衣橱、场合/天气建议、虚拟 dressing room、旅行打包和 wishlist | 上传衣物后价值更强 | 用场景和天气解释推荐，连接衣橱与计划 | 社区灵感流、wishlist 商业化和开放商城 |

共同问题是录入成本。市场产品通过图片识别、零售商导入、购买凭证、浏览器扩展甚至人工上门缓解，但没有消除“先提供自己的衣物”这个门槛。于是的内置人物和内置服装可以先给价值；后续真实衣橱必须显式标为“我的衣橱”，不能把内置目录记成用户拥有。

## 照片试穿与生成式产品

| 产品 | 官方公开的输入与结果 | 公开形态 | 对于是的含义 |
| --- | --- | --- | --- |
| [Google Doppl](https://blog.google/innovation-and-ai/models-and-research/google-labs/doppl/) | 建立用户的数字版本，输入任意来源的 outfit 图片进行试穿，并可生成 AI 视频 | Google Labs 实验性 iOS/Android 产品；初始公开范围为美国 | 图片结果后派生视频是已存在的产品模式；视频仍不是 3D 模型 |
| [Doji](https://apps.apple.com/us/app/doji-try-on-designer-fashion/id6737292650) | 创建照片级 AI likeness，试穿精选或自选服饰，保存和分享 | 消费级 iPhone App | 稳定人物身份、精选目录、结果收藏是同一闭环；本人 likeness 必然提高照片隐私和一致性成本 |
| [DRESSX](https://dressx.com/) | 面向品牌的 Virtual Try-On、AI Stylist Assistant 等模块 | B2B 品牌集成和数字时尚服务 | 供应商可承担生成能力，但品牌目录、权利和产品状态仍由项目负责 |
| [Perfect Corp](https://www.perfectcorp.com/business/products/ai-fashion-tryon) | 单张人物照片配合服装/造型输入进行 AI Fashion Try-On，提供企业 API | B2B API 与消费工具 | 可列为商业 Provider 候选；必须经过同输入质量、地域、保留和价格核验 |
| [Google Virtual Try-On](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/generate-virtual-try-on-images) | 人物图加商品图，生成 1–4 张 PNG | Google Cloud API | 适合作为内容生产对照，不解决跨视角身份一致性和 360° |
| [FASHN](https://fashn.ai/products/api) | Try-On、Model Create、Edit、背景处理和 Image-to-Video | 商业异步 API | 当前首个内容生产 POC 候选；运行时继续与供应商隔离 |

这类产品的核心质量指标是人物身份、衣物细节和结果审美。它们普遍输出媒体，不能据此承诺真实尺码、布料物理或可编辑模型。于是的首版不要求本人照片，因此应在发布前完成固定人物内容生产，把生成不确定性从用户会话移走。

## 电商虚拟造型

[Veesual](https://www.veesual.ai/vto/blog/virtual-try-on-styling-fitting) 把三种问题分开：Virtual Try-On 关注“看起来怎样”，Virtual Fitting 关注尺码，Virtual Styling 关注多个商品组成完整 Look。其 [Switch Model](https://www.veesual.ai/vto/solutions/switch-model) 使用多样化模特展示商品。该区分对于是很关键：首版属于 Virtual Styling/visualization，不是 fitting。

可借鉴的电商模式：

1. 预设人物减少用户上传和身份生成成本。
2. 只有具有完整视觉结果的组合才可选择。
3. 人物、服装目录、Look recipe 和媒体资产使用不同稳定 ID。
4. 尺码建议、合身预测和视觉结果必须使用不同文案、数据与验收。

暂不采用商品购买链路、品牌后台、多尺码交易和转化率优化；它们不能提高首版“选人、选衣、保存”的完成度。

## 真实 3D 产品为何不同

| 产品 | 官方可确认的 3D 证据 | 工程含义 |
| --- | --- | --- |
| [ZEPETO Studio](https://studio.zepeto.me/products/item) | 提供角色商品模板、3D 制作、发布和创作者销售体系；[Rigging 文档](https://docs.zepeto.me/studio-guide/rigging) 明确 mesh、joint、skin weight 和 Maya joint orientation | 真正 3D 换装需要长期资产规范、rig、蒙皮、内容审核和创作者工具，不只是一个 renderer |
| [Avaturn](https://avaturn.me/) | 自拍生成可定制 3D avatar，可导出到 Blender、Unity、Unreal、Maya 等；[REST API](https://docs.avaturn.me/api/) 明确 Avatar、User、Session 和 3D model export | 适合游戏/虚拟身份或需要连续相机的产品；会引入自拍、供应商身份、导出资产和运行时集成 |

ZEPETO 还允许从 2D texture template 创建简单商品，但这是把纹理应用到平台预制的 3D 模板，并不等于从任意衣物图片自动得到可穿网格。其公开文档反而说明：如果于是以后选择真实 3D，就必须同时投资资产模板、rigging、穿模治理、LOD、材质、动画和发布工具。

当前 Woo 演示没有公开上述任何 3D 生产证据，所以继续按 Design 18 的多视角媒体路线交付。

## 开源和研究方案复核

| 方案 | 官方仓库事实 | 许可/可用性 | 当前结论 |
| --- | --- | --- | --- |
| [OutfitAnyone](https://github.com/HumanAIGC/OutfitAnyone) | 阿里研究项目；公开 demo 因安全原因只允许上传衣物，人物为 AI 生成的固定预设 | 仓库没有可获取的根 LICENSE，也没有公开生产源码 | 产品模式与“预设人物”高度相关，可作概念证据；不可作为依赖 |
| [Kolors](https://github.com/Kwai-Kolors/Kolors) | 官方提供 Virtual Try-On demo、FaceID/IP-Adapter、Pose ControlNet 和 Diffusers 支持 | 代码 Apache-2.0；模型权重适用独立许可，商业使用需按官方规则登记/授权 | FASHN/Google 都 no-go 后的候选，不为首轮同时搭第三条生产链 |
| [OOTDiffusion](https://github.com/levihsu/OOTDiffusion) | 人物图加衣物图；full-body 按 upper/lower/dress 单类别运行；依赖 parsing、OpenPose、CLIP 等 | CC BY-NC-SA 4.0 | 商业产品 no-go；可读论文和公开结果，不接代码/权重 |
| [StableVITON](https://github.com/rlawjdghek/StableVITON) | 需要 DensePose、agnostic mask、cloth mask 等预处理，基于扩散完成试穿 | README 明确 CC BY-NC-SA 4.0 | 商业产品 no-go，预处理也超过 MVP |
| [VITON-HD](https://github.com/shadow2496/VITON-HD) | 1024×768 上装试穿研究基线；数据为正面女性与上装配对 | CC BY-NC 4.0，数据仅研究用途 | 不能用于商业训练或生产；类别和姿态覆盖也不足 |
| [FASHN VTON v1.5](https://github.com/fashn-AI/fashn-vton-1.5) | maskless 人物图/衣物图试穿，官方发布代码和权重 | 主仓库 Apache-2.0，但解析器和全部依赖仍需逐项审查 | 保留为自托管质量 POC，不直接进入 App 或正式服务 |

GitHub 搜索中存在大量包装 IDM-VTON、Kolors 或 Gradio demo 的个人仓库。缺少作者、模型来源、许可证、测试和维护证据的 fork 不进入候选，星数和“可运行截图”不能替代供应链审计。

## 可复用生成技术边界

Context7 对 Hugging Face Diffusers 当前文档的核对表明：

- [IP-Adapter](https://huggingface.co/docs/diffusers/using-diffusers/ip_adapter) 通过图像编码和新增 cross-attention 提供参考图条件，可调权重或使用多个 adapter；它提高控制能力，但不保证同一人物跨视角完全一致。
- [ControlNet](https://huggingface.co/docs/diffusers/using-diffusers/controlnet) 可用 OpenPose 等结构图约束姿态；它解决构图/姿态条件，不负责衣物真实性或身份事实。
- [Stable Video Diffusion](https://huggingface.co/docs/diffusers/api/pipelines/stable_diffusion/svd) 从单图生成短视频并需要明显 GPU/内存治理；普通 image-to-video 不自动等于 360° 转台。

如果商业 Provider 都不达标，内部 POC 可以组合固定人物 reference、固定 front/side/back pose、衣物试穿和人工修正验证上限。该实验只能在许可证和 GPU 预算获批后开始，不能提前建设通用 ComfyUI/模型平台。

## 竞争定位与需求取舍

### 于是首版的明确定位

**无需录入衣橱即可立即完成一次完整穿搭；结果可保存、复看，并能在后续连接真实衣橱与穿搭计划。**

| 选择 | 原因 |
| --- | --- |
| 保留三套预设人物和内置目录 | 避免 Whering/Acloset/Indyx 类产品的首次录入阻断 |
| 保留完整 Look 多视角结果 | 比 Stylebook 式单品拼贴更接近 Woo/Doppl/Doji 的人物结果 |
| 保存 recipe 与 render-set revision | 让一次生成视觉成为可复用的产品状态，而不是一次性图片 |
| 明确“探索衣橱”和“我的衣橱” | 内置商品不冒充用户拥有；后续真实推荐仍有可信事实 |
| Create 360° 独立 | 遵循 Doppl 类“结果后派生视频”的产品语义，不伪装 3D |
| 本人照片后置 | 保留 Doji/Doppl 的个性化价值，同时不让隐私和漂移阻断首版 |

### 首版不复制的市场功能

- 社交关注、朋友衣橱、公开动态、品牌市场和创作者交易。
- 真人造型服务、订阅、广告、联盟购买和二手转售。
- 尺码推荐、退货率承诺、身体测量和面料物理。
- 从购买邮件、浏览器插件或任意商城自动导入。
- 用户运行时开放提示词、模型选择、seed 或生成参数。
- 真实 3D 编辑、自由相机、动画市场和开放资产上传。

这些功能分别属于增长、商业化或平台化，不是首版穿搭核心闭环。

## 更新后的供应商 POC 顺序

1. **FASHN API**：验证固定人物、完整 outfit recipe、正/侧/背和衣物细节。
2. **Google Virtual Try-On**：使用相同输入与人工审核表对照。
3. 两者都未达到门槛时，先判断是输入设计、跨视角目标还是模型能力导致；只在明确问题后选择 Perfect Corp 商业 POC 或 Kolors 授权/自托管 POC。
4. OutfitAnyone、OOTDiffusion、StableVITON 和 VITON-HD 不进入产品依赖。
5. 静态 POC 通过后才单独测试 FASHN Image-to-Video、其他视频 Provider 或受控 SVD；视频不能反向阻断静态主线。

首轮仍只保留两个候选，避免同时接入多家 API。市场扩展提供备选顺序和 no-go 依据，不扩大 11-03 当前实现范围。

## 竞品研究 SOP

1. **发现**：按数字衣橱、照片试穿、电商造型、真实 3D、开源研究五类维护候选，不用“AI 穿搭”一个标签混合。
2. **一手核验**：记录官方 URL、核验日期、公开输入、输出、平台和限制；内部技术未披露就写未知。
3. **用户旅程拆解**：只比较首次价值、核心操作、结果复用和长期留存，不按营销功能数量排名。
4. **技术拆解**：把内容生产、用户运行、媒体保存、真实衣橱事实和异步任务分层。
5. **许可证检查**：代码、权重、数据集和输出条款分别检查；任一非商业或缺失均不得进入商业候选。
6. **同输入 POC**：候选使用相同人物、recipe、视角、审核表和成本口径；失败结果保留。
7. **需求回写**：只有验证能改善首版核心指标的能力才进入 PRD；其他能力进入候选清单，不创建空页面、空表或空服务。

## 对当前文档和计划的影响

- Design 18 的技术路线保持不变，市场研究提供跨产品佐证。
- PRD 10/11 的三套人物、六件衣物、24 套 Look、三视图、默认离线和不要求上传保持不变。
- 11-03 首轮仍比较 FASHN 与 Google；补充 Perfect Corp/Kolors 的条件候选，不扩大任务并发。
- Design 17 页面可吸收数字衣橱产品的计划/历史清晰度和照片产品的结果聚焦，但不复制社交、市场和商城。
- 真实 3D 仍须满足 Design 18 的重新准入条件；ZEPETO/Avaturn 只证明该路线需要完整资产生态。
