# Woo 页面与立体穿搭 UI 设计

更新：2026-09-22，设计 `approved`，页面实现待按切片交付。采用根 DESIGN.md 的黑白极简、内容优先和单一品牌行动色；三套人物预设共享一套页面。本次以图片优先、按需整套 GLB 替换旧模块衣物和体型编辑交互。

## 页面目标与参考边界

首页全身人物、清晰日期、关联衣物、选衣网格和真实生成状态参考 [Woo 可见流程](18-Woo立体数字衣橱技术路线研究与决策.md)。布局服务“查看、保存、尝试新穿搭”，不照抄品牌或未公开页面；参考图中的人物不是可直接发布资产。

## 导航

一级“今日、衣橱、穿搭簿”；账户从头像进入。社区页面和治理可用时增加“发现”。照片入口归“新建穿搭”，没有独立空照片 Tab。Web 账户页面仍按 Design 16，iOS 导航不自动复制至 Web。

## 页面规格

| 页面 | 信息层级与主动作 | 必须覆盖的状态 |
| --- | --- | --- |
| 今日 / Look 舞台 | 全身图片占主视觉；日期/标题、少量选衣缩略图；已有模型显示“查看立体”，无模型显示“生成立体展示” | 默认离线 Look、图片加载/失败、已有模型、模型任务中/失败、当前 Look 已删除 |
| 内置 Look 选择 | 按三个人物分组的完整套装缩略图，清楚标为内置 | 随包立即切换；其他内容未缓存时明确联网；不显示任意模块换装承诺 |
| 衣橱 | “我的衣物 / 内置参考”来源切换；实际分类同页网格；新增衣物与筛选 | 空衣橱、无图、加载、归档/不可用、选中、局部失败 |
| 选衣草稿 | 当前人物参考、选衣托盘、单品原图；主动作“生成穿搭图” | 不支持类别/输入不足明确提示；不自动替用户补衣物；可保存结构化草稿 |
| 照片准备 | 用途说明→本人/成年确认→系统选图→净化预览→确认 | 取消、多人/模糊/格式错误、离线云照片不可读、清理失败 |
| 图片生成 | 参考缩略图和真实阶段，允许离开/取消 | 排队、处理中、检查中、成功、失败/额度不足、待对账；无伪造进度条 |
| Look 结果 | 新图、原始衣物对照、保存/收藏、按需立体、主动分享图片 | 保存中/失败、日期、旧版/新版、模型不影响图片操作 |
| 三维查看 | 同版本 GLB、原生关闭/复位/角度控件；连续拖动、有界缩放 | 加载/坏包、上下文丢失、低资源、离线缓存、回到图片 |
| 穿搭簿 / 详情 | 按日期回看；区分 Look、计划、实际穿着、日记 | 空态、编辑/取消、删除影响与进度、媒体已删除、重启恢复 |

“Dress up”若保留英文风格，只能作为“生成穿搭图”的辅助文案，不可让人误以为离线即时改变新衣物。内置已完成 Look 使用“使用这套”，不模拟 AI 等待。

## 两种生成动作

图片和模型分别触发、分别计费说明、分别显示状态。图片 ready 后即可保存/分享；三维 ready 前显示“生成立体展示”，提交后显示“立体效果生成中”，就绪后才显示“查看立体”。失败展示持久说明和重试按钮，同时保留图片。重复点击同一有效任务只打开其状态。

用户修改衣物或人物参考后显示“新穿搭尚未生成”；旧结果可作为上一版本查看，不贴上新衣物标签。模型任务晚到时写回原图版本，用户主动选择才切换。收藏与保存须等持久化结果，renderer ACK 只能确认显示完成。

## 画布与美术

人物保留完整头脚与舒适留白，柔和光线、中性背景、轻接触阴影。生成图应与 GLB 的正面姿态/服装一致；旋转可看不同角度，但背面为生成推断。衣物图案、发型、鞋轮廓和脸部优先于微动。固定姿势和无眼部动画可满足首版质量。

静态图先作为 poster；Three.js 模型成功后切入同一内容区。加载新模型失败不清空已有图片；离开模型页停止并释放资源。首版不显示体型滑块、骨架控件、眼部开关、Create 360° 视频或没有真实功能的分享占位。

## 操作、反馈与可访问性

- 主按钮每屏一个；保存、生成图片、生成立体是不同步骤，避免同时抢主视觉。
- 选衣托盘的逐项移除具有独立 44pt 目标；同类别替换不等于已生成结果更新。
- 生成失败、删除失败保留到用户处理；短成功提示不代替持久化状态。
- VoiceOver 读出来源、选中数量、结果类型、生成状态和日期；角度/复位有原生替代操作。
- Reduce Motion 关闭装饰运动和自动旋转；直接拖动仍有效。减少透明度使用可读实色背景。
- 字体放大时操作可换行/滚动，底部操作不遮人物和错误；手势不抢系统返回、按钮或 sheet 拖动。
