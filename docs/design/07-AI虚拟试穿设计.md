## 目标与约束

### 目标

1. 用户先看到可解释的结构化穿搭，再只对主动选中的方案生成静态试穿图。
2. 推荐、衣橱和穿搭记录不依赖生成成功；试穿始终是可取消、可失败、可删除的增强能力。
3. 使用供应商无关的领域协议隔离模型能力、数据地域、保留策略、输入约束和错误。
4. 对人物身份、衣物关键特征、肢体完整性和不当内容设置上线质量门。
5. 记录完整输入快照、模型版本、同意记录和资产血缘，使结果可解释、可复现、可删除。
6. 明确告知用户结果只用于搭配视觉参考，不代表真实尺码、颜色、材质、垂坠或合身度。

### 非目标

- 不为推荐结果自动批量生成三套试穿图。
- 不在推荐滚动、页面预加载或后台定时任务中隐式消耗生成额度。
- 不支持他人照片、未取得同意的人物照片或换脸。
- 不承诺外套叠穿、鞋、包、帽子、首饰、透明材质、复杂 Logo 或文字的可靠生成。
- 不将用户照片、衣物图、生成结果或反馈默认用于训练、微调或供应商产品改进。
- 不把研究模型、非商业权重或许可证链不清晰的模型投入生产。
- 不预建自托管 GPU 集群；只有再评估触发器满足后才可提出独立方案。

## 术语与能力边界

| 术语 | 定义 |
| --- | --- |
| 静态虚拟试穿 | 输入一张人物图和一件受支持衣物图，输出合成的单张人物穿衣图。 |
| 选中方案 | 用户在推荐或穿搭编辑流程中明确确认的、带不可变修订号的 `Outfit`。 |
| `catalog_ready` | 衣物图足以参加衣橱浏览和穿搭推荐，但不保证适合生成。 |
| `render_ready` | 衣物主体、分类、可见区域和分辨率达到试穿输入门槛。 |
| 身份保持 | 结果不应明显改变人物脸部、发型、肤色、体型和姿态。该概念不授权持久化人脸模板。 |
| 衣物保真 | 主色、图案、领型、袖长、衣长和轮廓等可见关键特征不发生实质变化。 |
| 视觉模拟 | AI 对不可见区域和布料效果的推测；不是商品或身体的事实记录。 |

首个候选范围只支持：

- 单人、正面或轻微侧身、上半身或全身人物照片。
- 单件上衣、单件下装或单件连衣裙。
- 平铺图、衣架图或无遮挡的商品图；人物 OOTD 拆出的衣物只有达到 `render_ready` 才可生成。
- 一次任务只替换一个服装类别。

多件顺序生成会叠加身份、轮廓和纹理误差。外套叠穿、鞋包配饰和多件同时生成在独立评测通过前不得通过 UI 或 API 暴露。

## 前置条件

创建任务前必须同时满足：

1. `outfit_id` 已由用户明确选中，且请求携带当前 `outfit_revision`。
2. 人物资产来自用户已确认的数字形象，状态为 `render_ready`。
3. 目标衣物属于该用户、仍可用、类别受支持且状态为 `render_ready`。
4. 人物和衣物资产均通过输入质量、恶意文件和内容安全检查。
5. 用户已看到本次处理的目的、输入、第三方处理方、处理地域、保留时间和删除方式，并对本次生成提交有效同意。
6. 当前区域策略允许选定供应商处理这类数据。
7. 幂等键、用户配额和成本上限校验通过。

任何条件不满足时都应给出可恢复路径，例如补拍平铺图、换一张人物照、改用静态单品拼图或不生成继续保存穿搭。

## 完整用户与系统流程

```text
用户选定一套 Outfit
→ 立即展示结构化衣物清单和单品拼图
→ 用户点击“预览上身”
→ 展示视觉模拟说明和本次第三方处理同意
→ 检查人物、衣物、修订号、地域、配额和输入质量
→ 创建幂等 TryOnJob
→ 生成短时输入 URL 或隐私增强输入
→ 通过 TryOnProvider 提交
→ 异步查询或接收回调
→ 下载结果到受控临时区
→ 内容安全、身份和衣物质量检查
→ 合格结果进入私有对象存储并建立血缘
→ App 获取短时读取 URL 并替换单品拼图
→ 用户保留、重试、反馈异常或删除
```

生成期间用户可以离开页面。重新进入时通过 Job 状态恢复，不依赖 View 或 ViewModel 生命周期。超过预期等待时间时允许取消，不要求用户一直停留在前台。

## 状态机

### 用户前置状态

```text
not_requested
  → awaiting_consent
  → ready_to_create
```

`awaiting_consent` 被拒绝或取消时回到 `not_requested`，不会创建服务端生成任务。只有 `ready_to_create` 通过资格、区域、配额和幂等校验后才持久化 Job。

### TryOnJob 生命周期与处理阶段

为与 [`10-OOTD服务端与异步任务设计.md`](10-OOTD服务端与异步任务设计.md) 保持一致，权威 `lifecycle_state` 使用通用生成任务状态：

```text
queued
  → processing
  → succeeded

processing → retry_scheduled → queued
queued / processing → cancel_requested → cancelled
processing / retry_scheduled → failed
succeeded → expired
```

`processing` 内另存可观察但非独立权威状态机的 `stage`：

```text
validating
  → provider_submitted
  → generating
  → post_processing
  → quality_review
```

删除使用独立 `DeletionRequest`，按 [`11-OOTD权限隐私与安全设计.md`](11-OOTD权限隐私与安全设计.md) 从 `requested` 进入 `completed`，不把 Job 的 `cancelled` 冒充资产已经删除。

状态约束：

- `succeeded` 只表示至少一个结果通过质量门并已写入受控存储，不表示用户接受。
- `cancelled`、`failed` 和 `expired` 仍必须完成临时资产清理。
- Job 状态不可倒退；重试创建新的 attempt，保留原 attempt 的非敏感审计元数据。
- `stage` 只在 `processing` 中推进，客户端不得把某个阶段缺失解释为结果失败。
- 客户端不得自行把轮询超时解释为任务失败。

### TryOnResult

```text
pending_validation
  → accepted
  → user_kept
  → deleting
  → deleted
```

`pending_validation` 也可进入 `rejected_quality` 或 `rejected_safety`；这些结果不得下发给用户，并按临时资产规则清理。

## 页面与交互状态

- 未生成：显示单品拼图、支持边界和“预览上身”。
- 等待同意：明确列出第三方、地域、保留期和取消路径，不用总隐私政策代替。
- 生成中：显示真实阶段，如“检查照片”“生成预览”“检查结果”，不显示伪造的线性百分比。
- 后台中：显示“可以离开，回来后继续查看”；是否发送完成通知需另行取得通知权限。
- 完成：支持原始单品/AI 预览切换、局部缩放、保留、重新生成、删除和问题反馈。
- 失败：保留已选穿搭和单品拼图，说明当前成果未丢失，并提供与错误对应的下一步。
- 离线：允许继续编辑和保存穿搭；试穿请求保存为本地待提交动作，联网后必须再次确认同意是否仍有效。

所有结果页固定展示：

> AI 生成效果仅供搭配参考，可能改变颜色、细节和身体外观，不代表真实尺码、版型、材质或垂坠效果。

不得使用“真实上身”“准确合身”“尺码适配”等表述。

## 领域模型与数据流

### TryOnJob

| 字段 | 说明 |
| --- | --- |
| `id` / `user_id` | 全局唯一 ID 与数据所有者。 |
| `outfit_id` / `outfit_revision` | 发起时选中方案及不可变修订号。 |
| `avatar_asset_id` | 经用户确认的人物输入。 |
| `garment_item_id` / `garment_asset_id` | 受支持衣物及其 `render_ready` 资产。 |
| `category` | `top`、`bottom` 或 `one_piece`。 |
| `consent_record_id` | 本次第三方处理同意快照。 |
| `processing_policy_id` | 供应商、地域和保留期策略版本。 |
| `provider` / `model_version` | 实际执行方和模型版本。 |
| `seed` / `quality_mode` | 可复现参数；不得作为隐式用户画像。 |
| `lifecycle_state` / `stage` / `attempt` | 通用任务状态、处理阶段和执行次数。 |
| `idempotency_key` | 防止重复点击和重放造成重复计费。 |
| `input_snapshot_hash` | 输入 ID、修订号和参数的规范化哈希，不包含图片正文。 |
| `provider_job_id` | 删除和供应商审计所需的外部任务 ID。 |
| `error_code` | 稳定领域错误码，不保存供应商原始敏感错误正文。 |
| `cost_units` / 时间戳 | 成本、排队、执行和总耗时。 |

### TryOnResult

| 字段 | 说明 |
| --- | --- |
| `job_id` / `asset_id` | 生成任务和受控媒体资产。 |
| `representation` | 固定为 `synthetic_static_try_on`。 |
| `quality_flags` | 身份、衣物、肢体和内容安全的结构化结果。 |
| `model_version` / `seed` | 结果来源。 |
| `retention_class` / `expires_at` | 是否保存及到期时间。 |
| `deleted_at` | 删除状态。 |

媒体资产、派生关系和删除状态统一由 [`11-OOTD权限隐私与安全设计.md`](11-OOTD权限隐私与安全设计.md) 定义。Job 只引用 `asset_id`，不把对象存储 URL、路径或图片正文写入业务表。

## API 与异步任务

以下是领域级契约。功能进入受控 POC 或发布实施阶段时，必须先写入唯一 `backend/openapi.yaml` 并完成 OpenAPI、鉴权、幂等和契约测试评审，不能从本文另行维护第二份契约：

### 创建任务

`POST /v1/try-on-jobs`

请求至少包含：

- `outfit_id`
- `outfit_revision`
- `avatar_id`
- `wardrobe_item_id`
- `quality_mode`
- `consent_record_id`

请求头必须包含 `Idempotency-Key`。成功返回 `202 Accepted`、`job_id`、初始状态、可查询链接和预估区间；不返回供应商名称之外的秘密配置、供应商 URL 或 API Key。

### 查询、事件和取消

- `GET /v1/try-on-jobs/{job_id}`：返回领域状态、阶段、结果摘要或稳定错误。
- `GET /v1/try-on-jobs/{job_id}/events`：前台使用 SSE；断线后按事件序号恢复。
- `POST /v1/try-on-jobs/{job_id}/cancel`：幂等取消。
- `DELETE /v1/try-on-jobs/{job_id}`：发起结果和任务资产删除，不把取消冒充删除。

服务端须在同一事务写入 Job 和 Outbox。队列采用 at-least-once 语义，因此 worker 必须：

- 在调用供应商前持久化 attempt 和去重状态。
- 使用供应商幂等能力；供应商不支持时，以输入快照和已持久化 `provider_job_id` 阻止重复提交。
- 对超时、限流和短暂网络错误指数退避；输入无效、内容拒绝和地域阻断不得重试。
- 校验回调签名、时间窗、nonce 和 `provider_job_id`，防止伪造与重放。
- 任何终态都投递资产清理事件。

## TryOnProvider 抽象

领域层只依赖以下能力，不暴露供应商 DTO：

```text
capabilities(policy, category) -> TryOnCapabilities
submit(request, inputHandles) -> ProviderSubmission
status(providerJobID) -> ProviderStatus
cancel(providerJobID) -> CancelOutcome
delete(providerJobID, outputHandles) -> DeleteOutcome
```

`TryOnCapabilities` 至少声明：

- 支持类别和一次输入件数。
- 可接受的人物、衣物尺寸与格式。
- 是否支持 base64、私有连接或只能拉取签名 URL。
- 处理地域、子处理方、最长输入/输出保留期。
- 内容安全限制。
- 取消、删除和幂等能力。
- 模型生命周期、预计延迟和单次成本上限。

供应商适配器负责错误映射和传输，不能决定业务是否允许处理。最终允许性由版本化 `ProcessingPolicy` 决定。

### 候选 POC 供应商路线

以下只用于授权测试集的技术比选，不构成供应商准入或生产选型：

- 中国大陆 POC 可优先评估阿里云 Model Studio 的 [OutfitAnyone](https://help.aliyun.com/zh/model-studio/outfitanyone)，重点验证北京地域、输入 URL、输出保留、删除、类别支持和真实费用。
- 全球质量基准可在跨境和测试数据授权单独批准后评估 [FASHN Try-On v1.6](https://docs.fashn.ai/api-reference/tryon-v1-6)，不得把海外测试样本路由策略直接用于大陆生产用户。
- 自托管模型只有在完整许可证链、人体解析等辅助权重、训练数据来源、目标 GPU 性能和删除策略全部通过审查后才进入备选；研究或非商业权重不能进入产品。

比选报告必须使用相同输入集，分别记录类别支持、身份保持、衣物保真、严重伪影、p50/p95、成本、地域、保留和删除能力。供应商名称不得出现在领域状态或 iOS 业务逻辑中。

## 质量门与 POC 退出标准

### 自动质量门

- 输入只包含一个清晰人物，并满足目标服装区域可见性。
- 输出分辨率、色域、方向和文件类型有效。
- 不存在不合理裸露、额外人物、明显换脸或严重肢体缺失。
- 人物和衣物输入输出的一致性信号达到模型版本阈值。
- 输出经过内容安全检查，且检查服务不扩大数据地域和保留范围。

自动信号只用于阻断明显错误，不能代替授权人工评测；禁止为此长期保存人脸模板或身体 embedding。

### POC 数据集

- 至少 100 组取得明确授权的人物—衣物组合。
- 覆盖不同肤色、体型、年龄段、发型、姿态和光照。
- 覆盖纯色、条纹、格纹、Logo、文字、牛仔、宽松和贴身服装。
- 单独统计长发、手臂遮挡、复杂背景和非标准体型失败率。
- 不使用真实用户生产照片作为无同意测试夹具。

### POC 退出门槛

| 指标 | 门槛 |
| --- | --- |
| 有效输入任务失败率 | ≤3% |
| 基础质量端到端 p95 | ≤30 秒 |
| 身份保持人工可接受率 | ≥80% |
| 衣物关键特征人工可接受率 | ≥80% |
| 严重肢体、裸露或额外人物伪影率 | ≤5% |
| 跨用户、同意、地域和删除安全测试 | 100% 通过 |
| 单次成本 | 不超过经商业评审批准的硬上限 |

这些只是 POC 进入产品化评审的最低门槛，不是正式上线标准。上线前必须用更大盲测集按类别设门，并验证代表性最低支持设备、目标网络和真实供应商配额。

## 权限、隐私、安全与删除

- 人物图、面部、身体、穿衣照及其生成结果均按高敏感数据处理。
- 每次调用第三方 AI 前取得具体同意；用户拒绝后仍可使用衣橱、推荐、单品拼图和穿搭记录。
- 上传前在设备上移除 EXIF/GPS，只传实现本次任务所需的裁剪和分辨率。
- 输入使用最短可行有效期的签名 URL 或经审批的隐私增强传输；签名 URL 视同 bearer credential，禁止进入日志、分析和错误上报。
- API Key 和供应商凭据只存在于服务端密钥管理系统。
- 默认不用于训练；未来训练必须是与试穿服务分离的独立、可撤回 opt-in。
- 用户删除人物、衣物、穿搭、任务或账号时，应沿资产血缘删除所有输入副本、裁剪、mask、供应商任务、输出、缩略图、缓存和后续动态预览。
- 供应商无法提供地域、保留、删除或子处理方证明时，该供应商不得处理生产人物照片。
- 日志不记录图片、完整 URL、提示词正文、身体特征、衣物敏感描述或供应商响应正文。

完整数据分类、区域策略和删除协议见 [`11-OOTD权限隐私与安全设计.md`](11-OOTD权限隐私与安全设计.md)。

## 失败与降级方案

| 失败 | 用户可见行为 | 系统行为 |
| --- | --- | --- |
| 人物照片不合格 | 指出单人、光线、遮挡或构图问题，可换图 | 不创建供应商任务 |
| 衣物不是 `render_ready` | 提示补拍平铺图；仍可保存和推荐 | 保留 `catalog_ready` 资产 |
| 用户不同意第三方处理 | 回到单品拼图 | 不上传、不创建外部任务 |
| 地域无可用供应商 | 明确“当前地区暂不支持 AI 预览” | 阻断任务，不跨境回退 |
| 限流或短暂网络错误 | 保留选中搭配，可稍后重试 | 退避重试，不重复计费 |
| 供应商超时 | 允许离开、取消或稍后回来 | 状态保持可恢复，不把客户端超时设为失败 |
| 输出未通过质量门 | 显示静态拼图和可重试建议 | 拒绝结果并清理，不向用户展示危险图像 |
| App 被杀或切后台 | 重开后恢复任务状态 | Job 生命周期与页面解耦 |
| 用户取消 | 立即回到选中搭配 | 尽力取消供应商并清理所有临时资产 |
| 删除部分失败 | 显示删除处理中，不再允许读取 | 重试并进入删除告警，不恢复用户访问 |

生成失败不得改变 Outfit、WardrobeItem、Avatar 或推荐反馈的事实状态。

## 可观测性

只有静态试穿进入受控 POC 或发布实施阶段后才引入本节观测能力；门禁关闭的本地核心路径不发送生成遥测。

必须采集的非敏感指标：

- 创建、取消、成功和各类稳定错误计数。
- 排队、供应商、后处理和端到端 p50/p95/p99。
- 按类别、模型版本和质量模式分组的质量拒绝率。
- 重复投递去重率、重试次数和 DLQ 年龄。
- 每次任务成本与用户主动保留率。
- 删除积压、最老任务和供应商删除失败率。

Trace 仅使用 `request_id`、`job_id`、路由模板、阶段、模型版本和区域策略 ID。禁止记录 `user_id` 明文、对象 key、图片 URL、衣物/身体描述、供应商原始错误或媒体哈希。

模型升级必须创建新的评测报告和可回滚版本，不能原地改变既有 `model_version` 语义。

## 关键决策、替代方案与再评估触发器

### 只对选中方案生成

- 选择：推荐先同步返回结构化结果，用户主动点击后才创建试穿任务。
- 原因：降低等待、成本、隐私暴露和无效生成，并保证推荐在生成失败时仍可用。
- 替代：自动为三套推荐全部生成；因成本和隐私放大而拒绝。
- 再评估：只有主动试穿率、生成成本和同意研究证明批量预生成有明确净收益时，另行评审；不得静默上线。

### 托管 Provider 优先

- 选择：POC/MVP 使用通过准入的托管供应商和领域适配器。
- 原因：先验证真实用户价值和质量，避免提前建设 GPU 运维。
- 替代：自托管研究模型；当前存在资源、许可证链、模型治理和部署边界风险。
- 再评估：月度成本持续超过经批准自托管 TCO、地域/删除无法满足、供应商质量停滞或请求量达到稳定 GPU 利用率时启动独立评估。

### 单件静态试穿

- 选择：首版一次只替换上衣、下装或连衣裙之一。
- 原因：多件顺序生成会累积身份和服装漂移；鞋包和透明材质质量不稳定。
- 替代：全套多服装、视频或实时 AR；不进入首版。
- 再评估：各类别独立授权盲测达到上线门槛，且 Provider 能提供原子多件生成和明确输入语义时扩展。

### 不保存人脸模板

- 选择：身份质量检查的特征只在受控计算内存中使用并立即丢弃。
- 原因：持久化模板会扩大生物特征风险和删除面。
- 替代：建立长期人脸相似度档案；当前拒绝。
- 再评估：无默认再评估；若未来提出，必须完成独立生物识别 PRD、法律基础和威胁评审。

## 可执行测试与验收

### 自动化测试

1. Contract test：校验创建、查询、SSE、取消和删除的路由、状态码、schema 和稳定错误。
2. 状态机属性测试：所有合法转移可达；终态不可倒退；重复事件不能创建第二个结果。
3. 幂等测试：相同用户、相同幂等键和输入快照只产生一个外部提交和一次计费。
4. Outbox/队列故障测试：事务提交后杀死 dispatcher、worker 或 API，任务最终仍执行一次业务效果。
5. 回调安全测试：错误签名、过期时间、nonce 重放、错误 provider job ID 全部拒绝。
6. 输入安全测试：伪造 MIME、超大像素、截断文件、畸形图片和不受支持格式关闭失败且不进入供应商。
7. 授权测试：跨用户读取、取消、删除和替换 asset ID 全部返回安全错误。
8. 区域策略测试：不允许的供应商和处理地域在提交前阻断，禁止自动跨境回退。
9. 日志负向测试：注入含签名 URL、图片路径和身体描述的合成错误，验证生产遥测拒绝或清除这些字段。
10. 删除端到端测试：从 Avatar、衣物或账号删除后，枚举主存储、派生资产、Provider、缓存和动态预览均不存在。

### 真机和人工验收

1. 在最低支持 iPhone 上完成拍摄、切后台、杀进程、恢复、取消和删除。
2. VoiceOver 能朗读生成阶段、视觉模拟说明、错误和恢复动作。
3. Dynamic Type 最大尺寸下同意文本、取消、删除和尺码免责均可操作。
4. 弱网和断网下保留选中 Outfit，不产生重复任务。
5. 对 POC 授权数据集进行至少双人盲评；分歧按预先定义规则裁决并保留模型版本报告。
6. 人物身份、衣物保真和伪影质量门达到本文件 POC 退出标准。
7. 用户拒绝第三方处理后，衣橱、推荐、单品拼图和保存路径仍可完整完成。
8. 结果页和分享前预览始终出现视觉模拟与非尺码声明。

未满足全部门槛时，只能保留为内部技术验证，不得向生产用户开放。
