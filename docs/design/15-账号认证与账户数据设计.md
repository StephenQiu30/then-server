## MVP 目标与非目标

MVP 提供邮箱密码注册、Cookie 会话、读取本人账户、修改邮箱和显示名称、退出并删除本人账户。注册即 Create，本人端点完成 Read/Update/Delete。App 的无账号离线路径保持可用；用户开始云端功能时再使用同一服务端身份。

本切片不增加组织、租户、运营报表、角色权限矩阵、管理员代操作、社交登录 UI、找回密码、邮件验证、多因素认证、公开用户目录或第二套 BFF。Sign in with Apple 仍属于 App 云功能的后续认证方式，接入时复用用户主体。

## 身份、会话与安全边界

- 邮箱在服务端去除首尾空白并转为小写；数据库约束保持唯一。客户端校验只用于即时反馈，服务端是事实源。
- 密码长度固定为 12–72 个 UTF-8 字节，使用锁定版本的 `golang.org/x/crypto/bcrypt` 生成不可逆散列；响应、日志和数据库审计不保留明文。
- 注册成功和登录成功生成 32 字节加密随机会话令牌；PostgreSQL 只保存 SHA-256，浏览器只通过 `HttpOnly`、`SameSite=Strict` Cookie 接收原始令牌。
- 本机回环开发允许非 Secure Cookie；任何非回环监听必须配置 Secure Cookie，否则进程拒绝启动。生产由同源入口提供前端和无版本前缀的 API 根路径，不开放跨源凭据 CORS。
- 会话有效期固定 7 天。退出删除当前会话；账户删除在同一 PostgreSQL 事务中删除用户、凭据和全部会话。受保护端点识别到无效、过期或已撤销 Cookie 时返回 401，并用相同 Path、安全属性的过期 Cookie 清除浏览器状态；普通登录失败不清除浏览器中可能仍有效的会话。
- 认证失败统一返回 `AUTHENTICATION_FAILED`，不泄露邮箱是否存在。跨用户 ID 不进入公开接口；本人账户由服务端会话解析。
- 注册、登录、更新和删除只接受 `application/json` 或无正文的精确合同，拒绝未知字段、超限数据、查询参数和契约外路径。
- 注册和登录在进入 Account Service 前使用 Redis 固定窗口限制服务端直接观察到的源 IP。注册为每小时 5 次，登录为每 15 分钟 10 次；成功与失败都占用额度。Gin 继续禁用受信代理，本阶段不读取可伪造的转发头。
- Redis key 只保留作用域和规范化 IP 的 SHA-256，并设置窗口 TTL。超限返回 429 与恢复秒数；Redis 故障或源地址不合法时返回 503，不继续创建账户或执行密码散列比较。Redis 只保存临时限流状态，PostgreSQL 仍是用户和会话唯一事实源。

## 数据模型与事务

GORM record 创建：

| 表 | 事实 |
| --- | --- |
| `users` | UUID、显示名称、创建/更新时间；用户主体不保存密码 |
| `user_credentials` | `user_id`、规范化邮箱、bcrypt 散列；邮箱唯一 |
| `user_sessions` | UUID、`user_id`、令牌 SHA-256、到期时间、创建时间；删除用户级联删除 |

注册在一个事务中写入 `users`、`user_credentials` 和首个 `user_sessions`。修改邮箱与名称在一个事务中更新，任何唯一性冲突整体回滚。删除使用硬删除；当前处于开发阶段且用户已明确无需保留历史数据，不建立软删除兼容层。

Schema 只由 `internal/adapter/postgres` 的 GORM record 定义；`postgres.Migrate` 在 HTTP 监听前集中执行 `AutoMigrate`。当前开发阶段不保留历史数据，因此不维护 SQL migration 或兼容路径。空库迁移、唯一约束、事务回滚和级联删除使用真实 PostgreSQL 18 验证。

## Go 分层与文件职责

- `internal/domain/account.go`：纯领域值和稳定错误，不依赖 HTTP/GORM。
- `internal/application/account/account.go`：规范化、密码策略、会话创建和授权用例。
- `internal/adapter/postgres/account.go`：GORM/事务/唯一冲突映射，是账户数据唯一访问边界。
- `internal/adapter/httpapi/account.go`：JSON/Cookie/HTTP 状态映射，不承载业务规则。
- `internal/platform/database/database.go`：连接生命周期并向 repository 提供受控 GORM 句柄。
- `internal/platform/ratelimit/redis.go`：认证固定窗口、散列 key、Redis 探测和连接关闭。

不创建通用 BaseRepository、全局 Service 容器、`utils` 包、独立 auth 微服务或 Redis 会话事实源。限流只覆盖本次明确的两个认证入口，不抽象成通用配额平台；可信代理、多节点容量和公网攻击演练仍是发布门禁。

## API 与失败行为

| operationId | 方法与路径 | 成功结果 |
| --- | --- | --- |
| `registerAccount` | `POST /auth/registrations` | `201` + 用户 + HttpOnly 会话 Cookie |
| `createSession` | `POST /auth/sessions` | `200` + 用户 + 新会话 Cookie |
| `deleteSession` | `DELETE /auth/session` | `204` + 当前会话失效 |
| `getCurrentUser` | `GET /users/me` | `200` 当前用户 |
| `updateCurrentUser` | `PATCH /users/me` | `200` 更新后的用户 |
| `deleteCurrentUser` | `DELETE /users/me` | `204` 硬删除用户与全部会话 |

邮箱冲突稳定返回 `EMAIL_CONFLICT`/409；缺失、无效、过期会话和错误登录信息使用安全的 401；受保护端点的会话 401 同时清除失效 Cookie，登录凭据错误的 401 不改写现有 Cookie；输入错误返回 400；错误体始终保留 `request_id` 和 `retryable`，不透出数据库或散列细节。

## 测试与验收

- Service 单元测试：邮箱规范化、密码边界、错误脱敏、令牌散列和授权。
- PostgreSQL 集成测试：AutoMigrate、注册事务、唯一邮箱、登录、更新冲突和硬删除级联。
- HTTP 契约测试：全部端点和错误响应通过 OpenAPI request/response 校验，Cookie 属性可核对。
- Swagger 与 Umi：运行时契约驱动内嵌文档和未来 Web 请求文件生成。

## 重新评估触发器

公开注册开放前必须新增邮箱验证、密码找回、可信代理/边缘限流、会话撤销监控和生产 Cookie/TLS 验收。当前 Redis 固定窗口只证明应用内开发合同。需要后台管理其他用户时另立管理员授权和审计合同；不得把本人 CRUD 端点扩成可枚举用户目录。
