# 技术选型

更新：2026-09-30。本文维护现行个人自用 App 的技术决定；产品行为见 [PRD 10](../prd/10-OOTD产品需求.md)，从零调研证据、候选与费用见 [Design 29](29-Woo虚拟人偶与自用成本决策.md)。下方既有服务端/Web 工程登记保留原证据范围，不作为当前个人 App 的前置依赖；本轮未检查或修改实现、锁文件与工具链。

## 人物技术冻结与变更规则

决策 ID 保留 `AVATAR-BASELINE-01`，现行修订日期为 **2026-09-30**。用户要求以 Woo 的人物效果为目标，并明确个人自用、本人照片参考和成本约束。需求方向为 `scope_confirmed`；App 实施、供应商实测和真机验收分别为 `implementation_pending`、`real_validation_pending`。

**现行路线：本人身份及 Woo 风格参考版本 → 完整风格化穿搭图 → 本人确认 → 主动按需生成整套静态 GLB → Three.js 立体展示 → 本地保存和复用。**

人物保留本人脸型、发型、肤色、眼镜和体形等可辨识特征，比例正常，明显是半写实虚拟人偶。不得用照片皮肤质感、通用动漫/Q 版人物或仅加阴影的二维图替代目标。Woo 的宣传画面只证明可见效果与操作，不证明其内部模型、供应商或格式。

| 边界 | 当前技术决定 | 待验证事项 |
| --- | --- | --- |
| 用户与平台 | 单人自用，不发布；暂按 iPhone 原生端分析 | 本人的实际手机、最低系统与签名安装方式未确认，不继承公开产品的设备门禁 |
| 内容入口 | 本人照片和确认的虚拟形象参考；先测一套真实 Look，再扩展五套代表样本 | 三个预设人物、六套内置资产不再是必要条件；无资产时提供导入引导 |
| 页面与本地事实 | SwiftUI + Observation；新自用方案选择 SwiftData，媒体保存为沙盒文件 | 方案选择不代表现有 GRDB 已迁移；后续实现应制定实际存储适配与恢复合同 |
| 输入清理 | Vision / Core Image，本地校正、裁剪与可选主体抠图 | 主体掩膜不能冒称单件衣物分割、识别或完整自动衣橱录入 |
| 图片生成候选 | 先验证 Tripo `seedream_v5` 图像编辑；质量/满意成本不足再对照 FLUX.2 klein | 多参考数量、脸型/服装保真与 Woo 风格均待本人样本验证，不宣称供应商已经通过 |
| 三维生成候选 | Tripo H3.1 标准纹理为价格基线；少量 P1 对照 | 带纹理 GLB 的正侧背质量、几何完整、包鞋与移动性能待测 |
| 渲染运行时 | 隔离 WKWebView + 本地 Three.js / GLTFLoader，首轮 WebGL2，直接标准 GLB | 锁定版本和真机性能在实现时复核；不同时建设 USDZ、VRM、WebGPU 运行链 |
| 首版三维交互 | 静态姿势，连续旋转、有界缩放、复位、已保存整套 Look 切换 | 不要求骨架、眼部表情、走路或布料模拟；旋转必须是真实几何观察 |
| 网络与任务 | 原生 URLSession 直连个人供应商 API，API Key 放 Keychain；本地任务与费用账本 | WebView 不接触密钥；提交响应未知不自动重发；结果有效期与实际扣费需核对 |
| 结果保存 | 满意图、GLB 与元数据本地保存；导出到本人的设备备份 | 不依赖账号、MinIO 或公共后端；离线复用不触发付费生成 |
| 成本控制 | 图片确认后才转三维；逐阶段尝试上限、费用预留与月度上限 | 上限由本人设定，达到上限暂停；金额与估算仅维护在 Design 29，不是假账单 |
| 条件备选 | 固定人偶 + 兼容服装资产；必要时 Blender/MPFB 制作对照 | 只在跨套身份失败或即时换衣明确成为要求时试小样，不预建完整衣柜 |
| 不采用为默认路线 | 本地 img2threejs 工厂、自建 GPU 推理、LoRA 训练、公共任务中间件 | 旧路线或通用代码输出不能替代 Woo 风格实测；没有硬件/质量证据不假设本地更省 |

一套静态 GLB 对应一套完整服装；改衣需要新 Look 产物。保存后切换旧 Look 可即时复用，不能承诺同一头身任意换衣、离线生成未知衣物或照片未拍到的背面真实还原。若将这些要求提高为身份硬锁定或即时模块换装，需要重新比较固定资产路线。

### 当前验证顺序

1. 建立本人认可的 Woo 风格参考，先取得一套可旋转且愿意保留的真实 Look。工程 fixture、参考图或 HTTP 成功不能关闭人物效果验收。
2. 五套代表穿搭比较“直接图生三维”和“先风格化再三维”；每套两条路径合计最多两次 H，图片尝试初始上限两次，少量 P1。实验消费上限须由本人设定，不因文档估算自动发起付费调用。
3. 分别记录 Woo 风格、本人特征、跨套一致性、衣物准确性、正侧背、所有成功付费重做与人工时间；以实际保留套数计算满意成本。
4. 满意文件本地复用后，再测真机加载、拖动、切换、重启、离线与异常恢复。初始性能目标和完整场景见 PRD 10；全部仍待测。
5. 本轮不自动修改旧 Plan/Acceptance 的完成状态；旧切片只有完成到新 REQ 的映射、范围和证据调整后，才可用于个人 App 的执行。

### 变更 SOP

1. 2026-09-30 修订取代三预设/六资产门禁、本地工厂唯一来源、公共账号/发布前置与绝对禁用 Blender 的旧决定。首版仍不引入人工全衣柜建模；可选资产工具不等于已安装或已启用。
2. 日后改变运行时、生成模型或人物合同，先记录真实质量、满意成本、数据影响及验收差异，再同步 Design → PRD → 对应 Plan/Acceptance。批准需求不等于批准实际消费或认领通过。
3. 使用本人照片前明确原照/参考图将发送到何处、外部保留和删除能力；虚拟化或 file_token 不使云处理变成本地处理。实际云处理意愿尚待本人选择。
4. 保持一个现行技术决定；本文管选择，Design 29 管研究和金额，PRD 管行为，Plan/Acceptance 管执行与证据。锁定依赖版本以实现时核验的锁文件为准，不能用旧版本登记推断新方案已集成。

## 个人客户端选择与系统要求

以 iPhone 为假设选择 SwiftUI + Observation、SwiftData + 沙盒文件、URLSession + Keychain；人物展示采用隔离 WKWebView 和本地 Three.js/GLTFLoader。UI、业务状态和权限由原生侧拥有，WebView 只加载经过验证的本地模型与展示资源；不能携带供应商密钥或访问任意远程资产。

最低系统须根据本人设备、实际系统 API 和安装维护方式确定；不将 iOS 26 或 Liquid Glass 设为人物实验通过条件。免费 Personal Team 周期重装与付费会员年费计入选择，见 Design 29 §6。不存在必须先购买会员、部署后端或公开上线的要求。

SwiftData 是从零调研得出的新个人方案，既有客户端 GRDB 的真实使用与迁移工作本轮未评估。后续实现不得混用两个事实源或凭文档宣称迁移完成；应在明确目标仓库后选择直接新建/适配方式，保持 Look、任务、费用和文件引用的一致恢复。

## 既有服务端与 Web 工程登记

以下保留原工程配置和切片入口，属于此前服务端/Web 范围，本轮未重新核验；不代表这些能力已在个人 App 接入，也不构成其必需技术栈。既有工程维护仍按对应代码、锁文件、Plan 与 Acceptance 管理，个人范围优先级按本文及 PRD 10 判断。

## 2026-09-22 工程基线变更

按用户要求，消息队列由 RabbitMQ 切换为 Kafka，唯一入口放在 `backend/main.go`，保留 bootstrap 组装职责，不再保留 `cmd/then-server` 包装目录。新配置为 `KAFKA_BROKERS` 与 `KAFKA_TOPIC_PREFIX`；实际开发、隔离测试、迁移与回退合同见 [17-26](../plan/17-26-Kafka与工程规范化执行计划.md)。历史已完成计划中的 RabbitMQ 测试只证明当时版本。

## 后端最小技术栈

Go + Gin/Huma + GORM + PostgreSQL，模块化单体、一个 Go module、一个二进制和镜像。已实现 `api|worker|all` 角色，worker/all 仍受本地合成媒体开发开关约束。目录、依赖和 SOP 见 [后端架构](02-后端架构.md)。

Huma operation 与 Go struct tag 是接口唯一声明，运行时提供 `/openapi.json`、`/openapi.yaml`；内嵌 Swagger 门户及已接入的 `@umijs/openapi` 读取同一契约。不存在仓库 OpenAPI 物化文件、额外 Swagger Docker 服务或生成脚本。

Repository GORM record 与集中 AutoMigrate 是开发 schema 的唯一声明，监听 HTTP 前迁移失败即退出。当前不保留旧业务数据，不引入 Atlas、SQL migration 账本、旧 schema 探测或双写兼容层。iOS 本地数据库的 GRDB migration 与后端 AutoMigrate 分属两个数据库。

## 数据库与中间件接入决策

| 组件 | 当前接入 | 后续启用条件 |
| --- | --- | --- |
| PostgreSQL | 账号/会话、衣橱、计划/实际穿着、媒体、私人日记与社区事实及真实集成测试 | 新业务进入批准切片才加表；后端存在不代表 App 同步已交付 |
| MinIO | 已有私有上传、日记/社区图片及异步删除开发闭环，详见 17-19、19-03～19-06 | 正式人物目录和 AI 生成结果按对应切片接入；生产媒体准入仍独立验收 |
| Redis | 账号注册/登录固定窗口与本机 TTL/失效验证；不保存业务事实 | 新用途必须进入批准切片，不能把缓存升级为事实源 |
| Kafka | 替换 RabbitMQ；媒体检查、删除、通知使用 topic + consumer group，开发范围见 17-26 | 生产需 TLS/SASL/ACL、多副本与运维门禁 |
| FFmpeg | 未接入 | 已批准视频处理任务需要时在受限 worker 内运行 |
| OpenTelemetry | 尚未接业务链路；当前 slog/健康端点 | 云业务生产接纳前落实追踪、指标与告警 |

日常使用本机已安装服务。`docker-compose.yml` 与 `docker-compose-env.yml` 用于明确需要的隔离环境，不自动启动重复中间件。模型质量 POC 不要求预建全部队列服务；被正式接纳的用户任务必须具备持久化、重试和删除闭环。

## Web frontend

2026-09-16 用户确认 Web 基础工程使用 Next.js 及其 App Router，不使用 Vite、React Router 或 Vitest。顶层 `frontend/` 以官方 `create-next-app` 配置为基准，保留 TanStack Query、Axios、ESLint、Prettier 与 `@umijs/openapi`；请求文件从运行时 OpenAPI 生成，禁止复制 DTO 和手写第二份接口清单。

2026-09-22 按用户要求确认目标设计实现体系为 **shadcn/ui + Radix Primitives + Tailwind CSS v4**，shadcn 基础类型固定 `radix`。Vercel 插件的 Next.js/React 指南用于框架和性能规范，不等于选择 Vercel 托管。组件、语义 token、目录与验收规则见 [PROJECT.md](../../PROJECT.md)。业务组件归 `src/components/<business>`，请求 hooks 归 `src/hooks/<business>`，纯逻辑归 `src/lib/<business>`，不另建平行 `features` 目录。

17-27 已初始化 shadcn 的 radix-nova 配置，实际接入 Button/Badge、统一 token 与页面状态，移除 Themes Provider/样式/依赖。注册、登录和本人账户页面继续按 [Design 16](16-Web账户管理设计.md) 与 [17-13](../plan/17-13-Web账户管理执行计划.md) 推进。

## 变更策略

先确认当前用户需求，再更新 Design → PRD → 单切片 spec/checklist → 实现 → Acceptance。本次个人需求修订已获用户要求；只修改文档，不宣称历史工程被重构或新方案已集成。日后无新授权时，研究候选不能自动替换已确认栈。资产采购和实际 API 消费依本人设定的预算执行，未通过来源、画风、本人及衣物保真、设备测试的资产不得标记满意或可用。

只新增当前业务需要的依赖、文件和服务。语义化命名，不预建脚本、兼容层、通用 Repository、泛化工作流或多云网关。测试证据绑定版本和环境，模拟器通过不代表真机或整体发布通过。
