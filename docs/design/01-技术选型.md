# 技术选型

更新：2026-09-15。本文是技术栈与启用边界的唯一事实源；实现进度见 [产品计划](../plan/10-OOTD产品实施计划.md)。

## 人物技术冻结与变更规则

决策 ID：`AVATAR-BASELINE-01`。依据为用户明确要求 Three.js 灵动交互、禁止 Blender 建模及保持选型稳定。本节是人物技术的唯一当前基线；下方带日期的历史记录不能覆盖本节。

本轮用户授权确定人物格式、允许评估付费资产（采购前确认预算），并确认首版眨眼与轻微视线跟随。GitHub、Firecrawl、Context7 的依据及取舍见 [Three.js 人物研究](threejs-avatar-research.md)。定案为标准 GLB：Three.js 原生形变/节点能力可覆盖已确认动作，当前不增加 VRM/three-vrm 依赖；img2threejs 作为程序化造型研究参考，未验证为生产人物链。

| 边界 | 固定决定 | 验证状态 |
| --- | --- | --- |
| 产品需求 | 三套可爱成人预设、内置服装、零上传可用；保留连续三维观察、换装和轻量动态 | 用户已确认；完整产品尚未验收 |
| 页面与本地数据 | SwiftUI + Observation、GRDB/SQLite | 沿用现有实现 |
| 三维舞台 | 隔离 WKWebView + 随包 Three.js `0.185.1` + GLTFLoader；发布格式 GLB | 运行纵切已存在；生产资产与设备门禁未通过 |
| 资产取得 | 优先评估可直接交付 GLB 的授权成品人物及配套衣物，允许评估付费；来源须提供版本、使用权及可重复取得的交付包 | 具体来源、样本和价格 `pending`；采购前由用户确认预算与交付范围 |
| 首版眼部动态 | 眼睑 morph 实现眨眼、左右眼球节点实现轻微注视；支持 Reduce Motion 和生命周期 | 用户确认必需；生产资产和实现未通过，不能由整体微动抵扣 |
| 制作限制 | 项目开发、资产修复、转换、构建和验收均不依赖 Blender；不要求 `.blend` 母版，不自建建模流水线 | 用户明确约束，立即生效 |
| 图片与视频 | 已审核图片用于 P1 多视角结果、缩略图和静态回退；视频用于独立 Create 360° 结果 | 媒体切片与真三维需求分别验收；不能替换三维运行时决定 |
| 资源保存 | 可公开且有发布权的资源放 `public/`；内部输入/交付包放现有 `assets/`，不映射静态路由；大型/私人对象使用 MinIO；默认运行资源随 App 打包 | 按实际资源使用既有目录，不预建空目录或重复副本 |

Three.js 负责场景、相机、交互和动画播放，不承担生产人物的自动建模承诺。现有工程 GLB 继续作为回归夹具。正式资产不得要求开发者在 Blender 中补拓扑、绑骨、修衣物或重新导出；需要这些工序的候选判定不适配，由来源方重新交付合格包或淘汰。

**仍待确定的是实际资产来源、样本画风、采购预算和实测性能门槛。** 开工前用一个代表人物、两件可替换上装、一件下装和一双鞋，在既定 Three.js 舞台验证画风、连续观察、换装、微动、眨眼、轻微注视、离线加载和资源预算。通过后固定同一资产家族、骨架/槽位/眼部合同和 revision，再扩展到三人物与完整服装组合；不要求自制 20-joint 骨架、体型 morph、LOD 或通用表情编辑器。具体来源没有通过前，只可推进现有交互验收与资产验证，不能把生产人物任务标为可交付。

### 变更 SOP

1. 调研结果只进入候选记录，不自动修改当前基线、依赖或页面实现。
2. 更换渲染器、发布格式、资产取得方式或减少已确认能力，必须先记录：失败需求/实测证据、候选收益与新增成本、影响的 PRD/Plan/Acceptance、迁移步骤和验收条件。资产样本失败首先处理资产问题，不直接更换运行时。
3. 涉及上述产品/架构取舍时取得用户明确决定，再在同一变更中更新本节、Design 20、PRD 11、执行计划、验收和入口文档；日常缺陷修复与既定合同内的样本验证直接执行。
4. 实施前检查关联文档只存在一个现行决定；旧决定标为历史/已取代。不得把未经验证的建议写成 `approved` 或把 `pending` 写成已完成。


## 客户端最终决策与原生液态玻璃

SwiftUI + Observation 拥有全部产品页面、导航、业务状态与无障碍；最低 iOS 26，采用系统 Liquid Glass 控件。UIKit/WebKit 仅作受控适配。人物舞台固定本地 Three.js + 标准 GLB，由隔离 WKWebView 承载；不并行维护 Flutter、RealityKit/USDZ 或第二个 renderer。

GRDB/SQLite 保存本地业务事实，受保护文件保存媒体，保存、快照、删除与中断恢复使用明确事务。App 当前没有云请求 Client；登录和同步接入前先建立实际业务 spec，不创建空网络模块。

## 后端最小技术栈

Go + Gin/Huma + GORM + PostgreSQL，模块化单体、一个 Go module、一个二进制和镜像。当前仅实现 API 角色。目录、依赖和 SOP 见 [后端架构](02-后端架构.md)。

Huma operation 与 Go struct tag 是接口唯一声明，运行时提供 `/openapi.json`、`/openapi.yaml`；内嵌 Swagger 门户及未来 `@umijs/openapi` 读取同一契约。不存在仓库 OpenAPI 物化文件、额外 Swagger Docker 服务或生成脚本。

Repository GORM record 与集中 AutoMigrate 是开发 schema 的唯一声明，监听 HTTP 前迁移失败即退出。当前不保留旧业务数据，不引入 Atlas、SQL migration 账本、旧 schema 探测或双写兼容层。iOS 本地数据库的 GRDB migration 与后端 AutoMigrate 分属两个数据库。

## 数据库与中间件接入决策

| 组件 | 当前接入 | 后续启用条件 |
| --- | --- | --- |
| PostgreSQL | 账号、凭据、会话事实及真实集成测试 | 新业务进入批准切片才加表 |
| MinIO | 本机协议验证；当前 API 无媒体业务 | 私有上传、资产发布或生成结果需要对象存储时启用 |
| Redis | 本机 TTL/失效验证；不保存业务事实 | 明确限流/可丢缓存需求后接入 |
| RabbitMQ | 本机确认/重投协议验证；无生产任务消费者 | 持久云任务接纳、Outbox、幂等与取消共同实现 |
| FFmpeg | 未接入 | 已批准视频处理任务需要时在受限 worker 内运行 |
| OpenTelemetry | 尚未接业务链路；当前 slog/健康端点 | 云业务生产接纳前落实追踪、指标与告警 |

日常使用本机已安装服务。`docker-compose.yml` 与 `docker-compose-env.yml` 用于明确需要的隔离环境，不自动启动重复中间件。模型质量 POC 不要求预建全部队列服务；被正式接纳的用户任务必须具备持久化、重试和删除闭环。

## Web frontend

按用户要求暂停实现。项目名预留 `frontend`，不创建空目录；未来按 [Design 16](16-Web账户管理设计.md) 与 [17-13](../plan/17-13-Web账户管理执行计划.md) 开工。请求文件从运行时 OpenAPI 生成，禁止复制 DTO 和手写第二份接口清单。

## 变更策略

先确认用户需求与代码事实，再更新 Design → PRD → 单切片 spec/checklist → 实现 → Acceptance。技术选择不是调研候选列表；新发现不能自动替换已确认栈。资产采购需具体预算确认，未通过来源、画风、换装与设备测试的资产不得标记生产可用。

只新增当前业务需要的依赖、文件和服务。语义化命名，不预建脚本、兼容层、通用 Repository、泛化工作流或多云网关。测试证据绑定版本和环境，模拟器通过不代表真机或整体发布通过。
