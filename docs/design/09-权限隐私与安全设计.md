# 权限、隐私与安全设计

> **历史文档。** 本文只用于解释旧财务、日历和位置数据。当前照片、穿搭与 AI 数据安全基线见 [`18-OOTD权限隐私与安全设计.md`](18-OOTD权限隐私与安全设计.md)。

## 状态

P0 已批准并实施中，2026-08-11。权限分层、票据图片零持久化、原始轨迹确认后原子清理、When In Use 定位边界、权限只读可见性、结构化导出白名单、分层删除、异常导出清理、低存储失败关闭、分享/删除模拟器 UI 和后台任务切换遮罩已落地并通过自动化验证；分享成功到第三方目标、真机文件保护与最终诊断面人工抽查仍待完成。关联 [`../prd/03-最小可行产品需求.md`](../prd/03-最小可行产品需求.md)、[`03-系统总体设计.md`](03-系统总体设计.md) 和 [`08-同步与接口设计.md`](08-同步与接口设计.md)。本文是工程安全与产品隐私基线，不替代正式法律意见、隐私政策或上线合规评估。

## 目标

- 用户在授权前理解用途、范围、不开启的影响和撤回方式。
- 财务、日历、精确位置、票据和认证信息按敏感数据处理。
- 默认最小采集、最短保留和本地处理；当前不上传或长期保留票据图片与原始轨迹。
- 权限拒绝、撤回、账号退出和数据删除都有完整产品路径。
- 防止越权访问、重复写入、敏感日志、临时文件泄露和后台定位滥用。

## 数据分类

| 级别 | 示例 | 基本控制 |
| --- | --- | --- |
| 高敏感 | 交易/分录、日历标题与地点、精确坐标、原始轨迹、票据图片、备注。 | 最小采集、Data Protection、TLS；上云时强制字段级信封加密、严格授权、禁止日志。 |
| 认证秘密 | refresh/access token、Apple 会话凭据、服务端密钥。 | Keychain/KMS、短期、轮换、不可记录、最小权限。 |
| 敏感元数据 | 设备、同步游标、事件时间、行程摘要、错误上下文。 | 目的限定、限期保留、脱敏日志、owner 隔离。 |
| 一般产品数据 | 版本、feature flag、非个性化配置。 | 完整性校验、常规访问控制。 |
| 公开数据 | App 公开说明和无用户数据的帮助内容。 | 发布审核和完整性。 |

“已授权系统权限”“已开启产品功能”“已同意上传/长期保留”是三种独立状态，不能互相替代。

## 权限矩阵

| 能力 | 触发时机 | 请求 | 拒绝/限制 | 撤回后 |
| --- | --- | --- | --- | --- |
| 日历 | 用户点击同步日程 | EventKit Full Access | 手动计划；解释 iOS 无只读授权。 | 停止扫描，不误判来源删除；缓存按用户选择清理。 |
| 通知 | 用户首次启用出发提醒 | UserNotifications | 计划仍保存，页面显示“未安排提醒”。 | 取消/标记本地请求，提供系统设置入口。 |
| 定位 | 规划当前位置或开始行程 | When In Use；精确位置按场景 | 手动起点；无轨迹 Journey。 | 停止新增点，保存 partial 片段，要求完成或继续。 |
| 后台位置 | 用户主动开始实际行程 | iOS 可见后台活动会话 | 仅前台记录或手动摘要。 | 立即结束后台活动，不默认请求 Always。 |
| 相机 | 用户选择拍摄票据 | Camera | 相册或手动输入。 | 不再打开相机；当前识别会话临时图立即删除。 |
| 相册 | 用户选择已有图片 | Photos picker/必要范围 | 相机或手动输入。 | 不影响已确认交易；当前识别会话临时副本立即删除。 |
| 生物识别（P1） | 用户开启 App 隐私锁 | LocalAuthentication | 使用设备口令或不开启。 | 关闭额外 App 锁，不影响系统数据保护。 |

首次启动不批量请求权限。系统设置返回后重新读取真实授权状态，不以本地缓存假设成功。

系统权限弹窗中的 App 名称和用途说明是安全边界的一部分：P0 统一从 `InfoPlist.xcstrings` 提供已审核的简体中文文案，并与实际请求时机和权限范围一致。不得在不同构建配置中使用含义不同的用途说明，不得承诺未实现的云同步、后台常驻或只读日历权限；权限能力变化时必须同时更新本设计、PRD、字符串目录和真机验收。

## 数据最小化

### 默认不采集

- 日历正文、参会人、邮件地址和附件。
- 微信、支付宝、银行 App 私有流水或通知内容。
- Apple 地图的导航历史、收藏、偏航和到达状态。
- 未由用户主动开始的全天位置。
- OCR 无关区域的长期图片副本。
- 用户金额、商户、标题、地址或坐标的产品分析明文。

### 默认仅本地

- EventKit 原始标识及 HMAC 映射。
- OS 权限状态和系统通知 request ID。
- OCR 中间结果与会话临时图。
- 原始 TrackPoint。
- 未登录用户的账本、计划、Journey 和关系。

### 账号启用后的可选同步

- 账户、交易、用户确认计划、Journey 摘要和不涉及日历来源身份的正式关联。
- OCR 图片、票据原图、原始轨迹点和轨迹文件始终不进入当前同步范围，不提供保存或云备份开关。

日历同步到云的字段清单必须独立批准；默认只允许用户已确认的计划字段，不上传原始事件正文、EventKit 标识、HMAC 映射、CalendarOccurrence、`EventTripLink` 或 `TransactionEventLink`。这些事件关系在 P0 和当前 P1 同步范围内都仅存在本机。

## 本地安全

- access/refresh token 和长期凭据存 Keychain，不存 UserDefaults、SQLite 或日志。
- GRDB 数据库目录、SQLite 主文件、WAL 与 SHM 统一使用 `completeUntilFirstUserAuthentication` Data Protection，兼顾用户首次解锁后的锁屏行程可靠写入。生产启动和 Debug UI 测试数据库都必须经过同一个保护应用函数：每次打开先显式修复目录属性，再打开数据库并修复当时存在的主文件/WAL/SHM；以后由目录默认保护保证 SQLite 重建的 sidecar 继承同等级。不能只在目录首次创建时传入属性，因为既有目录不会因此被可靠修复。
- 原始轨迹随数据库保护；OCR 临时图若产生文件必须使用 `complete` 并在会话结束删除。每次结构化导出使用随机不可猜的独立目录，目录与最终 JSON 都显式设置 `complete`，系统分享结束后删除。
- iOS Simulator 当前不会可靠返回 `.protectionKey`，即使 `setAttributes` 成功也可能读到 `nil`，因此不得把模拟器属性读取写成 Data Protection 生效证据。自动化应注入一个仍委托真实 `FileManager` 的记录器，断言生产路径对数据库目录执行创建属性和每次启动显式修复，对当时存在的主文件/WAL/SHM逐一设置 `completeUntilFirstUserAuthentication`，并对导出随机目录与 JSON 设置 `complete`；这证明应用确实发出了完整保护操作，但不证明系统锁屏语义。最低 iOS 18 真机仍需检查实际文件属性，并验证首次解锁前后、锁屏记录写入、锁屏导出不可读与解锁恢复。
- P0 不默认使用 SQLCipher；若威胁模型要求设备解锁后仍对数据库内容二次保护，再评估字段加密或数据库加密及其后台写入影响。
- P0 只允许一个本地资料档案。未来若支持同机多账号，每个账号必须使用独立数据库文件和独立密钥；退出账号后先关闭数据库并清除内存中的查询结果，不能让后一账号打开前一账号的本地数据。
- App 从 `active` 进入 `inactive` 或 `background` 时，在根视图最上层立即覆盖不含业务正文的隐私遮罩，避免系统任务切换快照暴露账务、日历、地点或行程；重新进入 `active` 后移除。遮罩不销毁页面状态，也不冒充可选隐私锁；隐私锁仍进入 P1。
- 剪贴板只在用户明确选择复制地址/内容时写入，不复制金额或令牌。外部导航失败时不自动写剪贴板；用户点击后只复制已确认的非空目的地地址，无地址时才复制地点名称，不附带坐标、时间、标识符或行程/账务上下文。
- 调试菜单和诊断导出不得包含原始敏感正文。

## 网络与服务端安全

- 所有生产网络使用 TLS；禁止明文回退和忽略证书错误。
- 认证中间件从 token 得出 user ID；请求 payload 中的 owner 字段不作为授权依据。
- Repository 的每个用户数据查询都包含 owner 条件；关系创建校验两端同 owner。
- 创建和同步使用幂等标识，更新使用 base version，防止重放和覆盖。
- 使用请求体大小、分页、速率和并发限制，避免同步资源耗尽。
- refresh token 轮换、设备撤销和会话审计摘要进入服务端安全基线。
- 数据库和备份开启静态加密；KMS 权限与应用身份最小化。
- 所有上传的财务明细、用户确认的日历衍生上下文、精确地址/坐标与敏感元数据必须使用字段级信封加密：按用户和数据域生成 DEK，由 KMS KEK 包装；密钥版本随密文保存，支持轮换与账号删除时的密码学擦除。票据图片与原始轨迹当前不上传。
- 只有 owner、实体 ID、类型、状态、版本、cursor、时间桶和幂等处理所需的最小操作元数据可按批准 schema 明文保存。服务在严格授权后可于内存中短暂解密进行领域校验，明文不得进入日志、trace、缓存或错误响应。
- 在可搜索加密、受控聚合或等价方案通过专项威胁评审前，服务端不提供商户/备注/地址搜索，也不计算需要解密明细的报表；P0 搜索与报表全部在 iOS 本地执行。不能为了服务端功能降低加密要求。
- 后端部署、PostgreSQL 和 KMS 优先同一中国大陆地域与私网连接。

## 临时图片与轨迹

- 票据图片只在一次 OCR 会话内存在；确认、取消、权限撤回或会话异常结束后都删除，不复制到长期目录。
- 原始轨迹只服务于活动行程恢复和摘要计算；摘要确认或行程丢弃时与状态变更同一事务清理。
- 两类临时数据均不建立附件实体、不进入导出、mutation、OpenAPI、服务端 schema 或云备份。
- App 启动时扫描异常遗留的临时文件，并按可验证规则继续当前会话恢复或安全清理；P0 导出目录不承担恢复职责，因此启动时直接移除全部旧导出子目录，并在创建下一份导出前再次清扫。清扫只能作用于 App 自有的固定导出根目录，不能接受外部路径或扩大删除范围；清理失败不得继续生成新导出，并必须显示可重试错误。

## 日志、指标与追踪

### P0 本地模式

P0 不接入分析、崩溃、日志、追踪或诊断供应商，也不提供自建诊断包导出。`ThenApp` 生产源码不得直接调用控制台、统一日志、signpost 或标准输出 API；用户可见失败只通过脱敏领域错误和界面恢复路径呈现。这样既避免金额、日历和位置正文在开发时被无意插值，也使“零离机收集”的隐私清单具有可静态证明的代码边界。

“我的”中的诊断面不是数据采集或诊断包入口。P0 只读展示 App 名称、版本与构建号、“单设备本地”数据模式和“诊断收集未启用”状态。这些值来自发布包元数据与固定的 P0 能力边界，不读取账务、日历、位置、设备标识或系统日志，不创建文件，不写入剪贴板，也不发起网络请求。用户需要反馈时可手动提供版本号，但页面不鼓励附带金额、标题、地点或轨迹正文。

发布验证必须扫描生产 target 的 Swift 源码，至少阻断 `print`、`debugPrint`、`dump`、`NSLog`、`os_log`、`Logger`、`OSLog`、signpost、`CFShow` 与标准输出/错误写入入口；测试 target 为无障碍审计留下的合成诊断输出不进入 App 二进制，不属于该生产边界。验证器必须用独立临时副本注入一条合成敏感日志调用，证明非零退出，不能只以当前搜索无结果作为证据。Release Archive 仍需确认仅 Debug 的测试参数和合成测试数据没有进入可执行文件。

如果未来确需生产诊断，必须先批准独立数据流：定义稳定事件与错误码白名单、禁止自由文本、明确本地/离机位置和保留期、增加脱敏封装与测试，并同步修改 PRD、隐私清单和发布验收。在该评审完成前，不得以“仅调试”“私有级别”或供应商默认脱敏为理由绕过零日志边界。

### P1 服务端与获批观测

允许记录：

- request ID、route template、HTTP 状态、稳定错误码、耗时、重试次数。
- 队列长度、cursor 延迟、数据库池指标、临时清理结果和构建版本。
- 不可逆聚合后的功能结果计数，前提是分析方案获批。

禁止记录：

- access/refresh token、Apple credential 和服务端密钥。
- SQL 参数、请求/响应敏感正文。
- 金额明细、商户、备注、日历标题、地点、精确地址、坐标和轨迹。
- APNs payload 业务正文和票据 OCR 原文。

P1 获批后，OpenTelemetry trace attribute 使用路由模板而非完整 URL；日志脱敏在业务数据进入 logger 前完成，不能依赖采集平台事后过滤。

## 通知与锁屏隐私

- 本地出发提醒默认使用最小文案；用户可选择是否显示事件/地点。
- APNs payload 只包含不透明 ID、类型和同步唤醒所需最小字段，不包含金额、标题、地址或轨迹。
- 通知深层链接打开后仍执行本地/服务端授权检查。
- Focus、系统调度和用户设置可能阻止展示，App 只报告“已安排”而非“已送达”。
- 当前只使用普通本地通知，不启用 Time Sensitive 或 Critical Alerts，也不保留隐藏开关。

## 生命周期与保留

| 数据 | 默认方向 | 删除触发 |
| --- | --- | --- |
| OCR 中间图 | 识别会话内本地临时 | 确认、取消或会话过期后删除。 |
| 日历窗口快照 | 本地滚动窗口 | 来源取消选择、权限撤回后的用户选择、窗口过期。 |
| 用户 TripPlan/Journey 摘要 | 用户删除前保留 | 显式删除或账号擦除。 |
| 原始轨迹 | 活动行程期间本地临时 | 摘要确认或行程丢弃时立即删除；异常退出仅保留到恢复处理。 |
| mutation receipt/tombstone | 至少覆盖最长离线期 | 所有有效设备确认或批准期限后。 |
| 脱敏服务日志 | 有限运维窗口 | 到期自动清理。 |
| 备份 | 按 RPO/RTO 和隐私承诺 | 到期轮换；账号删除按披露期限清理。 |

具体天数必须由产品的最长离线、恢复和删除承诺决定，再成为配置和验收常量，不由实现人员自行选择。

## 导出

- 用户可以导出账户、交易、分录可读视图、计划、Journey 摘要和关联。
- 票据图片和原始轨迹不提供导出选项，也不能通过诊断包或分享流程绕过。
- 导出使用临时受保护文件，分享完成/取消后及时清理。
- 导出不包含 token、内部 HMAC、mutation、服务端审计或其他用户数据。
- 生成失败不破坏源数据。P0 的导出契约固定为单个 JSON，不在低存储时自动拆分、降级字段或改写为多文件；容量不足时关闭失败、删除随机临时目录中的任何部分文件，并让用户清理空间后重试同一操作。

### P0 结构化导出契约

- P0 只生成一个 UTF-8、可读缩进且键稳定排序的 JSON 文件，顶层必须包含 `schema_version = 1`、UTC `exported_at`、App 名称、本地资料摘要、账户、交易、分录、用户确认的出行计划、Journey 摘要和交易—行程关系。
- 金额同时保存整数最小货币单位与 ISO 4217 币种，不以浮点数表达；日期使用带时区的 ISO 8601；实体保留稳定 ID 以维持分录和关系的可解释引用，但不导出 owner ID。
- 计划只导出用户确认后的正文和已保存地点快照；不导出 EventKit 原始标识、HMAC、CalendarSource、CalendarOccurrence、来源 revision、系统通知 request ID、导航交接诊断或路线供应商内部对象。
- Journey 只导出状态、交通方式、起止时间、耗时、距离和采集完整性摘要；不导出 recording device ID、manifest、TrackSegment、TrackPoint 或任何坐标序列。
- 导出快照必须在一次 SQLite 一致性读取中形成。写入随机命名的专用临时目录，使用完整文件保护；只有文件成功关闭后才交给系统分享面板。分享完成、取消或失败都清理该目录，清理失败显示可重试状态。
- P0 不把导出文件长期保存到 App 容器，也不自动上传。空间不足或编码失败时不产生“成功”状态、不修改源数据库，并删除未完成文件。文件边界要把系统容量不足错误映射为稳定领域错误，界面只提示“存储空间不足、清理后重试、源数据未改变”，不展示底层路径或错误正文；自动化必须在写入一个合成部分文件后抛出容量不足，证明整个随机目录被清理且下一次正常导出仍可成功。

## 删除

### 分层删除

- 清理 OCR 临时数据。
- 丢弃进行中/待确认 Journey 的临时轨迹，或删除整个 Journey。
- 清理日历缓存并停止同步。
- 删除本机全部数据。
- 删除云账号和全部云端数据（账号启用后）。

每个入口明确会保留什么。例如删除 Journey 不删除正式交易；清理日历缓存不删除用户创建的计划。

### P0 本地删除契约

- “清理日历缓存”只删除 CalendarSource、Scan、Series、Occurrence、Revision 以及本地 EventTripLink，并停止后续自动扫描；用户确认的 TripPlan、提醒、Journey、交易和交易—行程关系继续保留。系统日历原始事件不受影响，系统权限也不会被伪装为已撤回。
- “删除单个 Journey”只允许对已完成或已丢弃记录执行；删除其摘要、临时轨迹与交易—行程关系，但绝不删除任何正式交易、分录或关联 TripPlan。未收口 Journey 必须先完成或丢弃，以确保定位驱动已停止。
- “删除本机全部数据”必须先停止当前定位会话并撤销本 App 已调度的出发提醒，再在一个 SQLite 事务中删除全部资料、账务、日历缓存、计划、Journey、轨迹和关系。任何数据库失败都整体回滚且不得显示完成。
- 全量删除成功后立即在同一安装内重新创建一个新的空本地资料和默认账户集合，状态回到首次确认本币之前；旧 profile ID、交易、计划和 Journey 不得被新环境继续访问。重新初始化失败进入明确的本地数据错误页，不静默恢复旧内容或伪造空态。
- 所有破坏性入口使用包含对象范围与保留项的二次确认；全量删除需要第二次明确确认。正在生成导出时禁止同时删除，删除开始后禁止创建新的导出。

### 账号删除状态

`requested -> deleting -> deleted | failed`。请求后停止非必要新云写入并撤销普通设备会话和推送；若存在撤销期，只保留一个仅能查询/取消删除的受限管理会话，或每次通过 Sign in with Apple 重新认证。进入 `deleting` 后撤销全部会话，由同进程任务清理主表、关联建议、冲突暂存、mutation receipt、change log、tombstone 和死信。状态和截止时间必须明确；失败保持可重试与人工诊断，不向用户提前宣称完成。

备份清理时限和不可立即擦除的法定/安全记录必须在隐私政策中说明。

## 主要威胁与控制

| 威胁 | 控制 |
| --- | --- |
| 丢失或借用已解锁设备 | Data Protection、可选 App 隐私锁、后台快照遮罩、可撤销会话。 |
| IDOR/跨用户访问 | 认证上下文 owner、Repository 限定、复合外键、集成测试。 |
| 重放导致重复记账 | mutation/幂等键、服务端规范化 payload 的带密钥摘要、唯一约束和事务。 |
| 客户端时钟篡改 | 服务端 version/cursor；客户端时间不决定冲突。 |
| 敏感日志和追踪泄漏 | 结构化 allowlist、无正文、测试扫描日志字段。 |
| 后台位置滥用 | 用户主动开始、明显状态、When In Use、可停止、无全天采集。 |
| 临时图片或轨迹残留 | 受保护临时目录、随机文件名、会话结束清理、启动恢复扫描和失败可见。 |

| 供应商 SDK 过采集 | P0 最少第三方 SDK；接入前审计权限、数据清单、地域、关闭方式。 |

## 第三方与供应商准入

新增地图、云 OCR、分析、崩溃或存储供应商前必须记录：

1. 必要性与无 SDK/端侧替代。
2. 收集字段、目的、频率、地域和保留期。
3. 用户同意与撤回路径。
4. SDK 初始化时机和隐私 API。
5. 数据处理协议、子处理者、删除与导出能力。
6. 密钥、配额、退出和替换方案。
7. 真机网络抓取和隐私清单验收。

供应商未批准前通过接口隔离且默认关闭，不在领域层引用厂商类型。

## App 隐私清单

- `ThenApp` target 必须把平台固定文件名 `PrivacyInfo.xcprivacy` 作为资源打包；该文件名属于 Apple 工具约束，不翻译、不编号，也不复制第二份清单。
- P0 不发送账务、日历、位置、OCR、诊断或分析数据到设备外，不接入追踪域，因此 App 自身清单固定声明 `NSPrivacyTracking = false`、空追踪域和空收集数据类型。只保存在用户设备并由用户主动系统分享的数据不伪装成后台收集。
- 当前 App 自有源码不调用 Active Keyboards、Disk Space、File Timestamp、System Boot Time 或 User Defaults 五类 Required Reason API，因此 `NSPrivacyAccessedAPITypes` 为空；以后新增任一受管 API，必须先记录准确批准理由，再修改清单和验收，不得用空泛理由占位。
- Swift Package 或二进制依赖对自身 Required Reason API 与收集行为负责；依赖升级时检查其内置隐私清单、签名和最终聚合报告，不能用 App 清单替代依赖声明。当前 GRDB 自带依赖清单，OpenAPI 生成器只参与构建，运行时包仍需随版本升级复核。
- 候选发布包的自动检查必须递归枚举 App bundle 内每一份 `PrivacyInfo.xcprivacy`，分别验证 plist 结构、追踪开关、追踪域、离机收集类型和 Required Reason API，并记录相对路径与总数；不能只验证 bundle 根清单。
- 任一嵌入依赖新增或改变声明都阻断发布，直到设计、PRD、数据流说明和人工复核同步更新。自动递归检查不能替代 Xcode Organizer 对签名 Archive 生成的聚合隐私报告；二者都必须保留证据。
- 每个候选发布构建必须验证 App bundle 中存在且仅存在一份 App 自身清单，并生成 Xcode 隐私报告复核聚合结果。若以后启用网络、分析、崩溃上报或 P1 同步，必须先重新完成数据类型、用途、关联性、追踪与第三方域名评审。

依据：[Apple Privacy manifest files](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)、[Describing use of required reason API](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api)。

## 安全测试与发布门槛

- 授权矩阵：未登录、当前用户、其他用户、已删除和已撤销设备。
- 幂等、版本冲突、重放、越权关联、cursor reset 和同机账号数据隔离。
- 日历/通知/定位/相机/相册的拒绝、限制、撤回和系统设置返回。
- P0 生产源码零日志/诊断入口扫描及负向夹具；P1 获批后再增加日志、崩溃、trace、通知和诊断包敏感字段扫描。
- Keychain、文件保护元数据自动验证，以及首次解锁/锁屏快照/后台轨迹的真机验证。
- 导出完整性、临时文件清理、本地删除和账号删除端到端证据。
- 依赖漏洞、固定版本、SBOM/依赖清单和第三方隐私清单审查。
- 生产 Swagger 默认关闭，调试端点不暴露敏感配置。
