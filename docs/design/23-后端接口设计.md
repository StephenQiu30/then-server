## 通用合同

- 沿用 Gin/Huma operation + Go DTO tag 运行时生成 `/openapi.json`；Swagger 与未来 Umi 均消费它。本文列业务接口和边界，不手写另一份 YAML，不创建 Swagger 容器。
- 沿用无版本前缀路径和现有 Cookie 会话。未登录 401；不属于本人或不可公开读取的资源统一 404；运营权限不足 403；版本/状态冲突 409；限流 429 并返回重试秒数；依赖故障 503；契约或领域输入错误统一 400。错误不得泄露私有实体是否存在。
- 更新/删除带 expected_revision；所有创建支持客户端 UUID 幂等，同 UUID 同规范化 payload 返回同资源，不同 payload 返回 409。公开创建需要同样幂等，但私有来源从会话校验。点赞、收藏、关注、屏蔽用 PUT 建立、DELETE 取消。
- 列表返回领域集合与 `next_after_id`，默认 20、最多 50；日期范围最多 366 日、月日历限一个月。服务端在同一筛选查询中查找 after ID 并取得稳定排序值，筛选不匹配返回 404；相同时间以 ID 排序。分页不等于固定快照，撤回内容立即过滤。
- 推荐/日记/公开帖/本人账号使用独立 DTO。禁止把 repository record 直接序列化；公开响应不返回 owner 私有 ID、内部来源、对象 key、同意记录或邮箱。
- 默认不保存敏感响应缓存；公开媒体入口逐次校验当前可见状态，撤回后的新请求拒绝。管理员操作记录最小审计信息，不能通过本人资料接口修改 role/status。

## 17-40 已实现的服务端增量接口

`GET /sync/changes?after=&limit=` 使用当前 active Cookie；`after` 为版本化、owner 绑定的游标，`limit` 为 1～100。返回按 owner 提交顺序排列的 `changes`、`next_cursor`、`has_more`，每项仅含 seq、kind、entity_id、action、可空 revision；`Cache-Control: no-store`。无效、跨账号、未来游标拒绝。实体详情与写入复用现有本人 CRUD；客户端主动启用与导入仍待实现。运行时 Huma OpenAPI 0.25.0 与本地验证见 [17-40](../plan/17-40-服务端增量同步执行计划.md)。

## 两个完整请求旅程

1. 日记：创建普通图上传意图 → MinIO PUT → complete → 查询到 ready → POST diary → GET calendar → 编辑 revision → 查询删除影响 → DELETE。任一失败不会虚构已保存/已穿。
2. 社区：POST 草稿（可选导入日记）→ 净化发布副本 ready → submit → 人工 review → GET feed/公开详情/图片 → 赞藏评关 → 举报/屏蔽 → withdraw → 详情、搜索、流、图片均不可读。原日记始终私人。

编码前在具体切片中补齐稳定 operationId、完整 DTO、字段预算、错误码和幂等响应例；运行时 OpenAPI 契约测试与 Umi 生成烟测验证实际客户端可消费。不能用本设计列表代替可执行接口验收。
