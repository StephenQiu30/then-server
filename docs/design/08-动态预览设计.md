# 动态预览设计

当前范围：2026-09-22 按低成本路线调整为 **deferred**。现行首版用静态 GLB 本地旋转满足立体观察，不调用 AI 视频；本文件只约束后续独立视频能力，既有 pending/blocked 场景不改为通过。Woo 的 Create 360° 按钮不能证明其内部产物格式，下述 MP4 是本项目的后续设计。

## 当前方案与边界

更新：2026-09-15。设计 approved_with_gates，尚未实施。本项目后续视频设计从已确认静态结果生成 5–10 秒 MP4，iOS 使用 AVFoundation 原生播放。产品需求见 [PRD 15](../prd/15-动态预览需求.md)，场景验收见 [Acceptance 15](../acceptance/15-动态预览验收.md)。真实交互人物使用 [Design 20](20-OOTD完整产品能力与阶段架构设计.md) 的 Three.js/GLB，两者共用 Look 身份而分别保存结果类型和生命周期。

## 最小架构

SwiftUI 请求层 → Go API → PostgreSQL 任务/Outbox → Kafka → 已批准视频 Provider → 质量审核 → 私有 MinIO → 原生 AVPlayer。

本图是待实现的视频业务设计。当前后端已为 17-19 合成本人照片实现私有上传、媒体检查和删除 worker，但没有视频 Provider、视频任务或 FFmpeg 路径。动态预览仍须独立批准 Provider、成本、地域、质量和删除合同，不能复用照片准备同意。

## 数据与状态

`TurntableVideo` 绑定 owner、source-result ID/revision、task ID、Provider/pipeline revision、同意收据、视频与 poster 的 MIME/字节/hash、时长/尺寸及删除状态。Manifest 保存允许发布的资源事实，不包含用户可执行代码；数据库不存媒体 BLOB，客户端不持久化临时签名 URL。

创建时固定输入版本和幂等键；同键同请求返回同任务，不同请求冲突。任务复用 Design 10 的 queued → running → validating → succeeded 状态，失败、取消与删除遵循各自可解释终态；播放器状态独立。请求取消不代表外部处理已停止；源撤回或删除 tombstone 阻止迟到结果重新发布。

## 生成与发布

1. 服务端验证 owner、静态结果有效性、独立同意、地域和配额，事务内写任务与 Outbox。
2. 消费者幂等取任务，调用批准的 Provider；保留受限重试、成本/时限上限和可恢复任务事实。
3. 验证媒体格式、长度、尺寸、字节、身份/衣物一致性、时间连续性和声明的转身覆盖。只有审核通过且结果事务提交才写 succeeded。
4. 对象写入和数据库发布之间的失败由清理/恢复任务处理；未完成发布的对象不暴露。
5. FFmpeg 仅在实际编码/检查需要时接入受限 worker，固定构建/codec，禁止在 API 请求线程做长时媒体处理。

## iOS 播放、保存与恢复

原生 ViewModel 持有任务和播放状态。静态图先显示；AVPlayerItem 只有 readyToPlay 后允许播放，failure 保留静态图和明确重试。离开/后台暂停，不自动循环；Reduce Motion 不自动播放，提供 VoiceOver 播放/暂停与状态文本。

下载写临时文件，完成字节/hash/媒体解码校验后原子替换。未知 revision、坏 hash、取消、低存储和迟到回调保持上一有效结果。保存绑定结果 ID/revision，重启从实际任务/本地记录恢复；失败不得产生虚假的已保存状态。

下载/系统分享只针对已确认结果，由用户触发并说明外部副本删除边界，不要求无关权限，不创建公开分享平台。

## 删除与故障验收

删除覆盖视频、poster、manifest、缓存、中间物、对象存储和供应商副本；部分失败显示处理中/待重试。已导出的外部副本不虚报已清除。源照片或授权撤回沿血缘关闭相应任务，迟到成功、重投和旧幂等键不能复活资产。

验收包含实际视频逐帧复核、源/任务/媒体所有权、取消和删除竞态、重复计费保护、断网/重启、低存储、坏媒体、最低真机帧率/内存/发热、辅助功能与开关回滚。具体预算、供应商、保留窗口必须在执行计划冻结；当前未取得这些通过证据。
