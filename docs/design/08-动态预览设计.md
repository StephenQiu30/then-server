## 目标与约束

### 目标

1. 在一张用户已接受的静态试穿图上增加可拖拽的动态视觉反馈，而不阻断推荐、试穿和保存。
2. 明确区分生成视角和真实人体/衣物事实，避免把模型推测包装成真实 3D。
3. 将图片转视频、抽帧、时序抠图、资源打包和 iOS 播放解耦，任一阶段失败都可回退。
4. 在最低支持 iPhone 上维持稳定帧率、有限内存、可恢复下载和无障碍操作。
5. 使用版本化 manifest 作为服务端资产与客户端播放器之间的唯一资源契约。
6. 沿用人物照片的高敏感分类、逐次第三方处理同意和资产血缘删除。

### 非目标

- 不生成人体 Mesh、骨骼、BlendShape、UV、材质或物理布料。
- 不提供可信角度、真实背面、量体、尺码或商品细节证明。
- 不支持实时相机 AR、自由视点、缩放到模型未生成的视角或服装交互。
- 不在推荐结果出现时自动为三套方案生成视频。
- 不将 MP4 连续 seek 冒充帧级拖拽体验。
- 不要求用户开启通知、相册写入或运动权限。
- 不在用户开启“减少动态效果”时自动播放或强制拖拽动画。

## 核心决策

首个候选实现固定为：

```text
用户接受的静态试穿图
→ 图片转 5 秒左右固定机位短视频
→ 服务端均匀抽取 36–48 帧
→ 视频级人物 mask 与背景透明化
→ 平滑人物位置和统一画布
→ 生成预览帧、显示帧和 manifest
→ SwiftUI 按拖拽位移计算离散帧
→ 获批 renderer 显示该帧或受控 2.5D 合成
```

生成的侧面与背面属于模型推测。manifest 和领域模型必须保存 `representation = generated_2_5d`，UI 统一称“动态预览”，不得使用“真实 360°”“3D 扫描”“完整背面”等表述。

## 资格与触发条件

只有同时满足以下条件才允许创建动态预览任务：

1. 来源为已通过质量门的 `synthetic_static_try_on` 结果。
2. 用户明确保留该静态结果，且对应 Outfit 修订仍有效。
3. 用户主动点击“生成动态预览”；不得因页面曝光、预取或推荐批处理自动触发。
4. 用户已看到本次图片转视频处理方、地域、输入、保留期和删除方式，并对本次外部处理同意。
5. 当前区域策略允许视频供应商处理人物图片。
6. 任务配额、成本上限、内容安全和输入尺寸校验通过。

来源静态图被删除、替换或质量撤销时，动态预览立即失去资格，并进入删除流程。

## 完整用户与系统流程

```text
静态试穿完成且用户选择保留
→ 用户点击“生成动态预览”
→ 展示 2.5D 说明、第三方处理信息和本次同意
→ 创建幂等 RotationJob
→ 以短时受控输入提交 MotionProvider
→ 异步生成短视频
→ 下载到隔离临时区并校验
→ FFmpeg 均匀抽取 36–48 帧
→ 视频级人物分割/传播 mask
→ 边界修正、人物框时序平滑、统一裁剪
→ 质量门检查身份、衣物、肢体、闪烁和位移
→ 输出低分辨率预览帧与标准显示帧
→ 生成版本化 manifest 和内容哈希
→ 写入私有对象存储并建立资产血缘
→ App 先加载预览帧，达到最小集合后允许拖拽
→ 后台按当前位置加载标准帧
→ 用户保存、删除或反馈异常
```

用户离开页面不取消任务。App 恢复后从 Job 和 manifest 恢复，不依赖内存中的播放器对象。用户取消后应立即停止新阶段，并尽力取消供应商任务和清理已有临时资产。

## 状态机

### 用户前置状态

```text
not_requested
  → awaiting_consent
  → ready_to_create
```

拒绝或取消同意时回到 `not_requested`，不会创建外部任务。`ready_to_create` 通过来源、区域、配额和幂等校验后才持久化 RotationJob。

### RotationJob 生命周期与处理阶段

权威 `lifecycle_state` 与 [`10-OOTD服务端与异步任务设计.md`](10-OOTD服务端与异步任务设计.md) 的通用生成状态一致：

```text
queued
  → processing
  → succeeded

processing → retry_scheduled → queued
queued / processing → cancel_requested → cancelled
processing / retry_scheduled → failed
succeeded → expired
```

`processing` 内的 `stage` 为：

```text
validating
  → video_generating
  → video_ready
  → extracting_frames
  → masking_frames
  → normalizing_frames
  → packaging
  → quality_review
```

删除使用独立 `DeletionRequest`，不把 `cancelled` 等同于视频、帧和供应商副本已经删除。

约束：

- `video_ready` 不表示可下发；只有 manifest 和最小预览帧集合通过质量检查后，Job 才能进入 `succeeded`，RotationAsset 才能进入 `ready`。
- 每次重试创建新的 attempt；不得覆盖已完成 attempt 的模型、输入和质量元数据。
- 来源静态资产进入删除时，未完成 Job 必须进入 `cancel_requested`，并创建或并入同一血缘的 DeletionRequest。
- `ready` 后某个帧对象丢失或 hash 不匹配时，资产变为 `degraded`，客户端停止帧拖拽并回退静态图。
- 客户端轮询超时不改变服务端状态。

### 客户端播放器

```text
idle
  → loading_manifest
  → loading_preview
  → interactive_preview
  → loading_standard_frames
  → interactive_ready
```

异常状态：

- `static_fallback`：manifest 无效、帧不足、内存压力、Reduce Motion 或服务端降级。
- `temporarily_offline`：继续使用磁盘中已校验帧；缺帧时回退最近可用帧或静态图。
- `asset_deleted`：立即清理内存和磁盘缓存，不再展示旧帧。

## 页面与交互

### 默认体验

- 静态试穿图始终先可见，不出现空白生成页。
- 生成中在静态图上显示非阻塞状态；用户可以继续选定、保存或退出。
- 达到最小预览帧集合后出现“左右拖动查看动态预览”的一次性提示。
- 横向拖拽在人物区域内生效；竖向滚动优先交给页面，需设方向锁避免冲突。
- 位移累计映射到离散 frame index，并按 `frame_count` 循环；不得显示未经验证的角度刻度。
- 拖动结束可使用短暂减速，但不自动长时间旋转。
- 提供“原始单品 / 静态试穿 / 动态预览”切换，用户可以核对生成变化。

### Reduce Motion 与无障碍

- 检测系统 Reduce Motion；开启时默认停留在静态试穿图，不自动播放、不显示惯性旋转。
- 用户仍可通过明确按钮查看一张下一帧，但不得连续自动动画。
- VoiceOver 提供“上一视图”“下一视图”“回到静态预览”和“删除动态预览”动作。
- 不以运动方向作为唯一状态提示；当前是 AI 动态预览的说明必须可朗读。
- Dynamic Type 最大尺寸下，说明、失败、取消和删除控件仍可访问。

## 服务端媒体处理

### 图片转视频

`MotionProvider` 输入只包含已批准的静态试穿资产和受控参数。提示词由服务端模板生成，不接收用户自由文本，候选语义限定为：

- 固定相机。
- 人物自然、缓慢转身。
- 中性姿态和稳定光照。
- 不增加人物、服装或道具。
- 背景简洁且不改变服装。

供应商无法稳定生成闭环时，不强制首尾相同；客户端循环只是一种浏览机制，不得声称动作连续真实。

### 抽帧

- 以源视频实际时长均匀取样 36–48 帧。
- 记录请求时间和实际帧时间，按实际时间排序并去重。
- 所有帧统一方向、色域、画布和像素尺寸。
- 抽帧必须异步执行，不阻塞 API 进程。
- 若有效唯一帧不足 36 帧，则任务不进入帧播放器质量门。

### 时序人物 mask

- 优先使用视频级分割或首帧 mask 跨帧传播，避免逐帧独立抠图造成轮廓闪烁。
- 对人物中心、脚底位置和包围框尺寸做受限时序平滑；不能通过拉伸人体来强行对齐。
- 边界、头发和手部不稳定超过阈值时拒绝透明帧结果。
- 背景去除失败时不下发带随机透明闪烁的帧；可回退为经审批的原背景短视频或静态图。

### 资源编码

候选 manifest 支持每帧独立资源。实际使用 PNG、WebP、HEIF 或其他格式须在最低支持系统完成解码、透明度、质量和内存评测后批准，不能只根据文件大小决定。

资源分两档：

- `preview`：36–48 帧、较低分辨率，目标是快速达到可交互状态。
- `standard`：同一时序和帧编号的较高分辨率，按需替换预览帧。

不同档位必须共享人物画布、时间顺序和内容哈希族，避免加载升级时跳动。

## Manifest 契约

manifest 是不可变、版本化的 JSON 资源，至少包含：

```json
{
  "schema_version": 1,
  "asset_id": "rotation_asset_id",
  "representation": "generated_2_5d",
  "source_try_on_result_id": "result_id",
  "frame_count": 48,
  "width": 512,
  "height": 768,
  "loop": true,
  "preview": [
    { "index": 0, "asset_id": "asset_id", "sha256": "...", "byte_length": 12345 }
  ],
  "standard": [
    { "index": 0, "asset_id": "asset_id", "sha256": "...", "byte_length": 45678 }
  ],
  "poster_asset_id": "asset_id",
  "content_hash": "...",
  "expires_at": null
}
```

约束：

- `frame_count` 只能在 36–48 之间，index 从 0 连续且无重复。
- manifest 不含对象存储内部 key、公开 URL、人物属性或供应商提示词。
- API 根据 `asset_id` 单独签发短时读取 URL，或返回同等受控的批量读取凭据。
- 客户端必须校验 schema、数量、尺寸、字节上限和 hash；校验失败进入静态降级。
- manifest 不标注“正面 0°、背面 180°”等未经真实几何验证的角度。

## iOS 播放器设计

### Renderer 抽象与 Three.js 适用条件

SwiftUI 页面通过纯 Swift `DynamicPreviewRenderer` 协议驱动渲染，不直接依赖 WebKit、JavaScript 或 Three.js 类型。候选实现为：

- `NativeFrameRenderer`：直接显示 manifest 的离散帧，是普通帧切换的默认方案。
- `ThreeJSRenderer`：在确需透视相机、分层 2.5D、深度图视差、着色器、粒子或 scene graph 时，通过 `UIViewRepresentable` 封装本地 `WKWebView` 与锁版 Three.js。
- `StaticRenderer`：poster/静态试穿图，是 Reduce Motion、VoiceOver 偏好、资源不足和任何 renderer 故障的永久可用降级。

Three.js 不自动成为 M5 实现。未来 `15-SS` 执行计划必须先用同一 manifest 和最低设备比较原生与 Three.js；若只是 36–48 帧逐帧切换，原生实现达到体验目标且 Three.js 没有可测增量价值，则不引入 WebContent 进程。若选择 Three.js，一个生产切片只保留获批 renderer，不长期维护两套等价生产实现。

Three.js renderer 采用以下边界：

```text
SwiftUI 页面 / 原生无障碍控件
→ @Observable ViewModel
→ DynamicPreviewRenderer
→ ThreeJSRenderer adapter
→ UIViewRepresentable(WKWebView)
→ 本地 Three.js WebGLRenderer
→ 受控本地 scheme 提供已验证资产句柄
```

- 页面、Tab、sheet、说明、切换、报告、保留和删除均为 SwiftUI；canvas 只是人物动态画布，不是 H5 页面。
- Swift 负责下载、认证、manifest/hash/尺寸校验、缓存、删除和 feature flag。JavaScript 不直接访问 API、对象存储、分析服务或文件系统，也不接收令牌、签名 URL、对象 key、用户 ID、真实路径或 base64 媒体。
- HTML、JavaScript、shader 和 Three.js 随 App 离线打包；严格 CSP 和 WebKit 配置拒绝 CDN、远程脚本、HTTP(S) 子资源、外部导航、弹窗、下载、动态代码执行和生产调试。
- bridge 使用版本化、大小受限的结构化消息，允许 `ready`、`capabilities`、`scene_loaded`、`frame_presented`、`recoverable_error`、`fatal_error` 与低频聚合性能样本；不得把用户或供应商正文拼成 JavaScript，也不得逐触摸点/逐帧跨 bridge 往返。
- Three.js 只把已批准帧、深度图或透明层作为纹理/平面参与受控合成；不得生成或推断人体 mesh、真实视角、可信背面、尺码或服装物理。
- 首个基线只允许 `WebGLRenderer`/WebGL 2。GPU 不支持、初始化超时、WebGL context lost、WebContent 终止、bridge/CSP/版本不匹配或 feature flag 关闭时立即销毁 renderer 并保持 SwiftUI 静态内容。

### 加载和缓存

- manifest 和 poster 优先，预览帧达到连续最小窗口后即允许交互。
- 预取当前位置左右相邻帧；快速拖动时只解码最新目标帧，取消过期任务。
- 使用双缓冲避免帧切换闪白。
- 解压后的帧保存在有上限的内存 LRU，压缩资源保存在有 TTL、按用户隔离的磁盘缓存。
- 收到内存警告时先清标准帧，再清预览帧，最终回退 poster，不让 App 崩溃。
- 缓存键包含 `asset_id + content_hash + rendition + index`，防止资产更新后复用旧帧。
- 用户删除或退出账号时同步清理内存、磁盘索引和后台下载任务。
- 采用 Three.js 时，原生 MediaStore 仍是唯一缓存实现；Web Storage、cookies、IndexedDB 和 WebKit URL cache 不保存业务或媒体事实。退出、删除或 renderer 销毁还必须撤销临时 scheme 映射并释放纹理与 blob。

### 渲染和手势

- 手势层只计算目标 index；图片解码在后台 actor/队列执行，主线程只交换已准备好的图像。
- 通过显示刷新驱动合并高频拖拽事件，不为每个触摸事件创建解码任务。
- 同一时刻最多一个前台目标帧提交；慢网络下保留最近已显示帧，不展示空白。
- 自动播放若未来获批，必须有明确停止入口并尊重低电量和 Reduce Motion；当前候选默认不开启。
- Three.js 路径由原生手势层提交合并后的目标 index 或低频 scene command；页面纵向滚动、VoiceOver adjustable action 和上一/下一按钮不交给 WebView 解释。只有需要 scene 内连续交互的获批效果才在 JavaScript 内部采样指针，不逐帧回传。
- 页面离开、转入后台、低电量或严重热压力时停止 animation loop；释放 renderer、texture、geometry、material、render target 和 message handler。最多自动重建一次异常终止的 WebContent，连续失败保持静态，避免恢复循环。

## 领域模型与数据流

### RotationJob

| 字段 | 说明 |
| --- | --- |
| `id` / `user_id` | 全局唯一 ID 与所有者。 |
| `source_try_on_result_id` | 唯一静态输入。 |
| `outfit_id` / `outfit_revision` | 发起时选中穿搭快照。 |
| `consent_record_id` | 本次图片转视频第三方处理同意。 |
| `processing_policy_id` | 供应商、地域、保留期策略。 |
| `provider` / `model_version` | 视频生成来源。 |
| `provider_job_id` | 取消、删除和供应商审计所需。 |
| `lifecycle_state` / `stage` / `attempt` | 通用任务状态、处理阶段与执行次数。 |
| `idempotency_key` | 阻止重复点击和重复计费。 |
| `frame_count` | 实际通过质量门的帧数。 |
| `quality_flags` | 身份、衣物、肢体、闪烁、对齐等结果。 |
| `error_code` | 稳定领域错误。 |
| `cost_units` / 时间戳 | 成本与各阶段耗时。 |

### RotationAsset

| 字段 | 说明 |
| --- | --- |
| `job_id` | 来源任务。 |
| `source_asset_id` | 静态试穿输入。 |
| `video_asset_id` | 受控原始生成视频；按保留策略可短期存在。 |
| `poster_asset_id` | 静态降级图。 |
| `manifest_asset_id` | 版本化资源清单。 |
| `representation` | 固定为 `generated_2_5d`。 |
| `state` | `building`、`ready`、`degraded`、`deleting`、`deleted`。 |
| `expires_at` / `deleted_at` | 保留和删除。 |

帧资源使用统一 `MediaAsset`，并通过 `derived_from` 边连接到视频和静态试穿源，便于完整删除。

## API 与异步任务

以下是领域级契约。功能进入受控 POC 或发布实施阶段时，必须先写入唯一 `backend/openapi.yaml` 并完成 OpenAPI、鉴权、幂等、资源上限和契约测试评审，不能从本文另行维护第二份契约：

- `POST /v1/rotation-jobs`：请求 `source_try_on_result_id`、`outfit_revision`、`consent_record_id`；请求头含 `Idempotency-Key`，返回 `202 Accepted`。
- `GET /v1/rotation-jobs/{job_id}`：返回阶段、终态和稳定错误。
- `GET /v1/rotation-jobs/{job_id}/events`：前台 SSE；按事件序号恢复。
- `POST /v1/rotation-jobs/{job_id}/cancel`：幂等取消。
- `DELETE /v1/rotation-jobs/{job_id}`：发起资产血缘删除。
- `GET /v1/rotation-assets/{asset_id}/manifest`：校验所有权后返回 manifest 及受控读取信息。

异步任务至少拆分为：

1. `generate_motion_video`
2. `download_and_validate_video`
3. `extract_frames`
4. `segment_and_normalize_frames`
5. `package_rotation_asset`
6. `quality_check_rotation_asset`
7. `delete_rotation_lineage`

每一步都必须幂等，输入和输出使用资产 ID，不把临时路径或签名 URL 持久化到消息正文。Worker 中断后从已完成阶段恢复；重新执行不得创建第二套用户可见资产。

## 权限、隐私、安全与删除

- 静态试穿图、生成视频、人物 mask、每一帧和 manifest 的访问关系均继承高敏感分类。
- 图片转视频可能由不同供应商处理，因此不能沿用静态试穿的模糊总同意；每次提交前应显示实际处理方、地域、输入和保留期。
- 不同地区不得自动选择未获准的海外供应商作为降级。
- 视频和帧只存私有对象存储，使用短时签名读取；不得生成公共 CDN URL。
- 生成视频若只用于抽帧，应在打包并验证后尽快删除；长期保存分享视频必须另有产品目的和用户选择。
- manifest 不应暴露对象 key、供应商 job ID 或内部媒体血缘。
- 日志不得记录帧 URL、人物图、提示词、mask、衣物描述或视频元数据正文。
- Three.js bundle、addon、shader 与构建产物必须有 lockfile、许可证、SBOM 和 hash；运行时不得下载或执行代码。Web bridge、CSP、scheme handler 和 Web 数据清理遵循 [`01-技术选型.md`](01-技术选型.md) 与 [`11-OOTD权限隐私与安全设计.md`](11-OOTD权限隐私与安全设计.md)。
- 删除来源静态试穿、Outfit、Avatar、账号或动态预览时，应删除供应商任务、视频、全部帧、poster、manifest、CDN/设备缓存和未完成后台下载。
- 删除完成前资源不可读取；部分删除失败进入可重试状态和告警，不能恢复展示。

完整策略见 [`11-OOTD权限隐私与安全设计.md`](11-OOTD权限隐私与安全设计.md)。

## 失败与降级方案

| 失败 | 降级 |
| --- | --- |
| 用户拒绝图片转视频 | 保留静态试穿，其他流程不受影响。 |
| 区域无合规 MotionProvider | 不生成，不跨境回退；保留静态试穿。 |
| 视频生成失败或超时 | 保留静态试穿，可稍后重试。 |
| 视频通过但有效帧不足 | 不下发帧播放器；经质量批准时可显示普通短视频，否则静态降级。 |
| mask 闪烁或人物边缘失败 | 拒绝透明帧；回退经批准的原背景视频或静态图。 |
| manifest 缺帧、超限或 hash 错误 | 客户端关闭拖拽并显示 poster。 |
| Three.js/WebGL 不可用、初始化或 bridge/CSP 失败 | 不显示白屏；切换原生帧 renderer，无法安全切换时显示 poster。 |
| WebGL context lost 或 WebContent 进程终止 | 停止事件与资源请求，最多重建一次；再次失败保持静态图。 |
| 网络中断 | 使用已校验缓存；缺帧时保持最近帧或 poster。 |
| 内存压力 | 清高清帧、缩小窗口、清预览帧，最终静态降级。 |
| Reduce Motion | 默认静态图，只提供用户主动的离散上一/下一视图。 |
| 来源静态图被删除 | 立即不可读并清理整个动态资产血缘。 |

任何动态失败都不得改变静态试穿、选中 Outfit、保存和穿搭反馈。

## 性能预算与可观测性

### iOS 性能预算

以下门槛在独立 OOTD 最低支持设备上验证：

- 已缓存 manifest 和预览帧：进入页面到可拖拽 p95 ≤300ms。
- 标准测试网络下首次预览可交互 p95 ≤2 秒，不包含服务端视频生成时间。
- 拖拽到目标帧反馈 p95 ≤50ms。
- 拖拽期间平均显示帧率 ≥55fps，主线程帧耗时 p95 <16.7ms。
- 1 分钟连续拖拽 hitch ratio <1%。
- 动态预览额外内存峰值 <100MB；收到内存警告后可回退且不崩溃。
- 页面退出后无持续解码、显示刷新或无所有者下载。
- 采用 Three.js 时，内存、能耗与崩溃预算必须合并 App、WebContent 和 GPU 相关进程评估；不得只测主 App 进程。记录 bundle 对安装包、冷启动和首次 shader 编译的增量，阈值由对应执行计划在 POC 前批准。
- Three.js 运行时网络请求必须为零；人物、衣物、令牌、签名 URL、对象 key、GPU 标识和 JavaScript stack 不进入遥测。

### 服务端和产品指标

- 视频生成、抽帧、mask、打包和质量检查各阶段 p50/p95/p99。
- 有效帧数、重复帧率、mask 拒绝率、对齐拒绝率和质量降级率。
- 供应商成本、重试、取消和 DLQ 年龄。
- manifest/帧 4xx、hash 错误和客户端静态降级率。
- 动态预览主动触发率、完成后拖拽率、保存率和异常反馈率。
- 删除积压、视频临时资产超期数量和设备缓存清理失败。

只有动态预览进入受控 POC 或发布实施阶段后才引入这些观测；门禁关闭的本地核心路径不发送生成遥测。指标只含任务、模型、阶段、格式和性能，不含人物、衣物、URL、对象 key 或自由文本。

## 关键决策、替代方案与再评估触发器

### 2.5D 帧序列而非真实 3D

- 选择：生成短视频后抽取离散帧，通过拖拽浏览。
- 原因：能提供相近视觉体验，同时避免人体网格、服装建模、蒙皮和布料物理成本。
- 替代：单图 3D 重建或完整 Avatar SDK；无法证明真实服装背面与合身度，首版拒绝。
- 再评估：用户研究证明自由视点、AR 或长期角色具有独立价值，并且获取多视角人体和 3D 服装资产的成本、许可及隐私可接受时，另立 PRD。

### 服务端抽帧而非每台设备本地抽帧

- 选择：服务端统一抽帧、mask、对齐和打包。
- 原因：结果一致、可做质量门、减少手机重复计算和临时视频保留。
- 替代：iOS 使用 AVFoundation 本地抽帧；适合技术原型，不适合统一透明帧结果。
- 再评估：若端侧模型能在最低设备上稳定完成时序 mask，且隐私收益显著高于下载和算力成本，再评估端侧路径。

### 帧资源而非 MP4 精确 seek

- 选择：manifest + 36–48 帧。
- 原因：拖拽索引确定、无关键帧 seek 延迟、易做逐帧缓存和透明背景。
- 替代：普通 MP4 seek；在长 GOP 下响应和帧精度不稳定。
- 再评估：若全关键帧视频、硬件解码或带 alpha 编码在全部最低设备上达到相同延迟且显著降低存储和请求数，可替换传输格式，但保持 manifest 语义。

### 独立帧而非首版 Sprite Atlas

- 选择：先用独立帧建立简单可验证契约。
- 原因：可按需加载、单帧校验和独立降级。
- 替代：Sprite Atlas、KTX2 或带 alpha 视频；会增加打包和解码复杂度。
- 再评估：当请求开销或首屏时间达不到预算，且 atlas 在最低设备的内存和解码评测通过时再启用新 rendition。

### 可替换 renderer，而非预先锁死 Three.js

- 选择：SwiftUI/Observation 与 manifest 契约之下使用 `DynamicPreviewRenderer`；普通帧切换默认原生，只有空间合成效果确有价值且 POC 达标时选择 Three.js。
- 原因：Three.js 能表达相机、深度、shader 和 scene graph，但会增加 WebContent 进程、JS bridge、供应链与 GPU 生命周期成本。按效果选择 renderer 能保持核心流程简单，并保留静态关闭路径。
- 替代：所有动态效果固定 Three.js，或全部固定原生。前者会让普通动效承担不必要成本，后者会限制真正需要场景图的设计。
- 再评估：设计只需离散帧时回到原生；Three.js 在包体、冷启动、触摸延迟、总内存、能耗、热状态、无障碍、安全或恢复任一门槛失败时不得进入生产。未来真实 3D、WebGPU 或自由视点必须另立 PRD/design，不由本决策自动批准。

## 可执行测试与验收

### 服务端自动化

1. 状态机测试：合法转移可达，终态不可倒退，来源删除会中止所有未完成阶段。
2. 幂等测试：重复创建、重复队列和重复回调只生成一份 manifest 和一套用户可见帧。
3. 视频安全测试：伪 MIME、超大分辨率、异常时长、畸形容器和解码炸弹关闭失败。
4. 抽帧测试：不同帧率、可变帧率、旋转元数据和短视频均输出连续 36–48 个唯一 index，或明确拒绝。
5. Manifest contract test：schema、连续 index、尺寸、字节上限、hash 和缺帧场景全部验证。
6. 质量门测试：合成闪烁、跳位、额外人物、肢体缺失和衣物突变样本被阻断。
7. 回调安全测试：伪造签名、过期时间和重放全部拒绝。
8. 删除测试：来源静态图、Job、动态资产或账号删除后，视频、帧、poster、manifest、缓存索引和供应商副本均不可达。
9. 日志负向测试：含 URL、对象 key、提示词和人物描述的合成错误无法进入生产遥测。

### iOS 自动化与性能测试

1. 使用有效、缺帧、重复帧、超限、hash 错误和未知版本 manifest 夹具验证安全降级。
2. UI 测试覆盖拖动、方向锁、快速反向、离线、页面切换、删除和恢复。
3. Reduce Motion 开启时验证无自动播放、无惯性动画且上一/下一视图可操作。
4. VoiceOver 可执行上一视图、下一视图、回静态图和删除。
5. `XCTMetric`、内存和 hitch 测试达到本文件性能预算。
6. 内存警告和系统杀进程后不崩溃、不显示已删除缓存，并能从服务端状态恢复。
7. 低电量、弱网和磁盘不足时关闭失败，静态试穿始终存在。
8. 若选择 Three.js，验证 Release 只含锁版本地 bundle、无 sourcemap/生产 inspector/外联，bridge 对未知版本、超限和非法状态关闭失败，CSP 与 scheme handler 拒绝远程和越界资源。
9. 若选择 Three.js，注入 WebGL context lost、WebContent 终止、初始化超时、后台/前台和连续失败；最多重建一次，Swift 状态不丢失且始终先显示 poster。
10. 若选择 Three.js，在飞行模式、Reduce Motion、VoiceOver 和最低设备上统计 App + WebContent + GPU 总资源，并与原生 renderer 使用同一夹具做 go/no-go 对照。

### 人工验收

1. 至少 100 组授权静态试穿样本评估身份、衣物、肢体、时序一致性和错误背面。
2. 严重身份或衣物变化、额外人物、异常裸露和肢体伪影结果不得下发。
3. 测试人员不能从 UI 文案误认为结果是真实 3D、真实背面或尺码预测。
4. 在最低支持设备连续拖拽一分钟达到性能预算，无明显白帧和人物跳位。
5. 用户拒绝本次视频供应商处理后仍可完成静态试穿、选定和保存。
6. 删除动态预览后，前台、后台下载和重新启动 App 均无法恢复旧帧。

任一安全、删除、无障碍或表示真实性验收未通过时，该能力只能保留为内部实验开关。
