## MVP spec

本切片只实现登录用户的无图结构化衣物 CRUD。API 从 HttpOnly 会话确定 owner；请求体不含 owner。字段固定为客户端 UUID、名称、`top|bottom|one_piece|outerwear|shoes|bag|accessory`、`wearable|laundry|lent_out|packed`、`wardrobe|quick_add`、revision 和服务端时间。

接口：

| method/path | operationId | 合同 |
| --- | --- | --- |
| `POST /v1/wardrobe/items` | `createWardrobeItem` | 201；同 ID 同内容幂等，不同内容 409 |
| `GET /v1/wardrobe/items` | `listWardrobeItems` | `limit` 1～100，默认 50；可选 `after_id`；稳定排序并返回下一游标 |
| `GET /v1/wardrobe/items/{item_id}` | `getWardrobeItem` | owner 内读取；不存在或跨 owner 均 404 |
| `PUT /v1/wardrobe/items/{item_id}` | `updateWardrobeItem` | 完整替换名称/类别/状态；`expected_revision` 命中后 revision +1 |
| `DELETE /v1/wardrobe/items/{item_id}` | `deleteWardrobeItem` | query 提交 `expected_revision`；成功 204，过期 409 |

名称去首尾 Unicode 空白后 1～80 个字符并拒绝控制字符。来源创建后不可改。列表游标必须属于当前 owner，跨 owner 与不存在均 404。删除为当前无同步消费者阶段的硬删除；不提前加入墓碑、同步游标、合并策略、图片、对象存储、队列或缓存。账号删除通过 PostgreSQL 外键级联。

## 文件职责

- `internal/model/wardrobe.go`：纯领域值、枚举、输入和稳定错误。
- `internal/service/wardrobe.go`：认证 owner、规范化、枚举/revision/limit 校验和用例编排。
- `internal/repository/wardrobe.go`：GORM record、owner 查询、幂等创建、条件更新/删除和稳定分页。
- `internal/transport/wardrobe.go`：Huma operation、DTO、Cookie 与错误映射。
- `main.go`、`transport/router.go`、`repository/schema.go`：显式组装、路由和 AutoMigrate。
- 同包 `_test.go` 与 `tests/wardrobe_services_integration_test.go`：Red/Green、OpenAPI 和真实 PostgreSQL。

## SMART 与 checklist

- Specific：完成一个账号内最小衣物 CRUD，不扩大到同步引擎或媒体。
- Measurable：5 个 operation；单元/HTTP/OpenAPI 通过；真实 PostgreSQL 验证两个 owner、幂等、冲突、分页、级联。
- Achievable：复用账号认证、Gin/Huma、GORM 和现有测试隔离，无新增依赖。
- Relevant：为 App 登录后的衣橱数据能力提供首个可调用后端纵切，同时保留无账号离线核心。
- Time-bound：一个开发切片内完成代码、证据、提交与 CI；任何外部设备或供应商不进入完成条件。
