## Spec

- 关联：COMMUNITY-REQ-001/002/003、COMMUNITY-ACC-001/002/009/011，[Design 21](../design/21-后端产品边界与领域设计.md)、[Design 22](../design/22-后端数据库设计.md)、[Design 23](../design/23-后端接口设计.md)。
- `POST /diary-entries` 使用客户端 UUID；同账号同 ID、同规范化内容幂等返回，内容不同或命中删除墓碑返回 409。记录保留 `local_date` 与 IANA `time_zone`，允许补记当天及过去，拒绝未来日期。
- 标题最多 80 Unicode 字符，正文最多 5,000，心情和场合分别最多 40；trim 后空值保存为 NULL。正文或 ready 的日记图片至少一项；同一媒体不能重复，顺序即展示顺序，最多 9 张。
- 日记图片复用现有私有媒体上传/净化/删除链，新增 `purpose=diary_image`、`category=ordinary_image`；首片固定 JPEG、12 MiB、24 MP、单帧，worker 重编码清除 EXIF。普通日记图片不要求本人照片同意或成年声明；本人照片用途仍维持原门禁。
- 可选 `plan_id` 和 `wear_event_id` 必须属于当前账号；实际事件 `local_date` 必须与日记相同。当前尚无 Saved Look 实体，因此本片不接受悬空 `saved_look_id`。
- `GET /diary-entries` 按 `local_date DESC, created_at DESC, id DESC` 稳定分页，可选最多 366 日日期范围；`GET /diary-entries/{id}` 只读本人。
- `PUT /diary-entries/{id}` 完整替换可编辑字段与有序媒体，必须精确 `expected_revision`；冲突不覆盖服务端内容。`DELETE` 必须精确 revision，删除日记和关联行并写 tombstone，不删除计划、实际事件或仍由用户拥有的媒体。
- `GET /calendar?month=YYYY-MM` 按原本地日期分别返回每天的 `plan_count`、`wear_event_count`、`diary_count`；三类事实不互相转换。
- 删除实际事件时将日记的 `wear_event_id` 置 NULL 并保留文字/图片。删除计划时将 `plan_id` 置 NULL。账号删除级联日记、关联和墓碑。
- 运行时 OpenAPI 是唯一接口源，Umi 从真实 `/openapi.json` 生成；不增加物化 spec、脚本、搜索引擎、全文索引或通用 CRUD 框架。

| --- | --- |
| `internal/application/diary/model.go` | 日记、分页、日历值、稳定错误，不含框架 tag |

| `tests/services` / `tests/integration` | 真实 PG、MinIO/RabbitMQ 媒体准备、实际 binary、恢复与跨账号验收 |
