## MVP spec

新增 7 个 operation：计划 create/list/get/update/cancel/delete，以及衣物 deletion-impact；现有衣物 DELETE 增加用户选择的 `history_policy` 与 `expected_impact`。OpenAPI 升级为 API 0.10.0，共 31 个 operation。

| method/path | operationId | 合同 |
| --- | --- | --- |
| `POST /outfit-plans` | `createOutfitPlan` | 201；客户端 UUID，同内容幂等，不同内容/删除 tombstone 409 |
| `GET /outfit-plans` | `listOutfitPlans` | 1～50，稳定 `after_id`；可选 `local_date` |
| `GET /outfit-plans/{plan_id}` | `getOutfitPlan` | owner 内读取，跨 owner 统一 404 |
| `PUT /outfit-plans/{plan_id}` | `updateOutfitPlan` | active 计划完整替换；expected revision 命中后 +1 |
| `POST /outfit-plans/{plan_id}/cancel` | `cancelOutfitPlan` | active → cancelled，revision +1；不创建实际穿着 |
| `DELETE /outfit-plans/{plan_id}` | `deleteOutfitPlan` | 永久删除并写 tombstone；迟到 POST/PUT 不能复活 |
| `GET /wardrobe/items/{item_id}/deletion-impact` | `getWardrobeDeletionImpact` | 返回影响数量和 64 位不透明影响摘要 |

创建/更新包含 `local_date`、`time_zone`、nullable `context_summary`、1～20 个有序唯一 `{item_id, revision}` 和 `confirmed_unavailable_ids`。快照由服务端从 17-21 衣橱事实生成，响应中 redacted 项的 `content` 为 NULL。17-22 完成时衣物删除只覆盖计划；17-23 接入实际事件后，当前运行时合同已从 `delete_affected_plans` 根本替换为覆盖两类历史的 `delete_affected_history`，不保留兼容分支。

不实现 mutation receipt 表、增量同步游标、WearEvent、反馈、提醒、图片/MinIO、RabbitMQ 或 Redis 新用途。POST 幂等和 revision 后读取用于处理网络结果不确定，避免为未启用的同步系统预建协议。

## 文件职责

- `internal/application/outfitplan/model.go`：计划、快照、分页、删除影响与错误。
- `internal/application/outfitplan/outfit_plan.go`：认证 owner、日期/时区/摘要/选择校验与用例编排。
- `internal/adapter/postgres/outfit_plan.go`：GORM records、服务端快照、事务、tombstone、稳定分页。
- 现有 `wardrobe.go`：删除影响查询和两个历史策略的单事务处理。
- `internal/adapter/httpapi/outfit_plan.go`：Huma operation/DTO/错误映射；router/bootstrap 显式组装。
- 同包和 `tests`：Service/HTTP/OpenAPI、真实 PostgreSQL、实际二进制与账号级联。
