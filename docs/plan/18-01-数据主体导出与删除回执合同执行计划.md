# 数据主体导出与删除回执合同执行计划

## 状态与范围

- 对应 `BL-DATA-01`、`PRIVACY-REQ-005/006/008`、`PRIVACY-RULE-008/012～020` 与 `PRIVACY-ACC-005/006/007`；技术合同状态 `approved（仅本地合成数据开发）`，实现 `pending`。处理目的仅为用户主动请求查阅/取得自身数据及核对删除结果，不含生成、分享或分析。
- 当前用户要求先做后端；Web、App、正式送达和云生成功能不在本片实现。首版离线 Look 与本地衣橱/推荐/记录的数据不会自动上传到后端，也不能被服务端导出包声称覆盖。
- 用户已明确本轮为本地开发，不以法务/隐私签署阻断合成数据实现。[PRD 18](../prd/18-隐私与数据控制需求.md) 的目标市场、法定请求补充路径、正式保留与地域结论仍是处理真实用户和发布时的独立门禁。用户主动请求是导出的触发条件；已有云生成或分享同意不能代替导出请求，撤回外部处理同意也不能关闭导出与删除入口。

## 当前代码事实（2026-09-23）

`backend/internal/adapter/postgres/schema.go` 当前迁移 38 张表。可由现有 owner 关联的数据分组如下；开发阶段采用后述最小字段合同，未实现的云任务或未上传的本地数据不进入导出。

| 分组 | 当前来源 | 待确认边界 |
| --- | --- | --- |
| 账号与公开资料 | `users`、`user_profiles` | 邮箱、资料及账号状态；不包含密码散列、会话令牌或邮件挑战 |
| 衣橱与穿搭 | `wardrobe_items`、`outfit_plans/items`、`wear_events/items`、`wear_feedback` | 保留当前事实、历史快照、删除占位及原日期/时区；不把计划当实际穿着 |
| 私人日记 | `diary_entries/media` | 仅本人仍可访问的结构化记录与受控媒体；删除墓碑是否作为用户数据需批准 |
| 社区活动 | `posts/revisions`、本人互动与举报/申诉 | 公开版本和本人草稿分开；第三方个人信息、审核内部理由与通知字段需逐项审定 |
| 同意与媒体 | `self_adult_declarations`、`consent_records`、`media_assets/derivations`、`deletion_requests` | 同意/撤回和对象元数据可盘点；原图/衣物图、自有衍生图与对象 key/签名 URL 不可混同 |
| 删除回执 | `account_deletion_requests` | 现有状态仅 `pending/complete`，无账号删除后的公开查询凭据、分阶段结果或已批准的留存期 |

当前 `DELETE /users/me` 返回一次性 `202` 回执并立即撤销会话；删除请求与账号无 FK，物理删号后内部仍可更新到 `complete`。现有 `GET /deletion-requests/{id}` 是**单媒体**删除回执，不能代替账号删除查询。服务器尚无 `/exports` 实现、导出产物表或账号删除后的本人查询入口；云生成任务与完整 Look 也尚未落库。用户设备内未上传数据不属于服务端事实。

## 本地开发合同

1. **身份**：导出发起要求当前 active 会话并再次输入当前密码，失败沿用认证限流与通用错误；读取/撤销导出仍逐次校验同一 active owner。删除账户后不再使用会话：删号 `202` 一次返回随机回执凭据，数据库只存其摘要；独立查询用该凭据和请求 ID，裸 UUID 不授予读取权。
2. **范围**：`structured` 覆盖该账号当前可读取的账户/资料、衣橱、计划及衣物快照、实际穿着及反馈、私人日记、本人帖子/互动、同意与媒体/删除元数据。导出字段采用各领域现有**本人可见响应字段**的明确 allowlist，并在包内列出类别、计数、字段说明与排除原因；不复制内部 credential/session/challenge、对象 key、签名 URL、Outbox/Inbox、审核安全规则或第三方私人正文。`with_media` 仅增加该 owner 当前仍可访问的用户提供原图与普通衣物/日记图；当前尚无衣物图用途时清单写未启用，不补造媒体。云任务、Look 与设备未上传数据写未实现或仅本机。两个档位都不借主动 Look 分享入口替代。
3. **格式与生命周期**：服务端私有 ZIP 内为 UTF-8 JSON、`manifest.json`、schema 版本、UTC 绝对时间与原记录时区；媒体按固定安全文件名放入包，不输出对象 key。一次请求一个持久任务，状态 `preparing/ready/partial/failed/expired/revoked`；仅本人通过会话下载或撤销，失败/中断不改写原数据。合成开发环境的可取窗口为 24 小时，过期撤销读权并清理临时包；该数字不是生产保留承诺。
4. **删除回执**：当前 `pending/complete` 只代表已实现的自有系统删号闭环，不能声称备份或外部副本清理。开发阶段回执凭据最长保留 7 天、可撤销，查询只暴露请求 ID、申请/更新时间、当前阶段和媒体数；到期后无查询权。更细的外部/备份阶段必须有实际状态来源后才能增加。
5. **安全与失败**：导出过程中删号、撤销、账号切换、并发请求、对象删除失败时不得跨 owner 取数或留下可用链接；不在日志/公开 DTO 中输出媒体 key、签名 URL、凭据、供应商正文或内部安全规则。高敏感媒体若存储不可用，返回明确失败/部分可用与遗漏范围，不伪装完整。

实现复用现有 Huma 运行时 OpenAPI、GORM 事务、私有对象存储和账号鉴权，按 `BL-DATA-02/03` 拆最小切片；不得先造第二套 schema 或万能导出器。生产范围与期限待实际部署和负责人确认，当前代码仅处理本地合成数据。
