## 依据与决定

- [Go 官方模块布局](https://go.dev/doc/modules/layout)给出 server project 的 `cmd`/`internal` 组织；本项目当前只有一个真实交付程序，采用用户确认的 `cmd/then-server/main.go`，让进程入口稳定且可发现。
- [Go 官方测试教程](https://go.dev/doc/tutorial/add-a-test)与 [`testing`](https://pkg.go.dev/testing) 约定测试文件使用 `_test.go` 并与被测包同目录，由 `go test` 单独编译。包内单元/契约测试因此保留。
- 通过 GitHub、Firecrawl 与 Context7 交叉核对 Go 官方、Kubernetes、GitHub CLI、CockroachDB、Grafana、Uber、CloudWeGo 与 Kratos；研究与取舍固定在 [Design 24](../design/24-Go后端工程结构研究与规范.md)。
- 当前保持一个模块化单体，采用 `command → bootstrap → application/adapter`；模型、错误、规则、用例和消费端口按业务能力共同归属，删除全局 `domain` 大包。
- 真正需要修复的是 `backend/tests` 曾把本机依赖、实际进程和镜像测试放在同一个目录及 package。它们拆为独立 suite，根目录不再放 Go 文件。

## 目录合同

```text
backend/
├── cmd/then-server/main.go
├── internal/
│   ├── bootstrap/
│   ├── application/{account,privacy,wardrobe,outfitplan,wearevent,diary,community,media,eventworker}/
│   ├── adapter/{httpapi,postgres,objectstore,messagequeue}/
│   └── platform/
├── tests/
│   ├── services/       # -tags=services，本机真实依赖
│   ├── integration/    # -tags=integration，实际二进制与隔离容器
│   ├── container/      # -tags=container，已构建 OCI 镜像
│   └── internal/       # 测试 suite 共享夹具
└── architecture_test.go
```

不创建 `controller/dao/entity` 的 Java 式镜像目录，不增加空 `pkg`、`common`、第二个 module 或 test 微服务。`cmd/then-server/main.go` 对应当前真实 binary，不是占位目录。

## 验证合同

```sh
cd backend
gofmt -l .
go mod verify
go vet ./...
go build -trimpath ./cmd/then-server
go test ./... -count=1
go test -race ./... -count=1
go test -race -tags=services ./tests/... -count=1
go test -race -tags=integration ./tests/... -count=1
go test -run '^$' -tags=container ./tests/... -count=1
```

只有显式构建本地镜像并设置 `THEN_BACKEND_TEST_IMAGE` 后，container 运行验收才记为通过。目录调整不改变 API、数据库 schema 或用户数据。旧 `cmd/main.go` 与 `internal/domain` 不保留 alias。
