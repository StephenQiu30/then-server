## 交付旅程

用户选人物/衣物 → 查看用途与费用并确认 → 提交图片任务 → 离开并恢复 → 核对和保存完整图 → 主动生成立体 → 等待仍可使用图片 → GLB ready 后旋转 → 再次查看命中缓存 → 改衣物形成新图版本 → 删除及迟到结果清理。只需图片的用户可在图片阶段结束，并主动保存/系统分享图片。

## 输入与功能边界

- 人物来自有权处理的内置虚构成人参考或经 11-01 准备的本人照片；真实本人入口需原生产照片门禁，不能借合成测试开放。
- 图片本地 POC 默认使用确定性的 `fixture` Provider；视觉质量验证只允许调用登记过的本地图片服务，最多四参考：一个人物加至多三件支持类别衣物。超过范围明确说明，不静默删项或自动变成多轮付费生成。
- 模型只从用户已确认的图生成，固定走本地 `img2threejs` → Three.js/材质烘焙 → 静态 GLB 导出与校验；无骨架、眼部、parts、retarget 和视频调用。核心工具若只产生代码工厂而不能导出带纹理 GLB，则该样本只能记录为模型 POC 不通过，不能用云 Provider 补齐。
- 本地 Codex CLI 只可作为受控开发编排器，不能直接充当图片 Provider；没有可返回图片字节的本地服务合同时，图片路线停在 fixture。
- Provider 终端服务许可、可用地域、保留/删除、价格/账号额度待核实；获准的合成素材 POC 与真实用户上线分开，不用免费网页体验替代 API 生产资格。

### 本地低成本 POC 路线（2026-09-24）

- 只运行现有 `then-server`，复用现有开发 PostgreSQL、Kafka 和 MinIO；不创建第二套数据库、第二个 Go module 或新的服务入口。
- image：`fixture` 用于单元/集成测试；可选 `local-image` 适配器只接收本地服务返回的图片字节或受控本地文件，不允许公共 URL、未定义的 Codex 工具调用或云端回退。
- model：worker 在临时目录调用固定版本 `img2threejs`，保存输入 hash、工具版本、spec/factory hash、GLB hash、纹理/面数/字节预算和校验结果；任务完成前不发布资产。
- local POC 的供应商费用为 0；仍记录本机计算时间、失败和资源限制。Codex 使用远程模型账户、托管 img2threejs 转换器或远端 GLB 插件时，按实际账户/额度重新计费并重新走准入。
- 本轮仅把已验证图片输出作为模型任务来源，并用内嵌小纹理的合成 GLB 补齐 `fixture` 的模型任务提交、观察、校验和私有发布链路；此 GLB 不是 `img2threejs` 的生成结果，不计入模型 POC、衣物保真或设备验收。模型接纳限定 local fixture 的固定 provider/model，维持零外部调用。
- 真实 Provider/本地图片服务合同和代表资产仍未获批；因此不创建 Provider adapter、不发起外部回调，也不开放真实素材。当前 DATA-01/WORKER-01 已先落地 Provider 无关的 GORM 任务、租约、提交状态和结算记录，本地 PG/HTTP 链路已验证；外部 worker 仍需 Provider 准入及真实集成验收。

### 当前统一配置与费用边界（2026-09-24）

`backend/internal/platform/config` 是生成相关运行配置的唯一解析入口。默认 `GENERATION_MODE=off`、`GENERATION_ENABLED=false`、`GENERATION_PROVIDER_CALLS_ENABLED=false`，本地开发、单元测试和 CI 不会向第三方图片/模型服务发起请求，也不会产生供应商生成费用。`GENERATION_MODE=local` 只允许 fixture 或回环 `GENERATION_LOCAL_IMAGE_ENDPOINT`，货币/外部预算必须为零；`remote` 仍是有门禁的后续意图。预算、配额、并发、最大提交次数、Provider 单次超时、任务时限和结果保留期集中由 `GENERATION_*` 配置读取；缺少启用所需的边界值时启动失败关闭。`GENERATION_TASK_TIMEOUT`（1 分钟至 24 小时）从 `created_at` 起计时，本地 fixture 到期后经对象盘点与事务复核结算为 `expired`，释放预留额度并登记清理目标；有效租约内的有界阶段结束后再结算。`GENERATION_PROVIDER_TIMEOUT` 是单次外部阶段的总等待预算，查询、取消与复查共用截止时间；租约至少多 30 秒，运行时取该预算加 1 分钟。`GENERATION_RETENTION` 是成功结果从 `published_at` 起的最长可读时间：到期后不再签发读取 URL、确认图片或以图建模；既有清理链按精确版本删除，成功任务与已消费额度保留原事实。签名 URL 的有效期不能越过该时间点；真实 Provider 超时和供应商副本保留仍需另行验收。

当前把 `GENERATION_PROVIDER_CALLS_ENABLED=true` 作为显式高风险动作，并在供应商准入、代表素材 POC、真实 worker 和删除合同完成前拒绝启动。未来通过门禁后，该开关可能触发按供应商账户计费的请求；`GENERATION_MAX_BUDGET_MINOR_UNITS` 是产品侧预算上限，不等于供应商免费或最终账单承诺。163 邮件只有完整 163 配置且实际调用账号验证/找回接口才会发送，本切片的配置测试不发邮件；网易账号是否存在套餐或配额费用需按实际账号条款确认。

## 数据与 API 合同

统一 `GENERATION_TASK_TIMEOUT` 从接纳起计时：逾期不领取/续租、开始提交或发布成功；迟到受理身份和对象版本保留供清理。

Go 侧实现两种任务用途 image/model、Look/revision 与媒体引用、输入快照、owner、Provider/model/参数、外部任务 ID、同意收据、费用/额度及删除状态。客户端不提交 owner，不以签名 URL 作为业务 ID。任务身份、mutation 幂等和模型内容去重分别定义，后者按 owner+Look/revision+image hash+模型参数。

提交任务返回 202 和可查询 ID，认证/输入/同意/配额不合格明确拒绝；查询只见本人任务；取消和删除各自幂等。具体 operation、字段和错误码在同一 Huma 类型定义中实现，运行 `/openapi.json` 后生成实际 Client；此计划不新建另一份接口文件或空服务层。App 只接所需认证、上传、任务和媒体 API，完整跨设备衣橱同步不作为本片前置。

每个任务输出绑定唯一私有对象 key：`owners/{owner_id}/generation/{task_id}/output.jpg` 或 `output.glb`。ResultFetcher 只能写入并返回与当前任务 owner/task/purpose 一致的 key 和 MinIO version；PostgreSQL 内部保存该引用，API 不返回 key。输出元数据按既有资产预算 fail-closed：JPEG ≤12 MiB，GLB ≤10 MiB；领域模型和 PostgreSQL CHECK 同时拒绝超限记录。ResultWorker 按固定 key+version 读取实际字节并复核大小、SHA-256：JPEG 必须净化且完整解码，像素 ≤24 MP；GLB v2 限单内嵌 BIN 与纹理，无外部 URI、required extension、动画、skin 或 morph，验证 buffer/accessor 边界、有限位置和纹理引用，单纹理最长边 ≤2048、累计解码像素 ≤24 MP、总三角形 ≤50,000。本地静态 profile 不替代完整 Khronos 验证或模型质量验收。任务/源/账号删除先把 key+version 固定进清理 manifest，再允许移除输出元数据。历史记录没有可验证 key 时保留空引用并阻止物理清理完成，不猜测或拼接旧路径。

输出读取由后端根据会话 owner、任务 `succeeded` 状态、未撤权状态与已验证输出记录签发短时凭据；凭据只能指向 PostgreSQL 固定的 MinIO key+version。客户端不提供对象 key/version。删除后不再签发；读取凭据 TTL 上限为 5 分钟。

提交结果为 `unknown` 时增加最小管理员对账入口：管理员分页读取待核对任务，不返回用户输入快照、参数或账号资料；每次核对带任务 `status_revision`、受理结果、证据类型和不含凭据的证据编号，并与状态变更在同一 PostgreSQL 事务留下操作者审计记录。确认已受理必须提供外部任务 ID，附加 identity 后沿用现有取消/清理流程；确认未受理时终结为 `failed/submission_not_accepted`，若任务已取消或撤销则结算为 `canceled`，同时释放用户预留额度。冲突 revision、仍有效的 worker lease、非 admin 操作者和不符合任务状态的决定均拒绝。该操作不自动重新提交，也不查询 Provider；新的用户尝试必须是新的明确接纳请求。

PostgreSQL 事务写任务、额度占用和 Outbox；Kafka 唤醒现有 Go worker。外部调用在事务外，租约与 fencing 防并发。获取 external task ID 后持久化并查询；提交超时是否已接纳未知时先对账，若供应商不能可靠查询/幂等，则暂停自动重提并显示可处理状态。

结果收取限制来源、重定向、大小和时限，图片净化/GLB 校验后落私有 MinIO；随后事务发布媒体和任务。旧 Look revision、已撤回同意或删除状态拒绝发布；失败留下可清理追踪，不复活。用户配额结算与供应商实际费用分开，不能承诺取消退款。

## App 与输出

SwiftUI 管理选衣草稿、真实任务阶段、取消/失败/重试，GRDB 保存必要任务引用与 Look 版本。前台退避轮询，后台由持久任务继续处理；返回页面恢复，不需要推送或 WebSocket。已确认图可独立保存，GLB 下载失败回图，命中缓存不创建新任务。

图片写入相册仅在用户点击时申请 Add Only；系统分享使用临时净化副本并清理 App 可控副本，不添加公开 URL。检查资产/人物/衣物的输出权利，告知外部副本不能由 App 远程撤回。下载/分享不生成 WearEvent 或偏好，社区发帖仍独立。

## 必测失败与退出

重复点击/重投只得到一个有效任务；Provider 已接纳但响应丢失不盲重提；图片失败不丢草稿；模型失败保留图；A 版本任务晚到不覆盖 B；删除后迟到结果不发布；对象写入成功但数据库失败可回收；worker/队列中断可恢复；跨账号素材/任务/签名读取被拒绝；配额耗尽不新建外部任务。

实际集成的技术通过、模型质量通过、供应商账单通过和生产许可分别记录。代表性小样本不替代真实人群质量；本片未通过不阻断原范围中已合格的离线Look或真实衣橱。原Design20报价仅保留历史追溯，当前个人候选价格统一引用 [Design29](../design/29-Woo虚拟人偶与自用成本决策.md#4-api-选择先把接入与现金成本一起算)，不能用新报价推断原任务已验收。

## 文件职责与输入输出

以下路径相对 `then-server`，iOS 行明确标出 `then-app`。拟新增项只在对应步骤实际开发时创建；文件名沿当前 `*_contract.go / *_routes.go / *_handlers.go`，不建立空 provider 平台或第二套服务入口。

| 位置 | 输入 → 输出 / 所有权 | 副作用和失败责任 |
| --- | --- | --- |
| `backend/internal/application/generation` | owner、输入快照、用途/同意、额度、命令 → Look 版本与任务状态；已实现 Provider 无关领域合同和任务应用服务 | 应用用例控制合法转换和去重，拒绝无效状态；不包含 HTTP、GORM 或供应商 SDK 类型；现有 worker 执行本地 fixture 链路 |
| `backend/internal/adapter/postgres/generation.go`、`generation_worker.go` | 合法接纳/查询/取消命令、worker 租约命令 → 事务结果与 Outbox 待办 | GORM 记录/唯一约束、任务+额度+Outbox 原子提交；状态 revision、owner 隔离和租约 fencing 条件写入，Provider 不在事务内调用 |
| `backend/internal/adapter/httpapi/generation_contract.go`、`generation_routes.go`、`generation_handlers.go` | 当前会话+实际 API 请求 → 202/查询/取消及稳定错误 | Huma 唯一 schema；owner 取会话，非法请求不接纳；日志只记脱敏关联 ID |
| `backend/internal/adapter` 下供应商语义包（拟新增） | 已批准输入句柄/参数 → 外部受理 ID、查询事实、临时输出 | 唯一外部调用位置；默认关闭可能计费 POST 的盲重试；超时/未知受理必须可区分；供应商密钥只在服务端 |
| 现有媒体应用、`adapter/objectstore` 与 generation worker | 输出流/血缘 → 私有固定版本资产、清理结果 | 来源/重定向/解码与字节限制，校验后发布；先写对象后事务失败保留回收依据，盘点后的迟到对象仍需长期对账；不得直接交付供应商临时 URL |
| `backend/internal/adapter/messagequeue/kafka.go`、`backend/internal/bootstrap/application.go` | 已提交 Outbox / 运行配置 → 唤醒实际 worker、关闭和恢复 | 复用现有进程角色；短消息仅携带 ID。长时间外部等待不占数据库事务、不长时间阻塞单条 Kafka 消费；持久任务定时对账保证重启后继续 |
| `then-app/ThenApp/Features/Avatar`、实际 Cloud Client、`Data/Avatar` | 用户选择/会话/服务端事实 → 可恢复草稿、任务/版本和页面 | 网络与存储在 Repository/adapter，View 只发命令；账号隔离；轮询生命周期与后台实际任务分开 |
| `then-app/ThenApp/Services/Photos` 与实际图片输出 adapter | 有权输出的已确认图 → 系统相册/分享临时副本 | 单次净化、按需权限；失败/取消清理 App 可控副本，不扩大照片库读取权限 |

具体 API operation/record 字段在 DATA-01 实现，本文不手写 OpenAPI 文件；能力开关、并发/额度/货币预算、最大尝试数、外部时限和保留期必须有真实配置、边界测试及上线前确定值。缺预算配置按关闭处理。

## 必测故障矩阵

| 故障注入点 | 必须观察到的结果 | 主要证据 |
| --- | --- | --- |
| 接纳事务前后终止，客户端重复提交 | 未提交不占额；已提交返回同 job；无第二 Outbox 意图 | PG 事务/唯一约束、HTTP 与 App 恢复 |
| Provider 已受理但响应丢失 / ID 未落库 | 持久不确定状态，供应商幂等/对账找回；无可靠恢复则人工核对，不自动新提交 | 实际 POST 次数、受理 ID 与账单；不能用只读 poll 次数代替 |
| 两 worker/重投/租约过期 | 过期执行者不能发布；同一任务无重复结算，新的执行者只恢复现有外部工作 | Kafka+PG 故障注入和 fencing 断言 |
| 外部输出过期、重定向越界、坏图/GLB、写库失败 | 不发布不合格资源；安全地址/解码失败分类；已写孤儿有清理追踪 | 受控输出服务、MinIO 固定版本清单和日志 |
| A 生成时编辑 B，或撤回同意/删源/删号 | A 不成为当前 B；删除后的产物只清理；账号访问先失效 | revision/owner 对照、UI、私有媒体拒绝与清理回执 |
| 429、额度竞争、成本上限、关闭入口 | 退避不刷请求；总占用不超上限；停止新提交，已接纳任务继续对账/清理 | 配额台账、外部计费次数、关闭恢复演练 |
| App 无网/被杀/切账号、坏缓存、相册拒绝 | 同账号恢复，其他账号不见前人内容；同版本取回不重新付费；图片仍可用 | 真机/模拟器旅程、网络事件与 GRDB 差分 |

### 验证与回退操作

在 `backend` 运行 `go vet ./...`、`go test -race ./... -count=1` 与受影响真实依赖/进程测试（`-tags=services`、`-tags=integration`）；测试复用隔离 PG/Kafka/MinIO 与唯一前缀，不清空共享库/队列。运行当前入口 `go run .` 读取实际 `/openapi.json`，在 `frontend` 以 `THEN_OPENAPI_SCHEMA=<本次实际地址> npm run openapi` 后做类型/测试校验；App Client 遵循 17-30 的生成决定，相关 iOS build/test 与真机结果单独记录。

故障矩阵先用替身完成，再在 GATE 已通过和预算内做少量受控真实调用，计费记录脱敏入证据。回退关闭 image/model 新任务接纳，不删 PG 任务、Outbox、额度账或清理回执；worker 保留查询/清理能力，用户保留已确认图和本地记录。未经许可不得在回退中改换供应商、地域或重建计费任务。验证结果见 Acceptance 17。
