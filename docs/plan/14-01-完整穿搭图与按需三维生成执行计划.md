## 输入与功能边界

- 人物来自有权处理的内置虚构成人参考或经 11-01 准备的本人照片；真实本人入口需原生产照片门禁，不能借合成测试开放。
- 图片本地 POC 默认使用确定性的 `fixture` Provider；视觉质量验证只允许调用登记过的本地图片服务，最多四参考：一个人物加至多三件支持类别衣物。超过范围明确说明，不静默删项或自动变成多轮付费生成。
- 模型只从用户已确认的图生成，固定走本地 `img2threejs` → Three.js/材质烘焙 → 静态 GLB 导出与校验；无骨架、眼部、parts、retarget 和视频调用。核心工具若只产生代码工厂而不能导出带纹理 GLB，则该样本只能记录为模型 POC 不通过，不能用云 Provider 补齐。
- 本地 Codex CLI 只可作为受控开发编排器，不能直接充当图片 Provider；没有可返回图片字节的本地服务合同时，图片路线停在 fixture。
- Provider 终端服务许可、可用地域、保留/删除、价格/账号额度待核实；获准的合成素材 POC 与真实用户上线分开，不用免费网页体验替代 API 生产资格。

### 本地低成本 POC 路线（2026-09-24）

- 只运行现有 `then-server`，复用现有开发 PostgreSQL、Kafka 和 MinIO；不创建第二套数据库、第二个 Go module 或新的服务入口。
- image：`fixture` 用于单元/集成测试；可选 `local-image` 适配器只接收本地服务返回的图片字节或受控本地文件，不允许公共 URL、未定义的 Codex 工具调用或云端回退。
- model：worker 在临时目录调用固定版本 `img2threejs`，保存输入 hash、工具版本、spec/factory hash、GLB hash、纹理/面数/字节预算和校验结果；任务完成前不发布资产。
- local POC 的供应商费用为 0；仍记录本机计算时间、失败和资源限制。Codex 使用远程模型账户、托管 img2threejs 转换器或远端 GLB 插件时，按实际账户/额度重新计费并重新走准入。
- 真实 Provider/本地图片服务合同和代表资产仍未获批；因此不创建 Provider adapter、不发起外部回调，也不开放真实素材。当前 DATA-01/WORKER-01 已先落地 Provider 无关的 GORM 任务、租约、提交状态和结算记录，后续仍需真实 PG/HTTP 验收及 Provider 准入后才能执行外部 worker。

## 数据与 API 合同

Go 侧实现两种任务用途 image/model、Look/revision 与媒体引用、输入快照、owner、Provider/model/参数、外部任务 ID、同意收据、费用/额度及删除状态。客户端不提交 owner，不以签名 URL 作为业务 ID。任务身份、mutation 幂等和模型内容去重分别定义，后者按 owner+Look/revision+image hash+模型参数。

提交任务返回 202 和可查询 ID，认证/输入/同意/配额不合格明确拒绝；查询只见本人任务；取消和删除各自幂等。具体 operation、字段和错误码在同一 Huma 类型定义中实现，运行 `/openapi.json` 后生成实际 Client；此计划不新建另一份接口文件或空服务层。App 只接所需认证、上传、任务和媒体 API，完整跨设备衣橱同步不作为本片前置。

每个任务输出绑定唯一私有对象 key：`owners/{owner_id}/generation/{task_id}/output.jpg` 或 `output.glb`。ResultFetcher 只能写入并返回与当前任务 owner/task/purpose 一致的 key 和 MinIO version；PostgreSQL 内部保存该引用，API 不返回 key。输出元数据按既有资产预算 fail-closed：JPEG ≤12 MiB，GLB ≤10 MiB；领域模型和 PostgreSQL CHECK 同时拒绝超限记录。实际字节解码、JPEG 净化、GLB 容器/纹理/三角形校验仍由输出收取 slice 完成，不能由元数据预算测试代替。任务/源/账号删除先把 key+version 固定进清理 manifest，再允许移除输出元数据。历史记录没有可验证 key 时保留空引用并阻止物理清理完成，不猜测或拼接旧路径。

输出读取由后端根据会话 owner、任务 `succeeded` 状态、未撤权状态与已验证输出记录签发短时凭据；凭据只能指向 PostgreSQL 固定的 MinIO key+version。客户端不提供对象 key/version。删除后不再签发；读取凭据 TTL 上限为 5 分钟。

提交结果为 `unknown` 时增加最小管理员对账入口：管理员分页读取待核对任务，不返回用户输入快照、参数或账号资料；每次核对带任务 `status_revision`、受理结果、证据类型和不含凭据的证据编号，并与状态变更在同一 PostgreSQL 事务留下操作者审计记录。确认已受理必须提供外部任务 ID，附加 identity 后沿用现有取消/清理流程；确认未受理时终结为 `failed/submission_not_accepted`，若任务已取消或撤销则结算为 `canceled`，同时释放用户预留额度。冲突 revision、仍有效的 worker lease、非 admin 操作者和不符合任务状态的决定均拒绝。该操作不自动重新提交，也不查询 Provider；新的用户尝试必须是新的明确接纳请求。

PostgreSQL 事务写任务、额度占用和 Outbox；Kafka 唤醒现有 Go worker。外部调用在事务外，租约与 fencing 防并发。获取 external task ID 后持久化并查询；提交超时是否已接纳未知时先对账，若供应商不能可靠查询/幂等，则暂停自动重提并显示可处理状态。

结果收取限制来源、重定向、大小和时限，图片净化/GLB 校验后落私有 MinIO；随后事务发布媒体和任务。旧 Look revision、已撤回同意或删除状态拒绝发布；失败留下可清理追踪，不复活。用户配额结算与供应商实际费用分开，不能承诺取消退款。

## App 与输出

SwiftUI 管理选衣草稿、真实任务阶段、取消/失败/重试，GRDB 保存必要任务引用与 Look 版本。前台退避轮询，后台由持久任务继续处理；返回页面恢复，不需要推送或 WebSocket。已确认图可独立保存，GLB 下载失败回图，命中缓存不创建新任务。

图片写入相册仅在用户点击时申请 Add Only；系统分享使用临时净化副本并清理 App 可控副本，不添加公开 URL。检查资产/人物/衣物的输出权利，告知外部副本不能由 App 远程撤回。下载/分享不生成 WearEvent 或偏好，社区发帖仍独立。

## 必测失败与退出

重复点击/重投只得到一个有效任务；Provider 已接纳但响应丢失不盲重提；图片失败不丢草稿；模型失败保留图；A 版本任务晚到不覆盖 B；删除后迟到结果不发布；对象写入成功但数据库失败可回收；worker/队列中断可恢复；跨账号素材/任务/签名读取被拒绝；配额耗尽不新建外部任务。

实际集成的技术通过、模型质量通过、供应商账单通过和生产许可分别记录。代表性小样本不替代真实人群质量；本片未通过不阻断已合格的离线 Look 或真实衣橱。详细价格只引用 Design 20，避免多处金额漂移。
