## 用户与状态合同

1. 从现有真实衣物中选 1～20 件，顺序确定、ID 不重复；允许部分组合，不补造其他单品。名称/类别/当前状态可见，无照片也可选择。
2. 新建默认今天，可选今天或未来公历日期；日期字符串 YYYY-MM-DD 与创建时 IANA 时区分开保存。日期不是 UTC 时间戳。空场景允许，摘要最多 120 字，无精确位置输入或 EventKit 权限。
3. 任一当前衣物不是 wearable 时，展示差异并要求明确确认。保存事务核对每件 ID/revision 与用户刚看到的版本，不因未来日期放宽并发检查；衣物删除、改名或状态变化都使旧提交拒绝并保留草稿。
4. 保存写入 active 计划与有序快照。查看、保存、取消、过期、照片操作均不创建实际穿着。一个日期允许多个不同计划，绝不因同日自动合并。
5. 编辑保留计划 UUID，以 expectedRevision 乐观并发。既有快照不会因后台衣物变化自动重写；编辑时显示当前差异并重新确认。删除占位不能当作可选择衣物，需要用户移除或替换后保存。
6. 取消计划为 cancelled，保留可查看内容；本片不提供“恢复取消”隐式状态转换，用户可编辑 active 计划或新建计划。永久删除须独立确认，清除计划、条目及相关敏感收据内容。
7. 草稿为会话内存数据；点取消/退出明确放弃未保存内容，保存失败保留内容可重试。页面拥有可取消的 Task，迟到读不覆盖当前草稿；提交完成以存储事实为准，重启重读而不回滚已提交数据。
8. 更改设备时区后日期分组不变；详情显示原始时区。过去 active 计划保持历史，不自动转换 completed/notWorn。修改过去计划保留原日期，若主动改日期只能选今天以后。

## 数据与一致性合同

- 新增 `ootd_v4_outfit_plans`；继续同一个 OOTD SQLite DatabasePool/WAL，不创建第二库、BLOB、全局服务容器或云同步层。
- `outfit_plans`：UUID id，localDate，timeZone，nullable contextSummary，sourceKind=manual，status=active/cancelled，revision，createdAt/updatedAt UTC；日期+创建顺序+ID 稳定索引。
- `outfit_plan_items`：planID FK cascade、ordinal（同计划唯一）、nullable wardrobeItemID、itemRevision、name/category/availability 快照、nullable photoAssetID；redacted 状态下所有原属性和关联均 NULL，只保留顺序与通用占位。禁止名称/属性藏入 JSON 或额外缓存。
- snapshot 值只由同一保存事务读取当前 wardrobe_items/ready photo 构建，客户端不得声明可信快照。未来未知字段不预建。
- 变更有全局 UUID mutationID 与目标 planID；重复相同命令不新增记录或 revision；同 ID 不同目标/内容返回冲突。收据不存原始衣物属性；计划彻底删除后去除其敏感摘要/指纹，仅保留防迟到创建复活的不透明删除标记。
- 永久删除计划不删除用户衣橱中的衣物或原照片。照片移除/替换后计划只能无图或使用同一有效资产 ID，不能静默换成新图片。
- 彻底删除衣物支持明确 policy：redactSnapshots 或 deleteAffectedPlans。Repository 先查询影响数，UI 确认后提交；事务再次核对衣物 revision 和受影响计划集合版本，影响变化要求重新确认。照片删除意图、历史处理和衣物删除必须一并提交，媒体字节按现有可重试清理。
- 读取无效日期/时区/枚举/快照结构显示安全存储错误，不自动修正或清库。通过纯领域类型验证输入，View/VM 不依赖 GRDB。
