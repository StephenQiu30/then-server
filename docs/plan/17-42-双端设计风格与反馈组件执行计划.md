# 双端设计风格与反馈组件执行计划

## 状态与范围

2026-09-24 用户要求按提供的 `vercel-DESIGN.md` 替换当前视觉风格，并明确覆盖 `then-server` Web 与 `then-app` iOS。设计目标写入两仓库字节一致的 `DESIGN.md`；实现范围为现有可见页面与共享组件，保留既有业务、隐私、导航和数据合同。视觉参考中的 Vercel 品牌内容与营销示例不进入产品。

## 实施合同

1. Web 以现有 shadcn radix-nova 配置为基础，将黑白画布、Geist、细边框、轻阴影、圆角和响应式排版归入语义 token 与共享组件。首页可有大面积氛围渐变，业务页只使用中性表面。
2. Web 的短暂完成反馈统一 Sonner；字段/页面错误、危险确认、重复记录确认和删除回执维持可持续读取的原位语义。跨 URL 业务导航保留链接；未来同页互斥面板才接入 Radix/shadcn Tabs。
3. iOS 使用 SwiftUI 共享色彩映射和系统 Dynamic Type 字体；主舞台、衣橱、计划、实际记录与内部照片 POC 的自有表面适配新风格，推荐页继承根级 tint，同时保留 VoiceOver、数据保护和系统控件语义。
4. 两仓库 DESIGN 字节一致；PROJECT、前端工程规范和本计划/验收状态反映实际实现。当前任务不增加云 API、媒体生成、付费操作或发布入口。

## 验收出口

同一保存成功只出现一次可读反馈；失败可就地恢复，删除回执不因 toast 超时而消失。Web 业务导航保持实际 URL，页面无伪 Tabs。两端主要表面使用共同语义层级，无旧蓝色主按钮和旧 SF 专用设计配置；无新假数据或越权读取。可访问性与响应式证据分别记录，真实设备和生产仍按发布验收执行。
