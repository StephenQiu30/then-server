# 多设备会话管理后端执行计划

## 状态与范围

- 对应 `BL-ACCOUNT-06` / `ACCOUNT-REQ-012` / `COMMUNITY-REQ-014`；本地合成账号开发合同 `approved`，后端实施 `completed`。只修改 `backend/` 与关联 Design、PRD、Acceptance；客户端入口和生产告警另验。
- 复用七天 Cookie 会话及 PostgreSQL `user_sessions`。不新增设备指纹、IP 历史、安全事件表或通知服务；成功撤销的 HTTP 结果是客户端后续提示的事实源。

## MVP 合同

1. `GET /users/me/sessions?limit=50&offset=0` 只返回本人未过期会话，按 `created_at DESC,id DESC` 排序。`limit` 为 1～100，`offset` 为 0～10000；响应 `{items:[{id,created_at,expires_at,current}],next_offset}`，末页 `next_offset=null`。当前标记由请求 Cookie 的散列在数据库比较，不暴露令牌、散列、IP 或猜测设备名称。成功响应 `no-store`。
2. `DELETE /users/me/sessions/{session_id}` 用当前有效 Cookie 撤销指定 UUID；数据库同一条件删除再次确认当前会话有效、目标归属本人，返回 204。其他人的、过期或不存在的 ID 同为 404；无效当前 Cookie 为 401 且清 Cookie；撤销当前会话同时清 Cookie。重复撤销返回 404，不伪称成功。
3. 成功的 `GET`/`DELETE` 响应不缓存；仅在服务端确认删除后客户端才可显示安全事件成功提示。客户端、本地之外的真实部署、审计/告警运营在后续切片验收。
