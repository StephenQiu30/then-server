## MVP spec

新增 7 个 operation：实际穿着 create/list/get/update/delete，以及计划 not-worn/restore。OpenAPI 升级为 API 0.11.0，共 38 个 operation。

| method/path | operationId | 合同 |
| --- | --- | --- |
| `POST /wear-events` | `createWearEvent` | 客户端 UUID；同内容幂等，不同内容或 tombstone 409 |
| `GET /wear-events` | `listWearEvents` | 1～50，稳定 `after_id`；可选 `local_date` |
| `GET /wear-events/{wear_event_id}` | `getWearEvent` | owner 内读取，跨 owner 统一 404 |
| `PUT /wear-events/{wear_event_id}` | `updateWearEvent` | expected revision 完整纠正，时区不可换 |
| `DELETE /wear-events/{wear_event_id}` | `deleteWearEvent` | 永久删除并写 tombstone；重算关联计划状态 |
| `POST /outfit-plans/{plan_id}/not-worn` | `markOutfitPlanNotWorn` | active 且无有效实际事件时转 not_worn |
| `POST /outfit-plans/{plan_id}/restore` | `restoreOutfitPlan` | not_worn 且无有效实际事件时恢复 active |

创建/纠正包含过去或今天的本地日期、原 IANA 时区、partial/complete、nullable 场景、1～20 个有序唯一衣物 ID/revision、逐件不可用确认、逐件待洗确认、可空来源计划与来源类型。服务端在同一 PostgreSQL 事务中读取账号衣橱并生成名称、类别、状态和四项确认属性快照；客户端不能提交快照正文。创建时保存完整规范化命令的私有 SHA-256 指纹，衣物顺序、待洗/不可用选择、来源和重复确认全部纳入同 UUID 幂等判定，指纹不进入响应或 OpenAPI。

同日其他事件与本次衣物集合的 Jaccard 相似度达到 0.8 时返回 409 和当前 `{id, revision}` 候选；请求必须原样确认完整候选集合，候选变化则再次冲突。保存实际事件、计划 `active↔completed` 和用户明确选择的 `laundry` 状态为一个事务；删除最后一条关联事件后计划回到 active。取消或 not_worn 计划不能关联实际事件。

衣物删除影响摘要同时覆盖计划和实际事件 revision。`redact_snapshots` 清空两类历史中的衣物正文并提升各自 revision；准确合同统一为 `delete_affected_history`，永久删除所有受影响计划和事件并分别写 tombstone。当前无历史数据，不保留原 `delete_affected_plans` 字符串兼容分支。

不实现 OutfitFeedback、推荐学习、穿着次数聚合端点、混合时间线、增量同步游标、App Client、RabbitMQ 或 Redis 新用途。创建幂等、revision 后读取和 tombstone 足以处理本片网络结果不确定，不预建 mutation receipt 框架。

## 文件职责

- `internal/application/wearevent/model.go`：实际穿着、来源、完整度、重复候选与领域错误。
- `internal/application/wearevent/wear_event.go`：认证 owner、日期/时区/集合/来源校验和用例编排。
- `internal/adapter/postgres/wear_event.go`：GORM records、快照、重复检查、事务、计划重算和 tombstone。
- 现有 outfit/wardrobe：四态计划操作与覆盖两类历史的删除影响。
- `internal/adapter/httpapi/wear_event.go`：Huma operation、DTO、重复候选和错误映射；router/bootstrap 显式组装。
- 同包和 `tests`：Service/HTTP/OpenAPI、真实 PostgreSQL、实际二进制与账号级联。
