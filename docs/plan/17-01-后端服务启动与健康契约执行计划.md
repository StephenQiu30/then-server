## 目标与非目标

交付一个能真实启动、连接 PostgreSQL 18、输出健康状态、接受取消并安全退出的 Gin API，拥有单一 OpenAPI、严格配置、请求 ID、脱敏日志、稳定错误和真实数据库故障验证。

本切片不实现 Apple 登录、用户数据、媒体上传、配额、任务、RabbitMQ/Redis consumer、对象存储、同步或三维业务。没有业务 schema，因此不创建空 migration、atlas.sum、占位 model/service/worker 包，也不声称完成 schema 兼容检查或业务鉴权。原 App 不连接健康接口，不改变离线边界。

## 用户可见与状态契约

运维健康接口与业务接口同源于 backend/openapi.yaml：

| 方法与完整路径 | operationId | 成功 | 失败与边界 |
| --- | --- | --- | --- |
| GET /v1/health/live | getLiveness | 200，status=live、request_id | 不访问数据库；数据库故障不把存活误报为死亡 |
| GET /v1/health/ready | getReadiness | 200，status=ready、request_id | 数据库探测超时/失败或进程退出时 503 NOT_READY，不暴露连接/SQL/版本细节 |

默认只监听 127.0.0.1:8080。两条只读健康路由无需用户身份，但部署必须限制运维访问；没有业务路由，未知路径/错误方法分别返回稳定 404/405 JSON，不重定向到其它路径。X-Request-ID 由服务端生成，不信任请求中的 ID；响应和日志一致。Cache-Control: no-store。

配置错误、数据库首次连接失败、PostgreSQL major 非 18、监听失败均非零退出，不进入假就绪。运行中数据库失联只使 readiness 失败，恢复连接后可再次就绪；SIGTERM/SIGINT 停止就绪和新接纳，在截止时间内清理 HTTP 与连接池。

## 配置与资源边界

| 配置 | 默认 / 校验 |
| --- | --- |
| APP_ROLE | api；worker/all 已保留为目标角色，但当前明确报未实现并退出，禁止空 worker 报成功 |
| HTTP_ADDR | 127.0.0.1:8080；必须是合法 IP:port，测试可显式使用端口 0 |
| DATABASE_URL | 必填 PostgreSQL URL；远端要求 verify-full，仅 loopback 允许 disable；连接选项白名单与重复项校验，不打印值；本地样例仅占位凭据 |
| DB_MAX_OPEN_CONNS / DB_MAX_IDLE_CONNS | 10 / 2；open 为 1–100，idle 为 0–100 且不大于 open |
| DB_CONN_MAX_LIFETIME | 30m，必须正数且有界 |
| STARTUP_TIMEOUT | 5s，必须正数且有界 |
| HEALTH_TIMEOUT | 1s，必须正数且小于 HTTP 写超时 |
| SHUTDOWN_TIMEOUT | 10s，必须正数且有界 |

HTTP 固定 ReadHeaderTimeout=5s、ReadTimeout=5s、WriteTimeout=10s、IdleTimeout=60s、MaxHeaderBytes=16KiB；健康接口不接受 body/query，输入不满足时返回 400。所有 I/O 传递 context，无请求后后台任务。配置解析接收 getter 便于隔离测试，错误只带字段名和原因，不带原始值。

## 领域、数据、API 与系统边界

- 一个 main.go 组装 config、database pool、Gin router 与 HTTP 生命周期；组件显式注入，不建立全局服务容器。
- GORM PostgreSQL driver 管理连接，禁止 AutoMigrate；只执行连接/版本检查和 Ping，不读取用户表。日志关闭 GORM 默认 SQL/错误正文输出。
- transport 只依赖带 context 的数据库探测协议；数据库实现不 import Gin。健康 DTO 是 transport 纯 struct。
- OpenAPI 仍为 3.1.2，servers=/v1，paths=/health/live 与 /health/ready；先校验并构建 Swift Client，再实现 Handler 和响应契约测试。
- Gin/GORM/driver/kin-openapi/Testcontainers 按 Design 01 精确锁定；本切片没有实际 trace exporter 或云指标，OpenTelemetry 的运行接入留给云接纳前的运维切片，不伪报已启用。

## 权限、隐私与安全

仅使用随机生成的隔离测试数据库和合成凭据，不读取生产配置。默认日志记录服务端 request_id、路由模板、状态、耗时；未知路径统一 unmatched，不记录 URL/query、请求体、令牌、数据库连接串或 panic 内容。未知路由不产生账户或任务。数据库集成测试的容器/网络必须由测试生命周期清理。

## 兼容、迁移与回滚

不改业务表、本地 GRDB、历史数据、iOS 产品页面或生成器配置；新接口为运维增量。Swift 生成产物仍在 DerivedData。回滚代码/停止本地进程即可，数据库无业务 DDL 需要回滚。后续第一份业务 migration 必须独立验证 Atlas/旧 schema，不能把本次 Ping 视为 migration 验收。

## 本轮实现影响面

继续落实已批准的启动/退出与脱敏契约，不变更业务行为或技术选型：

- `internal/platform/httpserver/server.go`：监听循环异常返回时关闭已接纳连接，使请求 context 取消，不让进程装配函数先关闭 DB 而 HTTP 仍活动。
- `internal/platform/httpserver/server_test.go`：真实连接触发监听异常，验证 drain、请求取消及有界退出；先观察失败再修复。
- `tests/runtime_integration_test.go`：复用固定 PostgreSQL 与实际 binary，验证非法角色、无配置、错误凭据、监听占用等失败非零退出；输出不得泄露随机密码或错误响应正文。
- 资源始终由测试/Serve 所有者关闭；API、schema、app 和依赖版本不变。失败测试通过后记录证据，Swift 构建阻断仍独立保留。
