## MVP Spec

### 结构化场景

- 会话只保存本地日期、原始时区、目标正式度、目标保暖度、必须防雨、必须便于步行和“本次允许使用已打包衣物”。退出推荐页即清理，不写数据库、不请求日历、位置、照片或网络。
- 正式度与保暖度允许保持“未指定”；未指定时不参与硬过滤。用户选择具体枚举后，该字段成为硬约束，只有用户确认值精确匹配的衣物才能通过；未知值不能被默认值、名称、照片或类别补齐。
- 必须防雨只校验鞋及候选中存在的外套；必须便于步行只校验鞋。未知或明确不适合都不能冒充满足。首片不推断医学温度、合身、颜色或材质。
- `packed` 默认不可用，只有用户明确打开“本次使用已打包衣物”后才与 `wearable` 一起进入候选；`laundry`、`lentOut` 始终排除。当前数据模型没有独立归档事实，因此本片不声明归档验收通过。

### 候选与解释

- 候选只来自当前仓储返回的真实 `WardrobeItem` ID 与 revision；完整路径固定为“上装 + 下装 + 鞋”或“连体衣 + 鞋”。外套、包和配饰不在首片自动组合中，避免无批准规则的组合膨胀。
- 引擎按稳定业务 ID 排序后生成确定性组合，最多返回三套，衣物不足时返回真实数量，不复制组合、不接入随机数或未批准权重。
- 每套理由只引用当前可用状态、完整路径及用户已选择且已确认满足的约束。未参与硬约束但衣物属性仍未知时，以不确定性摘要显示，不把未知写成正向理由。
- 无可行组合时返回稳定原因码和可执行说明，至少区分类别不足、当前状态不可用和确认属性不满足；不生成虚构衣物，不自动放宽用户约束。
- 引擎 API 不接受人物、照片、身体、价格、品牌、视觉生成结果或网络对象；这些数据无法参与过滤与顺序。

### 页面与失败恢复

- 今日页面提供“获取穿搭建议”入口；推荐页可确认场景、生成、重新生成并查看最多三套真实衣物名称、理由和不确定性。
- 仓储读取失败显示可重试状态；新请求以当前场景和衣橱重新生成，旧任务取消或迟到时不能覆盖新结果。
- 本片不展示不可工作的保存、锁定、换件、分享或 AI 入口。手工穿搭计划入口继续可用。
