## Spec与影响面

Design 05「单件图片持久化与恢复」→ PRD 12 WARDROBE-REQ-001/002/009/010/012/015 → 本计划 → WARDROBE-ACC-006/008/009 的相应子集。Woo 页面以 Design 03 逐页映射为最终 UI 目标，存储测试不能抵扣页面复现。

1. 单件图仍非必填；只使用主动选择且能安全形成单件素材的图片，人物/多件重叠按原规则换图、选主体或无图处理。完整图片入口在处理与生命周期联调后提供。
2. 规范化图和缩略图有稳定照片组 ID、用途、摘要与相对路径，原始输入只临时持有；本机无上传。照片组同删，衣物事实独立。
3. importing → ready → deleting 在 SQLite 持久登记。文件写入/移动和数据库提交分步，只有 ready 可见；换图失败保留原 ready，成功后清理旧图，重启清理未完成阶段。
4. 移除照片或衣物先事务持久删除意图，再清理文件；失败隐藏图片并保留重试依据。读取坏图/丢图返回不可用，衣物仍存在。
5. expectedRevision 防止过期编辑；同一命令 ID 可重试，不能覆盖新版本。路径由随机 ID 与固定文件名派生，不接受删除路径，拒绝符号链接与硬链接。
6. 隔离 POC 仅在测试 target 运行，已完成；DATA-01 已接入正式 OOTDSchema/启动与 Data 层。本轮按用户“先使用模拟器进行开发”接通原生 PhotosPicker、图片预览、单件复核、原子保存和移除；局部身体自动检测增强与真机发布门禁仍未通过，不宣称生产图片准入完成。OpenAPI、后端与依赖不变。

## 迁移、恢复与回滚

POC 仅在测试自建临时目录使用独立 SQLite schema；不访问 App 私有目录、用户图库或生产库，测试完成清理夹具。运行中断模拟在故障点直接抛出，重新创建存储 owner 后恢复；与真实进程 kill/最低设备测试分别记录。
