## MVP spec

现有五个 `/wardrobe/items` operation 保持不变，API 版本升级为 0.9.0。POST 与 PUT 的 `attributes` 为必填对象；对象内四项均可为空：

| API 字段 | 非空枚举 | 语义 |
| --- | --- | --- |
| `formality_band` | `casual|smart_casual|formal` | 用户确认的正式度 |
| `warmth_band` | `light|medium|warm` | 用户确认的保暖感受 |
| `rain_use` | `suitable|unsuitable` | 用户确认的雨天适用判断 |
| `walking_use` | `suitable|unsuitable` | 用户确认的步行适用判断 |

全部 NULL 合法且表示未知。请求不接受 `source`；响应把每个非空值表示为 `{value, source:"user_confirmed"}`，对应 NULL 字段返回 NULL。来源由受认证用户的显式写入推导，不建立来源列。API 的 snake_case 值与 App 本地 camelCase 枚举在未来 Client 边界做一次明确映射。

POST 的幂等内容比较加入四项属性。PUT 完整替换四项属性；单项 NULL 是清除为未知，成功与其他字段同事务 revision +1。任一非法枚举、未知字段、过期 revision、跨 owner 或约束失败都不写入部分结果。GET/list 返回相同属性结构。图片、模型建议、置信度、推荐、App 主动同步、墓碑和合并仍不在本片。

## 文件职责

- `internal/model/wardrobe.go`：四项值枚举、nullable 属性值对象。
- `internal/service/wardrobe.go`：对所有非空属性做穷举校验并编排完整替换。
- `internal/repository/wardrobe.go`：四个 nullable CHECK 列、幂等比较、事务更新与转换。
- `internal/transport/wardrobe.go`：请求/响应属性 DTO、只读来源和 Huma/OpenAPI 枚举。
- 同包 `_test.go`、`tests/wardrobe_services_integration_test.go` 与运行时集成：领域边界、HTTP、OpenAPI、真实 PostgreSQL 和实际二进制。
