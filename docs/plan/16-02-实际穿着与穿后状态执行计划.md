## 本机、账号与同步边界

- 本切片只修改 `then-app` 本机 GRDB、Swift 领域和 SwiftUI 旅程。它不调用或修改 [17-22 账号穿搭计划 API](17-22-账号穿搭计划API执行计划.md)，也不创建 Go endpoint、OpenAPI operation、网络 Client 或同步队列。
- 17-22 当前账号计划合同只有 `active|cancelled`，其 PostgreSQL 事实继续保持不变。本切片的 `completed|notWorn` 是设备本地实际结果状态；在账号实际穿着 API 获批并实现前，不得把本机四态写回 17-22，也不得用未知枚举、默认降级或兼容分支伪造同步成功。
- 账号实际穿着、反馈以及本机/账号计划合并另立后续服务端与 App 同步切片。届时从已经验证的 16-02 语义明确 ID、revision、tombstone、冲突和离线重放合同；17-22 完成不抵扣该工作。
- 本机 `WardrobeDeletionImpact` 与 17-22 的账号删除影响摘要分别由 SQLite 和 PostgreSQL 计算，名称相近不代表 wire contract 相同。未来接入必须显式映射并重新核对两端 revision，不能复用本机对象作为网络 DTO。

## 用户与状态合同

1. 今日和穿搭簿提供“记录实际穿着”。输入为今天/过去的合法公历日期、原始 IANA 时区、1～20 件不重复的真实衣物、明确的完整/部分选择、可空且最多 120 字场景。默认明确标为部分记录，只有用户确认整套已记录才标完整；未知单品/场景不补齐，不允许未来实际记录。
2. 今天或过去的非取消计划详情提供“按计划穿了”“换了几件”“穿了别套”“最后没穿”。详情展示日期、单品及“仅记录以下单品”说明；未变化时“按计划穿了”一键提交部分记录、默认不改衣物状态，可事后补全。换件预载原单品 ID，别套从空选择开始，复核页明确日期并点击“实际穿了”才提交；按计划遇到变化或删除同样先复核。计划到期、保存/查看、照片操作不创建事件；不弹自动通知或读取日历。
3. 已删除原单品不重建或自动替换；展示差异，要求选其他真实单品或改为部分记录。当前不可穿状态不否定过去发生事实，须复核差异但不强制变更状态。新建或显式更新的实际快照由事务读取用户刚复核的衣物版本生成；编辑中未改动的有效历史快照按第 6 条保留。
4. 每件穿后状态提供“保持当前状态/标为待洗”，默认全部保持。选择待洗仅适用于实际保留的单品，移除单品一并移除其待洗意图。保存必须原子提交事件、快照、明确状态变更、计划结果与幂等收据；取消不写任何一项。
5. 同一本地日期的有效事件，实际单品 ID 集合交集/并集 ≥0.8 时提示可能重复，不受顺序影响；编辑排除自身，空集合不匹配。用户可选择查看旧记录、返回修改或明确“另一次实际穿着”。确认绑定候选事件 ID/revision 集合，事务重新计算，集合变化拒绝并重新确认。同一 mutationID 的重试直接返回原结果，不按新事件重复提示。
6. 可编辑日期、实际选择、完整性和场景；修改前后都保留原计划，绝不以实际替换计划内容。编辑使用 expectedRevision；旧来源计划已变更时提示“原计划已修改”，不将当前计划冒充确认当时版本计算差异。新增或变动单品须复核，未变动且仍有效的历史文字快照保持；照片只能引用同一有效资产。
7. 实际详情提供纠正和永久删除。删除事件/纠正单品后从剩余有效事件查询穿着次数，不做累计加减或保留隐性偏好缓存；一次事件内同衣物最多一次，同日经确认的两次事件计两次。本切片在衣物详情展示派生次数，查询无事件为 0。
8. 纠正/删除事件不自动恢复衣物当前状态，防止覆盖之后手工修改或洗衣结果；确认页明确说明衣物状态保留，可到衣橱修改。若编辑时新选择待洗，仍校验最新衣物 revision 并随本次事件修改原子提交。
9. “最后没穿”要求二次明确确认且计划没有有效关联事件；不创建事件或计数。撤销未穿恢复 active，随后才可确认实际穿着。已有实际事件时必须先纠正/删除对应事件，不能一键抹去多次实际历史。未穿原因及体验反馈留给 16-03，不预建空表或默认中立值。
10. 本机计划主状态保持唯一：有效关联事件 ≥1 为 completed；删除最后一个关联事件恢复 active；明确未穿为 notWorn；已取消仍为 cancelled。取消只用于尚无实际/未穿结果的 active 计划；completed/notWorn 通过纠正结果恢复 active 后可取消，不把事实与取消叠加。状态重算与事件变更在同一 SQLite 事务；服务端 17-22 仍只认识 active/cancelled。
11. 删除计划仅清除计划、其快照及实际事件的来源引用/来源 revision，实际日期、真实单品快照、次数保留。删除事件不删除计划或衣橱衣物。彻底删除衣物则按下文独立影响预览执行，不能借来源关联扩大删除范围。
12. 时间线按各自原始本地日期合并计划与实际记录，稳定按日期、创建时间、实体种类及 UUID 排序；明确“计划中/实际穿着/部分记录/未穿/已取消”，无照片也完整可用。页大小固定 30，混合游标不得漏项/重复；只提供已有时间线，不将月历/收藏/复用当作已交付。

## 数据、事务与媒体合同

- 同一 GRDB DatabasePool、系统 SQLite/WAL；在 12-05 属性切片之后追加语义化 migration `ootd_wear_events_v1`，不修改 v1～v4、不清库、不使用 BLOB。旧 OOTD 数据不是可丢弃的旧生活管理数据。
- 基于包含已确认属性的本机 `outfit_plans` 重建状态约束以纳入 completed/notWorn；保留所有既有 UUID、字段、索引、子表外键与已删除不透明行，现有 active/cancelled 不自动转换为事实。迁移失败完整回滚；不据此修改服务端 PostgreSQL 状态约束。
- `wear_events`：UUID、nullable sourcePlanID/sourcePlanRevision、sourceKind（按计划/换件/别套/无计划）、localDate、timeZone、completeness、nullable contextSummary、revision、createdAt/updatedAt、live/deleted。删除态仅保留不透明 UUID/状态，其余字段全部清空，用于防迟到创建复活。
- `wear_event_items`：eventID、ordinal 0～19、nullable wardrobeItemID/itemRevision/name/category/availability/photoAssetID、redacted。快照沿既有最小字段规则，不保存未实施颜色或体型；删除态字段约束与计划快照等价。固定有效照片引用，不复制媒体。
- `wear_event_mutations`：mutationID、目标 UUID、动作、请求摘要/结果版本；只为幂等校验，不存正文。目标事件或对应敏感数据删除时清理相关摘要/关联，保留的删除标记不含日期、场景或衣物；不得从幂等收据恢复被删历史。
- 计划结果直接由现有计划主状态与关联事件的 sourceKind 表达，不额外创建空 PlanOutcome/Feedback/Preference 表。涉及计划结果的更改提升 plan revision；事件编辑也提升 event revision，不能静默采用新版本覆盖旧草稿。
- 所有更新统一由 Data 层一个事务执行；提交前核对事件/计划/实际衣物 revision、有效照片引用、重复候选集合及明确状态意图。相同 mutationID 不同内容/目标拒绝；重试优先命中幂等结果；目标已删除优先阻止复活。
- 历史未改动单品在编辑时沿旧快照保留；真正新增/替换单品读取已复核当前版本。要更新旧文字需用户明确复核，不因刷新自动提升版本。当前衣物变更只影响当前状态选项，不倒灌历史。
- `then-app` 原 `WardrobeDeletionImpact` 扩展为本机计划和实际事件的 ID/revision 集合，SQLite 删除事务重新核对两者。原 `.deleteAffectedPlans` 在 App 所有调用点统一替换为表达两类本机历史的 `.deleteAffectedHistory`，无旧 overload 或双 API；17-22 的 `expected_impact` 与 `delete_affected_plans` 字符串合同不随之改名。
- redactSnapshots 同时清空两类直接关联快照的原属性、衣物 ID 与照片引用，保留不含原属性的占位；deleteAffectedHistory 删除直接包含该衣物的计划/事件，并重算剩余关联计划结果。来源计划被删但自身不含目标衣物的事件只解除来源引用。
- 移除/替换照片复用既有媒体日志和文件删除链，同时失效实际/计划图片引用，旧详情不能显示新图冒充历史。数据库事务失败时删除意图和历史修改均回滚；事务已提交后的文件清理失败隐藏图片并可重试。

## 错误、删除和恢复

- 普通 I/O 错误保留内存草稿，提供重试；版本变化要求重读/复核，不自动覆盖；重复确认过期重新展示。所有错误用可本地化安全文案，不输出衣物、日期、场景或照片路径到日志。
- 退出编辑明确丢弃，后台立即遮罩并清除显示图片；迟到加载不可恢复被删内容。页面任务可取消，但已提交事务不因页面消失回滚；重启从真实库读取。
- notFound 与存储不可用分开，已知删除清空事件、场景、单品、来源和重复候选；删除失败保留不透明可重试目标，不暴露旧内容。
- 真机 Data Protection、锁屏及低存储仍需发布证据，先完成模拟器可执行开发。无照片/离线不阻止实际记录；不拿模拟器结果冒充物理保护通过。
