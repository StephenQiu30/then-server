## 用户与值合同

| 字段 | 已知枚举存储值 | 用户显示 | 未知 |
| --- | --- | --- | --- |
| `formalityBand` | `casual` / `smartCasual` / `formal` | 休闲 / 整洁休闲 / 正式 | NULL，显示“未知” |
| `warmthBand` | `light` / `medium` / `warm` | 轻薄 / 适中 / 偏暖 | NULL，显示“未知” |
| `rainUse` | `suitable` / `unsuitable` | 适合 / 不适合 | NULL，显示“未知” |
| `walkingUse` | `suitable` / `unsuitable` | 适合 / 不适合 | NULL，显示“未知” |

1. 四项独立，无默认推断、相互推导或必填依赖；所有已知值均由用户选择并点击保存确认。来源语义只有 `userConfirmed`；未知无来源，不建立虚构模型建议或置信度。
2. 既有原生衣物新增/编辑页增加可选属性区域，每项保留未知选项。首个建衣橱路径无需额外填写；详情可查看当前值及“由你确认”。文案明确是个人使用判断，不能宣称防水认证、精确保暖或步行舒适保证。
3. 取消编辑/选图不提交变化；失败保留当前草稿供重试。修改名称、类别、状态，或换图/移除图片时，不隐式清空已有属性。
4. 每次明确保存继续使用现有 expectedRevision；属性变化与其他衣物字段同事务、同一次 revision 更新。旧编辑器遇到冲突保留草稿且先复核，不借重试覆盖更新后的字段。
5. 单项改为未知只清除当前衣物该值。明确说明“已保存计划保留当时信息”；不暗中改历史，不创建学习事件。彻底删除衣物时才按现有历史策略清除相关快照或计划。
6. 计划编辑时显示已确认属性差异，沿现有复核后保存机制；有效历史详情只显示当时快照，不读取当前衣物填补旧未知值。旧快照全未知是合法历史，不升级为默认事实。
7. 不启用推荐按钮、权限、网络或分析埋点；后续推荐只能消费明确枚举与来源，不能把本片字段包装为效果保证。

## 领域、存储与事务

- `WardrobeAttributes` 为纯值类型，四个 Optional 枚举组成；`WardrobeInput` 显式接收属性对象，新增/编辑/带图保存及现有测试调用点一并更新，不保留旧重载或双写路径。全未知是业务允许值，不是旧 API 兼容层。
- 已知值的来源由本片唯一手工写入入口和已确认值语义确定，不重复存四套来源字符串。未来引入模型建议必须独立保存建议及来源并评审，不能直接写进已确认值。
- 候选不可变 migration identifier：`ootd_wardrobe_attributes_v1`；当前已实现基线为 v1～v4，16-02 的 `ootd_v5_wear_events` 仅为未执行草案。本片不重命名既有标识，不假定草案已落库。
- `wardrobe_items` 和当前 `outfit_plan_items` 各增加上述四个 nullable TEXT 列，以 CHECK 限定枚举。历史 redacted 行的新列必须全部 NULL，禁止仅清旧字段却残留属性；非法存储值返回安全数据错误，不自行修复或清库。
- 旧记录全部 NULL，不按名称、类别、照片、时间或模型填充；保留 UUID、revision、排序时间、原名称/状态、照片 ID/hash/文件和已有历史删除标记。
- 计划保存事务从核验 revision 后的真实衣物读取四项快照；属性更新不倒灌旧计划。所有当前快照读取/重存/删除分支一起修改，不把新列只接在 UI。
- 带图保存必须连同属性一次提交。相同创建/图片保存意图的重试包含完整属性相等性；同一 ID 携带不同属性不能当成已成功请求吞掉，也不能造成第二条衣物或遗留文件。
- `redactSnapshots` 清空全部四项与原字段；`deleteAffectedPlans` 按当前合同删除计划。照片移除仍只移除照片，不删除当前或历史衣物属性。业务删除提交后物理清理失败仍保持隐藏并可重试。

## 测试验收矩阵

1. **最小路径**：新增衣物只填名称/类别/状态，四项保持未知，保存重启仍未知。任意单项已知、其余未知也可保存；非法枚举/伪造输入被拒绝。
2. **真实编辑**：选择四项→保存→重启→只改名称或状态→保存，属性保持；清除一项只改变该项，取消清除保持原值。
3. **版本与失败**：两编辑器并发修改属性；旧版本拒绝且草稿保留，复核前不覆盖。注入写入前失败与提交后响应丢失，重试不重复创建、不吞掉不同属性输入。
4. **带图原子性**：合成衣物图与四项同次保存；SQL 失败衣物/属性/图片引用均回滚，按既有媒体恢复清理。不同图片替换、取消候选、移除照片均不丢属性。
5. **历史**：保存计划时四项固定；衣物修改后历史仍旧值；旧未知快照不补新值。显式编辑复核后新快照才采用当前值。
6. **删除**：两种历史策略覆盖四项；所有相关表中不得残留目标属性/关联，快照清空失败整事务回滚，照片清理失败不恢复已删内容。删除照片不能抹衣物属性。
7. **迁移**：从核定的真实基线含衣物、ready 照片、active/cancelled/已删除计划升级；逐行核对 UUID、旧值、媒体 hash、未知新列、外键与索引。重复开库不重跑；中断失败回滚；较新库拒绝打开而非清空。
8. **UI/无障碍**：专用模拟器真实填写/取消/保存/重启/清除/历史复核/删除；标准与最大辅助字号、深色、Reduce Motion、后台遮罩，不依赖颜色和图片辨认选项。人工 VoiceOver、物理保护/锁屏恢复另列发布证据。

每份证据记录测试选择项、注册通过/失败/跳过数、结果包、构建配置、fixture、实际源码哈希和限制。没有运行推荐引擎，不能用属性旅程关闭 RECOMMEND-ACC；没有运行真实图片流程，不能仅凭内存输入测试关闭图片原子保存。

未发布源码试改可成组撤回；已经升级的 OOTD 库不得清空、降级或用旧代码静默忽略新字段。旧版本须拒绝新 migration；恢复使用前向修复，测试仅恢复任务专用副本，保留实际用户数据。

当前不存在属性实现或运行证据。只有合同获批、顺序核定、四项实际行为/事务/删除/测试与 acceptance 同步完成，才标记对应任务完成；整片完成也不等于全部衣物属性、推荐、Woo 或三维项目完成。
