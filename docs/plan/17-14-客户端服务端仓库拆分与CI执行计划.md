## 可交付合同

本切片建立两个公开 GitHub 项目和同级本地目录：`Then/then-server` 对应 `StephenQiu30/then-server`，`Then/then-app` 对应 `StephenQiu30/then-app`。`Then/` 只是统一父目录，不是 Git 仓库。原 `app/` 的 Git 历史进入 App 项目，服务端项目删除该目录；不保留兼容副本或转发目录。

服务端继续拥有唯一 `backend/openapi.yaml`。App 的 `ThenApp/openapi.yaml` 是指向同级服务端工作树的符号链接；App CI 同级检出服务端后构建，保证生成链读取真实契约。两个项目分别拥有一份最小 GitHub Actions 工作流，不新增脚本文件。

完成条件：两个远程 `main` 均包含相应代码与 CI；本地目录和 remote 名称一致；Go unit/race/integration/container 门禁通过；iOS Debug 构建与非 UI 测试通过；远程 Actions 结论为成功；文档、链接、模块路径和工作区均无旧活动路径或未提交修改。

## 影响面与非目标

- 影响：Git 历史/remote、目录、Go module imports、OpenAPI 符号链接、README/AGENTS、CI、Design/PRD/Plan/Acceptance。
- 不影响：用户数据、GRDB/PostgreSQL schema、API operation、Bundle ID、App 显示名、云能力分期和暂停中的 `frontend/`。
- 不实施：微服务、Kubernetes、自托管 runner、自动发布、生产部署、额外 CI 平台、第二份 OpenAPI、兼容目录或迁移脚本。

## 迁移、失败与回滚

- 先从原 `app/` 生成保留路径历史的 split branch，再创建并验证 `then-app`，最后从服务端删除 `app/`；任何一步失败时原 main 仍保有完整代码。
- GitHub 仓库重命名后立即更新本地 remote 和 Go module imports；不依赖 GitHub 的旧 URL 转发作为长期兼容层。
- App CI 先同级检出 `then-server`，符号链接目标缺失、契约解析失败或生成代码无法编译时直接失败。
- 当前处于开发阶段且无历史用户数据，本次没有数据库或媒体迁移。回滚只涉及 Git revert、仓库名和本地目录，不修改用户数据。

## 完成判定
