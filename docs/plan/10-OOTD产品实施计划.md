# OOTD 产品实施计划

## 2026-09-08 方向确认与研究边界

首版已确认本地可调 3D 角色/直接换装、衣橱、推荐、记录与删除；下列路线承接该范围，不再等待云端静态试穿。研究依据见 [`../design/13-三维虚拟形象与服装系统研究.md`](../design/13-三维虚拟形象与服装系统研究.md)；生产实现仍以 POC 及获批切片为前置，已有照片/历史数据切片不扩展。

### 后端编码前规范入口

2026-09-08 用户要求先完成结构与标准流程。后端目录职责、服务规范及 SOP 集中于 [Design 02](../design/02-后端架构.md#后端开发与交付-sop)，精确版本与启用时点仍归 Design 01。当前先关闭 17-01 已知编译阻断；后续云身份/同意/删除、媒体、异步和生产接入按既有切片与前置推进，不预建全部表或空模块。本轮仅补齐文档，不新增执行计划或宣布生产云开放。

### 客户端平台已定案

2026-09-08 用户确认 SwiftUI 客户端 + 独立 Go 后端，最低 iOS 26，统一采用原生 Liquid Glass；事实源见 [Design 01 最终决策](../design/01-技术选型.md#客户端最终决策与原生液态玻璃)。Flutter 条件复评保留历史，不再作为待定前置。工程部署目标与架构守卫同步为 26.0；旧系统不属于新版本支持范围，历史数据不随此变更删除。

M1 的 SwiftUI shell 应按 [总体组件设计](../design/03-OOTD产品总体设计.md#swiftui-液态玻璃组件设计) 使用系统导航和玻璃操作控件，并在功能切片批准后实现。三维 POC 增加原生玻璃叠加 WebKit 的合成、手势、无障碍与能耗对照；具体组件和三维实现状态保持 pending。本次不新增执行计划，不改变现有照片/历史数据切片范围。

### 3D 优先路线提案

| 顺序 | 研究收敛后拟交付 | 进入下一步需要的证据 |
| --- | --- | --- |
| 1. 资产与 renderer 隔离 POC | 用授权模板验证本地模型加载、显示、直接换装与 SwiftUI 静态降级，并比较 Three.js/WebKit 与原生候选 | 资产来源/许可证、格式校验、最低设备性能、离线零外联与 renderer 选择结论 |
| 2. 人物与服装适配 | 收敛可调外观/体型范围、骨架与形变版本、服装兼容矩阵、层叠遮挡及不支持组合表现 | 参数极值、姿态、服装组合和穿插测试；制作与逐件适配成本 |
| 3. 本地 OOTD 闭环 | 用户调整角色、为真实衣物选择视觉模板、换装并保存组合；用户主动保存计划、主动确认实际穿着 | 离线持久化、取消/撤销、历史快照、不冒充真实衣物与穿着、迁移隔离和无障碍证据 |
| 4. 面向商业化的发布验收 | 验证资产生产可持续性、性能/功耗、删除恢复、供应链与发布回滚 | 成本和质量预算、最低真机、故障演练、删除完整性及独立验收；商业模式与付费行为另行评审 |

以上不新增或预分配 `FF-SS` 编号，不创建占位执行计划，不变更已有任务或验收状态。先把研究结论收敛进 PRD 11/12/15、design 01/03/04/05/08 和相关 acceptance；满足近期准入条件后，才在同一单切片文件固定契约、任务与证据。原 M4/M5 云端生成继续作为独立候选，云生成专属供应商、同意和生成质量门禁不套用到本地 3D 路径；本地 3D 另行验证资产质量、适配、安全与性能，照片、云处理和真实数据的既有边界仍按各自用途执行。

“功能范围已固定”“技术方案可编码”“生产可发布”是不同结论。资产实测和云合同不能由文档编造；只关闭当前切片实际依赖的事项，不以远期 Provider 未决阻断本地工作。

### 每个切片开始代码前必须具备

1. 所属功能与稳定需求 ID、明确非目标、用户输入/成功/失败/取消/恢复状态。
2. 领域实体所有权、约束、版本、删除与历史保留；需要 API 的切片必须完成 OpenAPI，纯本地切片明确无 API 变更。
3. 精确依赖和资产版本、真实模型/供应商输入、权限与媒体路径；相关高风险 POC 有结论。
4. 迁移与回滚、性能/容量/输入上限、测试夹具与可执行验收步骤。
5. 一份同文件统一契约、任务、状态、证据的 `FF-SS` 执行计划，契约获批后编码。现在不为未来功能批量创建占位计划。

后端合入证据必须覆盖 [Design 02 测试与合入检查](../design/02-后端架构.md#测试与合入检查)，首版发布增加 OOTD-SYS-ACC-012/013；本次新增验收均 pending。

### 排期修订

原 M0–M6 编号保留，历史任务与批准记录不重编号。M1–M3 现在必须承接本地角色和直接换装，照片/OOTD 批量导入候选不是首版退出条件；独立角色 POC 的近期切片在资产样本与范围确定后再分配编号。M4/M5 云能力按各自门禁延后，多设备同步不隐含包含在静态试穿里。

## 范围

本计划把已批准的 OOTD 产品与技术设计组织为可发布的 SwiftUI App 和 Go 后端里程碑。先保证本地衣橱、推荐与穿搭记录独立成立，再增加静态 AI 试穿；动态预览是条件增强。M1 及后续功能里程碑启动前，必须把工作包拆成一个或多个可独立交付的 `FF-SS` 执行计划，在同一文件中统一范围契约、任务与证据；下表只管理产品阶段与切片注册，不复制切片任务。M0 若开始任何用户功能实现，同样必须先建立获批执行计划。

计划不包含社区、电商导购、实时 AR、真实 3D 人体、精确尺码、面料物理、未批准多设备同步或用真实用户图片训练模型。

## 风险与缓解措施

| 风险 | 缓解措施 |
| --- | --- |
| 旧代码未跟踪或包含未保存成果 | 迁移前建立可恢复提交/分支；只成组清理，保留 Git 证据 |
| 旧真实数据被新产品切换破坏 | 未确认按已发布处理；先导出与升级测试，不自动清库 |
| 衣橱录入负担导致流失 | OOTD-first、批量确认、渐进补全，不设置机械件数门槛 |
| AI 生成改变人物或衣物细节 | 授权测试集、内容安全、质量门、诚实免责声明和一键反馈 |
| 队列重复造成重复计费或迟到结果复活 | 幂等键、Outbox/Inbox、租约、fencing token、删除 tombstone |
| 技术栈一次引入过多运维复杂度 | 按阶段启用；本地核心不运行后端，云生成才启用完整运行栈 |
| 图片与穿着规律泄露 | 端侧净化、私有存储、短签名、最小日志、目的分离与删除审计 |

## 发布与回滚

- `19-01` 未形成获批分支前，M1/M2 可以做不接触历史数据的隔离设计与研究，但不得发布会替换旧根入口、建立冲突 schema、改写或隐藏历史数据的版本。
- M1–M3 可以在不启用云端生成的情况下发布；云入口必须由服务端能力与 feature flag 双重门控。
- M4 先内部和小流量灰度，限制并发、日成本、单用户配额和供应商地域；删除演练未通过不得扩大流量。
- M5 使用独立开关，关闭后静态试穿、推荐与保存仍可用。
- 数据 migration 使用 expand/contract；发布前建立数据库与对象恢复点，不在同一版本执行不可逆旧数据删除和大规模 UI 切换。
- 客户端回滚不能依赖删除新数据；旧版本必须能忽略新表、新字段和未知任务状态。
