## 切片目标

1. 在不触碰生产资料、生产数据库和云端的前提下，验证一张全身照从系统单项选择到安全解码、净化、质量分析、预览与清理的完整端侧管线。
2. 建立可复用的纯 Swift 领域状态、质量策略、处理用例和 PhotosUI/ImageIO/Vision 适配边界，为后续生产照片准备切片提供经过测量的输入。
3. 用合成素材和取得书面授权的成人测试素材确定最低设备上的文件/像素/内存预算、Vision 阈值、误拒率、误收率、时延和失败恢复表现。
4. 证明取消、替换、失败、后台切换、进程中断和下次启动不会留下未受控原图、净化图、敏感内存或网络流量。
5. 保持无照片路径可见且可退出；任何测试失败都不得促使实现请求更宽相册权限、绕过门禁或启用生产入口。

## 非目标

- 不把照片入口接入正式数字形象页、旧 Profile、Today、Ledger、Calendar、Travel、Life 或其他生产旅程。
- 不实现系统相机、自拍增强、OOTD 衣物分割、风格化形象生成、AI 试穿、动态预览、分享、导出或跨设备同步。
- 不实现长期本机复用，不创建 `AvatarProfile`、`AvatarSourceAsset` 等生产持久化记录，不新增或修改 GRDB migration。
- 不修改 `backend/openapi.yaml`，不实现 Go API、账号、对象存储、RabbitMQ、Redis、供应商或任何网络上传。
- 不推断或记录身份、年龄、性别、种族、肤色、情绪、吸引力、身体尺寸、健康、尺码或真实合身度。
- 不宣称已完成裸露/性化内容识别。当前没有获批的端侧内容安全能力，因此即使技术质量 POC 达标，生产照片入口仍保持关闭。
- 不在本切片固定生产阈值、生产保留期限或生产设备支持矩阵；这些是 POC 输出，不是实现者可主观填写的常量。

## 用户可见契约

本切片只对内部测试人员和获授权参与者提供 DEBUG 测试壳，正式用户不可见。

1. 进入测试壳先看到“照片可选”、仅限年满 18 周岁的本人照片、仅在本机处理、不做量体/尺码判断、结束即清理和“改用风格化形象”说明。
2. 测试人员未主动确认“我是照片中的本人且已年满 18 周岁”时，不得打开系统照片选择器，不创建临时 session。
3. 每次只允许选择一张图片。使用 SwiftUI `PhotosPicker`，不得请求全图库权限、枚举图库或新增 `NSPhotoLibraryUsageDescription` 来扩大访问。
4. 处理成功时只展示重新编码后的净化预览，不展示或复用原始选择结果。
5. 门禁不能继续时，每次只显示一个中性、可操作的主要原因，并提供“换一张”和“使用风格化形象”。不得显示身体评分或人口属性。
6. 取消、离开、改用模板或发生错误后，界面回到可重新开始的安全状态；旧任务迟到结果不得重新显示照片。
7. 界面必须支持 Dynamic Type、VoiceOver、深色模式、提高对比度和 Reduce Motion；焦点顺序为状态、原因、恢复动作。

## 页面、交互与状态契约

### DEBUG 测试壳

- 入口位于 `#if DEBUG` 编译边界内，只能由 `--then-avatar-photo-intake-poc` 启动参数进入。
- 入口绕过旧 `AppEnvironment` 和账本数据库初始化，不挂到旧 Profile 或正式 Root 导航。
- Release 构建不得响应该参数，也不得出现通往测试壳的导航、按钮、URL scheme 或 deep link。

### 状态

`AvatarPhotoIntakeState` 是纯 Swift、`Sendable` 的封闭状态，至少包含：

```text
disclosure
  ├─ 未确认/退出 ─> templateFallback
  └─ 确认 ─> awaitingSelection
awaitingSelection
  ├─ 取消 ─> disclosure
  └─ 选中 ─> importing ─> sanitizing ─> analyzing
analyzing
  ├─ pass/passWithWarning ─> review
  ├─ needsReplacement ─> replacement
  ├─ unsupported ─> unsupported
  └─ 失败/取消 ─> recoverableFailure 或 disclosure
review/replacement/unsupported/recoverableFailure
  ├─ 换一张 ─> awaitingSelection
  └─ 使用模板 ─> templateFallback
```

- ViewModel 使用 `@MainActor @Observable`，通过初始化器接收精确依赖。
- ViewModel 拥有一个可取消的结构化任务；新选择、退出、scene 变化或显式取消会取消旧任务。
- 每次运行使用不可复用的 generation token。只有当前 token 的结果可以改变 UI，防止取消后的迟到结果覆盖新状态。
- `review` 仅持有受控净化预览句柄，不持有 `PhotosPickerItem`、原始 `Data`、绝对路径或 Photos 标识。

### 质量结果与主要原因

结果固定为：

- `pass`：当前 POC 策略认为技术输入可用。
- `pass_with_warning`：可继续评测，但存在一个非阻断技术提醒。
- `needs_replacement`：质量或第三方隐私风险阻止继续。
- `unsupported`：格式、资源、设备能力或安全解码不支持。

稳定主要原因码按以下优先级选择，最多返回一个：

1. `unsupported_format`
2. `unsafe_or_corrupt_input`
3. `resource_limit_exceeded`
4. `multiple_people`
5. `no_person_detected`
6. `person_not_fully_visible`
7. `person_obscured`
8. `image_too_blurry`
9. `image_exposure_unusable`
10. `device_capability_unavailable`
11. `analysis_failed`
12. `quality_warning`

原因码只描述当前技术流程，不得包含身体部位尺寸、面部特征、身份或人口属性。映射规则必须是纯函数并接受显式注入的 POC 阈值；不得把 Vision 默认置信度直接解释为生产质量标准。

## 领域与数据契约

### 领域类型

- `AvatarPhotoIntakeState`：测试壳状态。
- `AvatarPhotoInputHandle`：受控 session 与随机输入 ID，不暴露外部 URL、文件名或 Photos identifier。
- `SanitizedAvatarPhotoHandle`：净化图的受控 session/asset ID、像素尺寸和获批渲染属性，不含绝对路径。
- `AvatarPhotoTechnicalSignals`：当前调用内的人员数量、边界覆盖、遮挡/分割可用性、模糊与曝光等技术信号；只在内存中传递。
- `AvatarPhotoQualityAssessment`：结果、一个主要原因码和本地化恢复动作。
- `AvatarPhotoQualityPolicy`：从技术信号到 assessment 的确定性映射；阈值由 POC 配置注入。

领域层不得导入 PhotosUI、Vision、ImageIO、GRDB、UIKit、网络或旧生活管理类型。

### 临时 session

为避免 `loadTransferable(Data.self)` 对大文件的全量内存加载，本切片固定使用受控文件式导入：

1. 系统 picker 只提供一次性 file representation。
2. `AvatarPhotoTemporarySessionStore` actor 在固定 App 私有临时根目录创建随机 session；目录和文件使用 `FileProtectionType.complete` 并排除备份。
3. 输入先核验文件属性、UTType/魔数和像素头，再复制到随机 `original_import` 名称；不得保留原文件名或外部绝对路径。
4. ImageIO 使用 `shouldCache=false` 检查图像源，通过缩略图路径降采样，规范方向与色彩空间后重新编码为获批输出格式。
5. 输出采用元数据白名单；不得复制 GPS、EXIF、IPTC、TIFF、原文件名、创建日期、设备/镜头、编辑历史或 Photos 标识。
6. 生成净化图后立即删除 `original_import`。净化图只存活到当前测试会话结束、取消、失败、模板回退、后台安全清理或下次启动清扫。
7. 所有路径操作必须以固定根目录和解析后的 descendant 校验为边界，不接受 UI、测试素材或调用方传入任意删除路径。

本切片不写 SQLite，不创建长期媒体资产，不把图片写入剪贴板、系统相册、Widget、Spotlight、通知、诊断导出或分享面板。

## 权限、隐私与安全

1. 测试素材只允许使用合成图片或取得书面授权的年满 18 周岁成人本人素材；fixture manifest 记录稳定 ID、来源/授权依据、预期标签和哈希，不记录真实姓名或不必要属性。
2. 未确认 18+ 本人声明前不得打开 picker；不得使用视觉模型猜测年龄或验证身份。
3. 多人结果必须停止，不得自动裁掉第三方后继续。
4. Vision 只输出当前处理所需的瞬时技术信号；不持久化 observation、关键点、人脸框、embedding、遮罩或身体描述。
5. 日志、OSLog、分析、trace、崩溃附加信息和测试报告不得包含图片字节、绝对路径、原文件名、Photos 标识、哈希、质量信号明细或可还原个人特征的文本。
6. POC 不发网络请求。抓包或网络 spy 发现任何图片、元数据或状态外发即判定失败。
7. scene 进入 inactive/background 时先移除可见预览并释放敏感图像缓存，再依赖全局隐私遮罩保护系统快照；遮罩不能替代内存和文件清理。
8. 当前无获批内容安全检测能力，测试壳只能用于受控素材；该缺口是生产入口的硬阻断，不得在 POC 中以简单分类器或供应商 SDK 临时填补。

## 错误、降级与恢复

| 场景 | 行为 | 禁止行为 |
| --- | --- | --- |
| picker 取消 | 清理空 session，返回 disclosure，保留模板路径 | 把取消显示为错误或申请更宽权限 |
| iCloud 项目离线不可读 | 显示可重试原因，允许换图/模板 | 自动枚举图库或长期等待无取消 |
| 格式、魔数、尺寸或解码失败 | 返回 `unsupported` 对应主原因并清空临时字节 | 尝试按扩展名强行解码 |
| Vision 不可用或异常 | 返回 `device_capability_unavailable` 或 `analysis_failed` | 绕过质量门进入 review |
| 多人/零人/截断/遮挡 | 按优先级显示一个 replacement 原因 | 自动裁剪第三方或输出身体描述 |
| 低存储/写入失败 | 不产生可用句柄，清理部分文件并可重试 | 回退不受保护目录或只登记半成品 |
| 用户换图或取消 | 取消旧任务、清理旧 session、抑制迟到结果 | 旧结果覆盖新状态 |
| App 强制终止 | 下次 DEBUG POC 启动清扫固定根目录残留 | 恢复并自动展示敏感预览 |
| 进入后台 | 清除预览/缓存并安全收口 session | 仅盖遮罩但继续持有图片 |

所有失败都保留“使用风格化形象”出口，不接触推荐、衣橱或历史数据。

## 兼容、迁移与回滚

- 最低 iOS 18、Swift 6.3.3、SwiftUI + Observation 和严格并发设置不变。
- 没有数据库、OpenAPI、后端或媒体 schema 迁移；不存在历史数据升级和服务端兼容窗口。
- 回滚时移除 DEBUG host/launch argument 与新增 POC 文件及测试资源即可；固定临时根目录由当前或回滚版本的启动清扫删除。
- Release 不产生用户数据，因此回滚不得要求清库、删除账号或修改旧 GRDB migration。
- 若 POC 发现最低设备无法满足预算、不同群体误拒明显、ImageIO/Vision 行为不稳定或清理不可证明，则保持生产入口关闭并允许整切片停止，不以放宽安全边界换取通过。

## 可观测性与指标

生产日志和产品分析不适用。本切片只在隔离测试壳与测试进程中采集：

- 各阶段 p50/p95 时延、峰值内存、能耗/热状态和取消收口时间。
- 每类 fixture 的结果码、预期/实际差异、误拒和误收。
- 元数据净化字段清单、沙盒前后文件差异和零网络断言。
- 设备型号、系统版本、构建号和阈值配置版本。

报告不得嵌入图片、真实姓名、绝对路径或质量信号原始正文。长期证据使用可复核 CI artifact/评测报告引用，不以短期 `/tmp` 路径作为完成证据。

- policy：四种结果、全部原因优先级、阈值边界和“一次只返回一个主要原因”。
- Vision：单人、零人、多人、截断、遮挡、模糊、曝光、轮椅/辅助器具、宗教服饰和多样成人授权素材；报告分组失败率，不把未校准常量当作事实。
- ViewModel/use case：声明、picker 取消、处理中取消、换图、迟到结果、服务异常、scene 变化、模板回退和资源清理。
- 工程/UI：DEBUG 启动参数、Release 不可达、最大辅助字号、VoiceOver 顺序、深色/高对比度、Reduce Motion。
- 真机：真实 Photos picker 选择/取消、iCloud 离线、Data Protection、最低设备内存/性能、后台快照和进程中断恢复。模拟器结果不能替代这些证据。

## 发布、feature flag 与关闭路径

- 本切片没有生产 feature flag；使用更严格的 `#if DEBUG` 与显式启动参数双门禁。
- Release 构建中生产导航不可达，OpenAPI/URLSession spy 为零，照片能力不计入首发功能。
- POC 完成后必须形成 go/no-go 结论。任何安全、内容边界、公平性、最低设备、净化或清理门槛未通过时结论为 no-go，后续生产照片入口不得创建。
- 即使 POC go，仍需另建生产“本地照片准备”执行计划，固定阈值、支持矩阵、用户入口、媒体生命周期、真机验收和独立关闭路径。

## 待本计划产出的参数

本切片没有阻断实施的未决问题。以下是 POC 必须产出、由后续生产切片批准的决策，不得在本切片中静默转为生产常量：

1. 获批文件大小、总像素、输出像素、峰值内存和阶段超时预算。
2. Vision/图像技术信号阈值、原因优先级校准结果与最低设备支持矩阵。
3. 多样成人测试集的误拒/误收门槛及公平性关闭阈值。
4. 裸露/性化内容安全的获批端侧方案或其他可证明生产边界。
5. 后续是否启用一次性生产照片准备；长期本地复用、相机、自拍和云端仍分别另行评审。
