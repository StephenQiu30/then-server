# 可靠账号删除执行计划

## 状态

- 契约状态：`approved`。来源为 PRD `COMMUNITY-REQ-012`、Design 21/22/23 与用户已批准的 B1 后端范围。
- 执行状态：`in_progress`。
- 范围：后端开发。客户端/App 页面、邮件通知、生产备份过期和公开查询删除进度不在本片。

## Spec

`DELETE /users/me` 改为 `202 Accepted` 并返回删除请求 ID、`pending|complete`、待删媒体数量与时间。受理事务必须：

1. 锁定 active 账号，写入 `account_deletion_requests`；
2. 标记账号 deleting、撤销全部会话、关闭本人公开帖子并解除别人帖子对其私人日记的来源引用；
3. 为每个未删除媒体复用或创建 `deletion_requests` 与 `media.deletion_requested` Outbox；
4. 无媒体时在同事务物理删除账号并完成回执；有媒体时等待既有 RabbitMQ worker 删除 MinIO 全版本；
5. 最后一个媒体完成后，在同一 PostgreSQL 事务物理删除账号并把无 FK 的最小回执标为 complete；
6. 重投通知若目标已因级联删除不存在，写 Inbox 回执并 ack，不能形成毒消息。

本片不增加新服务、新队列、兼容旧 204 分支或手写 OpenAPI 文件。运行时合同升级为 API 0.17.0，operation 总数仍为 98；空库表数为 35。
