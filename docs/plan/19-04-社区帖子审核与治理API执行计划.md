# 社区帖子审核与治理 API 执行计划

状态：`approved / in_progress`（本地实现与全部门禁已通过，提交及远端 CI 待完成）。依据：用户已批准 PRD 19 与 Design 21～23，并要求按后端实施顺序继续开发；19-01 固定 B3 在私人日记 B2 之后交付。本片实现“私人草稿 → 人工审核 → 受控公开 → 举报/下架”的完整后端闭环，不开发 frontend/App 页面，也不提前实现 B4 的 Feed、关注、赞藏评关、屏蔽与通知。

## Spec

- 关联：COMMUNITY-REQ-004/005/010/011/012/015、COMMUNITY-ACC-003/004/007/008/009/010/011，[Design 21](../design/21-后端产品边界与领域设计.md)、[Design 22](../design/22-后端数据库设计.md)、[Design 23](../design/23-后端接口设计.md)。
- `POST /posts` 使用客户端 UUID，创建只对本人可见的 v1 草稿；同 owner、同 ID、同规范化内容幂等，内容不同或已删除返回 409。正文或图片至少一项；标题最多 80 Unicode 字符、正文 3,000、最多 9 图、最多 5 个标签且每个 1～20 字。
- 可选 `source_diary_id` 只验证来源属于本人。客户端必须明确提交实际公开的 title/body/media/tags；服务端不自动复制心情、日期、时区、衣橱/计划/实际 ID 或日记全文。来源只在本人 DTO 出现，公开 DTO 永不返回。
- 社区图片必须是单独上传的 `purpose=community_publish`、`category=ordinary_image`、ready JPEG；不允许直接引用 `diary_image` 或人物采集图。它沿用 12 MiB/24 MP/单帧净化链，但不要求人物照片同意。删除仍被任何未删除帖子 revision 引用的媒体返回 409，避免公开内容静默破图。
- 草稿更新使用精确 `expected_revision`，每次创建新的 draft revision，不原地修改已提交/批准版本；有 pending revision 时拒绝编辑。已发布帖子编辑时旧批准版本继续公开。
- `POST /posts/{id}/submit` 使用精确 post revision，只提交当前 draft，生成新的 review round，返回 pending 状态而不宣称已发布。无 handle 的作者不能提交；所有图片必须仍 ready/community_publish。
- moderator/admin 可读待审队列、候选 revision 和候选图片；审核决定携带 version、review_round、expected_revision、decision、reason_code。批准原子切换 published revision；拒绝保留原公开版本或回到私人草稿。相同决定幂等，不同/迟到决定 409。
- 作者撤回会立即使公开详情和图片返回 404，取消 pending，并复制最后可见候选为新的私人 draft；再次发布必须重新审核。作者删除将帖子标记 deleted、删除内容 revision 并保留最小 tombstone，迟到创建/审核不能复活。
- 匿名 `GET /posts/{id}` 和 `GET /posts/{id}/images/{ordinal}` 只读取 active 作者当前批准 revision；不返回 media ID、owner ID、对象 key、版本、来源日记或审核内部信息。图片由服务端从固定 MinIO derived version 读取，禁止长期签名 URL与匿名桶访问。
- 登录用户可对当前公开帖子创建/查询自己的举报；同一用户对同一帖子最多一个 open 举报。moderator/admin 可分页读取、resolve/dismiss；处理举报不自动下架，`POST /admin/posts/{id}/remove` 是独立带 revision 的审计动作。
- admin 可列出账号并 suspend/restore。suspend 在同一事务改变状态、递增 revision、撤销全部会话并使作者公开内容立即不可读；restore 不自动重新发布被撤回/下架内容。普通用户不能读取运营队列、举报者身份或执行任何运营动作。
- PostgreSQL 是帖子、revision、举报和审核动作的事实源；本片不新增 Elasticsearch、工作流引擎、通用权限框架、公共 MinIO 桶、Swagger 物化文件或兼容层。

## SMART 与退出条件

一个切片内完成“独立公共图片准备 → 私人草稿 → 提交 → moderator 批准 → 匿名详情/固定图片 → 新稿审核期间旧版仍可见 → 举报独立处理 → 作者撤回与运营下架立即拒绝读取 → 迟到决定不复活”的可测闭环。只有 checklist 全部完成并同步 Acceptance 19 才将本片标为 completed；B4 未实现前不得宣称 Feed 或互动社区已交付。
