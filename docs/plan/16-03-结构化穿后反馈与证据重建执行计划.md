## MVP Spec

### 反馈事实

- 每条未删除的 `WearEvent` 最多一条反馈；没有实际穿着事实时不能创建反馈。
- 四个维度都可空：冷热 `cold / comfortable / hot`，活动舒适度 `uncomfortable / okay / comfortable`，场合适配 `tooCasual / right / tooFormal`，再穿意愿 `yes / unsure / no`。
- 问题标签是去重集合，首版固定为鞋不舒适、叠穿别扭、不适合下雨、口袋不足、需要护理，最多 5 个。
- 本地备注可空，去除首尾空白后最多 240 个字符，拒绝控制字符；备注和问题标签不进入偏好证据。
- “跳过”关闭编辑器且不创建空记录。保存至少需要一个维度、标签或备注；清空已有反馈必须走明确的“删除反馈”。
- 保存和删除都携带客户端 mutation UUID 与预期 revision。同一命令重复提交幂等；相同 mutation UUID 对应不同内容时报冲突；删除后允许使用新命令重新创建。

### 可重建证据

- 不新增偏好缓存表。每次读取都从仍有效的反馈、实际穿着和实际单品重建候选证据。
- 证据桶只使用“排序后的未脱敏实际衣物 ID 集合 + 反馈维度”；不解析场景文字、备注或标签。实际单品全部脱敏时不产生证据。
- 同一桶同一维度至少有 2 条明确反馈，且唯一最高值严格领先时才产生候选证据；并列或只有一次反馈视为证据不足。
- 候选证据返回胜出值、胜出样本数、该维度总样本数和最近更新时间，供后续 13-03 推荐解释使用。本切片不改变排序。

### 生命周期与界面

- 实际穿着详情展示“添加反馈”或当前四维摘要，支持编辑和删除反馈。
- 删除实际穿着或选择删除受影响历史时，同事务删除对应反馈和幂等收据；仅脱敏衣物历史时保留反馈事实，但重建证据按剩余有效衣物 ID 重新计算。
- 不创建通知、网络请求、OpenAPI、账号同步或推荐入口。

## 文件责任

- Domain：反馈枚举、输入校验、mutation、候选证据和 repository 合同。
- Data：GRDB migration、原子保存/删除、幂等冲突、生命周期清理和证据重建查询。
- Presentation：实际穿着详情中的反馈摘要、编辑器、删除说明和错误恢复。
- Tests：输入预算、迁移约束、幂等/竞态、纠正/撤回、删除清理、脱敏重建和模拟器旅程。
