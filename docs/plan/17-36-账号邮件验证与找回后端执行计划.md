# 账号邮件验证与找回后端执行计划

## 状态与范围

- 契约状态：`approved_with_release_gates`；2026-09-23 固定网易 163 个人邮箱作为发信通道。开发只修改 `then-server/backend` 及其运行时 OpenAPI，Web 与 App 入口另排期。
- 实施状态：`completed（后端本地合成数据）`。`BL-ACCOUNT-01/02` 已完成；真实 163 送达、客户端链接入口与公开注册仍关闭。
- 163 是发信服务，不决定 API、数据库和用户数据的部署区域。生产部署/数据地域、发件额度与真实送达另在发布门禁确认，不阻断合成数据开发。

## 用户与接口合同

注册继续建立可登录账户，但新邮箱初始未验证。`GET /users/me` 与注册/登录响应新增 `email_verified` 布尔值；邮箱修改后恢复未验证并撤销该账户未完成的邮箱验证挑战。既有开发账户不自动标记已验证。客户端根据该字段提示用户验证；后续需要邮件验证的云入口必须单独检查服务端状态，不能信任客户端提示。

| operationId | 方法与路径 | 鉴权及结果 |
| --- | --- | --- |
| `requestEmailVerification` | `POST /auth/email-verifications` | 当前会话；`202`，为当前邮箱请求邮件；已验证时同样 `202` |
| `confirmEmailVerification` | `POST /auth/email-verifications/confirm` | 当前会话和邮件令牌；首次有效消费 `204`；无效、过期、已使用统一 `400` |
| `requestPasswordReset` | `POST /auth/password-resets` | 匿名邮箱输入；已存在/不存在、已禁用账号统一 `202`，不暴露账户 |
| `confirmPasswordReset` | `POST /auth/password-resets/confirm` | 邮件令牌与新密码；首次有效消费 `204`，原会话全部撤销；无效/过期/已使用统一 `400` |

所有请求沿用 Huma 运行时 OpenAPI、全局错误体与 `X-Request-ID`；不提交独立 schema。密码仍按现有 12–72 UTF-8 字节及 bcrypt 合同处理。确认验证必须再次匹配当前登录用户和当前邮箱；确认找回须锁定有效账户及其当前邮箱，不接受旧邮箱挑战。两类发起请求分别限制为每直连源 IP 每小时 5 次、每规范化邮箱摘要每小时 3 次；两类确认请求分别限制为每 IP 每 15 分钟 10 次。存在与不存在邮箱占用同样额度。Redis 不可用时返回 `503` 且不访问账号数据；超限使用现有 `429`/`Retry-After` 合同。客户端不回显令牌，不把邮件 URL 写入日志或分析事件。

## 挑战与投递

- 验证挑战有效 30 分钟，找回挑战有效 15 分钟；同一账户同一用途只有最新一条有效。新请求撤销旧挑战；消费、过期、删号或邮箱修改后不可重放。确认在 PostgreSQL 事务中锁定挑战与账户，原子写入已验证状态或密码散列，并撤销旧会话。
- PostgreSQL 只存挑战 ID、用途、目标邮箱、用户关联、有效期、发送/消费/撤销状态及最小重试元数据。邮件令牌为挑战 ID 与服务端稳定密钥计算的 HMAC；邮件发送端按持久挑战重建令牌，数据库、Outbox、响应和日志均不保存原始令牌。密钥从运行环境注入，轮换时让未完成挑战失效。
- 发送任务与挑战同事务持久化；单个后台发送循环认领待发挑战、通过 SMTP 发信并标记成功。发送失败在有效期内退避重试；发送成功但标记失败允许同一有效链接重复送达。并发发送有租约，过期/已撤销挑战不发送。邮件供应商接受连接不等于用户已收件。
- 只发送单用途纯文本邮件，链接指向受控应用入口，正文不包含密码。以完整发件邮箱账号和网易生成的**客户端授权码**认证，要求验证服务器证书的 TLS 连接；授权码不是网易网页登录密码。运行变量提供发件账号、授权码、SMTP 地址、公开链接基址和挑战密钥；缺项时邮件功能不启用，API 启动门禁不得将其误报为可公开注册。

## 本地实施证据（2026-09-23）

- 账号状态与四个 operation 进入运行时 OpenAPI；未配置邮件时端点返回 `503`。挑战保存在 PostgreSQL，邮箱修改/删号清理、并发替换、过期与一次消费由真实隔离 PostgreSQL 检验。
- 隔离 PostgreSQL/Redis 加邮件替身的 HTTP 测试覆盖匿名找回的相同响应、验证状态、会话撤销及限流；假 TLS SMTP 测试覆盖授权码和证书校验，邮件投递失败可重试。
- `gofmt -l .` 无输出、`go mod verify`、`go vet ./...`、`go test -race ./... -count=1` 通过；`go test -race -tags=services ./tests/... -count=1`、邮件服务定向重测、`go test -race -tags=integration ./tests/... -count=1` 通过。实际二进制套件运行时未启用邮件；带邮件的 HTTP 流程由同一路由、真实隔离 PG/Redis 和邮件替身验证。真实 163 邮箱和授权码未提供，因此没有实收邮件或部署环境验收。
