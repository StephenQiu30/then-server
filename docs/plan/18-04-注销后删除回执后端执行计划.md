# 注销后删除回执后端执行计划

## 状态与范围

- 契约：`approved（本地合成数据）`；实施：`completed（后端）`。接续 [18-01](18-01-数据主体导出与删除回执合同执行计划.md)、[19-06](19-06-可靠账号删除执行计划.md) 与 `BL-DATA-03`。本片只做 `then-server/backend` 和同一事实源文档；App/Web 展示另验。
- `DELETE /users/me` 的 202 响应一次性交付随机回执令牌和到期时刻；仅存 SHA-256 摘要，响应和日志不出现数据库摘要。会话照旧立即撤销。注销后 `GET /account-deletion-requests/{id}` 以 Bearer 回执令牌读取最小状态，`DELETE` 同路径撤销该令牌。请求 ID 单独不授权，错误统一 404；Redis 限流不可用时关闭查询。
- 回执只说明本服务实际可证的 `pending/complete`、访问已关闭、当前媒体清理阶段、剩余媒体数、是否观察到至少一次本次删号重试、申请/更新/完成时间。媒体删除请求在同一删号事务关联本次请求；既往单张删图不计入进度。不声称备份或 Provider 已清。令牌有效期最多 7 天；过期立即拒绝，定期清除过期摘要与已完成的最小回执。超过 7 天仍 pending 的内部记录保留到完成，查询权不延长。
- 仅扩展 `application/account`、`adapter/postgres`、HTTP account contract/routes/handlers 和 bootstrap 的现有责任边界。使用 GORM AutoMigrate、运行时 Huma OpenAPI 与本地真实 PostgreSQL/Redis/进程/OCI 验证。
