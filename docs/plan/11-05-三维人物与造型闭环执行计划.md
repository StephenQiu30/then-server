## Spec

1. **内容**：人物 ID 与 P1 三套预设保持一致；使用标准 GLB 与锁版 Three.js，供应方交付即适配，不由项目人员使用 Blender 建模或修复。3 人物 × 8 套衣物组合必须有真实适配证据。每个 preset 至少一套默认资源离线随包；正式供给不足不得用一模型改标签冒充三人物。
2. **槽位**：分类与实际穿着槽位分开定义，上装/下装/鞋各一项为最小完整组合。移除必需项后清楚提示缺槽，保持上一有效场景；禁止自动补默认衣物。外套只在独立兼容资产获准后提供，不沿用当前“分类不同却替换同一 top”的歧义。
3. **状态**：区分已保存配置、编辑草稿、已应用场景。Dress up 校验完整 recipe 后原子应用；渲染成功不自动保存，存储成功才显示已保存。取消外观/衣物编辑恢复原配置；恢复默认也是草稿变更，未经保存不改已有 Look。
4. **加载**：人物及必需服装全部校验通过才替换，任一失败保持上一完整场景；首次失败使用关联的已审核静态回退，并说明三维不可用。generation/session/revision 防止快速 A→B→C 切换时旧结果覆盖。回退不是保留旧格式兼容层。
5. **观察**：水平连续旋转、缩放、相机复位和原生替代按钮。缩放只改相机，不改身体/衣服尺寸。zoom 上下限、相机/裁切与允许外观参数由代表包验证后冻结；不沿用工程 ±0.25 作为正式资产承诺。未知/越界输入拒绝，不静默夹到另一个身体配置。
6. **动态**：复用 11-04 的同一控制器；人物切换时解除旧节点与动画引用，拖动优先，眨眼/视线不能跳脸。首版动作由 REQ-038 明确的眼部和已有微动组成；完整产品的其他短展示动作在实际 clip 获批后单独验收，不擅自增加行走/布料。
7. **持久化**：一个稳定 Look ID，保存人物/服装 ID 与 revision、已批准外观参数、收藏状态及必要资产依赖。不保存临时 URL、morph 瞬时权重或指针事件。旋转/缩放按批准的查看状态恢复规则记录，相机复位不更改造型事实。共享本地 Repository 服务未来媒体关联，不预建通用资产平台或未使用多态分支。
8. **编辑与重试**：明确 mutation/revision，重复保存不产生重复 Look；失败保留草稿，过期编辑不可覆盖新值，删除后迟到保存不能复活。格式合法与渲染 ready 不抵扣数据库保存结果。
9. **删除**：删除 Look/收藏清除其私有派生缓存；删除私人角色配置同时清除历史中的私人外观与引用，保留独立真实衣物/计划和共有母版。中断后可恢复清理，不用物理文件失败回滚已删除事实。重置当前舞台不是删除已保存 Look。
10. **页面**：原生 SwiftUI 页面共享三套人物 UI；按照 Design 17 逐状态对照，覆盖选择、缺槽、加载、失败、保存、编辑/取消、收藏、详情/删除。未实现的分享/下载/云生成不能只用说明 sheet 冒充完成；相关媒体能力仍归独立切片。
11. **生命周期**：原生场景状态和画布实际可见性共同控制动画；遮挡/后台/退出停止装饰运动，恢复不追赶后台时间。WebContent/context lost 可恢复当前有效 recipe；设备压力和坏资产可明确回退，真实资源释放有证据。
12. **服务边界**：先实现随包离线纵切，无需账号、Redis 或 RabbitMQ。以后远程资产确有需要时复用 11-03 的 Catalog/MinIO 与统一运行时 OpenAPI，不在本片另造下载后端或第二套 DTO。

## SMART 检查点

以代表包和规格可实施时为 T0；外部授权/采购等待时间不计入工程时间盒。每个检查点结束记录可运行结果与偏差，不把超时改成完成。

- T0 后首个 120 分钟：验证缺槽拒绝、3D 资产代表加载与源码职责；交付 Red→Green 的业务检查或具体不适配结论。
- 下一 120 分钟：完成单人物 Look 保存/重启/删除最小纵切及事务故障；未通过先解决该片，不扩人物数量。
- 随后检查点：接相机/切换/动态生命周期和页面，再扩三人物/24 组合；每次开始前按实际完成量估算并记录下一次可检查时间，不承诺未估算的全部交付日期。
- 内容质量、真机资源预算未定时，必须留有 owner/测量环境/准入结论；不能仅凭实现耗时或测试数量验收。
