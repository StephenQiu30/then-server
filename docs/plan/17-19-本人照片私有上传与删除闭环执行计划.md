## MVP Spec

本切片建立“逐次目的同意 → 私有直传 → 固定对象版本 → 异步媒体检查 → 立即撤销读取 → 可恢复物理删除”的最小闭环。它只处理用户当前主动选择的本人照片，衣物继续来自内置目录，不增加衣物上传。

### 固定产品参数

以下参数是本文建议值；契约获批时一并锁定，不在代码中留多套兼容分支。

| 参数 | MVP 值 | 原因 |
| --- | --- | --- |
| 用途 | `avatar_source_preparation` | 只准备本人形象输入，不授权第三方生成、训练、分析、同步或分享 |
| 数据类别 | `person_photo` | 不接收衣物、视频、自由文本或身份文件 |
| 处理方 | Then 自有服务 | Provider 另立逐次同意与生成切片 |
| 存储地域 | `local-development` 仅用于合成数据验收；真实市场地域待批准 | 开发证据不能冒充生产地域承诺 |
| 输入 | App 端去 EXIF/GPS、校正方向并编码的单帧 sRGB JPEG | 不兼容上传 HEIC/PNG/原始相机文件，缩小服务端攻击面 |
| 单文件上限 | 12 MiB、24 MP | 超限在签名之前拒绝，finalize 与 worker 再次核对 |
| upload intent | 10 分钟、单一意图、单对象、固定 `Content-Type`/长度/SHA-256 | 适配移动网络，同时限制凭据范围；对象 version ID 防止同一凭据重放后替换已核验输入 |
| 未完成上传 | 24 小时内清理 | 对齐 Design 11 候选期限 |
| 源照片 | 一次性；生成切片接纳后即清理，未被接纳或失败时最迟 24 小时 | 不在本切片建立长期人物图库 |
| 删除目标 | 请求受理后立即不可读；自有主系统 24 小时内完成 | 对齐 PRD 18 的用户可见目标 |

生产流量保持关闭，直到真实存储地域、公开保留文案、备份窗口、删除演练、TLS/KMS 和上线负责人全部形成批准记录。`local-development` 永远不能被生产配置接受。

### API 合同

Huma 标注类型和 operation 是唯一 OpenAPI 来源；不提交手写 `openapi.yaml` 或生成工具。

| 方法与路径 | operationId | 合同 |
| --- | --- | --- |
| `POST /consents` | `createConsent` | 创建当前账号的一次主动同意；固定用途、数据类别、处理方、地域、保留、训练禁用和文案版本。拒绝不创建记录 |
| `GET /consents/{consent_id}` | `getConsent` | 返回 owner 自己的当前状态、承诺摘要和撤回时间，不返回媒体或内部键 |
| `POST /consents/{consent_id}/withdraw` | `withdrawConsent` | 阻止新的上传/处理；重复撤回幂等，不声称已完成既有数据删除 |
| `POST /media/uploads` | `createMediaUpload` | 校验会话、当前 18+ 本人声明、有效同意、用途、MIME、长度、SHA-256 和限额；返回 10 分钟签名 PUT 信息 |
| `POST /media/{media_id}/complete` | `completeMediaUpload` | HEAD 并固定客户端从 PUT 响应取得的对象 version ID、MIME、长度和受签名摘要元数据；worker 再流式计算真实 SHA-256。重复相同 finalize 幂等，不同事实冲突 |
| `GET /media/{media_id}` | `getMedia` | 只返回 `pending_upload/uploaded/checking/ready/rejected/deleting/deleted`、稳定原因和非敏感元数据；本切片不向客户端签发源照片读取 URL |
| `DELETE /media/{media_id}` | `deleteMedia` | 事务内立即 tombstone 并创建删除请求；重复删除返回同一有效请求 |
| `GET /deletion-requests/{request_id}` | `getDeletionRequest` | 返回读取撤销、主系统清理和备份到期的真实阶段，不返回对象 key/URL |

所有资源 owner 只从 HttpOnly Cookie 会话获得。跨用户资源和不存在资源统一返回相同 404；授权检查先于幂等回放。签名 URL 只存在于当前响应，不写数据库、队列、日志、trace 或错误信息。

### 数据与状态合同

- `consent_records`：保存 owner、用途、数据类别、处理方、地域、最长保留、训练政策、文案/政策版本、主动确认与撤回时间；同一承诺重复提交返回既有有效记录，政策任一字段变化必须重新同意。
- `media_assets`：保存 owner、用途、受控对象引用、对象 version ID、SHA-256、MIME、长度、像素、状态、过期和删除时间；数据库不保存 BLOB、原文件名或签名 URL。
- `media_derivations`：只在 worker 产生规范化对象时记录明确来源；不通过文件名前缀推断血缘。
- `deletion_requests`：记录目标、阶段、尝试次数、下一次执行时间、完成/备份到期时间和稳定错误码；回执不保留媒体正文或对象 key。
- `outbox_events` 与 `inbox_receipts`：PostgreSQL 是事实源；事务只写业务事实和 Outbox，不在事务中访问 MinIO/RabbitMQ。
- MinIO 使用私有 `raw-private` 与 `derived-private` 边界并启用 versioning。finalize 后 worker 只读取已固定的 version ID；仍有效的旧 PUT URL 即使创建新版本，也不能替换已核验输入。删除覆盖该资产的全部版本和派生对象。

状态只允许前进：

```text
pending_upload → uploaded → checking → ready
                         ↘ rejected
pending_upload/uploaded/checking/ready/rejected → deleting → deleted
```

- `complete` 只表示对象事实已固定，不表示图片安全或可用于生成。
- worker 先核对 JPEG magic、单帧、实际像素、解码预算和元数据，再重新编码到不可变的新对象；未知或超限输入关闭失败。
- 撤回同意阻止新 upload intent 和未开始的处理，但不把撤回表述为删除；用户仍可显式删除既有资产。
- 删除请求受理后所有 GET/worker 路径都拒绝内容；RabbitMQ 至少一次投递，Inbox 和状态条件更新保证重复消息只有一次业务效果。
- 对象已不存在可视为单项删除成功，但仍需验证数据库血缘无可达副本；部分失败保持不可读并进入受限重试，不能恢复内容。

### 运行角色与开发边界

- 同一 module、`cmd/then-server/main.go`、binary 和 OCI 镜像开始支持 `APP_ROLE=api|worker|all`；`eventworker` 运行 Outbox relay、媒体检查、删除与社区通知消费者，`all` 只便于本机开发/集成，生产仍使用独立 API/worker 进程。
- 默认连接本机 PostgreSQL、Redis、RabbitMQ 和 MinIO；不增加 Kubernetes、微服务、Kafka、Atlas、手写迁移或常驻 test 服务。
- 测试仍位于独立 `_test.go` 与 `backend/tests`，通过 build tag 隔离真实依赖；不增加 script 文件或 `APP_ROLE=test`。
- 真实照片入口、第三方 Provider、生成 Job、配额、分享、导出、CDN、长期源照片和多设备同步不属于本切片。

## SMART 与验收映射

- Specific：只交付本人照片的一次性私有上传、检查和删除闭环。
- Measurable：8 个稳定 operationId；跨用户、过期/篡改签名、对象覆盖、重复 finalize、撤回、删除竞态、进程重启及 24 小时期限均有自动化证据。
- Achievable：复用账号/声明、GORM AutoMigrate、Huma 运行时 OpenAPI、本机四项依赖和现有 OCI/CI 门禁。
- Relevant：落实 `AVATAR-REQ-001`～`AVATAR-REQ-010`、`AVATAR-REQ-013/016`，`CLOUD-REQ-002/004`、`CLOUD-RULE-001/004/006/007/009/012/014/019`～`CLOUD-RULE-024` 与 `PRIVACY-RULE-001`～`PRIVACY-RULE-003`、`PRIVACY-RULE-005/006`、`PRIVACY-RULE-009`～`PRIVACY-RULE-020`，为本人 AI 试穿建立必要的数据生命周期前置。
- Time-bound：合同批准后按 Red → Green → Refactor 一次完成代码、真实依赖、实际进程、受限 OCI 和远程 CI；生产地域和法务门禁不因工程通过自动解除。
