## POC 要验证的能力

1. 一张有权处理的完整人物 Look 图片，能否经实际本地 `img2threejs` 和 Three.js 导出/材质处理产生对应的带纹理静态 GLB。只有 TypeScript 工厂、平面贴图、fixture 小模型或第三方样例不能通过。
2. 有登记且获准的本地图片服务时，人物与受支持衣物参考能否实际产生完整图。无服务时记录该能力待验，允许先做受控参考图→模型；不得称完整 AI 图片生成已完成。
3. 同一实际图/GLB 能否经过既有认证、任务、私有存储和最小 Web 界面，完成明确触发、连续观察、再次查看、恢复与删除。

先验一个代表样本及损坏/不合格对照，记录全部尝试。单样本只判断技术可行性和进入 Demo 的资格，不宣称通用衣物保真、生产人群质量或完整产品通过。正式六套、至少 12 组质量矩阵与最低真机目标仍按原验收执行。

## 输入、状态与数据合同

| 项目 | 本轮合同 |
| --- | --- |
| 输入 | 固定版本、已登记来源/权利的合成或授权虚构成人参考；记录图片 hash、工具/模型版本和实际处理路径。真实用户/本人照片入口保持关闭 |
| 图片来源 | 真实本地生成与受控参考图导入分别记录。导入仍须净化、校验、私有发布与明确确认，不伪装成 AI 生成，不绕过模型任务来源检查 |
| 最小界面 | 默认复用现有 Web，会话入口之外只补一个演示旅程：看图/确认→明确生成立体→等待/失败→观察模型→再次查看→取消/删除。参考图路线明确标识“参考图导入→3D 演示” |
| 任务与版本 | 沿用现有 Look/revision、输入快照、owner、image/model 状态与内容去重。页面曝光、刷新、保存和重开不自动生成；旧结果不得覆盖新版本 |
| 持久化 | 使用实际 PostgreSQL 任务/输出事实和私有 MinIO 固定对象版本；重读字节核对 SHA-256。再次查看读取同一有效产物，不用浏览器内存/静态文件冒充后端结果 |
| 保存范围 | 本轮保留的是现有生成结果与任务引用；不新增完整 Look 日期/收藏/穿搭簿领域，不宣称 GRDB 或跨设备保存已完成 |
| 失败与删除 | 失败保留可用图片，用户明确重试；取消/删除立即撤销新访问，再清理实际工具工作目录、对象及迟到结果，重启不复活。只删模型可保留图片 |
| 格式与预算 | 复用实际图片/GLB 校验，GLB ≤10 MiB、纹理最长边 ≤2048、三角形 ≤50,000、一个活动模型；拒绝外部 URI、未知必要扩展、坏 hash 和超限。记录 glTF 合规报告及正/侧/背、连续观察质量 |
| 费用与网络 | 保持本地路线，不自动切云、充值或新增托管服务。工具使用远程模型/转换器时不能记为零费用本地能力，须先收敛实际账户/预算/地域与删除条件；缺条件失败关闭 |

真实返回文件还须核对脸/发型、肢体、衣物数量、款式/图案、遮挡及背面合理性。明显肢体错误、衣物丢失、身份严重变化、意外裸露或仅以平面冒充立体均不通过。记录本机加载耗时和资源占用；本轮 Web 数据不抵扣最低 iOS 真机的 NFR-003。

## 复用与允许影响的职责

| 现有位置 | 本轮职责 |
| --- | --- |
| `backend/internal/application/generation` | 复用接纳、来源确认、去重、状态、结果验证及清理规则；只修真实路径暴露的缺口 |
| `backend/internal/adapter` | 只按实际工具合同增加必需的本地适配，复用 postgres/objectstore；不建通用多 Provider 平台 |
| `backend/internal/bootstrap`、`backend/internal/platform/config` | 在现有 api/worker/all 组装与唯一配置中显式接入；默认关闭，缺工具/边界不启动生成 |
| `backend/internal/adapter/httpapi`、`frontend/src/api` | 复用实际 Huma operation；缺口先更新唯一 Go 契约，再由运行时 OpenAPI 生成 Client，不手写生成文件 |
| `frontend/src/app`、`frontend/src/components`、`frontend/tests` | 沿当前路由布局、DESIGN token、正式组件与请求入口补最小旅程及相应验证；开工时读 frontend/AGENTS，不创建独立 Demo 应用 |
| 本 Plan、Acceptance 14、Backlog | 分别维护任务状态、真实结果及全局优先级，不把 fixture 回归抄成真实生成通过 |

不新增第二个数据库、Go module、服务入口、GPU 服务、工作流引擎、WebSocket 或通用资产上传平台。开发隔离库沿用现有 GORM 规则；生产数据保留迁移仍需在部署前关闭。已有并行工作不得覆盖或重新实现。

## Checklist 与执行顺序

- [ ] `14-02-BASELINE-01` 核对 `then-server/main` 与生成后端 worktree 的实际提交/改动，明确本片采用的基线及必要增量；登记真实工具版本、离线/网络依赖、运行合同、授权代表图与隔离 PG/Kafka/MinIO。缺工具或需要未获准的远程服务时写明阻断，不用 fixture 代替。依赖：本轮范围；退出：一条可复现命令/运行合同和实际输入具备，或有明确失败结论。
- 复用原 `14-01-LOCAL-POC-01`：先执行实际图片→工厂/中间产物→带纹理 GLB→格式/视觉/预算校验；有真实本地图片服务时再验证图片生成子范围。模型与图片分别记录，不新造同义 POC 任务；部分通过时原任务保持未完成。
- [ ] `14-02-DEMO-01` 在模型 POC 通过后接最小 Web 旅程。实际参考图导入或本地图片服务路径先形成可执行合同，再接既有图片发布/确认与模型来源规则；不可通过伪造 fixture 图片绕过。退出：UI、实际 HTTP、PG 输出与 MinIO 字节指向同一图/GLB，刷新和重复点击复用，不自动生成。
- [ ] `14-02-VERIFY-01` 验证两账号/访客隔离、同版本重复请求、API/worker 重启后读回与任务恢复、坏产物/工具失败、取消和删除后迟到结果不复活；检查私有对象和本地中间文件实际清理。既有工程测试可复用，但真实工具的故障/清理能力必须独立证明。依赖：DEMO；退出：对应场景有实际步骤、结果与可长期复核证据。
- [ ] `14-02-DECISION-01` 回写 Acceptance 的尝试清单、通过子范围、失败/未验项、耗时/实际费用及 go/no-go，再同步 Backlog。依赖：POC/VERIFY 的实际结果；退出：能判断继续单套真实产品实现、仅保留图片路线，或因模型不可行停下，不默认解锁全部后续能力。

环境核对约 0.5 人日；代表能力 POC 首个检查点 1～2 人日。Demo 的 1～3 人日估算仅在 POC 与复用基线具备时有效，不含工具缺失、质量返工及外部条件等待。每 1～2 个工程人日复核实际结果；超时记录问题并决定下一步，不把时间盒结束记为通过。
