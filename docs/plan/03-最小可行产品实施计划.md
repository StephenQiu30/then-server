## 实施原则

- 先交付单设备、本地优先的 P0 完整闭环；账号与多设备同步固定进入 P1。
- 每个阶段都形成可运行的垂直切片，不先铺满空目录、空接口和空表。
- 先完成领域模型、数据库和系统能力 POC，再扩展页面数量。
- 记账正确性、活跃行程可靠落盘和权限降级优先于视觉动效和智能建议。
- OpenAPI 与 PostgreSQL schema 只有在关联设计批准后才加入业务定义。
- 穿搭、社交、共享、预算、票据附件、长期原始轨迹、国内地图适配、特殊通知、商业化和云 OCR 不进入本计划。

### 阶段 0：范围冻结（已完成）

目标：固定当前边界，避免 schema、接口和 UI 为不实施能力留下占位。

已确认：

1. P0 单设备本地优先，首笔正式交易前确认本币；只支持同币种转账。
2. 正式交易通过退款、冲销和原子更正处理，不直接改写历史分录。
3. 原始轨迹只保留到摘要确认或行程丢弃，票据图片只保留在 OCR 会话内。
4. Apple 地图按系统能力尽力提供路线与交接，不设置城市/交通方式覆盖门槛，不接国内地图供应商。
5. 不实现预算、Time Sensitive、订阅、付费、免费容量或权益分层。

退出条件：上述决定已写入 PRD、设计、计划和验收，且不存在相关空入口、空表、空接口或临时 SDK。文档范围冻结已满足；静态仓库边界由阶段 5 的可重复脚本持续守护，运行时文件/网络与深链证据在阶段 6 收口。

### 阶段 1：工程与数据基础

目标：建立最小可构建 App、集中本地数据库、依赖容器和真实系统能力 POC。

- 创建 Xcode 工程、单 ThenApp module 和测试 target。
- Exact 固定 GRDB 与 Swift OpenAPI packages，提交 Package.resolved。
- 建立 App/Core/Features/Services/Data 的最小真实代码边界。
- 建立 DatabasePool、集中 DatabaseMigrator、领域 ID/时间/金额/坐标值对象。
- 统一数据库 Data Protection 应用函数：每次打开显式设置目录，再设置主文件/WAL/SHM 为 `completeUntilFirstUserAuthentication`；Debug UI 测试路径复用同一实现。自动化用委托真实文件系统的记录器断言每个保护操作，真机再检查实际属性和锁屏语义。
- 冻结已经执行的 migration identifier；`v6_relax_manual_location_coordinates` 在旧版地点坐标三列仍为 `NOT NULL` 时原子重建地点表并保留既有数据、外键与索引，在当前结构上为空操作；`v7_add_journey_expense_review_state` 只追加 Journey 消费复盘三态并按既有关系安全回填。
- 建立历史 `v1...v5` schema 夹具：先插入带坐标地点和关联计划/路线/提醒，再执行全部最新 migration，断言旧数据不变、三列可为空、`foreign_key_check` 与 `integrity_check` 通过，随后实际保存纯文字目的地。
- 建立 App Router、权限状态和脱敏错误体系。
- 完成 EventKit、UserNotifications、Core Location、MapKit 和 Vision 真机 POC。

退出条件：工程可构建测试；空数据库创建/迁移通过；每个系统能力有真机证据和降级结论。

### 阶段 2：本地记账闭环

目标：无需账号和网络完成可靠个人账本。

- 账户、分类、交易和分录本地 schema。
- 首次离线初始化 LocalProfile、系统账户、默认现金账户和内置分类；发布首笔正式交易前确认本币。
- 完成现金、银行卡、电子钱包、信用卡与一级收入/支出分类的创建、归档、恢复和选择器；状态切换保持父子分类始终一致，余额始终从 posted 分录按账户正常方向重建。
- 支出、收入、转账、期初、退款、冲销和原子更正领域用例。
- 在快速记账中提供“还款”展示选项，复用 `transfer` 领域命令并把来源约束为资产、目标约束为信用卡负债；不新增交易种类或报表口径。
- 为退款、冲销和更正实现 canonical root head compare-and-swap、当前 replacement 解析、有效退款累计、稳定命令标识与原子幂等回读。
- 快速记账、流水、详情、账户/分类和基础月报。
- 余额与月度收支可重建查询、月度/时区边界测试。
- 在同一只读快照中生成所选月份合计、分类排行与截至该月的六个月支出趋势；零月份补齐，不新增报表缓存表。
- 增加资金账户、收入/支出分类、行程关联状态与现有本地搜索词的组合筛选；流水匹配 current replacement，月报按命中 canonical root 的全部正式分录保持退款、冲销与更正净额。
- OCR 候选与确认流程；识别不达标时保持手动入口并关闭非必要入口。

退出条件：所有账务不变量和 [`../acceptance/03-最小可行产品系统验收.md`](../acceptance/03-最小可行产品系统验收.md) 的本地记账场景通过。

### 阶段 3：日历与出行闭环

目标：从日历或手动计划到提醒、导航和实际行程。

- 日历授权、来源选择、完整扫描和事件快照。
- 重复事件、全天、时区、事件移动/取消/删除处理。
- 地点确认、TripPlan、RouteEstimate 和 DepartureReminder。
- 完成事件到计划的本地垂直切片：从真实 `GRDBCalendarRepository` 持久化的 occurrence 构建编辑器 seed，覆盖普通事件来源值、地点确认和全天事件显式时间门禁。
- 使用真实 SQLite 仓储断言 TripPlan 字段来源、`event_trip_links` 的 occurrence ID/source version、提醒期望状态和 CalendarOccurrence 不变；再以失效 occurrence 注入证明地点、计划、提醒和关系全部回滚。
- 在计划保存后再次提交同一 occurrence 的标题、地点与时间新版本，断言 CalendarOccurrence 产生 pending revision，而 TripPlan、LocationSnapshot、DepartureReminder 与 EventTripLink 保留用户采用时的值和 source version。
- 追加 `v8_add_trip_plan_revision_review`：为 TripPlan 增加乐观版本和标题来源字段，为 revision 增加解决时间与状态一致性约束；历史标题安全回填为用户值，空库、v7 升级、重复执行、外键与完整性都必须测试。
- 扩展 Calendar/TripPlan Repository：读取来源差异与关联计划；同一 occurrence 重复建计划闭合失败；“保留当前计划”只解决所见 revision；“采用到计划”在一个 SQLite 事务中校验 occurrence/link/plan 三重版本，更新计划与关系、使旧路线失效并解决 revision。
- 增加统一来源变化处置页和计划编辑确认页；日程事件与 Today 待处理入口复用同一状态。采用前必须重新确认事件地点文本、到达/出发时间、路线与提醒；陈旧页面显示重新加载，不静默重试。
- 自动化覆盖无关联事件、单一关联计划、历史重复关系、忽略、采用、再次扫描、陈旧 plan/source version、事务故障、路线失效、提醒拒绝与 UI 可达性；Debug fixture 只能证明本地产品流，真实 EventKit 变化通知仍由真机验收。
- 自动化只覆盖编辑器、领域和真实 SQLite 边界；EventKit 真实授权、系统事件变化通知到可见页面和系统通知 request 仍在最低 iOS 18 真机上取证。
- Apple 地图路线/调起和无结果/打开失败降级，不设置覆盖率门槛。
- 为打开失败降级增加可注入的 `DestinationClipboard` 系统边界：ViewModel 保存失败所属 TripPlan，只在用户点击后按“非空地址 → 地点名称”规则写入，并显示成功状态；不自动读写剪贴板。
- 失败卡片使用原生 `Section`/`Label`/`Button` 和 SF Symbol，同时展示错误、目的地和复制操作；不只依赖红色。联合开始地图失败时先展示已保存 Journey，关闭后保留该计划的复制降级。
- 添加 fake 剪贴板的 ViewModel 测试，覆盖失败前零写入、地址优先、空白地址回退名称、成功文案和新失败清理旧成功态；再以仅 Debug 导航失败夹具运行真实 GRDB XCUITest，断言 handoff 失败、复制入口和返回计划。Release 可执行文件必须不包含夹具参数。
- `v4_create_journey_recording` 集中定义 Journey、TrackSegment 和 TrackPoint，以部分唯一索引限制每设备一个未收口行程，并验证状态、segment/point 序号、坐标和 manifest 约束。
- App 级 `JourneyRecordingService` 使用 When In Use、iOS 18 live location updates 与可见后台活动；实现开始、暂停、新 segment 恢复、样本先落盘后质量投影、定位拒绝/低精度降级和启动恢复。
- 结束固定经过 `finalizing → reviewing`，冻结 sequence/point count/SHA-256 manifest 并计算摘要；确认或丢弃在同一 SQLite 事务中清理所有原始点与片段，任意故障不得宣称已完成。
- 使用 fake location adapter 和故障注入覆盖重复开始、权限拒绝、单调点序、暂停/继续新段、收尾幂等、无点摘要、确认/丢弃清理、清理回滚与冷启动恢复。
- 真机验证锁屏、后台、低精度、权限撤回、系统杀进程和耗电。

退出条件：不依赖第三方回传完成计划—导航—Journey 闭环，所有高风险真机场景有证据。

### 阶段 4：今天与生活关联

目标：把两条独立能力组织为一个产品。

- `TodaySnapshotService` 只读组合今日事件、下一次出发、月度收支摘要、唯一未收口 Journey 和真实待处理项；不创建首页汇总表，各块失败独立降级。
- 把根导航完整为固定“今天—账本—日程—行程—我的”五 Tab；行程 Tab 同时显示计划、未收口状态和已完成摘要，我的 Tab 不留伪账号/云备份入口。
- `v5_create_life_links` 只建 `transaction_journey_links`；关系引用 posted canonical root，同 owner 交易 root + Journey 唯一，只允许用户确认并幂等创建。
- 新增前向 `v7_add_journey_expense_review_state`，为 Journey 持久化 `pending | no_expense | has_expense`；既有正式关系回填 `has_expense`，其余只回填 `pending`，不修改已执行的 `v4`，并用历史 `v1...v6` 升级夹具证明既有 Journey、关系与账务不变。
- 行程结束后提供记账/关联已有交易/显式“本次无消费”分支；标记无消费、创建关系和解除关系必须在显式事务中同步维护复盘状态。汇总从关联 root 的 posted 分录净影响重建，解除最后一条关系后回到待复盘且不删除任一端。
- 待处理只展示已持久化的 CalendarOccurrence pending revision 与 `finalizing | reviewing` Journey；OCR、文件导入和同步冲突不留空分组。
- 全局新增面板和无权限/无数据空态使用系统控件、SF Symbols 和语义样式，不依赖自定义组件才能完成主流程。

退出条件：事件—计划—Journey—交易主闭环端到端通过；解除/删除关系不破坏两端实体。

### 阶段 5：本地 MVP 加固

- 实现版本化 JSON 导出：在一次 SQLite 一致性读取中导出账户、交易、分录、确认计划、Journey 摘要和生活关系，金额使用最小货币单位，排除日历来源身份、通知 request、导航诊断、票据图片和原始轨迹。
- 用委托真实文件系统的记录器断言每个导出随机子目录和最终 JSON 都收到 `complete`，数据库目录、主文件、WAL 与 SHM 都收到 `completeUntilFirstUserAuthentication`。Simulator 不可靠返回保护属性，最低 iOS 18 真机必须检查实际属性并完成锁屏读写门槛。
- 实现受保护临时导出目录、系统分享完成回调与成功/取消/失败清理；生成失败不得修改源数据或留下半成品。
- 把文件数据写入纳入可替换文件系统边界；用实际写出合成部分文件后抛出 `fileWriteOutOfSpace` 的故障注入，断言容量不足映射为稳定领域错误、随机目录完全删除、源数据库计数不变、用户看到脱敏可重试提示，随后正常导出仍能成功。P0 不实现分批或多文件降级。
- 实现日历缓存清理：先删除本地 EventTripLink，再原子清理 revision、occurrence、series、scan 和 source，保留计划、提醒、Journey 与账务。
- 实现已收口 Journey 删除：级联清理轨迹和交易—行程关系，保留 TripPlan、交易与分录；未收口记录继续走完成/丢弃状态机。
- 实现本机全量删除协调器：停止定位、取消本 App 出发提醒、原子清空全部用户表、重新 bootstrap 新本地资料，并让根环境切换到新 identity。
- 在根视图按 scene phase 覆盖无业务正文的隐私遮罩，确保 `inactive/background` 的系统任务切换快照不显示敏感内容。
- App 环境启动时清扫固定导出根目录；创建新导出前再次清扫，失败时阻止生成并交给现有可重试错误入口展示。
- 提供本地数据风险说明，不虚构云备份。
- 将“诊断与关于”收敛为只读发布元数据：用纯值模型从 App bundle 读取名称、版本与构建号，显示固定的“单设备本地”和“诊断收集未启用”状态。缺失 bundle 字段降级为“未知”，不增加日志、诊断包、剪贴板或网络边界。
- 为发布信息模型增加缺字段和完整字段单元测试；扩展真实 App XCUITest 滚动到诊断与关于区域，断言 `0.1.0 (1)`、单设备本地与诊断收集未启用，并纳入“我的”最大辅助字号及原生无障碍审计。
- 以 Xcode 编译器导出的生产字符串建立 `Localizable.xcstrings` 简体中文基线，移除空键并保留类型正确的位置参数；手工审核 `InfoPlist.xcstrings` 中 App 名称和日历、相机、定位权限用途说明。两份目录加入 ThenApp target Resources，不创建 `.strings` 或第二份目录。
- 新增 `scripts/validate-ios-localization.sh`：验证两份目录唯一存在且 `sourceLanguage = zh-Hans`、无空键、可由 `xcstringstool` 编译、项目资源引用唯一；通过 Xcode 导出的生产字符串逐键比对目录，并可对候选 `.app` 断言 `zh-Hans.lproj` 中的 `Localizable.strings` 与 `InfoPlist.strings` 均已打包。使用独立临时副本删除一个合成键，证明漂移门槛稳定失败。
- 完成数据库迁移失败、低存储、断网和异常恢复。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| P0 范围过大 | 账号、预算、国内多地图、票据附件、长期轨迹、特殊通知、商业化和穿搭均不进入当前实现；优先四段主闭环。 |
| 账务正确性返工 | 先批准分录/更正语义并完成领域测试，再写页面。 |
| 日历来源不稳定 | 完整扫描、来源与 overlay 分离、模糊匹配人工处理。 |
| 后台轨迹丢失或耗电 | App 级 owner、先落盘、真机长行程和自适应采样 POC。 |
| MapKit 路线不可用 | 允许手动出发时间、复制地址和返回计划；不以供应商扩展或覆盖率承诺阻塞发布。 |
| 同步拖慢首版 | P0 固定本地模式；云同步只在 P1 专项批准后启动。 |
| 单 schema 生产演进受限 | 初始业务模型一次批准；首次复杂生产变更前重新评估迁移。 |
| 视觉设计缺失 | 系统流程批准后再对四个关键场景进行三方向视觉探索，不提前固化 token。 |

## 发布与回滚

- 每个阶段保持可关闭的 feature flag；关闭后不得遗留无法访问的用户数据。
- 本地 schema 一旦进入用户构建只通过有序 GRDB migration 演进，不重建用户数据库。
- OpenAPI 破坏性变更必须提供兼容版本或升级路径。
- PostgreSQL 变化先在专用非空库 Atlas dry-run，任何 DROP 默认阻断。
- MapKit、OCR 或同步失败可切回本地手动路径；当前不切换第三方地图或云 OCR。
- 活跃 Journey、未同步账务和待确认草稿在版本升级/回滚前有兼容验证。
