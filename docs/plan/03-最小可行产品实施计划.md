## 实施原则

- 先交付单设备、本地优先的 P0 完整闭环；账号与多设备同步固定进入 P1。
- 每个阶段都形成可运行的垂直切片，不先铺满空目录、空接口和空表。
- 先完成领域模型、数据库和系统能力 POC，再扩展页面数量。
- 记账正确性、活跃行程可靠落盘和权限降级优先于视觉动效和智能建议。
- OpenAPI 与 PostgreSQL schema 只有在关联设计批准后才加入业务定义。
- 穿搭、社交、共享、预算、票据附件、长期原始轨迹、国内地图适配、特殊通知、商业化和云 OCR 不进入本计划。

### 阶段 0：范围冻结（已完成）

目标：固定当前边界，避免 schema、接口和 UI 为不实施能力留下占位。

已确认：

1. P0 单设备本地优先，首笔正式交易前确认本币；只支持同币种转账。
2. 正式交易通过退款、冲销和原子更正处理，不直接改写历史分录。
3. 原始轨迹只保留到摘要确认或行程丢弃，票据图片只保留在 OCR 会话内。
4. Apple 地图按系统能力尽力提供路线与交接，不设置城市/交通方式覆盖门槛，不接国内地图供应商。
5. 不实现预算、Time Sensitive、订阅、付费、免费容量或权益分层。

退出条件：上述决定已写入 PRD、设计、计划和验收，且不存在相关空入口、空表、空接口或临时 SDK。当前已满足。

### 阶段 1：工程与数据基础

目标：建立最小可构建 App、集中本地数据库、依赖容器和真实系统能力 POC。

- 创建 Xcode 工程、单 ThenApp module 和测试 target。
- Exact 固定 GRDB 与 Swift OpenAPI packages，提交 Package.resolved。
- 建立 App/Core/Features/Services/Data 的最小真实代码边界。
- 建立 DatabasePool、集中 DatabaseMigrator、领域 ID/时间/金额/坐标值对象。
- 建立 App Router、权限状态和脱敏错误体系。
- 完成 EventKit、UserNotifications、Core Location、MapKit 和 Vision 真机 POC。

退出条件：工程可构建测试；空数据库创建/迁移通过；每个系统能力有真机证据和降级结论。

### 阶段 2：本地记账闭环

目标：无需账号和网络完成可靠个人账本。

- 账户、分类、交易和分录本地 schema。
- 首次离线初始化 LocalProfile、系统账户、默认现金账户和内置分类；发布首笔正式交易前确认本币。
- 支出、收入、转账、期初、退款、冲销和原子更正领域用例。
- 快速记账、流水、详情、账户/分类和基础月报。
- 余额与月度收支可重建查询、月度/时区边界测试。
- OCR 候选与确认流程；识别不达标时保持手动入口并关闭非必要入口。

退出条件：所有账务不变量和 [`../acceptance/03-最小可行产品系统验收.md`](../acceptance/03-最小可行产品系统验收.md) 的本地记账场景通过。

### 阶段 3：日历与出行闭环

目标：从日历或手动计划到提醒、导航和实际行程。

- 日历授权、来源选择、完整扫描和事件快照。
- 重复事件、全天、时区、事件移动/取消/删除处理。
- 地点确认、TripPlan、RouteEstimate 和 DepartureReminder。
- Apple 地图路线/调起和无结果/打开失败降级，不设置覆盖率门槛。
- TripRecordingService、临时轨迹批写、异常恢复、行程总结和确认后的原始点原子清理。
- 真机验证锁屏、后台、低精度、权限撤回、系统杀进程和耗电。

退出条件：不依赖第三方回传完成计划—导航—Journey 闭环，所有高风险真机场景有证据。

### 阶段 4：今天与生活关联

目标：把两条独立能力组织为一个产品。

- 今天首页的时间线、下一次出发、月度收支摘要、进行中行程和待确认事项。
- 本机 `EventTripLink`、`TransactionEventLink` 与可同步设计边界内的 `TransactionJourneyLink`；事件身份及事件关系不得上传。
- 行程结束后的记账/关联/无消费分支。
- 待确认箱统一容器和各领域独立处理器。
- 深层链接、通知入口、全局新增面板和无权限/无数据空态。

退出条件：事件—计划—Journey—交易主闭环端到端通过；解除/删除关系不破坏两端实体。

### 阶段 5：本地 MVP 加固

- 完成结构化数据导出和本地分层删除。
- 提供本地数据风险说明，不虚构云备份。
- 完成数据库迁移失败、低存储、断网和异常恢复。
- 隐藏账号和冲突入口，但保留协议边界；不创建云附件或原始轨迹入口。

### 阶段 6：真机 Beta 与发布

- 在最低支持设备和目标系统版本完成核心旅程。
- 使用脱敏或合成数据验证 OCR、长列表和轨迹。
- 完成 VoiceOver、Dynamic Type、减少动态效果和锁屏隐私。
- 完成依赖、安全、隐私清单、日志、诊断包和删除证据。
- 通过小规模 beta 确认记账耗时、行程恢复、路线成功/失败降级和电量目标。
- 冻结发布范围；未通过能力通过 feature flag 关闭，不用文案掩盖。

### P1：Go 后端与同步

仅在 P0 发布并完成账号、合规、云地域和同步范围专项批准后执行，不作为 P0 发布条件：

- Sign in with Apple、会话、设备和账号删除设计落地。
- 依据批准领域模型一次性写入 `backend/schema.sql` 初始业务结构。
- 依据批准接口目录写入 `backend/openapi.yaml`，完成 Swift 生成 POC。
- 实现单进程 Go HTTP、Repository、Service、contract test 和同进程 Outbox。
- 实现 mutation push、按用户串行分配的 cursor pull、tombstone、conflict staging 和稳定分页 snapshot reset。
- 完成 Testcontainers PostgreSQL、Atlas dry-run 和越权/幂等测试。

退出条件：多设备、长期离线、冲突、删除和信封加密验收通过；本地模式不受影响，且图片/原始轨迹不进入同步。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| P0 范围过大 | 账号、预算、国内多地图、票据附件、长期轨迹、特殊通知、商业化和穿搭均不进入当前实现；优先四段主闭环。 |
| 账务正确性返工 | 先批准分录/更正语义并完成领域测试，再写页面。 |
| 日历来源不稳定 | 完整扫描、来源与 overlay 分离、模糊匹配人工处理。 |
| 后台轨迹丢失或耗电 | App 级 owner、先落盘、真机长行程和自适应采样 POC。 |
| MapKit 路线不可用 | 允许手动出发时间、复制地址和返回计划；不以供应商扩展或覆盖率承诺阻塞发布。 |
| 同步拖慢首版 | P0 固定本地模式；云同步只在 P1 专项批准后启动。 |
| 单 schema 生产演进受限 | 初始业务模型一次批准；首次复杂生产变更前重新评估迁移。 |
| 视觉设计缺失 | 系统流程批准后再对四个关键场景进行三方向视觉探索，不提前固化 token。 |

## 发布与回滚

- 每个阶段保持可关闭的 feature flag；关闭后不得遗留无法访问的用户数据。
- 本地 schema 一旦进入用户构建只通过有序 GRDB migration 演进，不重建用户数据库。
- OpenAPI 破坏性变更必须提供兼容版本或升级路径。
- PostgreSQL 变化先在专用非空库 Atlas dry-run，任何 DROP 默认阻断。
- MapKit、OCR 或同步失败可切回本地手动路径；当前不切换第三方地图或云 OCR。
- 活跃 Journey、未同步账务和待确认草稿在版本升级/回滚前有兼容验证。
