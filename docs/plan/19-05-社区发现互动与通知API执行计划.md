## Spec

- 关联：COMMUNITY-REQ-006/007/008/009/010/013/015、COMMUNITY-ACC-004/005/006/007/010/011，[Design 21](../design/21-后端产品边界与领域设计.md)、[Design 22](../design/22-后端数据库设计.md)、[Design 23](../design/23-后端接口设计.md)。
- `GET /feed?type=discover|following` 以 `(published_at,id)` 倒序稳定分页。discover 可匿名；following 必须登录。请求携带有效 Cookie 时，discover/详情返回本人 `liked/bookmarked/following_author` 状态并过滤双向屏蔽；携带无效 Cookie 返回 401 并清除旧 Cookie，不能静默降级成匿名。
- `GET /search/posts?q=...&tag=...` 至少提供一个条件；q 规范化后 2～80 字，使用 PostgreSQL 有界 `ILIKE` 并转义 `%/_`，tag 为已规范化的 1～20 字；不引入搜索集群、全文索引服务或热度排序。`GET /profiles/{handle}/posts` 与详情、Feed、搜索共用 active 作者 + 当前批准版本 + 屏蔽过滤。
- 公开摘要返回允许公开的作者资料、文字、标签、图片数量、发布时间及从关系表聚合的点赞/评论计数；不返回收藏计数或收藏者身份。登录态 viewer flags 只描述本人关系，不暴露其他用户 ID。
- 点赞、收藏、关注和取消使用 PUT/DELETE，重复请求幂等。收藏列表仅本人可读并执行当前可见性过滤；不能自关注。关系表是事实源，首版不新增计数缓存或 fanout 表。
- `PUT /users/me/blocks/{user_id}` 在按 UUID 排序锁定两账号后建立屏蔽并删除双方关注；解除屏蔽不恢复关注。双向屏蔽阻止后续关注、点赞、评论、收藏和个性化列表命中，但不承诺阻止退出登录后的匿名公开浏览。
- 评论 ID 由客户端 UUID 提供；正文规范化后 1～500 字。只允许根评论和一级回复，回复必须与父评论同帖且父为根评论；创建后进入 pending，正文不可编辑。moderator/admin 审核通过后公开，拒绝保持私人；作者删除或运营下架时清空正文并保留最小占位，已批准一级回复仍可按树读取。
- 评论审核决定携带 `expected_revision/decision/reason_code` 并锁定评论；相同决定幂等，不同或迟到决定 409。原帖不再公开、作者/评论者被封禁或双方屏蔽时，评论列表与新互动立即拒绝；审核不能让不可见原帖上的评论公开。
- 现有 `POST /reports` 扩展为 `target_type=post|comment`，始终保存所属 post；同一举报人对同一目标最多一个 open 举报。评论举报处理与评论下架独立，解决举报不自动删除评论。
- 通知种类固定为 `comment_published/reply_published/followed/post_reviewed/comment_reviewed/appeal_resolved`；赞和收藏不通知。产生动作的业务事务写 Outbox，RabbitMQ 至少一次投递，worker 以 `(recipient,event_id,kind)` 唯一键和 Inbox 去重落库。消息只传 ID/版本/种类，不传正文、邮箱或图片地址。
- `GET /notifications` 仅本人分页读取；被撤回/下架/删除或屏蔽后不可见的公开目标从新列表中滤除，审核结果只向所属作者返回最小状态。`PUT /notifications/{id}/read` 幂等标记本人通知；Redis 丢失不影响通知事实。
- 用户只能针对作用于本人帖子/评论的 `post_remove/comment_remove/post_reject/comment_reject` 治理动作创建一条 open 申诉；理由 1～500 字。admin 可 uphold/reverse；反转写新治理动作并复核作者、原帖、屏蔽和当前状态，不能覆盖原审计，也不能自动恢复作者主动撤回/删除的内容。账号封禁申诉不在本片，避免为已失效会话伪造入口。
- PostgreSQL 是关系、评论、通知、申诉与状态事实源；RabbitMQ 只承载可重放投递。本片不新增兼容路径、通用 RBAC、通用工作流、公共 MinIO 桶、物化 OpenAPI 或独立 test 服务。

## SMART 与退出条件

一个切片内完成“一名作者发布 → 第二名用户发现并关注/赞藏/评论 → moderator 批准评论 → 作者收到不含正文的通知 → 任一方屏蔽后关系和新互动被阻断 → 作者撤回后 Feed/搜索/评论/通知目标均不再公开 → 合法治理动作可申诉且反转不绕过作者状态”的可测闭环。只有 checklist 全部完成并同步 Acceptance 19 才将本片标为 completed；frontend/App 页面、机器学习 Feed、私信、短视频和账号封禁申诉不在本片。
