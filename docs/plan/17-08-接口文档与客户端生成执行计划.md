## 范围契约与影响面

提供仅回环地址的 Swagger UI、同源原始 YAML 地址和 iOS 显式生成命令。输入固定为唯一 `backend/openapi.yaml` 与现有生成配置，输出为页面及忽略目录中的 Types/Client；正式 App 构建继续使用插件。容器只读挂载契约，不接收鉴权、不开放请求调试或外部 validator。

新增 Compose 的职责是固定开发文档镜像、端口和挂载；`openapi-docs.sh` 只管理独立项目的 up/down/status；`generate-ios-api.sh` 解析当前工程 BUILD_DIR 并运行已缓存的锁定生成器。失败必须保留非零状态；生成器未准备时明确告知，不静默安装替代工具。文档/API 服务相互独立，无数据、数据库 migration、媒体生命周期变化。页面审查发现 400/500 错误继承了通用 NOT_READY 示例，本切片同步按实际 Handler 修正响应示例，不改变 schema 或运行行为。

不包含业务 API 扩展、Go Swagger 注解、第二份契约、线上发布、远程 Try it out、额外 Swift module 或修复现有 MainActor 编译冲突。后者继续归 17-01 和 Design 01 的待确认提案。

## 验收与失败场景

1. 本地 Swagger 显示 OAS 3.1（原始契约精确版本为 3.1.2）和两个已实现健康 operationId；页面不加载 Petstore，关闭外部 validator；400/500 示例与实际错误对应。
2. `/openapi.yaml` 与源文件逐字节相同；容器端口仅绑定回环地址。
3. 生成 Types/Client 与实际插件产物一致；非法参数、缺失生成器或生成失败返回非零。
4. 生成产物不入 Git，不加入 App target；明确区分生成通过与当前编译失败。
5. up 可重建挂载，down 只清理本工具容器；无 API、数据库或用户数据副作用。

## 迁移、回滚与完成判定

无需数据迁移。执行 `scripts/openapi-docs.sh down` 并回滚新增工具和对应文档即可撤销；不修改生产后端、现有符号链接、插件及生成配置。完成要求所有本切片任务有真实验证证据；17-01 的 App 编译阻断不在本切片伪标为通过。
