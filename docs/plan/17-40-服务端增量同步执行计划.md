## 状态与范围

- 只改 `then-server/backend` 与相关文档。服务端不自动上传本机事实、不新建匿名账号、不处理 Look/媒体字节。已有单实体 CRUD、revision 与权限合同继续作为写入入口。

## MVP 实施合同

1. PostgreSQL 增加 `sync_positions(owner_id,seq,seeded)`、`sync_changes(owner_id,seq,kind,entity_id,action,revision,created_at)` 和 `wardrobe_item_deletions(owner_id,id,deleted_at)`。同一 owner 的首次读取或写入在事务中一次性登记现有结构化记录与已有墓碑；水位锁覆盖种子和后续修改，账号删除级联清理。
2. 衣橱、计划、实际穿着/反馈、日记的所有真实变更在业务事务内追加记录；同内容创建/反馈命令重试不追加。衣橱删除的历史处理、计划/实际状态重算与解除日记引用、媒体删除的日记修订同样记录；失败回滚不推进水位。衣橱墓碑阻止原 ID 迟到重建。
3. `GET /sync/changes` 使用当前 active Cookie，`after` 为版本化 owner 绑定游标，`limit` 默认为 50 且范围 1～100；返回有序 `{changes,next_cursor,has_more}`。每项只含 seq、kind、entity_id、action、可空 revision；不返回正文、凭据或媒体 key。坏/跨账号/超前游标拒绝，成功响应 `no-store`；无万能批量写入端点。
4. 真实 PostgreSQL 验证两账号、种子、跨页、并发提交、不漏变更、重复命令、所有领域和连带修订、删除防复活、删号级联；HTTP/运行时 OpenAPI 验证认证、游标和最小字段。未启用媒体同步时不能宣称图片已恢复。
