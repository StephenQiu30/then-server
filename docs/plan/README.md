## 单切片要求

每份执行计划合并以下内容：状态与授权、需求/设计/验收 ID、可见输入/状态/保存/删除/失败合同、影响文件与职责、带状态和依赖的 checklist、可复现测试与退出条件。

用户要求的全局 Backlog 维护在仓库根目录唯一的 [`BACKLOG.md`](../../BACKLOG.md)；未形成 Plan 的条目使用 `BL-*` 临时业务追踪 ID，正式开工时登记接续 FF-SS 任务，不另造同义事项。先回写原 Plan/Acceptance，再同步 Backlog 勾选；延期/退役不勾为完成。

SMART 时间盒用于及时暴露风险，不替代真实完成标准。测试不足保持待验；当前未实施功能不提前创建空代码。完成后同步现有状态与证据，不追加重复日志。

## 编号与阅读顺序

本轮审核决定保留现有文件编号，不为补齐空号整体重排。

- PRD/Acceptance 的 10～19 是稳定领域标识，必须对应；Plan 的 FF-SS 属于同一领域的独立切片。REQ/ACC/checklist ID 是追踪身份，不是排序序号。
- Design 使用独立序号，通过总索引映射领域，不能把 Design 11 误认为 PRD 11。研究类语义文件名（如 threejs-avatar-research.md）无需补数字。
- 删除编号不复用，新切片在本领域继续递增。11-05 是新三维闭环，不挪用已退役的 11-02。
- 阅读顺序由本页与产品计划表示，当前阶段按 Design 20 的代表资产、离线闭环、按需生成与日常产品能力组织，不复用旧 P1/P5 并行路线。
- 只有职责/语义确实改变才重命名，必须在同一提交更新两个仓库引用和证据索引；不得为顺眼批量改几百个链接、制造旧新编号映射兼容表。
