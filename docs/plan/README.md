## 文档类型

| 类型 | 文件名 | 职责 |
| --- | --- | --- |
| 产品级实施计划 | `NN-中文名称实施计划.md` | 管理跨功能阶段、里程碑、顺序、依赖、风险和发布节奏 |
| 单切片执行计划 | `FF-SS-中文名称执行计划.md` | 固定一个可独立交付切片的范围契约、系统影响、任务、测试、证据、回滚和完成判定 |

`FF` 对应稳定的单功能 PRD 编号，`SS` 是该功能内从 `01` 开始递增的切片编号。design 独立编号并通过 [`../README.md`](../README.md) 显式映射；design 重排不改变执行计划编号。

## 何时创建单切片执行计划

只有同时满足以下条件才创建：

1. 对应单功能 PRD 与 design 已批准。
2. 切片已进入近期产品实施计划，用户价值、范围和发布边界明确。
3. 会影响行为、数据、接口、隐私或兼容性的关键决策已经关闭，或被明确写成阻断任务与关闭路径。
4. 计划能够同时说明用户/系统契约、可执行任务、依赖、测试、证据、迁移和回滚；不得只写模糊 TODO。

远期能力继续维护 PRD/design 和产品级实施计划，不预建可能失效的占位执行计划。

## 状态规则

单切片执行计划保留两个正交状态：

- 契约状态：`draft`、`approved`、`superseded`。
- 执行状态：`pending`、`in_progress`、`completed`、`blocked`。

任务状态只使用 `pending`、`in_progress`、`completed`、`blocked`；同一份执行计划同一时间最多有一个任务处于 `in_progress`。没有测试、评审、构建、迁移演练或其他约定证据时，不得仅凭代码存在标记任务或执行计划为 `completed`。

契约发生会影响行为、数据、接口、隐私、兼容或验收的变化时，先把契约状态退回 `draft`，将受影响任务标记为 `blocked`，回写 PRD/design 并重新批准，再继续修改代码。POC 得出 no-go 不妨碍执行计划在证据和关闭结论完整时标记 `completed`，但不能因此启用被否决的生产能力。

```markdown
## 状态
- 契约状态：draft | approved | superseded
- 执行状态：pending | in_progress | completed | blocked

## 追踪关系
- PRD：
- 覆盖的需求 ID：
- design：
- 产品计划/里程碑：
- acceptance：

## 目标与非目标

## 用户可见与状态契约

## 领域、数据、API 与系统边界

## 权限、隐私与安全

## 错误、降级与恢复

## 兼容、迁移与回滚

## 影响面确认

## 开工检查

| ID | 任务 | 状态 | 依赖/阻断 | 完成证据 |
| --- | --- | --- | --- | --- |

## 实现任务

## 测试与验收任务

## 发布与回滚任务

## 完成判定与后续计划
```

任务 ID 使用 `FF-SS-AREA-NN`，`AREA` 可使用 `DOC`、`IOS`、`API`、`BE`、`DB`、`SEC`、`TEST` 或 `REL`。已经在评审、提交或缺陷中引用的 ID 不重排。

## 拆解规则

- 每项任务必须有可观察的完成条件，避免“完成前端”“联调一下”等模糊表述。
- 按交付契约拆解，不机械地为未受影响的技术层创建占位任务；不适用的系统边界在影响面中明确说明。
- 涉及 OpenAPI 时先更新唯一契约，再生成 iOS Client、实现 Go Handler 和契约测试。
- 涉及数据库或本地数据时，计划必须包含 适用的 migration、数据保护/恢复和回滚证据；旧开发数据按当前用户决定无需保留，不创建兼容层。
- 涉及人物或衣物媒体时，计划必须包含权限/同意、最小处理、血缘、删除链和日志脱敏验证。
- 发现需求或设计缺口时暂停相应任务，先更新 PRD/design/执行计划，不在代码或任务表中静默改变行为。
- 执行计划完成不自动代表功能发布通过；最终结论仍以对应 acceptance 的可执行结果为准。
