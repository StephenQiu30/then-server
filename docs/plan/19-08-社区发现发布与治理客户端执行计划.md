# 社区发现发布与治理客户端执行计划

## 状态、范围与追踪

2026-09-22；契约 `approved_with_gates`，执行 `pending`。本轮拆解已批准的图文社区，不开发或开放发布。依据 [PRD 19](../prd/19-每日记录与穿搭社区需求.md) COMMUNITY-REQ-004～015 与 Design 21～23；复用已完成的19-02/04/05/06后端。验收 COMMUNITY-ACC-003～011/013，系统OOTD-SYS-ACC-016；非功能引用OOTD-NFR-004～013中适用项，3D性能不适用普通社区页面。

交付一个受控发布闭环：App明确送审→最小Web治理操作→批准内容进入发现→互动/通知→举报/撤回/下架。匿名公开详情是必要阅读面；独立营销站、复杂推荐、私信、视频、商城及生成图直接发布不在本片。已有Look图片系统分享仍归14-01。

## 功能与状态合同

| 功能 | 输入和成功行为 | 失败/权限/撤回 |
| --- | --- | --- |
| 发现、关注与公开详情 | 只看已批准版本，时间序稳定游标；登录后才显示自己的关注流 | 下架/屏蔽后的旧分页不泄漏；401/429/无网有可恢复状态；已失效详情不展示缓存正文冒充仍公开 |
| 草稿/发布 | 从零写或从19-07选私人字段导入；预览标题/正文/选定普通图；明确送审 | 未选择的私人字段、来源ID不公开；离开编辑保留私有草稿；送审≠公开，失败不重复发帖 |
| 修改/撤回 | 修改产生新版本，旧批准版可见至新审核通过；作者可主动撤回 | 撤回与批准竞态以服务事实为准，迟到审批不能恢复；拒绝原因仅作者及有权限运营可见 |
| 赞藏关、评论、通知 | 幂等操作；评论/一级回复需审核；站内通知指向当前仍可访问目标 | 不显示收藏者身份或通知私有正文；请求失败回滚乐观状态；重复点击不增多条关系/评论 |
| 屏蔽、举报、申诉 | 两账号行为受屏蔽约束；用户提交原因，运营查看权限内队列和动作历史 | 不承诺匿名公开内容绝不可见；解除屏蔽不恢复关注；普通用户不能看到举报者/内部审核数据 |
| 最小治理端 | Web按实际角色显示待审/举报/下架/封禁/申诉；操作需具体目标版本及原因，返回真实审计结果 | 无权限关闭入口且API拒绝；拒绝/下架失败不得本地伪造已处理；不能无理由打开私人日记/采集源 |

## 检查点与验证

先用合成普通图和测试账号打通一篇帖子：私有草稿→送审→Web批准→匿名可读→作者撤回→正文/图片不可读，建议每1～2工程人日核对一个可运行节点。只有这个闭环通过后再扩所有互动和治理状态；不把后台已有98个API当成客户端工期依据。

App按11-05构建/测试/xcresult与真机方法；Web在`frontend`运行所改契约的`npm run openapi`后执行typecheck/test/lint/build及受影响格式检查，并实际浏览匿名、作者和运营界面。后端有变更才跑相应Go/真实PG/Kafka/MinIO/进程门禁。结合两账号和匿名验证撤回、封禁、屏蔽、同时间游标、迟到审核、重复通知；本轮不运行这些命令。

## 关闭与回退

投稿、互动、公开阅读按运营需要关闭，已接纳审核、举报和媒体删除继续处理；撤回/账号删除路径保持可用。保留批准/待审版本和审计，不清库或重新发布下架内容。发布门禁缺失时可继续受控测试，不能称完整社区已上线。
