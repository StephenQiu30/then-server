## 功能合同

1. 在最多三套候选中锁定衣物，换指定未锁位置；每次基于当前 owned/available 状态和相同硬约束重算。无替代时保留原候选并解释原因，不强制替换其他已锁项。
2. 锁件冲突直接列出冲突与“解锁/修改场景”，不悄悄放宽天气/场合要求。撤销恢复上一步选择，恢复后仍校验当前衣物资格。
3. 保存打开日期/场景确认，事务内复核衣物 revision、拥有/状态和硬约束；通过才创建一次 OutfitPlan。保存失败/冲突保留当前选择，修正或重算后再明确保存。
4. 保存计划不创建 WearEvent、Look 图片任务或偏好。只有“实际穿了”进入 16-02；只浏览或分享不计推荐采纳。
5. 读取 16-03 可重建的本地、允许用途的明确反馈；只能在合格候选中调整软排序。撤回/纠正后重新计算，不能使用照片、模型分数、收藏或浏览行为学习。
6. 没有反馈沿用确定性基础排序；不得为此新增 embedding、LLM、画像服务或自动上传穿着史。首片不承诺多设备学习同步。

## 验收矩阵与执行方法

| 给定 / 操作 | 必须断言 | 验收 |
| --- | --- | --- |
| 两个锁定衣物冲突，再换未锁项/取消锁定 | 已锁项不暗改；无解原因具体；解除后重新计算 | ACC-002 |
| 候选生成后另一操作把衣物设待洗/删除；此时保存 | 明确冲突且计划不新增；刷新并确认后保存一次，旧画面不误报成功 | ACC-006 |
| 同一命令重复保存，切后台/杀进程再回来 | 仅一条计划，日期/原时区不漂移，实际穿着计数不变 | ACC-006/010 |
| 相同合法候选、有/无明确反馈；撤回与纠正反馈 | 硬约束始终满足；软排序理由可追溯；撤回后重建不保留旧偏好 | ACC-007 |
| 快速修改场景、无网、最大字号、VoiceOver | 旧异步结果不覆盖新条件；核心操作和无解说明可访问 | ACC-009 |

按 11-05 的 iOS 命令步骤运行相关 build/test 与独立 xcresult，真实数据库和 UI 均核验。首次 DOMAIN/DATA 完成时（建议 1～2 工程人日）检查单候选调整→计划保存，再扩反馈；不以时间到期标记完成。

回退关闭新增调整/反馈排序入口并保留基础候选与已存计划；不删除真实穿着/反馈或重置数据库。当前全部实现/运行时验收均未执行。
