## 切片目标

1. 以可复核证据判断旧生活管理版本是否曾通过 App Store、外部 TestFlight、企业/Ad Hoc 或其他可能触达真实用户的渠道分发；不能证明时明确保留“发布未知”。
2. 仅从源码、既有 migration、工程配置、资源清单和经授权的非敏感运维元数据中，盘点历史数据类别、来源、用户意义、敏感级别、关联代码和潜在副本范围。
3. 建立旧生活管理数据与新 OOTD 领域的隔离矩阵，证明盘点过程不会把历史记录解释为衣物、搭配、推荐偏好或穿着事实。
4. 给出书面 Go/No-Go 决策，明确下一步只能进入哪个规划分支，以及哪些未知项继续阻断 schema、migration、入口替换、数据改写和清理。
5. 固定发布隔离、恢复优先、证据保护和停止条件，使后续团队不能把“完成盘点”误解为“已获准迁移或删除”。

## 非目标

- 不创建、修改、重排或执行 iOS GRDB 与 PostgreSQL migration，不运行 `DatabaseMigrator`、Atlas apply、GORM `AutoMigrate` 或任何 schema 变更。
- 不打开、查询、复制、导出、修复或抽样真实用户数据库、媒体、Keychain、备份、对象存储对象或供应商正文；不申请生产数据访问权。
- 不修改 RootView、旧 Feature、AppBootstrap、权限声明、Bundle ID、媒体目录、后端、OpenAPI、队列、对象存储或发布配置。
- 不删除、移动、重命名或改写旧代码、资源、测试、数据库、缓存、媒体、发布记录或云端副本。
- 不决定最终保留期限、历史入口、只读展示、导出格式、删除范围、用户文案或发布批次。
- 不证明迁移、只读、导出或删除已经可用，不创建面向真实用户的迁移入口或清理脚本。
- 不以团队记忆、没有投诉、当前仓库缺少发布文件、未发现数据或单一渠道无记录作为“从未发布”的结论。

## 用户可见与状态契约

本切片没有正式用户入口、页面、通知、后台任务或产品分析事件，不改变旧用户和 OOTD 用户能够看到或操作的任何状态。盘点状态只存在于本文的契约/执行/任务状态和受控证据登记中；Go/No-Go 是内部后续规划门禁，不得映射为“已迁移”“无历史数据”“可以删除”或任何用户可见结论。

## 只读范围契约

### 允许的证据源与动作

| 证据域 | 允许的只读动作 | 允许记录的结果 |
| --- | --- | --- |
| Git 与仓库 | `git log/show/tag`、`rg`、`plutil -p` 等不改动工作树的静态检查；读取既有源码、工程文件、文档、资源目录名和 migration SQL | 提交、tag、路径、版本、引用关系、文件哈希与缺口；不复制敏感正文 |
| Apple 与其他分发渠道 | 由有权负责人提供只读导出、审计截图或带签名/时间戳的查询结果；覆盖所有已知账号、Bundle ID、build、渠道与时间窗 | 渠道、版本、build、状态、发布日期/测试窗口、受众类型、证据所有者和稳定证据 ID |
| 本地数据结构 | 读取既有 migration 源码、GRDB Record、Repository、文件路径构造和测试 fixture 的结构说明 | 表/字段类别、关系、用户意义、敏感级别、版本来源、潜在副本；不读取记录值 |
| 媒体与系统能力 | 读取代码中声明的目录、用途、权限、导入、导出、缓存、备份和清理路径 | 数据类别、产生者、消费者、生命周期声明和未知项；不打开图片、导出包或系统数据库 |
| 后端与运维 | 读取仓库内契约、配置键名和经授权提供的非敏感资源清单、保留策略或账单/审计元数据 | 是否存在资源、地域、类别、时间窗、责任人和证据 ID；不记录令牌、URL、对象 key 或用户标识 |
| 支持与分析 | 读取经隐私审查的聚合计数或“未建立该系统”的正式证明 | 数据源、统计口径、覆盖期和局限；不读取工单正文、事件属性或可还原个人规律的信息 |

只读不等于“可以读取所有内容”。本切片只读取完成事实判断所需的最少元数据；真实用户记录正文、媒体字节、凭据和可访问资产位置始终在范围外。

### 明确禁止的动作

- 对任何数据库执行查询、pragma、修复、vacuum、迁移、回填、导出或删除；包括生产库、设备库、备份副本和来源不明的数据库文件。
- 启动旧 App 后走会初始化、升级或写回数据库的路径；用真机/模拟器运行旧 migration；用“先备份再试”绕过只读边界。
- 调用可能改变 TestFlight/App Store、云资源、对象、账号、配额、保留策略或日志状态的控制面 API。
- checkout、格式化、自动修复或运行会生成/改写受盘点文件的脚本；若工具的只读性无法证明，停止使用该工具。
- 把截图、导出文件或盘点结果放入临时公开位置、个人网盘、issue 正文或普通日志；不得以短期 `/tmp` 路径作为长期证据。
- 根据文件名、表名或当前引用数直接决定业务价值、删除范围或迁移方法。

## 盘点交付物

盘点执行后必须形成以下五类受评审交付物。具体受控存放位置由 `19-01-SEC-01` 批准，不得在本 `draft` 计划中预设含敏感信息的公共路径。

1. **发布证据登记表**：列出所有已知 Apple 开发者账号、Bundle ID、版本/build、渠道、时间窗、受众类型、证据 ID、证据所有者、采集日期、覆盖结论和缺口。
2. **历史版本与代码谱系表**：把 release/tag/commit、Xcode target、数据库版本、旧 Feature、权限与资源关联起来，并明确推断与直接事实的区别。
3. **历史数据类别清单**：逐项记录来源、用户意义、敏感级别、结构版本、关系、可能的本地/云端/备份/导出副本、当前生产者与消费者、未知项；不得包含记录值。
4. **新旧隔离矩阵**：标出旧 Ledger、Calendar、Travel、Life、Today、Profile 数据与 OOTD 衣橱、推荐、试穿、记录的边界，任何自动转换或共享事实源均记为阻断问题。
5. **Go/No-Go 决策记录**：引用全部关键证据和缺口，记录评审人、结论、适用版本、决策日期、复核触发条件与唯一允许的后续规划分支。

每条结论必须区分 `direct_evidence`、`corroborated_inference` 和 `unknown`。`unknown` 不得被空值、零计数或“未发现”替代。

## Go/No-Go 门禁

### `GO-BASELINE-PLANNING`：可规划全新 OOTD 基线

仅当以下条件全部满足时可选：

1. 对全部已知账号、Bundle ID、构建范围、分发渠道和适用时间窗取得权威且可复核的直接证据，证明旧生活管理版本未触达真实用户。
2. 发布证据与 Git、CI、签名、版本和支持/运维元数据相互一致，不存在无法解释的 build、渠道或时间缺口。
3. 历史数据类别、代码和测试数据已经完成结构级盘点，未把“从未发布”误写为“可以忽略工程测试数据或历史决策”。
4. 产品、隐私、安全与发布负责人共同签署结论，并记录未来发现相反证据时立即停止的复核触发条件。

该结论只允许起草后续“新 OOTD 数据基线与历史实现成组清理”执行计划；后续计划获批前仍不得修改 schema、migration、数据或代码。

### `GO-PROTECTION-PLANNING`：可规划已发布保护路径

在已确认发布，或无法排除发布但数据类别与适用版本已盘点到足以设计保护路径时选择。必须做到：

1. 所有未知版本和未知副本继续按已发布、高敏感、默认保留处理。
2. 数据类别清单足以分别规划保留、只读访问、结构化导出和明确删除，且没有把这些能力打包成一次不可逆迁移。
3. 新旧隔离、分版发布、观察窗口、停止条件和恢复责任已有书面约束。
4. 评审人明确下一步只允许创建一个经批准的近期保护切片，不授权数据读取、迁移或处置。

该结论不是生产发布的 Go，也不是删除或 UI 替换授权。

### `NO-GO-EVIDENCE`：证据不足，继续冻结

出现下列任一情况即选择 No-Go：

- 已知账号、Bundle ID、build、渠道或时间窗没有可靠覆盖，或关键证据互相矛盾且无法关闭。
- 数据类别、版本、关系、敏感级别或潜在副本存在会改变处置路径的未知项。
- 完成判断需要读取真实用户正文、获取超出本计划的生产权限或执行任何写操作。
- 无法证明新旧领域隔离，或发现当前启动、构建、迁移或清理路径可能自动改写数据。
- 证据存储、访问控制、脱敏或审计要求不能满足。

No-Go 时保持旧实现、migration、数据与生产入口冻结；只允许补充证据或回写上游决策，不得用工程清理规避门禁。

## 权限、隐私与安全

1. `19-01-SEC-01` 必须先定义证据分级、允许字段、存放位置、访问角色、脱敏、保留期和销毁责任；未批准前不得收集控制面导出或截图。
2. 只申请只读发布元数据访问；若平台无法提供足够细粒度的只读角色，由有权负责人代为导出最小证据，不向执行者共享高权限凭据。
3. 不把生产账号、团队成员邮箱、设备 ID、测试人员身份、用户 ID、对象 key、签名 URL、数据库路径或日志正文写入仓库文档。
4. 哈希只用于证明工程文件或已批准证据包版本，不对真实用户媒体或记录做哈希盘点。
5. 盘点报告只记录聚合计数、存在性、结构、时间窗和稳定证据 ID；任何能够还原个人生活、位置、财务、日历或穿着规律的内容都必须停止采集并按安全事件处理。
6. 发现凭据、生产数据正文或越权访问时立即停止，保留最小事件元数据并通知安全负责人；不得自行复制、清理或继续调查内容。

## 错误、停止与恢复

| 场景 | 立即动作 | 恢复条件 |
| --- | --- | --- |
| 证据互相矛盾 | 标记 `unknown`，停止形成“从未发布”结论 | 权威来源补证并完成交叉评审 |
| 只读权限不足 | 不提升权限、不借用凭据，记录缺口 | 有权负责人提供最小只读导出或批准新授权 |
| 工具可能写入 | 终止命令，不以副本或备份绕过 | 证明工具只读，或改用静态证据源 |
| 发现真实用户正文或媒体 | 停止查看与复制，按安全流程报告 | 安全负责人确认处置完成并重新批准范围 |
| 发现自动 migration、清库或写回路径 | 保持相关启动/发布路径关闭并记录阻断 | 另行设计并批准保护与恢复方案 |
| 无法识别数据类别或副本 | 默认高敏感、保留、发布未知 | 产品/隐私/安全补齐分类结论 |
| 证据包无法安全长期保存 | 不以本地临时文件或聊天记录替代 | 批准受控存放位置和访问审计 |

本切片不操作产品状态，因此没有数据恢复动作。发生异常时的“恢复”是恢复到继续冻结、零写入的审查状态，而不是恢复或重建数据库。

## 兼容、迁移与回滚

- 本切片没有数据库、媒体、API、客户端或服务端迁移；兼容窗口不适用。
- 不生成 migration，不更改已发布 migration identifier，不建立 OOTD schema baseline。
- 不改发布配置、Bundle ID、版本号或入口，因此不会改变现有安装与回滚行为。
- 盘点文档若有错误，使用 Git 追加更正并保留审计历史；不得通过删除原证据掩盖结论变化。
- 若发现结论错误或出现新的发布/数据证据，立即撤销依赖该结论的后续规划批准，恢复 `NO-GO-EVIDENCE` 并重新评审；本切片本身不执行数据回滚。

## 证据标准

- “从未发布”必须由覆盖全部已知分发控制面的直接证据支持，且至少与 Git/CI/签名/版本事实中的两个独立来源交叉一致；仓库中没有 tag 或当前负责人不知情均不足以证明。
- 每个证据项包含稳定 ID、来源系统、所有者、采集日期、覆盖范围、完整性校验、访问级别和局限；截图需同时保留可验证来源与时间窗说明。
- 数据清单按类别和结构记录，不附记录样例、截图正文、媒体缩略图、路径、用户 ID 或真实计数的小样本明细。
- 所有命令和工具必须可证明只读；完成记录包含使用的命令类别和零工作树/零控制面 mutation 核对结果。
- 长期证据位于经批准的受控位置，引用稳定证据 ID；不得依赖 `/tmp`、个人目录、聊天附件或会过期的签名 URL。
- 盘点结论必须标明事实、推断与未知；任何改变决策分支的未知都不能降级为备注。
