# 账号状态与公开资料执行计划

状态：`approved / in_progress`。用户于 2026-09-16 同意 [19-01](19-01-后端需求与数据设计审核计划.md) 的设计方案并要求开始实现；本切片只交付社区前置的账号状态、并发版本和公开资料纵向闭环，App 与 frontend 页面继续暂停。

## Spec

- 关联：COMMUNITY-REQ-014/015、COMMUNITY-ACC-008/011，[Design 21](../design/21-后端产品边界与领域设计.md)、[Design 22](../design/22-后端数据库设计.md)、[Design 23](../design/23-后端接口设计.md)。
- 注册账号固定为 `status=active`、`role=user`、`revision=1`；本人接口可读但不能修改 status/role。suspended/deleting 账号不能登录、使用既有会话或公开资料。
- `PATCH /users/me` 必填 `expected_revision>=1`，只修改邮箱/显示名称；版本不匹配返回 `409 REVISION_CONFLICT`，成功后 revision 加一。当前开发阶段不保留旧请求兼容。
- 公开资料只有 lowercase ASCII `handle`、当前 display_name、可空 bio、revision 和时间；不返回邮箱、会话、内部 user ID、账号状态/角色、衣橱或私有来源。
- `PUT /users/me/profile` 首次 `expected_revision=0`，更新必须精确匹配当前 revision；handle 全局唯一且保存为小写，bio trim 后为空即清除，最多 300 Unicode 字符。
- `GET /users/me/profile` 只限本人；`GET /profiles/{handle}` 可匿名读取 active 账号。不存在、未创建或非 active 统一 404。
- 本片不实现头像、邮件挑战、会话列表、异步账号删除、日记或社区帖子；这些按 19-01 后续顺序独立切片，避免把媒体与治理半成品接入公开路径。

## SMART 与退出条件

一个切片内完成“注册安全状态 → 创建本人资料 → 匿名读取 → 更新冲突 → 停用立即隐藏 → 删除账号级联”的可测闭环。退出要求所有非发布 checklist 完成，生成客户端可消费，Acceptance 19 写明命令和边界；邮件、头像、运营封禁 API、日记和社区不得冒充本片结果。
