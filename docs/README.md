## 如何使用证据

作者自述、官方精选样片、源码静态审查、本地工程检查和用户视觉验收是不同证据，不能相互替代。新 checkout 不一定具备旧 `.tmp` 素材、运行进程或开发数据库。账单未知保留未知；生成失败与视觉弃用都计入投入。产品待办见 [BACKLOG](../BACKLOG.md)，工程接手见 [HANDOVER](../HANDOVER.md)。

## 编写约定

按用户要求，产品与执行文档采用 pm-execution 的精简 PRD、验收场景方法，文字复核采用 pm-toolkit 的 grammar-check 方法。方法用于整理现有文档，不新增第二套事实源。

1. **先给决定，再给细节**：需求入口维护摘要、背景、目标、目标用户、六要素价值主张、方案与交付；详细 FR/CL/SYS/NFR 和技术事实链接到对应主题。
2. **明确状态**：分别标注已确认方向、研究观察、建议、待验证假设；“设计已补齐”“原型可点击”“业务已实现”“真实效果通过”不得混用。
3. **验收可执行**：每个场景写目标、角色、前提、步骤和可观察结果，并关联需求编号。测试结果放 validation，要求放 requirement。
4. **术语固定**：单品是稳定的衣物身份；照片是媒体；搭配收藏是可复用 Look；计划是未来安排；实穿是本人确认的事实。只有实穿驱动计数。
5. **写作检查**：检查语法、逻辑和衔接；针对错误给出位置、修正与原因。删除重复和模糊指代，不为统一格式重写无关材料；未做的访谈、性能、成本与成功率不造数。
6. **可追溯且简短**：保留 FR/AC 等稳定编号、更新时间、来源和证据链接；BACKLOG 只放待办，CHANGELOG 简短记录，设计节点更新回现有范围与验收文档。
