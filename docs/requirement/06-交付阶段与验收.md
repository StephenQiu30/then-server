## 3. 小样如何避免浪费

**先验证一个完整效果，再谈全衣橱。** 不重新启动已经拒绝的 img2threejs/程序体块路线，也不因为某模型名称热门就同时部署多套服务。

建议实验合同（待执行时确认）：

- 第一关：1个人物、3件候选衣服，分别只换一个支持部位；每输入首次1次，允许一次有明确原因的纠正重试，总计最多6次静态尝试。各结果与共同原图和目标单品对照。
- 若第一关通过，再使用未参与调参的3个人物×4个支持范围内输入，共12个输入意图；每意图最多2次，总计最多24次。组合覆盖深/浅色、纹理、宽松/贴身及不同外观，不声称这足以代表所有人和衣物。
- 两关最多30次仅是建议请求数上限，不是费用授权。开始前还须设实际金额/额度与人工时间上限；任何一项达到即停止。未获明确成本上限，不启动付费任务。
- 只对已接受的静态 Look 测环绕；单套先验证，再扩三套。环绕另算预算，不能隐藏在静态尝试里。关键失败重复出现且无可解释修正时停止，保留所有输出。
- 记录所有首次输出和重试，不能只展示最好三张。结果被人工修图时记录步骤和用时，区分自动输出与人工修正版。
- 如只用现有示例图做 UI，对应结论只能是交互可操作，不能记为模型试穿成功。

### 视觉评价与门槛

每个输出由素材本人（或其授权评价者）和另一名评审分别看原图、单品与结果，按 NFR-09 的身份、目标衣物、保留区域、完整度、决策帮助给出“接受/需改/拒绝＋原因”；分歧保留，未解决不当通过。关键错误如换脸、错衣、改掉保留部位，不能用综合平均分掩盖。

建议第一关三件均得到接受结果且完整报告初次失败；留出集报告首次接受数/12、限次后接受数/12。继续开发的暂定门槛为首次至少9/12、限次后至少10/12，并且不把关键错误输出交付为成功；这只是低成本筛选门槛，不是生产成功率承诺，未获实际用户认可仍不能宣布 Woo 质感达标。

环绕至少检查正、左右侧、背面、完整一周和首尾连接，比较头发、衣纹、纽扣、鞋与身体重心；单张照片推断的背面只能评观感，不能称真实还原。实际拖动/反向/快速拖动、触摸、键盘、重新进入、失焦和内存释放分别测试。

## 5. 产品指标与成本口径

所有指标当前均为未测；先报告分子/分母、样本量、日期与招募方式，再谈百分比。预设演示、自有用户输入、测试账户分开统计。

| 指标               | 定义                                                                              | 避免误读                                                              |
| ------------------ | --------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 首次价值完成       | 首次会话完成有效选衣、比较并明确保存/改选/否决之一的独立用户数 / 尝试该任务用户数 | 否决有理由也是决策；只点生成不是完成；主持人帮助单列                  |
| 首次价值耗时       | 开始录入到第一次明确搭配决定，分离准备素材、排队与操作时间                        | 建议先观察，不拍脑袋宣称节省几分钟                                    |
| 首次/限次接受率    | 首次可接受输入意图数 / 有效输入意图数；限次内可接受意图数 / 同一分母              | 有效输入在提交前按支持范围确定，失败后不移出分母                      |
| 任务技术成功率     | 可访问合法输出的任务数 / 已提交任务数                                             | 不等于衣物保真或用户接受率；取消与未知另列                            |
| 单份可接受结果成本 | 某批全部已结算支出（含失败/重试）/ 接受的输入意图数                               | 接受数为0时显示无法计算与总支出；不同币种/credits不乱加；未知部分单列 |
| 时间与人工投入     | 排队、推理、后处理、人工修图、总等待分别报 p50/p95及样本数                        | 小样尾部指标不稳定；供应商用时不等于用户等待                          |
| 搭配复用           | 7日内再次打开并用于选择/计划/实穿的保存搭配数 / 有完整7日观察窗的保存搭配数       | 单纯打开、计划、实穿三个动作分别报，不能混称穿过                      |
| 记录价值           | 本人确认实穿的用户/事件数、纠错数、统计明细查看，以及访谈中回答的问题             | 无记录≠没穿；不把提高打卡量本身当产品成功                             |
| 自愿返回           | 有完整7日观察窗的激活用户中，再次主动完成核心任务的人数                           | 排除测试与主持人安排回访；小样不推出总体留存率                        |
