# 系统与非功能需求

更新：2026-10-13。本文定义产品运行需要满足的合同，**不等于当前实现已经满足，也不指定新的表、接口或服务**。沿用 PROJECT 中现有工程，详细设计进入实现阶段后再落到既有事实源。各量化值均为建议验收目标，需在试用前固定环境和样本；没有生产 SLA 或实际测量结果。

## 1. 系统边界与角色

用户负责确认衣物、选择人物与服装、判断结果、确认实际穿着；系统负责保存事实、组织任务、呈现状态、保护资料并计算统计。生成供应商提供候选媒体，不拥有修改衣橱事实或写入实穿记录的权限。

| 角色            | 可做                                              | 不可默认拥有                                       |
| --------------- | ------------------------------------------------- | -------------------------------------------------- |
| 访客/预设体验者 | 看公开且有授权的示例，体验明确标注的演示          | 访问私人媒体、把示例自动计入衣橱、无限调用生成     |
| 个人用户        | 操作自己的衣物、照片、搭配、任务、实穿、导出/删除 | 通过猜 ID 读取别人内容，自动公开本人资料           |
| 系统任务执行者  | 在当前授权范围处理指定输入并写回任务结果          | 任意扫描衣橱、绕过删除请求、用旧授权继续新任务     |
| 支持/运维       | 查询脱敏错误与用量；处理任务故障                  | 默认浏览私人照片；需要内容诊断时应有明确范围与审计 |

个人本地验证可沿用现有访问保护，不为演示先建全套身份平台；开放多用户试用前必须通过跨账号访问隔离验收。

## 2. 系统需求

| ID     | 必需合同                               | 验收与依赖                                                                                                                                                                 |
| ------ | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SYS-01 | 数据与媒体按 owner 隔离，权限不只在 UI | 衣物、人物、结果、统计、导出、任务查询与下载均验证所属关系；用户 A 猜 B 的 ID 不能读取/修改                                                                                |
| SYS-02 | 明确对象版本、来源和输入快照           | 一份结果可追溯人物/衣物图版本、替换与保留项、实际执行模型版本；用户改草稿不改旧请求                                                                                        |
| SYS-03 | 异步任务可查询、可恢复、状态可解释     | 刷新/断网/工作进程重启后能继续查询；回调重复、乱序不覆盖终态；未知提交状态不盲目重发                                                                                       |
| SYS-04 | 幂等、并发和事务保护                   | 同一提交一次业务结果；供应商请求号可对账；重复消费队列不重复提交收费任务；实穿与关联提交原子化                                                                             |
| SYS-05 | 生成与业务写入解耦                     | 供应商不可用时衣橱、搭配清单和实穿可使用；试穿成功不写次数，质量拒绝不删除真实衣物                                                                                         |
| SYS-06 | 输入/结果/草稿/备份的生命周期与清理    | 明确依赖，删除任务可查询可重试；取消任务后迟到产物不能复活已删除私人内容                                                                                                   |
| SYS-07 | 上传与衍生资产校验                     | 实际格式、解码尺寸、所有权、内容类型有效；损坏文件有说明；对展示/供应商输入清理 EXIF 定位等不必要元数据；原文件如保留须私有并按同一删除策略管理；不把任意 URL 当可信下载源 |
| SYS-08 | 费用上限、执行尝试与质量弃用分别计量   | 调用前有额度/预算约束；按任务/尝试记录支出和估算状态；取消后可能仍计费的执行可对账                                                                                         |
| SYS-09 | 导出、备份恢复与环境隔离               | 导出关联完整；恢复能重算实穿统计；开发样例不混入真实用户数据；备份恢复后重新应用删除清单                                                                                   |
| SYS-10 | 兼容演进与可诊断性                     | 沿用现有 API/数据库事实源；迁移不丢已有单品/记录；脱敏 request ID 可定位失败，密钥不在前端/日志                                                                            |

## 3. 试穿任务状态合同

建议业务状态：`draft → validating → queued → running → succeeded / failed`；另有 `submission_unknown`（供应商是否接受未确认）、`cancel_requested / cancelled`。这些是需求语义，具体枚举适配既有合同。

- 提交前校验输入、支持品类、版本与额度；无效输入不进入付费推理。
- 草稿变化不自动生成。相同 mutation ID/相同输入返回原任务；相同 ID/不同输入返回冲突。
- 网络超时不等于供应商失败。进入未知态后查询原 request ID 或对账，直到明确未受理才允许安全重发；不能通过按钮连续建立新任务。
- 页面离开不必取消任务；再次进入能找到状态与结果。只有确认供应商停下才显示取消成功；否则显示停止等待/取消请求已发送。
- 本地已删除或撤销访问后，不再把迟到成功结果发布给用户；后台清理也应覆盖该产物。
- `succeeded` 表示合法输出已安全保存且可访问，独立字段表示质量待评/接受/拒绝。200 响应、任务完成、用户喜欢不是同一指标。
- 运行阶段有事实才显示；无供应商进度时显示等待/处理中和耗时，不制造百分比或保证剩余秒数。
- 外部失败、输入失败、存储失败与质量弃用分开。默认不无限自动重试；首轮受控实验每输入至多一次纠正重试，生产策略在实际成本结果后确定。

## 4. 数据生命周期建议

下列期限是待确定的产品政策，不是法律结论。供应商未确认保留与删除能力前，不开放真实用户照片的外部处理。

| 数据              | 建议保留/删除规则                                                 | 产品必须说明                                                           |
| ----------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 本地未提交草稿    | 默认仅当前会话；如启用跨会话恢复，采用有限期和明确清除入口        | 是否只在设备、是否上传；不能长期在 localStorage 裸存私人图像           |
| 衣物原图/展示图   | 物品存续期间按需保存；移除资产需检查历史引用                      | 归档与删图不同，删原图会影响重新处理能力                               |
| 人物照片/试穿结果 | 用户可主动删除；建议未保存结果 7 天后清理，保存的 Look 随用户管理 | 7 天为待确认提案；删除人物源时默认连同其私人衍生结果，并先展示影响范围 |
| 已确认实穿与快照  | 与图片可独立存在；单品归档保留历史                                | 永久删除物品与账号采用明确范围，不能留下伪造可点击的失效引用           |
| 失败临时文件      | 建议 24 小时内清理，不保留作训练                                  | 若为诊断需延长，要记录原因和授权范围                                   |
| 备份/供应商副本   | 建议备份最长 30 天轮转；供应商期限单列                            | 本系统删除完成≠第三方/备份全部清除；未确认显示待核实，不给虚假承诺     |
| 诊断与成本记录    | 保存去标识元数据与账单关联，期限按运营需要另定                    | 不默认存照片、完整提示词、带签名 URL、身份密钥                         |

默认不将用户照片用于模型训练或公开画廊；选择供应商时核验实际条款与设置，不能只在页面写一句“不会”。地区、跨境、个人信息分类及适用法规需在 D-01/D-05 确定后专门核验，本文件不宣称合规审计已完成。

NFR-01～08 延续旧编号，集中到本文；每项均是试用前的验证目标。

| ID     | 维度               | 建议目标与测试条件                                                                                                               | 失败处理                                                    |
| ------ | ------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| NFR-01 | 数据正确性         | 04 的计数用例全部满足；并发双击、超时重试、改件/删除均只有正确最终贡献；跨账号读取为 0 次成功                                    | 阻止开放试用，不以视觉效果抵扣                              |

| NFR-05 | 可靠性与恢复       | 队列重复/乱序、进程重启、对象存储失败、网络未知逐项注入；无重复业务结果或重复付费提交；备份恢复演练可重算统计                    | 未确认终态可停留未知，不伪装成功；先修恢复路径              |

| NFR-08 | 可观察与成本       | 每次请求记录排队/推理/后处理/总时长、尝试、失败类、拒绝原因、实际支出/估算/未知；汇总分母完整                                    | 账单未知写未知；未核账不得称免费/零成本                     |

| NFR-10 | 生成体验及资源上限 | 静态试穿暂定 p95≤60s 作为待验证目标，超过10s显示可离开后再查看；每次请求≤1个活动同输入任务；环绕单独测首帧、拖动与内存           | 没有真实数据不展示预计完成时间；等待/成本不接受时不批量生成 |

## 6. 视觉质量不是单一“好看”分数

对每份候选输出分别判定：

1. 人物身份与成人比例：与输入对照脸、头发、身形，不能偷偷换成更好看的另一个人。
2. 目标衣物：颜色、图案、领口、袖长、整体版型符合已提供证据；看不到的背面标为推测，不计真实还原。
3. 非目标区域：没有要求更换的裤子、鞋、手部、姿势与场景不能被明显改写；保留区域必须写入验收。
4. 图像完整度：无缺肢、明显融化、穿模、破面、文字/图案灾难性变化；光线与边缘自然。
5. 可用性：用户能据此判断搭配差异；好看但不可信属于拒绝，不算成功。
6. 环绕另评：方向连续、首尾衔接、身体位置、脸与衣纹跨帧稳定；播放器拖动顺滑不能证明源素材合格。

这套标准验证视觉搭配参考，不验证真实尺寸、触感、活动舒适度或量体精度。支持范围按实际通过的输入类别公布，不使用“所有衣服/任意照片”承诺。
