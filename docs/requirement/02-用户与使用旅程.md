# 用户需求与使用旅程

更新：2026-10-13。方法：pm-market-research / user-personas、customer-journey-map。**以下是有来源线索的假设画像，不是已访谈用户画像**；不编造姓名、年龄、收入、引语或人群比例。C/E/U 编号见 [需求入口](README.md) 与 [研究证据](01-市场与竞品调研.md)。

## 1. 三类任务画像

| 画像                 | 触发与要完成的事                                   | 三个主要痛点假设                                            | 三个期望收益                                            | 依据与优先级建议                                         |
| -------------------- | -------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| P-A 日常穿搭决策者   | 出门前/前一晚，用现有衣服选择通勤、约会或日常组合  | 看平铺难想象本人效果；反复换衣费事；推荐不符合手边衣物/场景 | 看同一人换衣后的区别；一次只调整一件；收藏后能再次穿    | C-01/02、E-02/07、U-02；建议主画像，尚待首批用户确认     |
| P-B 衣橱整理与复盘者 | 换季、搬家或想减少重复购买时，弄清有什么和穿了什么 | 完整录入负担；漏记使次数难信；同款/借用/归档混算            | 渐进建档；有记录可追溯；旧记录和图片可导出              | E-03/04/08、U-01～03；次画像，支撑长期价值               |
| P-C 搭配探索者       | 有一件想穿的衣服，想尝试新组合                     | 模特不代表自己；生成改变衣服；保存太多却找不到              | 可选择本人/预设；锁定其他衣物作对比；快速找到已保存方案 | C-02、E-02、U-02；用于检验视觉价值，暂不引入社交平台功能 |

对画像的进一步判断（推论，待观察）：P-A 的一次“明确不选这套”也可能是成功，不应只优化保存率；P-B 可能宁可缺图也不愿填满属性，应允许先建档；P-C 喜欢漂亮图不必然喜欢记录，不能由一次生成兴趣推断长期衣橱需求。这些分别影响决策完成、录入门槛与留存测量。

同一用户可切换三种任务。首版不按性别限制分类，不要求体型分析或真实姓名；不以专业造型师、电商商家、家庭多人协作为主要对象。

## 3. 完整旅程与关键时刻

本旅程以 P-A 为主，P-B 的复盘与 P-C 的探索在相关阶段补充。以下“想法/情绪”为研究假设，须通过观察核验。触点按任务定义，不强制增加页面。

| 阶段       | 用户动作与触点                       | 可能的关切/情绪             | 主要摩擦                       | 产品响应                            | 观察信号                        |
| ---------- | ------------------------------------ | --------------------------- | ------------------------------ | ----------------------------------- | ------------------------------- |
| 发现       | 看演示、朋友展示或产品介绍           | 好奇：是不是只对示例有效    | 误以为实时 3D/保证合身         | 标注示例，说明支持衣物与试穿范围    | 能否复述产品能做什么            |
| 评估       | 看原图和结果，了解照片用途           | 想确认像自己、像衣服        | 精选输出掩盖失败/等待          | 展示有对应输入的结果及限制          | 是否愿用自己的素材验证          |
| 初次进入   | 选本人照或预设，录少量衣物           | 期待与隐私顾虑              | 一开始要求身体数据/全库录入    | 最少信息，预设可体验，私人资料分开  | 中断位置、首件录入用时          |
| 首次选衣   | 从衣橱选择/替换一件                  | 希望其余不变                | 分类与穿着位置混淆、找不到衣物 | 分类检索、已选清单、缺图/不支持原因 | 无引导能否完成单件替换          |
| 等待结果   | 提交、等待、离开再回来               | 不确定是否成功/是否重复消费 | 假进度、刷新丢失、盲目重试     | 真实状态、可恢复任务、有限重试      | 提交次数、取消/退出原因         |
| 判断结果   | 原图与试穿图比较、放大；有环绕时拖动 | 欣喜或不信任                | 换脸、改裤子、纹理漂移         | 默认可对照，质量问题反馈与回到选衣  | 是否认得本人/衣服，是否帮助决定 |
| 留存复用   | 保存搭配、下次再选                   | 希望不用重做                | 保存只留图片、找不到实物       | 图片关联单品与版本；明确“保存搭配”  | 再次打开与复用任务成功          |
| 实穿复盘   | 确认当天实际，查看单品记录           | 希望轻松且可信              | 把保存当穿过、补录麻烦         | 日期核对，允许部分记录，次数可追溯  | 记录负担、纠错、返回原因        |
| 推荐或退出 | 自愿展示效果/导出/删照片             | 希望掌控资料                | 默认公开、迁移损失             | 私人默认、先可导出；分享后置        | 数据带走是否成功、退出原因      |

两个价值时刻分开：**首次价值是通过对比作出一个搭配决定；持续价值是复用该搭配并形成可追溯的实穿记录。** “生成成功”只是系统事件，不能独立代表产品价值。

改进顺序建议：先处理首次录入与选衣找不到的摩擦，再解决结果身份/服装不可信的问题，最后优化复用与记录负担。字段渐进和保存/实穿命名可低成本验证；真实人物试穿与连续环绕依赖较高，应在 G2/G4 独立验收。此排序基于当前方向与公开线索，不是已经测得的转化损失排名。

## 4. 高频异常与恢复需求

| 情境                         | 用户应获得的结果                                           |
| ---------------------------- | ---------------------------------------------------------- |
| 人物裁断、多人、身体被遮挡   | 提交前说明具体问题，允许换照；不能静默选错人               |
| 单品无照片/格式不支持        | 可以存衣橱；试穿入口说明缺什么，不替换成示例衣服           |
| 选两件同位置或连衣裙+裤子    | 解释冲突并让用户确认选择；支持的叠穿规则见 CL-03           |
| 队列慢/额度不足/供应商不可用 | 当前选择不丢，说明等待或稍后再试，衣橱与记录可继续使用     |
| 提交后网络断开               | 先查询原任务状态；不自动创建新付费任务                     |
| 生成途中再次换衣             | 返回旧任务结果时标明对应旧选择，不覆盖当前草稿             |
| 结果漂亮但不是自己的衣服     | 允许标记不可用并回到选衣，不作为视觉验收成功               |
| 只记得部分穿着、同日两次     | 可部分记、可明确新增事件，次数与天数各自表达               |
| 衣服归档或图片删除           | 历史清单保留可解释快照；删除的照片不能靠旧链接继续公开访问 |

## 5. 用户研究计划（尚未执行）

建议先招募 6 位成年自愿参与者：3 位 P-A、2 位 P-B、1 位 P-C，兼顾不同衣物风格、设备和身体外观；这个小样用于发现问题，不代表市场。先取得观察与素材处理同意，不自动发送邀请或上传照片。

每人 30～45 分钟，先问最近行为，再看原型：

1. 回忆最近一次不知道穿什么的情境；当时拿了哪些衣服、怎么决定、花了多少时间？避免问“你喜不喜欢 AI 试衣”。
2. 看其愿意展示的现用相册/工具，了解录入、找衣与记录方法；不要求提供私人照片。
3. 独立录入 3～5 件常穿衣物，选一个人像，只换一件并找回原选择；记录卡点与帮助次数。
4. 用相同输入的平铺与试穿样本交叉顺序比较，询问哪些信息改变了决定、哪些不能相信；没有真实试穿时明确是原型，不测生产成功率。
5. 区分“保存”“计划”“实际穿过”；模拟补录、换件和删除，检查次数理解。
6. 讨论可接受等待与实际替代成本；付费只记录意愿线索，不将口头金额视为成交。

| 假设                            | 支持信号                                        | 推翻/调整信号                                |
| ------------------------------- | ----------------------------------------------- | -------------------------------------------- |
| H-01 渐进录入可形成首次价值     | 能用少量物品完成自己的选择任务                  | 必须录完整库才有用，或主要障碍其实是拍照质量 |
| H-02 人物试穿帮助决策           | 比较中指出具体改选原因，回访实际采用/有意识否决 | 只想保存好看图片，不帮助选择；应重估价值定位 |
| H-03 写实一致性比旋转新奇更关键 | 错脸/错衣结果被拒绝，静态准确结果有用           | 用户必须看侧背才能决定，需把环绕前置验证     |
| H-04 实穿记录值得持续维护       | 一周内自愿复用并记录，知道统计能回答什么        | 记录负担高于收益；简化入口，不自动伪造记录   |
| H-05 Web 优先匹配任务           | 桌面选衣比较更顺手，手机能完成上传和记录        | 用户只用手机且浏览器受阻；再评估原生端优先级 |

访谈输出只记录匿名编号、任务完成/帮助、耗时、问题、相反证据与素材授权范围；未开始前这些字段为空。不要制作虚构“用户语录”或满意度。具体决策门槛和度量见 06。
