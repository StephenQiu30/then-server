# 市场、竞品与需求证据

访问日期：2026-10-13。方法：pm-market-research / competitor-analysis。研究范围为个人数字衣橱、穿搭决策、人物试穿、实穿记录；以五个直接竞品为主，另纳入中文市场搭搭和视觉参照 Woo。**本轮完成公开资料研究及 Acloset 官网示例的 Chrome 目视检查，未安装并实测五款完整 App，未开展用户访谈。**

## 1. 先区分证据

- E：官方帮助/功能文档说明可用入口和规则；不能证明成功率、速度或普遍视觉质量。
- V：实际看见的公开示例画面；只能评价这一个样本，不能代替自有输入测试。
- U：公开用户反馈；可提出需求假设，有自选、地区、版本和平台偏差，不代表人群占比。
- L：本项目已有本地验证记录；说明我们做到了什么，不能证明用户愿意使用。
- C：本会话用户明确要求，见需求入口；是产品方向约束，不是市场调研样本。

未核实融资、营收、市场份额、留存、付费率与同口径市场规模；不引用厂商“衣橱闲置比例”等营销数字作为需求强度。没有足够数据建立 TAM/SAM/SOM，后续应以可触达目标人群、激活、留存、付费与单位成本自下而上估算。

### 效果应该怎样比较

V-01：在 Chrome 打开 Acloset 中文官网并滚到虚拟试穿区。可见原白 T/短裤人物、针织开衫/黑裤等单品和对应全身结果；画面为静态展示，提供比较结构的参考。没有自有输入、运行等待、失败记录、背面或拖动验证，故不能给其“试穿成功率高”“已达到 Woo 360°”评级。

后续如实测，应使用有授权的相同人物/衣物集，记录输入条件、每次输出、失败、耗时、费用、保存和纠正流程；平台不允许相同输入时单列不可比。精选成片的吸引力、任意输入的稳定性、日常可用性分别评分，不给未测项填分。

| 来源                  | 实际读到的反馈摘要                                                                   | 推导的待验证需求                                                  | 局限                                                       |
| --------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------- | ---------------------------------------------------------- |
| U-01 Whering 录入讨论 | 发帖者录约 10 件后觉得工作量大；回复提出分批录入、少填标签、穿到再录                 | US-01；先少量常穿衣服得到价值，属性渐进补充，批量不能成为唯一入口 | 英语社区单个讨论，未验证账号与实际耗时，不估算平均录入时间 |

## 4. 中文参照、Woo 与替代方案

**搭搭（E-08）**：当前商店描述覆盖录入/整理/搭配/规划/记录/统计，包含多图、商品图优化和衣物拆分；免费＋内购，描述列 ¥13/月，SKU 不能合并成统一价格。中文分类和统计已有供给，仅做中文化不构成差异。本轮没有实际试穿效果证据。

**Woo（E-09，沿用项目已保存研究，非本轮重新试用）**：用户要求的视觉参照。已有研究记录作者解释使用视频帧；源视频怎样制作、真实用户成功率、手工处理和成本未公开验证。值得借鉴的是“人物居中、选衣、看变化”的决策路径；不能据此把 GLB 或特定模型写成需求。详见 [技术证据与边界](../research/人物展示可行性.md)。

| 替代品            | 已能满足的任务        | 衣序必须提供的增量价值（假设）                 |
| ----------------- | --------------------- | ---------------------------------------------- |
| 相册/备忘录       | 留下真实 OOTD，成本低 | 找到这张图中的具体衣物、换一件比较、复用与追溯 |
| Excel/Notion      | 自定义库存与次数      | 降低维护工作，自动从已确认记录汇总             |
| 电商试衣/穿搭内容 | 新衣灵感、购买前查看  | 从已拥有衣物作决定，少量投入即可使用           |
| 真实镜前换衣      | 获得实际合身与触感    | 减少试错步骤；生成图不能替代最终合身判断       |

## 5. 定位与可检验的差异

建议定位：**面向个人日常穿搭的可视化衣橱——用自己的衣服看搭配、作比较、留下实穿记录。**

| 竞争机会假设                   | 为什么值得验证                                    | 如何证伪                                                           |
| ------------------------------ | ------------------------------------------------- | ------------------------------------------------------------------ |
| 人物对比比单纯拼贴更帮助决定   | C-02 的强烈诉求；Acloset/Cladwell 也提供此类能力  | 用相同组合比较原图、平铺、试穿；仅觉得新奇但没有更好的决定则不成立 |
| 渐进建档降低首次退出           | U-01 与 Stylebook 渐进录入建议方向一致            | 少量录入仍无法完成任务，或用户必须先整理全库才感到有用             |
| 选择、输出与实物一致形成信任   | 用户反复否决失真人物；U-02 提及材质信息           | 用户不能识别这是自己的衣服，或未选部件经常被改写                   |
| Web 选衣更顺手，手机记录更方便 | 用户已要求 Web；部分竞品平台有限、U-02 有桌面诉求 | 目标用户只愿在手机操作，Web 不增加任务成功率                       |
| 保存→实穿→统计提供持续价值     | 成熟竞品均有资产/记录路径                         | 用户只生成一次娱乐图，后续不复用也不记录                           |

初期通过现有目标使用者与小范围自愿试用验证，不以付费广告规模化获客。未来可比较免费衣橱＋有限试穿额度和订阅，但必须先测每份可接受结果成本、使用频率与付费意愿；不在当前加订阅系统。未来 12～18 个月的分析风险：竞品增加相似 AI 功能、生成价格变化、图片迁移成本与移动端便利性可能压缩差异；这是情景判断，不是增长预测。
