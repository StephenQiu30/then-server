# 衣序：首版 MVP 产品需求

更新：2026-10-13。工程名 WEARLOG。状态：**MVP 范围已用于本轮 Figma 调整；真实效果、成本及发布条件仍待验证**。本入口按 pm-execution 的精简 PRD 方法组织，详细合同沿用 01～07，不另建重复 PRD；pm-toolkit 用于术语、逻辑和表述检查。未知的联系人不虚设，未知的指标结果不填成事实。

## 1. 摘要

帮助个人使用自己的衣服，看清在同一个人物上换一件后的整体效果，再决定是否保存和实际穿着。首版主线为：人物照片或预设 → 选一件 → 试穿与对比 → 收藏搭配 → 明确确认实穿 → 单品次数与明细。

当前衣橱和实穿已有局部业务基础，人物页面仍是固定素材演示。Figma 本轮补齐主流程与必要状态，**设计完成不代表真实试穿、持久收藏或统计闭环已经实现**。

## 2. 背景与证据

| 已确认方向                                    | 产品约束                                                              |
| --------------------------------------------- | --------------------------------------------------------------------- |
| C-01 自己管理衣服、换装、收藏和统计           | 衣橱身份稳定；照片、收藏、计划与实际穿着分别表达                      |
| C-02 人物展示、选衣、前后对比，Woo 为质感参照 | 成人比例与写实质感需实际验收；可拖动是目标，不预设必须 GLB 或物理布料 |
| C-03 Vercel/Geist 与 shadcn，先看 Web         | 沿用根 DESIGN 和最新版 Figma；首版响应式 Web，不重做视觉体系          |
| C-04 避免浪费、记录耗时费用与失败             | 效果验证先约定预算与停止条件；不能只展示精选成功输出                  |

这些方向来自用户明确要求。01 的公开竞品和反馈为研究观察 E；02 的人物画像、持续记录意愿为假设 H；D-01～05 为待收敛决定。尚无外部访谈、付费意愿或真实试穿接受率数据。

## 3. 目标与成功标准

| 业务目标             | 用户可以观察的结果                     | 需求           |
| -------------------- | -------------------------------------- | -------------- |
| BG-01 低成本开始     | 几件常穿衣服即可开始，无需录完整衣橱   | FR-02～05      |
| BG-02 帮助决定穿什么 | 看同一人物换一件后的变化，并接受或否决 | FR-40～45      |
| BG-03 复用搭配       | 收藏可再次找到单品，图片失效仍有清单   | FR-08/46       |
| BG-04 可信实穿记录   | 只对本人确认的衣物计数，可以纠错和反查 | FR-13～17      |
| BG-05 可控使用与投入 | 私人资产受保护，失败可恢复，费用可追踪 | FR-25，SYS/NFR |

三个阶段结果均为**建议门槛，当前未测**：

1. G1 结束前，6 名自愿参与者中建议至少 4 名无需帮助完成选择→比较→作出决定，并区分收藏与实穿；仅用于发现问题，不推断市场比例。
2. G2 结束前，同一人物三件衣服的有限尝试通过身份、衣物、保留区域检查；继续使用留出集时，按 06 报告首次及限次接受数、全部失败、耗时与支出，不把样片当成功率。
3. 真实内测前，AC-01～12 与适用非功能条件获得相应证据；若首发包含环绕，还必须通过 AC-13。设计原型与业务运行分别验收。

## 4. 目标用户

首版以 **P-A 日常穿搭决策者**为主：出门前或前一晚，想知道手边一件衣服换上去是否适合。**P-B 衣橱整理与复盘者**为次：希望渐进整理常穿衣物，并看懂真实使用记录。P-C 搭配探索者保留为研究对照，不扩大为社区或多人造型平台。以上划分按任务，不按性别或虚构人口比例；详见 02。

## 5. 价值主张

| JTBD 要素              | P-A 日常穿搭决策者                                   | P-B 衣橱整理与复盘者                                 |
| ---------------------- | ---------------------------------------------------- | ---------------------------------------------------- |
| Who：谁                | 用现有衣服决定日常穿搭的人                           | 想弄清有什么、穿过什么的人                           |
| Why：要完成什么        | 少反复换衣，看清单件变化                             | 降低整理负担，保留可信记录                           |
| What before：现有做法  | 看相册、脑补平铺或反复上身                           | 相册、备忘录、手工表格或靠记忆                       |
| How：我们如何帮助      | 保持同一人物和其余衣物，只换一件再对比               | 渐进录入；收藏与实穿分开，支持部分记录和纠错         |
| What after：期望变化   | 更清楚地选择或否决，并能复用组合                     | 已记录的次数可反查，资料可导出和管理                 |
| Alternatives：替代选择 | 镜子、实物试穿、现有搭配工具；我们的优势仍需效果验证 | 表格、其他衣橱 App；我们的记录负担与复用价值仍需观察 |

价值主张：让“这件换上去怎样”更容易判断，让“真正穿过什么”有据可查。当前是待验证的价值假设，不宣称节省了具体时间或提高了留存。

## 6. 方案与尚未解决的问题

### 6.1 流程与原型

[桌面试衣间](https://www.figma.com/proto/DgasIy7ulxxb1MWmew76Zs/?node-id=65-141&starting-point-node-id=65%3A141&scaling=scale-down) · [设计验收入口](https://www.figma.com/design/DgasIy7ulxxb1MWmew76Zs/?node-id=65-151)。本轮沿用当前文件，补齐单件选择、搭配收藏、部分实穿和恢复状态；设计证据见 [Figma MVP 设计验收](../validation/Figma-MVP设计验收.md)。人物结果复用历史素材并标注视觉占位，不作为单件效果证明。

### 6.2 首版必须具备

- 真实衣物录入、照片、全库查找、可用状态、归档恢复；未知属性保留未知。
- 私人人物输入或授权预设，限定品类单件试穿；选择不自动提交。
- 输入版本固定、任务恢复与真实失败解释、原图/结果对比。
- 无日期要求的搭配收藏及版本，再打开和继续调整。
- 明确实穿确认、部分/补录/同日多次/纠错、单品次数与明细。
- 权限隔离、导出删除、费用与失败记录、手机和键盘可用。

范围及当前差距见 07；业务定义不按 Figma 画面数量扩张。
