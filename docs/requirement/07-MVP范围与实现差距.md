## 1. 结论与首版承诺

建议首版面向中文个人日常穿搭，先做响应式 Web，验证一个价值：**用自己的衣服在同一个人物上试换一件，看清变化，保存可复用的搭配，并可靠地记录实际穿着。** 人物始终是试衣间主视觉，衣橱和统计服务于这个决定，而不是把首页变成管理仪表盘。

当前有两块可复用基础：真实衣橱、照片整理、日期计划及实穿记录的局部业务闭环；最新版 Figma 的人物展示、选衣、对比交互。**二者还没有由真实试穿与账户内的 Look 串起来，因此当前不能标记为 MVP 已完成。**

### 首版边界

| 必须包含       | 最小交付边界                                                                                  | 不以什么代替完成                                   |
| -------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 自己的衣橱     | 名称、类别、可后补照片；编辑、全库名称搜索、分类筛选、分页；拥有/参考与可用状态分开；归档恢复 | 固定素材列表、仅筛选已经加载的 30 件               |
| 人物输入       | 本人有效全身照与至少一个有权使用的成人比例预设；明确来源和支持条件                            | 本地预览本人照，却仍展示预设人物的试穿结果         |
| 选衣和真实试穿 | 先分别验证上衣、下装的单件替换；选择不触发费用；未知原衣物只作为保留区域                      | 换一张提前画好的结果图，或把“选中了”当“穿上了”     |
| 对比与保存     | 同一基线，手机切换、桌面对比；保存人物、单品、结果的固定版本；再次进入可找回                  | localStorage 只存名称/场景，或必须指定日期才能收藏 |
| 实穿与最小统计 | 从搭配或直接记录，核对已知单品；支持部分、补录、纠错；单品次数、天数、最近日期和可追溯明细    | 保存/浏览即计数，或只给年度总数                    |
| 可放心使用     | 私人资产隔离；任务恢复、防重、真实失败与费用记录；导出/删除及清理进度；手机和键盘可操作       | 单有接口定义、示例状态或静态检查通过               |

**环绕是用户已明确要求的产品目标。** D-02 只决定交付批次，不能用于取消该目标。建议分开命名验收：上述闭环通过可成为“静态试穿内测候选”；只有连续素材、实际拖动、手机性能和成本通过 AC-13，才可称包含环绕的 Woo 目标版本。如果首发必须环绕，AC-13 就是首发硬条件；静态候选不能绕过它上线为完整承诺。

暂不扩展原生 App、自动拆衣入库、多件同时换装、外套叠穿、鞋包试穿、日历规划、推荐天气、旅行胶囊、高级统计、价格分析、动作库。已有相关功能可以保留，不因“后置”删除并行实现，也不把其完善作为人物闭环的前置。商城、社区、订阅支付与尺码合身保证仍不在本版。

### 必须拿到的首版证据

1. **AC-01/03**：新用户录入自己的衣服、补图仍为同一件；不支持输入在提交前被拦截，管理和记录继续可用。
2. **AC-02/06**：原人物、目标单品、真实结果共同对照；换上衣不改掉裤鞋；在桌面/手机可以比较并明确接受或否决。工程成功与视觉接受分别记录。
3. **AC-04/05/10/12**：双击、断网、刷新、旧结果、供应商未知/失败都不悄悄多下单；等待、失败、重试和已知/估算/未知费用有完整分母。
4. **AC-07/08**：收藏、计划、环绕不计数；只记录已确认单品；补录/同日两次/纠错/删除可从明细重算；归档不丢历史。
5. **AC-09/11**：两账户交叉访问失败；删除后迟到产物不复活；导出能关联单品、照片、Look、实穿；备份恢复按同一核对集重算。
6. **AC-13（条件）**：同一套合格 Look 实际拖动一周，服装和人物连续、首尾可接、手机可用；离散多图或鼠标事件工作不算通过。

05 中等待/性能/容量目标仍是拟定阈值，不是已测 SLA。试衣间既有报告中人物图约 1.6 MB/张，不能仅凭响应式截图推断手机冷加载已达标；新图片交付和缓存策略需实测。质量未达标时停止扩量，保留失败，不用更多页面掩盖效果风险。
