## 系统验收场景

### OOTD-SYS-ACC-001 技术基线、SwiftUI 唯一架构与原生媒体/3D 边界

- 适用层级：全部。
- 前置条件：干净克隆，依赖锁定；如目标包含动态预览，renderer 决策已批准。
- 操作步骤：运行工具链、iOS 架构、契约和依赖检查，执行 clean build/Archive；盘点 UIKit/WebKit/Three.js、视频和 RealityKit 引用。
- 期望结果：产品页面使用 SwiftUI + Observation，GRDB/OpenAPI/Go 基线唯一；360° 使用原生视频能力，真 3D 只使用隔离 WKWebView 中锁版 Three.js/GLB；产品包内没有第二个 renderer、远程可执行代码或 CDN 依赖。
- 边界情况：人物 GLB 必须先通过 Swift 原生校验再进入 renderer；不增加 RealityKit/USDZ 兼容路径。
- 验收证据：脚本/build/Archive 日志、依赖/许可证/SBOM 和 adapter 引用清单。
- 结果：`pending`

### OOTD-SYS-ACC-002 干净启动、恢复与三个一级入口

- 适用层级：本地核心 GA 及以上。
- 前置条件：分别为干净安装、可恢复历史数据和启动依赖失败。
- 操作步骤：启动 App，访问“今日”、“衣橱”、“穿搭簿”和头像内账号/隐私/任务入口，注入数据库/Keychain 启动失败并重试。
- 期望结果：首屏不被同步初始化长期阻塞；三 Tab 职责和空状态正确；失败有可恢复状态；不自动清数据、不进入旧五 Tab。
- 边界情况：历史发布事实未决时不隐藏获批保护入口；旧数据失败不影响新 OOTD 领域恢复。
- 验收证据：启动性能报告、XCUITest 和失败注入录屏。
- 结果：`pending`

### OOTD-SYS-ACC-003 无照片、无新权限、离线本地闭环

- 适用层级：本地核心 GA 及以上。
- 前置条件：干净安装，无账号、无网、不授权相册/相机/通知/日历/位置。
- 操作步骤：手工创建至少两件可组合衣物，获取基础推荐，保存计划，主动确认实际穿着和反馈，杀进程并重启。
- 期望结果：全流程本地成功并恢复；无登录、照片或新权限强制；推荐仅用用户真实拥有且可穿衣物；计划和实际是独立事实。
- 边界情况：写入期间低存储/杀进程时事务全提交或全回滚，不留悬空媒体/重复穿着事实。
- 验收证据：飞行模式真机录屏、数据库/文件对比、跨功能 XCUITest。
- 结果：`pending`

### OOTD-SYS-ACC-004 一张本人 OOTD 照到可编辑组合草稿

- 适用层级：含人物 OOTD 录入的本地发布；未启用时可以开关关闭且不阻断无照片核心。
- 前置条件：书面授权成年本人测试照片，用户主动选择“本人 OOTD”模式并完成 18+ 本人声明。
- 操作步骤：选图，查看用途，通过净化/中性质量门，生成多衣物草稿，逐项确认名称/类别/状态，保存可编辑组合草稿。
- 期望结果：外来建议与用户确认值分离；未知不被虚构；达成此自愿真实衣橱分支的“至少确认两件衣物 + 保存组合草稿”建档指标，不替代零录入主激活；不自动创建 `OutfitPlan` 或 `WearEvent`。
- 边界情况：多人、非本人、分割失败、遮挡和中断有安全恢复；同一照片如同时用于数字形象与衣物拆分，两个目的分别选择且删除/派生关系可见。
- 验收证据：真机录屏、元数据检查、草稿/计划/实际数据查询和失败恢复报告。
- 结果：`pending`

### OOTD-SYS-ACC-005 推荐—计划—实际—反馈—后续解释闭环

- 适用层级：本地核心 GA 及以上。
- 前置条件：衣橱包含可行组合、不可用衣物和硬约束冲突夹具。
- 操作步骤：设置场景/硬约束，查看最多三套推荐，锁定/替换/撤销，保存计划，确认按计划或换件实际穿着，提交/撤回反馈，再查看后续推荐解释。
- 期望结果：硬约束先于排序；不虚构衣物；无解如实说明；只有实际穿着和单独明确反馈影响长期学习；撤回后偏好可重建。
- 边界情况：在推荐后归档/标记待洗时，保存前复核且不静默换件；查看、保留静态/动态生成媒体不自动成为偏好。
- 验收证据：纯领域属性测试、快照/特征审计、时区/并发测试和 XCUITest。
- 结果：`pending`

### OOTD-SYS-ACC-006 静态试穿、云任务与隐私全链路

- 适用层级：静态试穿受控发布必选。
- 前置条件：14、17、18 号验收的目标地域/版本场景已通过，完整穿搭详情和合格本人素材就绪。
- 操作步骤：从已选中穿搭详情主动替换一个目标类别，查看处理方/地域/保留/删除并当次同意，在生成中离开/重启，再测取消、超时、质量拒绝、保留和删除。
- 期望结果：任务可恢复且幂等；结构化穿搭和本地拼图始终可用；只发布通过安全/质量门的结果；真实性声明明确；保留和删除与配额结算符合获批规则。
- 边界情况：重复提交、取消/完成竞态、Provider 失败和迟到回调不重复计费、不复活已删除结果、不修改衣橱和历史。
- 验收证据：端到端 trace、队列/幂等/配额记录、供应商/删除证据和真机录屏。
- 结果：`blocked`

### OOTD-SYS-ACC-007 Create 360° 条件启用、原生播放与静态隔离

- 适用层级：动态预览实验/灰度必选。
- 前置条件：静态试穿已在目标地区稳定生产；15、17、18 号相关验收通过；动态独立开关只对测试账号开启。
- 操作步骤：从用户主动保留的合格静态结果派生 360° MP4，播放/暂停并切换 Reduce Motion/VoiceOver/离线/内存压力，注入视频加载故障，关闭动态开关并删除来源。
- 期望结果：静态先显示；视频明确是 AI 生成动态结果；Reduce Motion 不自动播放；播放器失败降级静态；关闭开关不影响静态/推荐/保存；来源删除级联视频、manifest 和缓存。
- 边界情况：客户端只使用原生视频播放，不引入 Three.js、逐帧拖拽或 Web renderer；MP4 不得标记为可交互真 3D。
- 验收证据：Provider/视频 POC、真机播放性能/能耗/热状态、故障回退/删除和开关记录。
- 结果：`blocked`

### OOTD-SYS-ACC-008 跨账号 API、资产与任务隔离

- 适用层级：任一处理用户云数据的发布。
- 前置条件：两名隔离用户各有资产、Outfit、job、结果和删除请求。
- 操作步骤：替换所有资源 ID、伪造 owner、使用过期/篡改签名 URL，重放幂等键和回调。
- 期望结果：owner 只由服务端认证上下文确定；跨用户请求拒绝且不泄漏存在性；对象二次授权；回调不能跨 owner 关联。
- 边界情况：任意 Repository 漏掉 `user_id`、公开 bucket/CDN 或对象枚举均阻断发布。
- 验收证据：契约/属性/安全测试、ACL 扫描和安全审计元数据。
- 结果：`blocked`

### OOTD-SYS-ACC-009 跨域资产血缘与删除

- 适用层级：所有；按发布层级覆盖实际存在的本地/云副本。
- 前置条件：合成账号包含人物图、衣物图、结构化历史、静态结果、动态帧、缓存、运行任务、Provider 副本和备份状态。
- 操作步骤：分别删除某张照片、某件衣物图、某个生成结果、全部 OOTD 数据和账号，注入中断、迟到结果和备份恢复。
- 期望结果：影响范围先可见；图片删除后结构化历史可无图降级但不保留被删图片快照；血缘覆盖已批准副本；tombstone 阻止复活；部分失败不显示全部完成。
- 边界情况：未启用云能力时必须证明零云副本；备份等待期和 Provider 无法即时删除都如实展示。
- 验收证据：血缘/删除 manifest、数据库/对象/缓存查询、Provider 回执、备份演练和真机录屏。
- 结果：`blocked`

### OOTD-SYS-ACC-010 开发基线与后续 OOTD 数据恢复

- 适用层级：当前开发基线；出现正式 OOTD 持久数据后覆盖相应 schema 的升级与恢复。
- 当前决定：用户确认开发阶段不保留旧业务数据；只验证当前 OOTD 的数据恢复，不建设历史生活管理兼容层。
- 操作：核对当前安装只有 OOTD 页面/权限；在隔离数据上验证重启与后台恢复，当前数据保护按各功能验收。
- 后续验收：12-01 建立首份真实衣物 schema 后测试事务、启动失败、重启恢复及数据删除；未来追加 migration 必须以 OOTD 合成历史数据验证，不新增旧生活管理兼容层。
- 结果：开发清理子集通过；12-01 首份 OOTD 持久化/事务/恢复已有自动化证据；未来 schema 升级及真机恢复仍 `pending`，也不等于系统 GA 通过。

### OOTD-SYS-ACC-011 Release Archive、隐私披露、许可证、无障碍与安全门禁

- 适用层级：全部生产发布。
- 前置条件：目标版本、地域、账号群和 feature flag 已锁定，Release Archive 可安装。
- 操作步骤：扫描签名、App Icon、Privacy Manifest、权限文案、第三方许可证、调试/网络/日志/分析和包内可执行内容；用真机完成目标发布的关键旅程。
- 期望结果：声明与真实数据流/开关一致；生产关闭调试和未授权 Swagger UI；无密钥/敏感正文/资产 URL 泄漏；按需权限和本地替代路径成立；最大字号、VoiceOver、Reduce Motion 与后台遮罩等通过。
- 边界情况：分析、分享/导出生成媒体、静态试穿或动态预览未进目标发布时，包内入口/外联/远程开关必须不可达。
- 验收证据：Archive/隐私/秘密/依赖扫描、网络抓包、真机无障碍录屏、App Store 披露与开关快照。
- 结果：`pending`

### OOTD-SYS-ACC-012 本地多视角完整旅程

- 适用层级：当前无上传本地核心 GA 必选；开发先用 Xcode 模拟器，物理发布另验。
- 前置条件：最低支持真机、获批内置资产和 iOS 26 构建；全新安装、零真实衣物、断网、未登录、不授权人物或衣物照片。
- 操作步骤：选择三套人物之一和 tops/bottoms/shoes 完整组合；切换两件不同上装；观察正/侧/背；撤销再保存 Look 与日期；终止重启；日期回看；删除 Look 后重开。
- 期望结果：只解析完整 `published` 渲染集，人物/衣物/视图/revision 一致且删除不复活；无账号/权限/网络前置；模板 Look 不创建拥有、计划或实际穿着事实。
- 边界情况：快速连续选择、未知/撤销 revision、坏 hash、下载中断、低存储、Reduce Motion 和 VoiceOver；始终保留上一完整有效 Look。
- 验收证据：72 张视觉矩阵、模拟器/真机录像、manifest、状态/保存记录、缓存故障与无障碍结果。仅构建通过或单张样片不满足本场景。
- 结果：`pending`

### OOTD-SYS-ACC-013 云能力按目的启用与本地独立

- 适用层级：P1 多视角与本地核心必选。
- 前置条件：Release 候选，能记录网络请求；后端未运行；设备分别处于有网和断网。
- 操作步骤：完成角色、衣橱、推荐、保存、删除；查看登录/生成/同步/下载入口与运行配置。
- 期望结果：未认证/未逐次同意时无照片上传或生成；已批准云能力仅接纳用户主动且经过授权的最小输入。没有隐含匿名账号、完整衣橱/角色/记录同步或远程脚本；离线仍可用本地衣橱和记录，未开放能力不能接纳任务。
- 边界情况：未授权远程配置不能启用本次发布未批准的云能力；未来云生成错误不得诱发偷偷上传完整衣橱。
- 验收证据：Release 配置、包内资源清单、网络记录与本地状态对照；区分 OS 自身网络活动和 App 业务请求。
- 结果：`pending`

### OOTD-SYS-ACC-014 Woo 全流程组合交付

- 页面复现：逐项比对 Design 03 的 WOO-REF 页面映射；同视口、同状态检查主视觉比例、分类网格、已选托盘、操作与日期浏览。保留来源和 App 截图、差异及复核结果；仅宣传片中已观察页面可认领复现，当前尚未通过。
- 覆盖需求：OOTD-REQ-014/015，PRD 11/12/14/16/17/18 与多视角 ACC-012。
- 当前决定：无上传内置多视角优先；本场景验收后续完整 Woo 组合目标。本人照片、静态试穿、动态、下载和分享分别记录覆盖/缺口。
- 前置条件：合规测试照片、准入 Provider、实际生成客户端、对应服务与资产版本固定；先完成内置多视角和照片静态各自 POC。
- 操作：完成无上传人物/内置衣物/三视图/保存；再选择本人照片并确认用途→主动生成→离开/重入查看最终状态→收藏/下载/分享→创建并删除 360 媒体；核对照片和派生范围。
- 期望：请求由唯一 OpenAPI 生成 Client 发起；重复、失败、取消、迟到结果与删除不产生错误事实。正侧背图片和 360 MP4 按各自媒体类型呈现，不冒充可编辑 3D mesh。
- 证据：真实请求/数据库/队列与删除断言、Provider 测试报告、资产 hash、设备屏幕旅程、离线与辅助功能。不得上传真实用户数据作为测试夹具。
- 结果：`pending`；只有静态流程或只有本地模板均不能判定完整目标已交付。

### OOTD-SYS-ACC-015 可交互真 3D 独立交付

- 前置条件：P5 对应 PRD/design 与 `FF-SS` 契约获批；人物、服装、动作和 GLB manifest 已通过权利与资产检查。
- 操作步骤：在最低支持真机进入 3D 工作室，异步加载人物，连续旋转/缩放，依次替换上装、下装和鞋，触发一次展示动作；再注入弱网、坏 hash、低存储、内存压力和缺失动作。
- 期望结果：正常路径保持可交互帧率与固定人物/衣物语义，动作结束回到稳定待机；失败保留上一有效场景，首次失败可回到关联多视角 Look；VoiceOver、Reduce Motion 和相机复位可用；MP4 或三视图不能作为通过证据。
- 结果：`pending`。

### OOTD-SYS-ACC-016 完整产品端到端交付

- 前置条件：P1–P6 对应单功能验收均通过，生产配置、供应商、隐私、许可证和数据生命周期获准。
- 操作步骤：以零数据新用户完成无上传穿搭；建立真实衣橱并完成推荐—计划—实际—反馈；用本人授权照片完成试穿和 360°；完成真 3D 换装；在第二台设备恢复允许同步的数据；最后导出并删除账户数据。
- 期望结果：每一步产生真实、可恢复、可删除的产品状态；三类视觉结果标识正确；跨账号隔离成立；删除覆盖数据库、本地缓存、MinIO、队列任务和供应商副本；Release、无障碍、安全和恢复门禁均有证据。
- 结果：`pending`。
