## 系统验收环境

- 固定工具链、依赖锁文件和干净克隆；候选 Release Archive 必测。
- 最低支持的真实 iPhone/iOS 18 与主流尺寸模拟器；覆盖深色模式、最大辅助字号、VoiceOver 和 Reduce Motion。
- 干净安装、每个已批准历史 schema 的合成夹具、离线/弱网/低存储/杀进程/重启环境。
- 云端层级使用隔离的 PostgreSQL 18、RabbitMQ、Redis、私有对象存储和 Provider 沙箱，不使用真实用户素材。
- 所有证据保存到持久的 CI artifact、测试报告或发布记录，不以 `/tmp` 作为长期证据。

## 系统验收场景

### OOTD-SYS-ACC-001 技术基线、SwiftUI 唯一架构与局部 renderer 边界

- 适用层级：全部。
- 前置条件：干净克隆，依赖锁定；如目标包含动态预览，renderer 决策已批准。
- 操作步骤：运行工具链、iOS 架构、契约和依赖检查，执行 clean build/Archive；盘点 UIKit/WebKit/Three.js 引用。
- 期望结果：产品页面使用 SwiftUI + Observation，GRDB/OpenAPI/Go 基线唯一；UIKit/WebKit 只位于明确 adapter；Three.js 仅在对照 POC 通过并锁版后可作局部 renderer，不是 H5 Feature。
- 边界情况：未启用动态能力时包内不应存在占位 Three.js runtime；禁止未批准同类框架和远程可执行代码。
- 验收证据：脚本/build/Archive 日志、依赖/许可证/SBOM 和 adapter 引用清单。
- 结果：`pending`

### OOTD-SYS-ACC-002 干净启动、恢复与三个一级入口

- 适用层级：本地核心 GA 及以上。
- 前置条件：分别为干净安装、可恢复历史数据和启动依赖失败。
- 操作步骤：启动 App，访问“今日”、“衣橱”、“穿搭簿”和头像内账号/隐私/任务入口，注入数据库/Keychain 启动失败并重试。
- 期望结果：首屏不被同步初始化长期阻塞；三 Tab 职责和空状态正确；失败有可恢复状态；不自动清数据、不进入旧五 Tab。
- 边界情况：历史发布事实未决时不隐藏获批保护入口；旧数据失败不影响新 OOTD 领域恢复。
- 验收证据：启动性能报告、XCUITest 和失败注入录屏。
- 结果：`pending`

### OOTD-SYS-ACC-003 无照片、无新权限、离线本地闭环

- 适用层级：本地核心 GA 及以上。
- 前置条件：干净安装，无账号、无网、不授权相册/相机/通知/日历/位置。
- 操作步骤：手工创建至少两件可组合衣物，获取基础推荐，保存计划，主动确认实际穿着和反馈，杀进程并重启。
- 期望结果：全流程本地成功并恢复；无登录、照片或新权限强制；推荐仅用用户真实拥有且可穿衣物；计划和实际是独立事实。
- 边界情况：写入期间低存储/杀进程时事务全提交或全回滚，不留悬空媒体/重复穿着事实。
- 验收证据：飞行模式真机录屏、数据库/文件对比、跨功能 XCUITest。
- 结果：`pending`

### OOTD-SYS-ACC-004 一张本人 OOTD 照到可编辑组合草稿

- 适用层级：含人物 OOTD 录入的本地发布；未启用时可以开关关闭且不阻断无照片核心。
- 前置条件：书面授权成年本人测试照片，用户主动选择“本人 OOTD”模式并完成 18+ 本人声明。
- 操作步骤：选图，查看用途，通过净化/中性质量门，生成多衣物草稿，逐项确认名称/类别/状态，保存可编辑组合草稿。
- 期望结果：外来建议与用户确认值分离；未知不被虚构；达成“至少确认两件衣物 + 保存组合草稿”首次价值；不自动创建 `OutfitPlan` 或 `WearEvent`。
- 边界情况：多人、非本人、分割失败、遮挡和中断有安全恢复；同一照片如同时用于数字形象与衣物拆分，两个目的分别选择且删除/派生关系可见。
- 验收证据：真机录屏、元数据检查、草稿/计划/实际数据查询和失败恢复报告。
- 结果：`pending`

### OOTD-SYS-ACC-005 推荐—计划—实际—反馈—后续解释闭环

- 适用层级：本地核心 GA 及以上。
- 前置条件：衣橱包含可行组合、不可用衣物和硬约束冲突夹具。
- 操作步骤：设置场景/硬约束，查看最多三套推荐，锁定/替换/撤销，保存计划，确认按计划或换件实际穿着，提交/撤回反馈，再查看后续推荐解释。
- 期望结果：硬约束先于排序；不虚构衣物；无解如实说明；只有实际穿着和单独明确反馈影响长期学习；撤回后偏好可重建。
- 边界情况：在推荐后归档/标记待洗时，保存前复核且不静默换件；查看、保留静态/动态生成媒体不自动成为偏好。
- 验收证据：纯领域属性测试、快照/特征审计、时区/并发测试和 XCUITest。
- 结果：`pending`

### OOTD-SYS-ACC-006 静态试穿、云任务与隐私全链路

- 适用层级：静态试穿受控发布必选。
- 前置条件：14、17、18 号验收的目标地域/版本场景已通过，完整穿搭详情和合格本人素材就绪。
- 操作步骤：从已选中穿搭详情主动替换一个目标类别，查看处理方/地域/保留/删除并当次同意，在生成中离开/重启，再测取消、超时、质量拒绝、保留和删除。
- 期望结果：任务可恢复且幂等；结构化穿搭和本地拼图始终可用；只发布通过安全/质量门的结果；真实性声明明确；保留和删除与配额结算符合获批规则。
- 边界情况：重复提交、取消/完成竞态、Provider 失败和迟到回调不重复计费、不复活已删除结果、不修改衣橱和历史。
- 验收证据：端到端 trace、队列/幂等/配额记录、供应商/删除证据和真机录屏。
- 结果：`blocked`

### OOTD-SYS-ACC-007 动态预览条件启用、renderer 回退与静态隔离

- 适用层级：动态预览实验/灰度必选。
- 前置条件：静态试穿已在目标地区稳定生产；15、17、18 号相关验收通过；动态独立开关只对测试账号开启。
- 操作步骤：从用户主动保留的合格静态结果派生动态资产，拖动/原生按钮查看，切换 Reduce Motion/VoiceOver/离线/内存压力，注入 renderer 故障，关闭动态开关并删除来源。
- 期望结果：静态先显示；动态明确是 2.5D AI 推测；Reduce Motion 不运行连续动画；renderer 失败降级静态；关闭开关不影响静态/推荐/保存；来源删除级联所有帧、manifest 和缓存。
- 边界情况：如使用 Three.js，必须是本地锁版 bundle、CSP/零外联、按 App + WebContent + GPU 总资源验收，context lost/WebContent 终止最多重建一次后静态降级；原生帧 renderer 更合适时不强行引入 Three.js。
- 验收证据：renderer POC Go/No-Go、真机性能/能耗/热状态、零外联/供应链、故障回退/删除和开关记录。
- 结果：`blocked`

### OOTD-SYS-ACC-008 跨账号 API、资产与任务隔离

- 适用层级：任一处理用户云数据的发布。
- 前置条件：两名隔离用户各有资产、Outfit、job、结果和删除请求。
- 操作步骤：替换所有资源 ID、伪造 owner、使用过期/篡改签名 URL，重放幂等键和回调。
- 期望结果：owner 只由服务端认证上下文确定；跨用户请求拒绝且不泄漏存在性；对象二次授权；回调不能跨 owner 关联。
- 边界情况：任意 Repository 漏掉 `user_id`、公开 bucket/CDN 或对象枚举均阻断发布。
- 验收证据：契约/属性/安全测试、ACL 扫描和安全审计元数据。
- 结果：`blocked`

### OOTD-SYS-ACC-009 跨域资产血缘与删除

- 适用层级：所有；按发布层级覆盖实际存在的本地/云副本。
- 前置条件：合成账号包含人物图、衣物图、结构化历史、静态结果、动态帧、缓存、运行任务、Provider 副本和备份状态。
- 操作步骤：分别删除某张照片、某件衣物图、某个生成结果、全部 OOTD 数据和账号，注入中断、迟到结果和备份恢复。
- 期望结果：影响范围先可见；图片删除后结构化历史可无图降级但不保留被删图片快照；血缘覆盖已批准副本；tombstone 阻止复活；部分失败不显示全部完成。
- 边界情况：未启用云能力时必须证明零云副本；备份等待期和 Provider 无法即时删除都如实展示。
- 验收证据：血缘/删除 manifest、数据库/对象/缓存查询、Provider 回执、备份演练和真机录屏。
- 结果：`blocked`

### OOTD-SYS-ACC-010 历史版本升级、新旧共存与回滚

- 适用层级：本地核心 GA 及以上。
- 前置条件：`19-01` 已给出获批分支，覆盖每个适用历史 schema 的合成夹具和允许回滚版本。
- 操作步骤：从每个历史版本升级，使用新 OOTD 核心，注入旧数据故障，执行保留/只读/导出/删除中获批的路径，再回滚到允许版本。
- 期望结果：无静默丢失或自动重置；旧数据不自动成为 OOTD 事实；旧故障不破坏新 OOTD；不可逆删除和大规模根界面替换不同版；回滚不崩溃或复活数据。
- 边界情况：升级中断、磁盘不足、局部损坏和重复执行都保持原数据和安全恢复点。
- 验收证据：逐版本 migration/属性测试、新旧隔离查询、回滚录屏和产品批准。
- 结果：`blocked`

### OOTD-SYS-ACC-011 Release Archive、隐私披露、许可证、无障碍与安全门禁

- 适用层级：全部生产发布。
- 前置条件：目标版本、地域、账号群和 feature flag 已锁定，Release Archive 可安装。
- 操作步骤：扫描签名、App Icon、Privacy Manifest、权限文案、第三方许可证、调试/网络/日志/分析和包内可执行内容；用真机完成目标发布的关键旅程。
- 期望结果：声明与真实数据流/开关一致；生产关闭调试和未授权 Swagger UI；无密钥/敏感正文/资产 URL 泄漏；按需权限和本地替代路径成立；最大字号、VoiceOver、Reduce Motion 与后台遮罩等通过。
- 边界情况：分析、分享/导出生成媒体、静态试穿或动态预览未进目标发布时，包内入口/外联/远程开关必须不可达。
- 验收证据：Archive/隐私/秘密/依赖扫描、网络抓包、真机无障碍录屏、App Store 披露与开关快照。
- 结果：`pending`

## 证据规则

每份证据必须记录：唯一 `evidence_id`、commit/build、设备与 OS、环境/地域、夹具/策略/模型版本、命令或人工步骤、持久 artifact 地址、时间、执行人、复核人、结果和已知限制。不得保存真实用户素材、生产凭据、敏感正文或依赖临时路径。

执行计划只生产并链接证据，不自动改写验收结果。场景结果由独立执行与复核记录决定。

## 已知阻断与最终判定

- 历史发布事实和数据处置策略尚未关闭，`OOTD-SYS-ACC-010` 当前为 `blocked`。
- 生产 Provider、地域、配额、保留、删除、质量和容量数值未批准，云端场景当前为 `blocked`。
- 动态预览尚未通过增量价值、供应商、renderer 与最低设备 POC，`OOTD-SYS-ACC-007` 当前为 `blocked`。

只有目标发布层级的所有必选系统场景和对应单功能验收均为 `passed`，且不存在未接受的隐私、安全、迁移、删除、无障碍或回滚阻断项时，才能判定该层级发布通过。
