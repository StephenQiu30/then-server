## 验收环境

- 固定 Xcode、Swift、Go 与依赖版本通过 `scripts/verify-toolchain.sh`。
- 最低支持的真实 iPhone/iOS 18，以及当前主流尺寸模拟器；测试深色模式、最大辅助字号、VoiceOver 和 Reduce Motion。
- 干净安装、历史生活管理数据库样本、OOTD 前一 schema 样本和低存储环境。
- 网络覆盖正常、离线、弱网、超时、乱序与断线恢复。
- 隔离的 PostgreSQL 18、RabbitMQ、Redis、私有对象存储与 AI Provider 沙箱；不使用生产账号或真实用户素材。
- 图片夹具使用经过授权的合成或内部测试资产，覆盖肤色、服装类别、姿态、遮挡、背景和失败样本。
- 长期证据保存到 CI artifact、版本化测试报告或发布记录，不以本机短期 `/tmp` 路径作为唯一证据。

## 验收场景

### 场景：技术基线与 SwiftUI 架构唯一

- 前置条件：干净克隆，依赖锁文件存在。
- 操作步骤：运行工具链和 iOS 架构脚本；搜索替代 UI、状态与持久化框架；执行通用模拟器 clean build。
- 期望结果：App 入口为 SwiftUI `App`；产品页面只使用 SwiftUI；Observation、Swift 6 严格并发、Main Actor、GRDB 与 OpenAPI 锁版均满足；UIKit 仅存在于明确系统桥接。
- 边界情况：系统选择器或分享控制器需要 UIKit 时，桥接文件不能拥有业务状态或全局导航；禁止 SwiftData、Core Data、Realm、RxSwift 和 Combine 全局状态。
- 验收证据：脚本日志、依赖清单、Xcode build log 与 UIKit 引用清单。
- 结果：pending

### 场景：首次启动与三个一级入口

- 前置条件：干净安装，无账号、无照片权限、无网络。
- 操作步骤：启动 App，依次进入今日、衣橱、穿搭簿，并打开头像入口。
- 期望结果：首屏不被同步数据库初始化长期阻塞；三个 Tab 名称与职责正确；每个空状态只有一个主要行动；数字形象、账号、隐私和删除位于头像入口。
- 边界情况：数据库或 Keychain 初始化失败时显示可恢复状态，不进入旧五 Tab，也不自动清空数据。
- 验收证据：XCUITest、启动性能报告、失败注入录屏。
- 结果：pending

### 场景：无照片与权限拒绝仍可使用

- 前置条件：未授权相册和相机，衣橱为空。
- 操作步骤：拒绝权限，选择手工创建衣物，填写最小分类并保存；尝试基础推荐入口。
- 期望结果：App 解释权限影响并提供手工路径；不要求上传人物照片或登录；保存的衣物可进入本地推荐准备状态。
- 边界情况：权限随后从系统设置撤回或重新允许时，已有数据不丢失，界面状态及时更新。
- 验收证据：真机权限录屏、Repository 测试和 UI 测试。
- 结果：pending

### 场景：一张 OOTD 建档与批量确认

- 前置条件：使用授权测试图片，包含可识别人物与多件衣物。
- 操作步骤：从 PhotosPicker 选择图片，查看质量提示，确认端侧净化，生成衣物草稿，只修正低置信度字段并批量保存。
- 期望结果：原图方向正确，EXIF/GPS/原文件名不进入云端或日志；用户能看到并修改识别结果；分类是最小必填项；可搭配与需要补拍的素材质量分开表达。
- 边界情况：全身未入镜、遮挡、多人、非本人、未成年人风险或分割失败时，保留安全可恢复路径，不虚构高置信度结果。
- 验收证据：授权样本报告、净化后 metadata 检查、Vision 测试与真机录屏。
- 结果：pending

### 场景：衣橱增删改与历史快照

- 前置条件：衣橱包含各类别、归档、待洗和借出衣物，已有历史搭配。
- 操作步骤：编辑属性、替换图片、修改可用状态、归档并删除一件衣物，再查看历史搭配。
- 期望结果：当前衣物版本更新；不可用衣物不进入新推荐；历史搭配保留当时名称、分类和图片快照；删除触发明确影响确认与资产血缘处理。
- 边界情况：重复图片、并发编辑、保存时版本已变化、源图片缺失和低存储都不会产生半写入记录。
- 验收证据：GRDB 事务/并发测试、媒体 manifest 与 UI 旅程。
- 结果：pending

### 场景：结构化推荐与无解说明

- 前置条件：衣橱具备至少一组完整可穿组合，并包含硬约束冲突样本。
- 操作步骤：选择场景、环境、正式度和体感，指定必须穿/不想穿衣物，查看三套结果，锁定一件并执行只换鞋、更暖和撤销。
- 期望结果：最多返回三套有明确差异的方案；只使用真实、可用衣物；解释与实际约束一致；锁定项保持；撤销恢复上一稳定状态。
- 边界情况：无可行方案时指出具体冲突并提供放宽或添加衣物路径，不偷偷放宽要求、不虚构单品。
- 验收证据：纯领域属性测试、固定 seed 快照、ViewModel 测试与 XCUITest。
- 结果：pending

### 场景：离线核心闭环

- 前置条件：已有本地衣橱，设备进入飞行模式，云端无缓存成功响应。
- 操作步骤：浏览和编辑衣物，生成基础推荐，保存今日穿搭，记录穿后反馈，重启 App。
- 期望结果：所有操作本地成功并在重启后保留；云端试穿入口明确显示需联网或排队，不阻断本地成果。
- 边界情况：在保存中断网、杀进程或存储不足时，事务要么完整提交要么完整回滚，不留下悬空媒体。
- 验收证据：网络故障注入、GRDB 事务测试、重启录屏与文件清单。
- 结果：pending

### 场景：计划、实际穿着与反馈学习

- 前置条件：有推荐搭配和可替换衣物。
- 操作步骤：收藏方案、计划到未来日期、标记今天实际穿着，分别提交完整穿了、换了几件和没有穿的反馈。
- 期望结果：计划与实际穿着是不同记录；换掉的衣物可准确选择；温度和正式度反馈可跳过且可撤销；推荐学习使用实际行为，不把查看或收藏当作真实穿着。
- 边界情况：跨时区、跨日、衣物随后归档或删除时，历史记录保持可解释。
- 验收证据：状态机测试、时区测试、XCUITest 与推荐特征审计。
- 结果：pending

### 场景：静态 AI 试穿异步与降级

- 前置条件：用户年满 18 周岁，已登录，已对单次云生成明确同意，供应商沙箱可用。
- 操作步骤：从推荐卡主动发起试穿，在生成中离开页面并重启 App，返回查看结果；分别执行取消、超时、供应商失败和质量举报。
- 期望结果：创建返回稳定 job；页面退出不丢任务；结构化搭配与即时拼图始终可用；结果明确标注不代表真实尺码、颜色或面料；失败不修改衣橱或已保存搭配。
- 边界情况：重复点击、重复消息、迟到结果、取消与完成竞态不会重复计费或让已删除结果复活。
- 验收证据：iOS/Go 端到端日志、幂等记录、队列故障测试、供应商报告与 UI 录屏。
- 结果：pending

### 场景：动态预览条件启用与 Reduce Motion

- 前置条件：静态试穿门槛已通过，动态预览 feature flag 仅对测试账号开启。
- 操作步骤：生成帧资产，拖拽人物旋转，切换 VoiceOver 和 Reduce Motion，关闭服务端开关。
- 期望结果：帧顺序和 manifest 校验正确；拖拽流畅且有按钮替代；Reduce Motion 下只显示静态视图；关闭开关后静态试穿、推荐和保存继续可用。
- 边界情况：帧缺失、FFmpeg 超时、内存告警和后台恢复均降级为静态结果，不崩溃。
- 验收证据：最低设备性能数据、资源上限测试、无障碍录屏与开关回滚记录。
- 结果：pending

### 场景：后端认证、授权与接口契约

- 前置条件：隔离后端、两名测试用户、有效/失效 Apple token、契约测试环境。
- 操作步骤：校验 OpenAPI；用两用户创建、读取、取消和删除任务；尝试伪造 owner、越权资产 ID、过期签名 URL和重复幂等键。
- 期望结果：Go Handler 与 OpenAPI 状态码/schema 一致；owner 只来自认证上下文；跨用户请求统一拒绝且不泄漏资源存在性；同一幂等键返回稳定结果。
- 边界情况：token 撤销、设备时钟偏差、超大 body、恶意 content type 和分页游标篡改均安全失败。
- 验收证据：契约测试、安全测试、审计日志样本和生成的 iOS Client build。
- 结果：pending

### 场景：队列重复、恢复与资源隔离

- 前置条件：真实 PostgreSQL/RabbitMQ/Redis 容器，API 与 worker 分角色运行。
- 操作步骤：在事务提交、Outbox 发布、Provider 请求、对象上传和结果提交各窗口注入进程终止；重复和乱序投递消息；恢复服务。
- 期望结果：已提交任务最终恢复；未提交任务不出现；Inbox/租约/fencing 阻止重复业务效果；API 延迟不被媒体 worker 阻塞；DLQ 和告警可追踪。
- 边界情况：RabbitMQ 或 Redis 完全不可用时，PostgreSQL 事实不丢失；Redis 清空后系统能重建，不影响任务真相。
- 验收证据：Testcontainers 报告、状态表快照、队列指标和 trace 链路。
- 结果：pending

### 场景：照片、资产与账号删除

- 前置条件：账号包含本地人物图、衣物图、静态结果、动态帧、缓存、队列中任务和供应商副本。
- 操作步骤：分别删除单张人物照片、单件衣物、单个生成结果和全部 OOTD 数据；在处理中断网、重启 worker 并接收迟到回调。
- 期望结果：界面展示影响范围和进行中状态；资产血缘覆盖对象版本、缓存、派生物、供应商和任务；删除 tombstone 阻止迟到结果复活；完成后有不含敏感正文的审计证据。
- 边界情况：部分供应商删除失败时不得显示全部完成，系统重试、告警并说明备份保留窗口。
- 验收证据：删除清单、对象列表、供应商回执、数据库查询和恢复演练。
- 结果：pending

### 场景：旧生活管理数据迁移与回滚

- 前置条件：覆盖每个历史 GRDB schema 的非真实用户 fixture，并有批准的保留、导出或删除策略。
- 操作步骤：安装旧版本样本，升级到 OOTD 版本，执行批准路径，再回滚到允许的上一客户端版本。
- 期望结果：没有静默丢失；保留路径仍可访问或导出，删除路径先取得明确确认并可审计；新表和媒体迁移不会让旧版本崩溃。
- 边界情况：升级中断、磁盘不足、数据库损坏和用户取消删除时均闭合失败并保留可恢复数据。
- 验收证据：逐版本 migration 测试、导出 schema 校验、manifest、回滚录屏和产品批准记录。
- 结果：pending

### 场景：隐私、日志、无障碍与发布包

- 前置条件：Release Archive 候选，生产配置关闭调试和 Swagger UI。
- 操作步骤：扫描源码、日志、trace、通知、包内权限说明和 Privacy Manifest；用 VoiceOver、最大辅助字号、深色模式、Reduce Motion 完成核心旅程；检查签名与 App Icon。
- 期望结果：没有令牌、图片 URL、用户提示词或供应商正文泄漏；权限按需请求且有替代路径；所有关键控制可识别、可操作、无裁切；发布资源和隐私声明与真实数据流一致。
- 边界情况：后台任务完成通知不含敏感穿搭正文；系统任务切换遮罩不显示人物照片；分析关闭时不发送事件。
- 验收证据：Archive 报告、隐私扫描、网络抓包、无障碍审计、真机录屏和 App Store 配置快照。
- 结果：pending

## 已知限制

- 当前尚未选择生产云地域、对象存储和 AI Provider，所有云端验收保持 `pending`。
- 动态预览不是静态试穿或首发本地核心的通过前提；若未过门槛，应保持关闭而不是阻断产品发布。
- 旧生活管理真实用户数据状态尚未确认，因此对应迁移和删除场景不能标记通过。
- 模拟器不能替代照片权限、Data Protection、内存、后台恢复、VoiceOver 与最低设备性能的真机证据。

## 最终结论

只有所有首发范围场景结果为 `passed`，且不存在未接受的安全、隐私、数据迁移、无障碍或删除阻断项时，才能判定 OOTD 首发通过。条件动态预览可以保持 `pending` 并关闭 feature flag；不能通过删除验收项或复用旧生活管理测试结果获得通过结论。
