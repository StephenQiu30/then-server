# 验收文档

此目录存放面向用户结果和系统发布门槛的验收标准与结果。acceptance 验证“交付是否成立”，不复制单切片执行计划中的编码任务；每份执行计划必须标明自己覆盖的验收场景和证据。

10 号仅负责跨功能闭环和发布级结论；11–19 号分别验证单功能。追溯链固定为：

`DOMAIN-REQ → design 测试/状态 → FF-SS 执行计划任务与证据 → DOMAIN-ACC → OOTD-SYS-ACC`

执行计划只生产和链接证据，不能自动把任何验收场景改为 `passed`；单功能通过也不代表系统组合通过。

推荐模板：

```markdown
# 功能名称验收

## 状态与结论

## 关联文档

## 需求覆盖

## 验收环境

## 验收场景

### DOMAIN-ACC-NNN 场景名称

- 覆盖需求：
- 适用层级：
- 前置条件：
- 操作步骤：
- 期望结果：
- 边界情况：
- 验收证据：
- 结果：pending | passed | failed | blocked

## 证据与判定
```

验收条件必须可观察、可重复，覆盖正常路径、权限拒绝、断网、重复数据和失败恢复。证据至少记录 `evidence_id`、commit/build、设备/OS、环境/地域、夹具版本、步骤/命令、持久 artifact 地址、时间、执行人、复核人、结果和限制；不得使用真实敏感素材或依赖临时路径。
