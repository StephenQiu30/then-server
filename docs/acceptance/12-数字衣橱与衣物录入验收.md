## 验收环境与证据规则

- 覆盖干净安装、空衣橱、已有历史穿搭、离线、权限拒绝、低存储、进程中断和数据库升级环境。
- 使用合成衣物图片、合规商品图夹具与脱敏数据库 fixture；不得使用真实用户衣物、订单、地址或生产数据。
- 覆盖无图、单件图片、OOTD 多件草稿、疑似重复、图片丢失和现实状态冲突。
- 每份证据记录场景 ID、需求 ID、commit/build、schema/fixture 版本、环境、步骤、结果、时间与复核人，并存入 CI artifact、版本化报告或发布记录；不得依赖短期 `/tmp` 路径。
- 媒体证据只保存哈希、元数据摘要、血缘/manifest 和不可访问性结论，不保存真实敏感素材或可访问 URL。

## 验收场景

### WARDROBE-ACC-001 无图最小保存与稳定身份

- 覆盖需求：`WARDROBE-REQ-001`、`WARDROBE-REQ-002`、`WARDROBE-REQ-009`。
- 设计依据：Design 05“场景一”“场景八”。
- 适用层级：本地核心，首发必选。
- 前置条件：空衣橱；无网络；相机和照片权限未授权。
- 操作步骤：从“今日”和“衣橱”分别新增无图衣物，只填写名称、类别和当前状态后保存；重启 App，再编辑和筛选。
- 期望结果：三项最小信息可保存，图片、品牌、价格、材质和尺码均不是必填；两个入口写入同一对象语义；每件衣物获得稳定全局业务 ID，不使用文件名、哈希、Photos identifier 或本地顺序作为跨端身份；重启后数据存在。
- 边界情况：名称或类别缺失、重复点击保存、权限拒绝和离线均关闭失败或幂等恢复，不产生半记录、重复记录或不可用空入口。
- 验收证据：领域验证测试、GRDB Repository/事务测试、XCUITest、重启录屏和网络零请求记录。
- 结果：`pending`。

### WARDROBE-ACC-002 OOTD 与批量草稿逐项确认

- 覆盖需求：`WARDROBE-REQ-003`、`WARDROBE-REQ-004`、`WARDROBE-REQ-007`、`WARDROBE-REQ-014`。
- 设计依据：Design 05“场景一”“场景六”。
- 适用层级：本地核心；自动识别部分按批准能力条件启用。
- 前置条件：准备包含多件衣物、遮挡和叠穿的合成 OOTD，以及五项批量处理夹具。
- 操作步骤：从 OOTD 形成多件草稿，逐项修正、保存、跳过；在第三项原子提交前注入低存储并重启后继续。
- 期望结果：草稿不是已录入衣物；每项独立确认，已确认项不因后续失败回滚；遮挡细节保持未知并标记需要补拍，不生成隐藏细节作为事实；恢复或丢弃未确认草稿的行为明确，重试不重复已确认项。
- 边界情况：识别失败、退出、重复回调、草稿顺序变化和部分图片丢失时，已确认衣物稳定，未确认项目不进入推荐事实。
- 验收证据：批量状态机测试、GRDB 原子事务测试、低存储/杀进程故障注入、草稿与正式记录计数及 UI 录屏。
- 结果：`pending`。

### WARDROBE-ACC-003 建议、确认值与未知分离

- 覆盖需求：`WARDROBE-REQ-003`、`WARDROBE-REQ-004`。
- 设计依据：Design 05“场景二”。
- 适用层级：本地核心的数据语义；识别供应方式可替换。
- 前置条件：模型建议颜色为蓝色、正式度为休闲，用户改为蓝绿色、商务休闲；另有无法判断材质和保暖的样本。
- 操作步骤：保存用户修正，模拟模型版本升级和重新处理；再参与筛选与推荐准备。
- 期望结果：建议值、来源、置信度、用户确认值和未知状态可区分；重新处理只产生新建议，不覆盖确认值；未知属性不以默认值补齐，也不作为硬过滤事实。
- 边界情况：用户撤销确认、模型不可用、建议 schema 升级和旧建议字段缺失时，结构化衣物仍可查看、编辑和保存。
- 验收证据：领域映射测试、GRDB migration/Repository 测试、模型版本 fixture、ViewModel 测试和 UI 截图。
- 结果：`pending`。

### WARDROBE-ACC-004 疑似重复由用户决定

- 覆盖需求：`WARDROBE-REQ-001`、`WARDROBE-REQ-008`。
- 设计依据：Design 05“场景四”。
- 适用层级：本地核心。
- 前置条件：两件外观近似但状态、历史或来源不同的白色 T 恤。
- 操作步骤：触发疑似重复提示，分别选择保留两件、取消新增和明确合并；对保存操作重复提交。
- 期望结果：系统只提示不自动合并；选择保留时产生两个稳定 ID，状态和历史互不覆盖；取消不改变原衣物；合并仅在用户明确确认范围后执行且可验证。
- 边界情况：图片相同、图片缺失、离线、并发编辑或模型相似度变化均不得触发隐式覆盖或删除。
- 验收证据：Repository 唯一性/幂等测试、并发测试、UI 对比录屏和合并影响清单。
- 结果：`pending`。

### WARDROBE-ACC-005 现实状态、历史快照与未来冲突

- 覆盖需求：`WARDROBE-REQ-005`、`WARDROBE-REQ-006`、`WARDROBE-REQ-011`。
- 设计依据：Design 05“场景三”。
- 适用层级：本地核心，首发必选。
- 前置条件：同类衣物分别处于可穿、待洗、借出、已打包和归档；已有历史搭配和未来计划。
- 操作步骤：在普通和匹配旅行场景请求候选；编辑名称、状态和归档；打开历史和未来计划。
- 期望结果：普通新推荐只使用可穿衣物；已打包仅在用户明确匹配场景中可用；当前编辑不改写历史最小文字快照；未来计划显示状态冲突，由用户选择替换、恢复状态或保留计划，不静默替换。
- 边界情况：状态在推荐与保存之间变化、衣物离线编辑或同时在另一页面更新时，版本复核阻止无提示保存；历史始终与当前状态分离。
- 验收证据：领域过滤属性测试、GRDB 并发/版本测试、历史快照断言和端到端 UI 旅程。
- 结果：`pending`。

### WARDROBE-ACC-006 移除照片但保留衣物与无图历史

- 覆盖需求：`WARDROBE-REQ-009`、`WARDROBE-REQ-010`。
- 设计依据：Design 05“场景五”。
- 适用层级：本地核心；存在云端条件任务时扩展为跨端删除。
- 前置条件：单品含规范化图、前景图、缩略图、本地特征、历史引用和条件任务引用。
- 操作步骤：选择“移除照片但保留衣物”，注入一次删除失败后重试；查看详情、推荐、历史和关联任务。
- 期望结果：照片立即隐藏，全部直接派生媒体与特征进入删除范围；衣物名称、属性、状态和历史引用保留；历史降级为文字、色块或无图占位，绝不保留已删除的图片快照；引用该图的条件任务被阻断、取消或清理。
- 边界情况：对象已不存在、进程终止、迟到结果、重复删除和部分清理失败时，照片不重新可见，也不误删其他衣物或历史事实。
- 验收证据：媒体血缘遍历、数据库/文件差异、任务竞态测试、幂等删除报告和 UI 录屏。
- 结果：`pending`。

### WARDROBE-ACC-007 商品图主动确认与零隐式上传

- 覆盖需求：`WARDROBE-REQ-012`、`WARDROBE-REQ-013`、`WARDROBE-REQ-019`、`WARDROBE-REQ-021`。
- 设计依据：Design 05“场景七”“场景十”。
- 适用层级：本地核心输入边界；任何云端用途另行验收。
- 前置条件：合规商品图、含订单号/地址/价格/页面文案的购物截图和含 GPS/EXIF 的图片夹具。
- 操作步骤：主动选择图片，分别确认和否认“该衣物属于本人衣橱”；完成基础录入、浏览、筛选和状态维护并抓包、扫日志与持久化字段；尝试系统分享、文件导出和公开链接。
- 期望结果：未确认拥有时不创建衣物；确认后先在本机移除可识别人物、价格、订单、地址和无关页面内容，只保存必要衣物工作图和用户确认事实；无法安全净化时不保存原图；原文件名和元数据不成为衣物事实；基础操作无图片、属性或标签上传；首发没有衣物、组合或生成媒体下载、导出、社交分享和公开链接。
- 边界情况：来源不明、图片含人物或多个重叠主体时，提供换图或无图新增，不自动保存人物区域，也不扩大照片权限；系统分享表、文件协调器和深链不能绕过首发限制。
- 验收证据：网络抓包、metadata/log/persistence 扫描、净化前后差异、UI 测试、沙盒文件清单和分享/导出入口扫描。
- 结果：`pending`。

### WARDROBE-ACC-008 离线、中断与可访问性

- 覆盖需求：`WARDROBE-REQ-002`、`WARDROBE-REQ-009`、`WARDROBE-REQ-014`。
- 设计依据：Design 05“场景六”“场景八”“场景九”。
- 适用层级：本地核心，首发必选。
- 前置条件：飞行模式；图片缺失与损坏样本；最大 Dynamic Type、VoiceOver 和深色模式开启。
- 操作步骤：新增无图衣物、编辑属性、筛选、修改待洗/可穿状态；在保存和媒体写入窗口杀进程并重启；完成重复比较。
- 期望结果：核心路径完全离线；事务完整提交或回滚，无悬空媒体；图片丢失只降级无图，不删除衣物；文本替代、状态、错误和主要操作均可读可操作且不只依赖颜色。
- 边界情况：数据库初始化失败、低存储和辅助字号下弹窗空间不足时，提供保留数据的恢复路径，不自动清空或隐藏衣橱。
- 验收证据：故障注入、GRDB 事务测试、重启文件清单、XCUITest、Accessibility Inspector 和真机录屏。
- 结果：`pending`。

### WARDROBE-ACC-009 输入模式与 OOTD 双目的安全隔离

- 覆盖需求：`WARDROBE-REQ-015`、`WARDROBE-REQ-016`、`WARDROBE-REQ-018`。
- 设计依据：Design 05 的输入流程、端侧质量门和领域边界；Design 04 的本人照片规则。
- 适用层级：本地 OOTD/衣物输入核心与人物照片条件能力的共同门禁。
- 前置条件：准备本人成人单人 OOTD、多人 OOTD、单件衣物图和商品图夹具；同一 OOTD 可分别选择衣物拆分和人物参考目的。
- 操作步骤：逐种模式输入夹具；在 OOTD 路径不确认本人且 18+、选择多人图、只选衣物拆分和同时选择人物参考；检查净化输出与资产血缘。
- 期望结果：本人 OOTD、单件衣物和商品图使用三套明确规则，一种模式的允许内容不扩展到另一种；本地无照片核心不要求年龄声明，但 OOTD 选图前确认本人且 18+；多人阻断并先完成元数据净化；未选择人物参考时不保留可复用人物源图、人体派生物或数字形象。
- 边界情况：用户在确认中途改变目的、只保存部分衣物或重启恢复时，目的状态仍明确；不得以衣物草稿存在为由延长人物素材生命周期。
- 验收证据：输入模式参数化 UI 测试、质量结果码、metadata dump、媒体血缘/文件差异和零非预期上传抓包。
- 结果：`pending`。

### WARDROBE-ACC-010 两分钟首次价值与事实创建边界

- 覆盖需求：`WARDROBE-REQ-017`、`WARDROBE-REQ-020`。
- 设计依据：Design 05 的 OOTD-first 快速添加、批量原子提交与领域关系。
- 适用层级：本地核心产品门禁。
- 前置条件：空衣橱；获授权的本人成人 OOTD 或等价合成输入；从用户主动开始录入计时。
- 操作步骤：形成至少两件衣物草稿，逐项确认并原子保存组合草稿；在另一轮只完成自动识别或留下未确认/半保存草稿；随后分别主动保存为计划和主动确认某日实际穿着。
- 期望结果：只有两分钟内至少两件衣物确认成功且组合草稿原子保存成功才计为首次价值完成；未确认草稿、半保存和仅自动识别均不计入；OOTD 导入本身不创建 `OutfitPlan` 或 `WearEvent`，只有后续明确保存计划或确认日期与“实际穿了”才创建对应事实。
- 边界情况：第二件保存失败、组合事务失败、重复提交、杀进程和跨日时，不得虚报激活、生成半组合或误计实际穿着；重试不重复已确认衣物。
- 验收证据：计时口径测试、GRDB 原子事务/故障注入、草稿/衣物/组合/计划/实际记录计数和端到端录屏。
- 结果：`pending`。

2026-09-12 实施准备审核：以下场景仍为 pending。验收输入按 [Design 05 资产交付 SOP](../design/05-数字衣橱与衣物录入设计.md#三维服装资产交付sop) 固定；视觉检查覆盖全部声明支持的体型/姿态/叠穿组合和连续参数采样。未来动作进入范围时，追加整段动作的衣物适配与打断检查，站姿截图不能证明动态不穿模；格式合法也不能代替质量与最低真机预算通过。

### WARDROBE-ACC-011 真实衣物与视觉示意分离

- 前置条件：有正面图片的真实衣物、近似三维模板和无模板单品。
- 操作步骤：关联模板、调整示意颜色并观察背面；将无模板单品加入推荐/组合。
- 期望结果：真实照片/确认属性不被模板覆盖；背面与形状明确是示意；无模板单品不被丢弃或失去推荐资格。
- 验收证据：模型/关联数据测试、UI 录像与推荐输入对照。
- 结果：`pending`

### WARDROBE-ACC-012 直接换装与兼容失败

- 前置条件：发布兼容矩阵、两个不同几何服装、冲突/未知版本夹具。
- 操作步骤：在合法体型域快速换件并撤销，切换视角，提交冲突组合和损坏资源。
- 期望结果：最新场景生效且撤销可恢复；失败保留可用草稿；不静默改变体型，不以丢掉真实单品来解决视觉冲突；适配矩阵验证通过。
- 验收证据：资产组合检查、revision 用例、真机性能和故障录像。
- 结果：`pending`

### WARDROBE-ACC-013 组合快照与本地恢复

- 前置条件：草稿含角色、多个真实单品及视觉版本；可在文件发布/数据库提交间注入中断。
- 操作步骤：保存、终止重启、恢复核对；修改当前衣物后打开历史组合；检查实际穿着记录。
- 期望结果：文件/索引可恢复一致，历史不被新版本改写；保存不自动创建 WearEvent；不完整三维呈现有说明，不伪装已完整穿着。
