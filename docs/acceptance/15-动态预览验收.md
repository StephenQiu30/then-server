# 动态预览验收

## 文档状态

- 标准状态：`draft`，2026-08-30。
- 验收结论：`pending`；生产启用门禁为 `blocked`。
- 功能边界：动态预览是从用户主动保留的合格静态试穿派生的可选 2.5D 视觉效果，不是真实 3D、360° 扫描、可信背面、数字孪生或服装物理模拟。
- 当前实施：暂无 `15-SS` 近期执行计划；本文只定义未来隔离 POC、renderer 选择和生产启用标准，不授权预建 Three.js/WebKit runtime 或处理真实用户素材。

## 验收环境与证据规则

- POC 只使用合成素材或取得书面授权的成年内部测试素材；不得使用真实用户、生产照片、生产生成结果或来源不明媒体。
- 服务端隔离环境覆盖真实 PostgreSQL、RabbitMQ、Redis、私有对象存储、受限 FFmpeg worker 和供应商沙箱；iOS 覆盖最低支持真机、弱网、离线、低电量、热压力、低存储、后台与进程终止。
- renderer POC 必须用同一 manifest/帧 fixture 比较获批原生实现与 Three.js 候选；只在场景图、着色器、粒子或其他 GPU 效果具有明确产品价值时考虑 Three.js。
- 每份证据记录场景 ID、需求簇、commit/build、模型/供应商/FFmpeg/renderer 版本、fixture 版本、设备与系统、步骤、结果、App/WebContent/GPU 总资源、时间与复核人，并存入 CI artifact、版本化报告或发布记录；不得依赖短期 `/tmp` 路径。
- 证据不得包含人物帧、可访问 URL、对象 key、令牌、提示词、供应商正文或真实敏感素材。

## 验收场景

### MOTION-ACC-001 静态结果前置与明确触发

- 覆盖需求：`MOTION-REQ-001`。
- 设计依据：Design 08 的资格与触发条件、完整用户流程。
- 适用层级：隔离 POC 与条件生产能力。
- 前置条件：分别准备未保留、质量不合格、已删除、已过期和用户主动保留且合格的静态试穿结果。
- 操作步骤：从每种静态结果尝试进入动态预览；在合格结果上主动点击生成；另测试页面曝光、保存穿搭、浏览历史和滑动静态图。
- 期望结果：只有用户主动保留、质量通过且仍有效的静态结果显示入口；只有明确点击才创建任务；页面曝光、静态完成、保存、历史复用和滑动均不自动生成或计费；前置失效时入口关闭并清理派生内容。
- 边界情况：静态结果在提交前被删除或状态变化时阻断任务并回到静态/拼图；重复点击保持单一提交意图。
- 验收证据：资格领域测试、任务创建 spy、幂等记录、网络抓包和 UI 录屏。
- 结果：`pending`。

### MOTION-ACC-002 2.5D 表示边界与时序质量

- 覆盖需求：`MOTION-REQ-002`、`MOTION-REQ-006`。
- 设计依据：Design 08 的质量门、manifest 契约和人工验收 1–4。
- 适用层级：授权 POC 与条件生产门禁。
- 前置条件：至少 100 组授权静态试穿样本，以及闪烁、跳位、额外人物、肢体缺失、衣物突变、错误背面、缺帧、重复帧和 hash 错误夹具。
- 操作步骤：生成、抽帧、校验 manifest 并进行双人复核；查看所有用户文案和角度表示。
- 期望结果：只有完整、连续且通过身份、衣物、肢体、时序和内容安全门的 36–48 个唯一 index 结果可拖动；严重异常不下发；界面不展示真实角度刻度，也不使用“360° 扫描”“真实背面”“3D 数字孪生”等表达。
- 边界情况：可变帧率、旋转元数据、短视频、畸形容器和解码炸弹必须稳定输出合规结果或关闭失败，不得用插值伪装缺帧。
- 验收证据：manifest contract、抽帧/视频安全测试、hash 清单、模型与 FFmpeg 版本报告、盲评及质量/公平性报告。
- 结果：`pending`。

### MOTION-ACC-003 静态先显示、直接操控与 Reduce Motion

- 覆盖需求：`MOTION-REQ-003`。
- 设计依据：Design 08 的页面与交互、iOS 自动化测试 2–5 和人工验收 4。
- 适用层级：条件客户端能力。
- 前置条件：有效 manifest；开启/关闭 Reduce Motion、VoiceOver 和方向锁；最低支持真机。
- 操作步骤：进入结果、左右拖动、快速反向、停止手势；使用原生上一/下一/回静态按钮；开启 Reduce Motion 和 VoiceOver 后重复。
- 期望结果：静态图始终先显示并是最终降级；不自动播放，拖动结束后不持续旋转；快速反向不跳帧或白屏；Reduce Motion 下无自动、惯性或循环动画；VoiceOver 可通过原生控件完成浏览和删除。
- 边界情况：方向锁切换、触摸取消、后台恢复、资源未缓存和帧加载慢时，仍可操作静态结果，不让 Web/renderer 手势接管页面导航或无障碍语义。
- 验收证据：XCUITest、帧索引断言、hitch/触摸延迟报告、Accessibility Inspector 和最低设备录屏。
- 结果：`pending`。

### MOTION-ACC-004 独立同意、地域与拒绝降级

- 覆盖需求：`MOTION-REQ-004`。
- 设计依据：Design 08 的权限、隐私与安全；Design 11 的目的分离和区域策略。
- 适用层级：条件生产能力。
- 前置条件：动态与静态使用不同处理方、地域或保留策略的测试配置；准备拒绝、撤回、文案版本变化和无合规供应商场景。
- 操作步骤：分别拒绝和接受动态处理；在发送前改变处理方/地域/保留期；模拟当前地区不可用。
- 期望结果：动态处理取得独立、具体的当次同意；静态同意不能自动扩展；拒绝或撤回时不上传、不创建动态任务，静态结果、推荐、保存和反馈完整；无合规供应商时关闭入口且不自动跨境；生产素材和结果不用于训练。
- 边界情况：用户自愿、内测或不保存结果不能绕过地域、供应商、训练禁用和删除门禁。
- 验收证据：同意矩阵、区域策略自动化、网络抓包、UI/VoiceOver 录屏和供应商准入记录。
- 结果：`pending`。

### MOTION-ACC-005 状态、manifest、取消与失败恢复

- 覆盖需求：`MOTION-REQ-003`、`MOTION-REQ-006`。
- 设计依据：Design 08 状态机、失败与降级、服务端/iOS 自动化测试 1–7。
- 适用层级：隔离云端集成与条件生产能力。
- 前置条件：有效、缺帧、重复帧、超限、hash 错误和未知版本 manifest；可注入队列重复、回调重放、FFmpeg 超时和 App/worker 终止。
- 操作步骤：创建任务后离开、断网、取消并恢复；注入各失败；重启 App 和 worker；尝试读取损坏 manifest。
- 期望结果：状态合法前进且终态不倒退；重复事件只产生一份 manifest 和一套用户可见帧；取消停止进入新阶段并诚实显示清理；任何 manifest、网络、存储或处理错误都关闭失败为静态图，不白屏、不破坏静态结果和穿搭事实。
- 边界情况：迟到成功不能覆盖取消/删除；低电量、热压力、内存告警和磁盘不足时可主动降级并释放资源。
- 验收证据：状态机/幂等测试、Testcontainers 故障注入、manifest 负向测试、资源释放断言、恢复 trace 和 UI 录屏。
- 结果：`pending`。

### MOTION-ACC-006 Three.js/WebKit 条件 renderer 门禁

- 覆盖需求：`MOTION-REQ-003`、`MOTION-REQ-006`。
- 设计依据：Design 08 的 Renderer 抽象、iOS 自动化测试 8–10；Design 11“本地 Web renderer”。
- 适用层级：仅在后续 `15-SS` 执行计划明确选择 Three.js 时适用；未选择时不得创建占位 runtime。
- 前置条件：同一帧 fixture 的原生 renderer 基线和锁定版本 Three.js 候选；Release 构建；飞行模式和受控抓包环境。
- 操作步骤：检查 lockfile、许可证、SBOM、bundle hash、HTML/JavaScript/shader 和 addon；注入 CSP/bridge/scheme/manifest 错误、未知消息、超限资源、路径穿越、WebGL context lost、WebContent 终止、初始化超时、后台/前台和连续失败；执行 Reduce Motion、VoiceOver、删除和一分钟连续拖动。
- 期望结果：Three.js 只是 `DynamicPreviewRenderer` 后的局部可替换实现；SwiftUI/Observation 继续拥有页面、状态、语义和生命周期；只加载离线锁版 bundle，无 CDN、远程 import、远程 shader/WASM、sourcemap、生产 inspector、外部导航、HTTP(S) 或 DNS；Web storage/cookie/cache 为空；bridge 只接受版本化、限长、不含敏感语义的命令；最多自动重建一次，连续失败保持 SwiftUI 静态图。
- 边界情况：JavaScript 不接收 token、签名 URL、对象 key、用户 ID、任意文件路径或 base64 人物正文；退出、后台、删除、context lost 和进程终止后纹理、blob、scheme 映射、handler 与临时文件不可恢复；Reduce Motion 不启动连续 loop。
- 验收证据：依赖/许可证/SBOM 与 bundle hash、静态扫描、CSP/bridge 负向测试、零外联抓包、删除/终止测试，以及 App+WebContent+GPU 总内存、延迟、hitch、能耗、热状态和包体与原生方案的 go/no-go 对照。
- 结果：`blocked`，当前没有对应 `15-SS` 执行计划和 renderer POC；不阻断静态试穿或本地核心。

### MOTION-ACC-007 动态删除、来源级联与防复活

- 覆盖需求：`MOTION-REQ-005`。
- 设计依据：Design 08 服务端自动化测试 8、iOS 测试 2/6 和人工验收 6。
- 适用层级：云端集成与条件生产能力。
- 前置条件：测试血缘包含来源静态图、原视频、中间物、36–48 帧、poster、manifest、设备缓存、后台下载、供应商副本和可选 Web renderer 资源。
- 操作步骤：删除动态结果；再分别删除来源静态结果、人物、衣物、关联穿搭和账号；在过程中断网、杀 worker、终止 App 并发送迟到回调。
- 期望结果：目标立即不可读；全部可达派生物进入删除范围；后台下载停止；本机纹理、缓存、Web storage/scheme 映射和供应商副本收敛；tombstone 阻止迟到结果、缓存和备份恢复使内容复活；部分失败保持不可访问并显示真实状态。
- 边界情况：重复删除、对象已不存在和供应商超时均幂等；取消不能替代已存在内容的删除。
- 验收证据：资产血缘遍历、对象/数据库/设备缓存清单、供应商回执、竞态与幂等测试、备份恢复演练和 UI 录屏。
- 结果：`pending`。

### MOTION-ACC-008 动态行为不是穿着或偏好事实

- 覆盖需求：`MOTION-REQ-002`、`MOTION-REQ-007`。
- 设计依据：Design 08 的领域边界与 Design 09 的实际穿着模型。
- 适用层级：条件能力与推荐学习共同门禁。
- 前置条件：准备生成、查看、拖动、停留、明确保留、删除、重试、举报、实际穿着和独立结构化反馈事件。
- 操作步骤：逐类执行后检查穿着次数、计划、推荐证据、衣物属性和分析事件。
- 期望结果：动态结果不改变静态试穿、穿搭组成、属性、推荐依据、计划或实际穿着；生成、查看、拖动、停留、保留、删除、重试和举报都不计实际穿着或穿搭偏好；只有与媒体保留分离、目的明确且可撤回的结构化反馈可以进入推荐学习，并不得覆盖真实穿着事实。
- 边界情况：重复事件、离线重试、媒体回调和页面停留时长不能重复计数或推断身体/审美属性；媒体“保留”不能被分析层重新解释为弱偏好。
- 验收证据：事件到领域事实映射测试、派生统计审计、分析 payload 扫描和删除/撤回测试。
- 结果：`pending`。

### MOTION-ACC-009 生产启用、独立止损与静态回退

- 覆盖需求：`MOTION-REQ-001`、`MOTION-REQ-003`、`MOTION-REQ-006`。
- 设计依据：Design 08 文档状态、性能预算、发布门禁和人工验收。
- 适用层级：条件生产能力，不属于静态试穿或本地核心发布前提。
- 前置条件：静态试穿已在目标地区通过并开放；动态供应商/许可证、地域、训练禁用、删除、质量、成本、延迟、最低设备性能、无障碍及 renderer POC 均获批准。
- 操作步骤：小流量开启独立 feature flag；注入质量、成本、延迟、供应商、GPU/内存和 renderer 止损；关闭客户端和服务端开关并恢复已接纳任务。
- 期望结果：只有全部门禁有效且独立开关开启时才接纳真实流量；止损立即停止新任务并收敛已接纳任务；开关关闭或任何失败时始终回退用户静态图，推荐、保存、计划、实际穿着和反馈不受影响。
- 边界情况：静态试穿发布、POC 通过、用户自愿或灰度不能自动批准动态能力；不得为了延迟或成本自动跨境或更换未披露供应商。
- 验收证据：go/no-go 决策、供应商与发布批准、feature flag/熔断/回滚演练、质量/成本/SLO 看板、最低设备报告和跨文档追溯。
- 结果：`blocked`，当前动态供应商、地域、质量、成本、生成延迟、最低设备预算和 renderer 选择均未批准；不阻断静态试穿或本地核心。

## 已知限制

- 当前没有 15 号近期执行切片，不应创建 Three.js、WebKit renderer、FFmpeg 或供应商占位实现。
- PRD 15 已为业务规则分配稳定 `MOTION-RULE-*` 并映射到 `MOTION-REQ-*` 需求簇；本文按需求簇判定功能验收，后续执行计划仍须同时声明其覆盖的规则 ID，映射变化时同步复核且不得复用已有 ID。
- Three.js 是条件 renderer，不是既定实现；只有与原生方案的同夹具 POC 证明其产品价值和资源成本可接受后才能采用。
- 动态预览不是静态试穿或首发本地核心的发布前提。

## 最终结论

当前验收结论为 `pending`，生产启用与 Three.js renderer 门禁为 `blocked`。在 `MOTION-ACC-009` 解除阻断且全部生产适用场景 `passed` 前，不得处理真实用户素材或开放动态入口。动态能力保持 `pending`、`blocked` 或关闭时，不阻断静态试穿、衣橱、基础推荐、保存、计划和反馈。
