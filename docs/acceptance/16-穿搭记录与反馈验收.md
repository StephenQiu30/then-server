- 最低支持的真实 iPhone/iOS 18 与主流尺寸模拟器。
- 具有无图、含图、归档、待洗、借出和已删除衣物的合成数据夹具。

- 最大辅助字号、VoiceOver、深色模式和 Reduce Motion。

## 验收场景

### OUTFIT-ACC-001 计划不等于实际穿着

- 覆盖需求：`OUTFIT-REQ-001`、`OUTFIT-REQ-006`；设计测试 `LOG-01`。
- 前置条件：已有一套可保存的结构化穿搭。
- 操作步骤：分别保存组合草稿、将其计划到未来日期，查看穿着次数和历史。
- 期望结果：只有计划记录，不产生 `WearEvent`、不增加穿着次数、不形成长期偏好。
- 边界情况：修改、取消或过期计划不得被转换为实际穿着。
- 验收证据：领域状态机测试、GRDB 事务查询和 UI 录屏。
- 结果：`pending`

### OUTFIT-ACC-002 实际结果和部分事实

- 覆盖需求：`OUTFIT-REQ-002`；设计测试 `LOG-02`～`LOG-05`。
- 前置条件：存在到期计划和可用替换衣物。
- 操作步骤：分别确认“按计划穿了”、“换了几件”、“穿了别套”、“未穿”、“无计划但穿了”和仅记录部分衣物。
- 期望结果：计划快照不被改写；实际穿着精确保存已确认事实；“未穿”不惩罚衣物。
- 边界情况：未确认的类别保持未知，不自动补齐成完整套装。
- 验收证据：用例测试、快照对比和 XCUITest。
- 结果：`pending`

### OUTFIT-ACC-003 结构化反馈可跳过、纠正和撤回

- 覆盖需求：`OUTFIT-REQ-003`；设计测试 `LOG-04`、`LOG-11`。
- 前置条件：已确认一次实际穿着。
- 操作步骤：跳过反馈，再填写冷热、舒适、场合和再穿意愿，然后纠正并撤回该证据。
- 期望结果：空值不等于负面；最新用户明确值生效；撤回后个性化特征可重建且不残留已撤回信号。
- 边界情况：快速连续修改、重复提交和杀进程不产生重复证据。
- 验收证据：特征重建测试、幂等测试和推荐解释审计。
- 结果：`pending`

### OUTFIT-ACC-004 穿后衣物状态原子提交

- 覆盖需求：`OUTFIT-REQ-004`；设计测试 `LOG-08`。
- 前置条件：实际穿着包含多件衣物。
- 操作步骤：逐件选择保持可用或标为待洗，分别注入成功和写入失败。
- 期望结果：成功时实际记录和衣物状态一次提交；失败时整体回滚并允许重试。
- 边界情况：衣物已被其他操作归档时提示冲突，不静默覆盖。
- 验收证据：GRDB 事务测试、版本冲突测试和恢复录屏。
- 结果：`pending`

### OUTFIT-ACC-005 历史快照与再次穿着

- 覆盖需求：`OUTFIT-REQ-005`；设计测试 `LOG-06`、`LOG-07`。
- 前置条件：历史穿搭中一件衣物已改名或不可用。
- 操作步骤：查看时间线/月历和详情，选择“再次穿这套”。
- 期望结果：历史保留当时结构化快照；图片已删除时无图降级；复用前重新检查当前衣物状态并说明冲突。
- 边界情况：已删除衣物按获批的占位/重建策略表示，不虚构当前可用性。
- 验收证据：快照迁移测试、当前/历史对比和 UI 录屏。
- 结果：`pending`

### OUTFIT-ACC-006 离线、中断、幂等与时区

- 覆盖需求：`OUTFIT-REQ-006`；设计测试 `LOG-12`～`LOG-14`。
- 前置条件：设备离线，时区和日界线夹具已准备。
- 操作步骤：创建计划和实际记录，在保存时杀进程/注入低存储，重启并重复确认，再切换时区。
- 期望结果：无网可完成核心流程；事务全成功或全回滚；重复操作不增加穿着次数；展示日期与原始时区语义一致。
- 边界情况：草稿无法恢复时明确说明已丢弃的未提交内容，不谎称保存成功。
- 验收证据：故障注入报告、时区属性测试和重启录屏。
- 结果：`pending`

### OUTFIT-ACC-007 视觉生成不是穿着事实

- 覆盖需求：`OUTFIT-REQ-007`、`OUTFIT-REQ-008`；设计测试 `LOG-09`、`LOG-11`。
- 前置条件：穿搭关联静态或动态 AI 结果。
- 操作步骤：查看、保留并删除生成结果，然后检查实际穿着和推荐偏好。
- 期望结果：浏览、拖动、保留和删除媒体均不创建 `WearEvent`，不自动成为长期偏好；删除人物图后历史使用模板或结构化拼图。
- 边界情况：迟到的生成结果不能回写已删除或已撤回的穿着证据。
- 验收证据：数据查询、偏好特征审计和删除链测试。
- 结果：`pending`

### OUTFIT-ACC-008 不打扰和最小生活上下文

- 覆盖需求：`OUTFIT-REQ-008`；设计测试 `LOG-15`。
- 前置条件：未授予通知、日历或位置权限。
- 操作步骤：使用应用内到期提示、跳过反馈，并检查分析/同步网络流量。
- 期望结果：核心记录不请求新权限；跳过不重复打扰；原始日程、精确位置和穿着正文不因核心功能离机。
- 边界情况：未来若开启推送、分析或同步，本场景保持阻断，直到目的分离和独立验收通过。
- 验收证据：权限录屏、网络抓包和通知计数检查。
- 结果：`pending`

### OUTFIT-ACC-009 可访问性与语义一致

- 覆盖需求：`OUTFIT-REQ-005`、`OUTFIT-REQ-008`；设计测试 `LOG-16`、`LOG-17`。
- 前置条件：最大辅助字号、VoiceOver、深色模式和 Reduce Motion 分别开启。
- 操作步骤：完成计划、实际确认、反馈、状态更新和历史复用。
- 期望结果：信息不裁切；关键控件有可理解标签和足够点击区；计划、实际和反馈的语义不只依赖颜色。
- 边界情况：无图、部分记录和错误状态与完整记录一样可操作。
- 验收证据：Accessibility Inspector 报告、真机录屏和 UI 测试。
- 结果：`pending`
