## 验收环境

- 覆盖每个已发现历史 schema/版本的合成夹具，包含空、正常、边界、局部损坏和大数据量。
- 只读副本、隔离设备和与生产凭据分离的历史发布记录审计环境。
- 覆盖离线、低存储、强制退出、重复执行、版本重试和允许的客户端回滚。
- 所有证据先脱敏；真实历史用户数据不得成为开发、CI 或文档夹具。

## 验收场景

### MIGRATION-ACC-001 发布事实、默认保留与完整盘点

- 覆盖需求：`MIGRATION-REQ-001`、`MIGRATION-REQ-002`、`MIGRATION-REQ-003`；执行计划 `19-01`。
- 前置条件：仅授予只读访问，未批准任何处置策略。
- 操作步骤：审计 Git/构建/发布记录，盘点 schema、表、字段、权限、文件、Keychain/UserDefaults、媒体、备份和可能外部副本，记录不确定性。
- 期望结果：证据支持“已发布/未发布/仍未知”之一；未知按已发布和默认保留处理；清单含来源、用户意义、敏感级、副本范围和证据缺口。
- 边界情况：没找到发布记录不等于从未发布；不得对库、媒体或凭据写入标记、执行 migration 或清理。
- 验收证据：脱敏证据索引、盘点矩阵、只读操作日志和双人复核记录。
- 结果：`pending`

### MIGRATION-ACC-002 新旧数据隔离

- 覆盖需求：`MIGRATION-REQ-004`。
- 前置条件：合成历史数据包含故障样本，新 OOTD 存储使用独立领域边界。
- 操作步骤：启动新版，使用无图衣橱和记录闭环，注入旧数据读取失败。
- 期望结果：旧记账/日历/出行数据不自动转成衣物、穿搭或偏好；旧读取失败不破坏新 OOTD 数据。
- 边界情况：新旧字段同名或历史表损坏时仍不产生隐式映射。
- 验收证据：端到端录屏、数据库对比和故障注入报告。
- 结果：`blocked`

### MIGRATION-ACC-003 无暗黑模式的用户选择

- 覆盖需求：`MIGRATION-REQ-005`。
- 前置条件：保留、稍后决定和明确删除文案已产品/隐私/无障碍审核。
- 操作步骤：用键盘、VoiceOver 和最大字号查看选项，分别选择保留、跳过和删除。
- 期望结果：保留/稍后决定与删除同等可见；无预选删除、倒计时、反复打扰或功能惩罚；跳过后数据保留。
- 边界情况：文案或动线未批准时不得提供生产删除入口。
- 验收证据：可用性报告、无障碍录屏和选择后数据查询。
- 结果：`blocked`

### MIGRATION-ACC-004 只读访问真实性

- 覆盖需求：`MIGRATION-REQ-006`。
- 前置条件：只读支持期和展示语义已批准。
- 操作步骤：打开、排序、搜索和重复查看历史记录，对比前后库/文件。
- 期望结果：原值、时区、币种和必要语义一致；查看行为不回写业务字段、转换数据或触发上传。
- 边界情况：无法解析值显示安全未知状态，不自动修复/归零。
- 验收证据：逐字段对比、读写监测和零外联报告。
- 结果：`blocked`

### MIGRATION-ACC-005 可验证导出且失败不改原数据

- 覆盖需求：`MIGRATION-REQ-007`、`MIGRATION-REQ-010`。
- 前置条件：导出格式、字段字典、安全交付和过期策略已批准。
- 操作步骤：导出各历史夹具，校验 schema、计数、语义和完整性；注入磁盘满、杀进程和交付失败。
- 期望结果：仅完整交付后显示成功；失败包不伪装完整；原数据及其保留选择不变；敏感信息受保护。
- 边界情况：导出成功不等于用户授权删除。
- 验收证据：schema/完整性报告、故障注入、前后数据对比和交付日志。
- 结果：`blocked`

### MIGRATION-ACC-006 明确删除、部分失败与备份状态

- 覆盖需求：`MIGRATION-REQ-008`、`MIGRATION-REQ-009`、`MIGRATION-REQ-010`、`MIGRATION-REQ-012`。
- 前置条件：删除范围、SLA、备份窗口、副本清单和用户文案已批准。
- 操作步骤：独立确认删除，分别注入主数据、文件、副本和备份等待失败，重启后继续。
- 期望结果：只删除批准范围；部分失败保持处理中/需处理；不恢复已删除部分；全部承诺达成前不显示完成。
- 边界情况：卸载、权限撤回、导出成功或不再访问均不是删除授权。
- 验收证据：确认录屏、删除 manifest、失败/恢复记录和备份防复活报告。
- 结果：`blocked`

### MIGRATION-ACC-007 中断、低存储、损坏、重复和恢复

- 覆盖需求：`MIGRATION-REQ-011`、`MIGRATION-REQ-012`、`MIGRATION-REQ-013`、`MIGRATION-REQ-015`。
- 前置条件：存在每个历史 schema 及损坏边界夹具。
- 操作步骤：在每个非删除处理检查点注入低存储、杀进程、损坏和版本重试，重复打开/重试。
- 期望结果：原数据保留；从安全检查点恢复或进入保留数据的恢复页；无重复记录、重复删除或状态倒退。
- 边界情况：“重置 App”不得作为故障恢复指引。
- 验收证据：迁移属性测试、故障注入矩阵、重试对比和 UI 录屏。
- 结果：`blocked`

### MIGRATION-ACC-008 分版发布、expand/contract 与回滚

- 覆盖需求：`MIGRATION-REQ-014`、`MIGRATION-REQ-015`。
- 前置条件：每个阶段的兼容窗口、观察期、停止条件和回滚负责人已批准。
- 操作步骤：依次发布兼容读取、新写入边界和后续处置，在每阶段执行允许的客户端/服务端回滚。
- 期望结果：不可逆历史删除和大规模根界面替换不同版发布；较旧允许版本不因提前 contract 崩溃；异常时首先停止进一步改写。
- 边界情况：任一阶段没有可执行回滚/恢复时不得发布后续阶段。
- 验收证据：版本化 migration 报告、回滚演练、观察仪表盘和发布批准。
- 结果：`blocked`

### MIGRATION-ACC-009 合成夹具和敏感诊断边界

- 覆盖需求：`MIGRATION-REQ-010`。
- 前置条件：历史数据工具、CI、崩溃报告、日志和证据存储均可检查。
- 操作步骤：扫描源码/测试/文档/产物，向每个诊断出口注入合成敏感字段。
- 期望结果：仅合成夹具进入开发/CI；日志和证据仅含允许元数据；导出/诊断路径使用合适数据保护且不进入分析。
- 边界情况：文档长期证据不得依赖 `/tmp` 或包含可重识别真实用户数据。
- 验收证据：秘密/敏感扫描、运行时脱敏测试和夹具来源清单。
- 结果：`pending`

## 证据与判定

每份证据必须记录唯一 ID、commit/build、历史版本/schema、夹具版本、环境、操作类型与只读证明、持久 artifact 地址、时间、执行/复核人、结果和限制。

`MIGRATION-ACC-001` 可在本文总结论仍为 `blocked` 时独立通过。只有处置策略获批且其余适用场景全部 `passed`，再通过 10 号跨功能升级/回滚验收，才能将本功能结论改为 `passed`。
