## 验收场景

### 场景：工具链版本被仓库固定

- 前置条件：在仓库根目录执行命令。
- 操作步骤：运行 `scripts/verify-toolchain.sh`；读取 `.xcode-version` 与 `backend/go.mod`。
- 期望结果：Xcode 为 26.6；Go module 为 `github.com/StephenQiu30/then/backend`，language 为 1.26.0，toolchain 为 go1.26.5。
- 边界情况：本机工具链不一致时脚本必须失败，不能静默使用 beta 或更新版本；CI 尚未创建，因此暂未证明远程 runner 强制执行。
- 验收证据：当前机器执行脚本退出码为 0；Xcode 26.6/17F113、Swift 6.3.3、Go 1.26.5 与 module 指令检查通过。
- 结果：passed

### 场景：OpenAPI 只有一份事实源

- 前置条件：仓库文件完整。
- 操作步骤：解析 `backend/openapi.yaml`；执行 `test -L ios/ThenApp/openapi.yaml` 和 `readlink ios/ThenApp/openapi.yaml`；搜索第二份 OpenAPI 文档。
- 期望结果：规范版本为 3.1.2；符号链接目标为 `../../backend/openapi.yaml`；除该链接外没有第二份 YAML/JSON 契约。
- 边界情况：失效链接、复制文件、`api/` 目录或 Swagger 注解契约均失败。
- 验收证据：人工验证 passed。Generator tag `1.13.0`（commit `af9a2a1f5dcfb00a278d4bb29c6d75080932e99e`）的 CLI 生成验证退出码为 0；Xcode Build Tool Plugin 进一步从同一符号链接生成并编译 `Types.swift` 与 `Client.swift`。生成文件只存在于 DerivedData，持续 CI 仍为 pending。
- 结果：passed

### 场景：单 module、单进程结构约束成立

- 边界情况：文档示例中把禁用结构描述为现状也视为失败；仅在“明确不采用”语境中出现不失败。

### 场景：数据库事实源适配声明式流程

- 前置条件：`backend/schema.sql` 存在。
- 操作步骤：检查文件是否包含完整 DDL 占位说明，是否禁止 P0 未受 Atlas Community 管理的对象；确认没有其他 schema 或 migration 文件。
- 期望结果：只有一个 `backend/schema.sql`；P0 限于 enum/table/column/constraint/index/comment；已有库只管理专用数据库的 `public` schema，任何 DROP 默认阻断，人工确认和生产禁用 auto-approve 已写入设计。
- 边界情况：应用启动时自动改 schema、生产直接执行 `psql` 作为增量升级器、无评审 `--auto-approve` 均失败。
- 验收证据：只发现 `backend/schema.sql`；schema、AGENTS、后端 README 和技术基线约束一致。
- 结果：passed

### 场景：固定项、排除项和待决项没有互相矛盾

### 场景：Xcode 工程落实 iOS 基线

- 前置条件：`ThenApp.xcodeproj` 已创建。
- 操作步骤：检查 build settings、Package.resolved、Build Tool Plugin、Compile Sources 并执行 clean build/test。
- 期望结果：最低 iOS 18、Swift 6、Complete Strict Concurrency、四个 Exact package 版本、OpenAPI Client 可重新生成并编译。
- 边界情况：生成文件被提交、契约被复制、依赖自动升级或存在第二套网络 Client 均失败。
- 验收证据：`xcodebuild -showBuildSettings` 确认为 iOS 18.0、Swift 6、`complete` strict concurrency、Main Actor 默认隔离和 Approachable Concurrency；`Package.resolved` 固定 GRDB 7.11.1、Generator 1.13.0、Runtime 1.12.0 与 URLSession 1.3.1。`xcodebuild ... clean build` 退出码 0，插件在 DerivedData 生成并编译 Client/Types；iPhone 17 Pro（iOS 26.5 Simulator）执行 `xcodebuild ... test` 退出码 0，Swift Testing 1 个测试通过。两份 YAML 因必须加入 Compile Sources 会产生 `no rule to process file` 警告，但不影响插件执行或构建；这是当前已知构建噪声。
- 结果：passed

- 结果：pending

### 场景：iOS 本地数据库基础可迁移和恢复

- 前置条件：GRDB 与 `ThenApp.xcodeproj` 已配置。
- 操作步骤：对独立临时数据库执行集中 migration 两次；检查 WAL、外键、migration 记录与账本基础表；重复执行本地账本初始化；尝试写入第二个 LocalProfile 和缺少发布时间的正式交易；启动模拟器 App 并读取其沙盒数据库。
- 期望结果：migration 幂等且不启用 schema 变化自动重建；只有一个 LocalProfile 和一套稳定 system key；默认现金账户处于待确认本币状态；非法写入被 SQLite 约束拒绝；生产数据库位于 Application Support 并使用 `completeUntilFirstUserAuthentication` 文件保护配置。
- 边界情况：迁移失败必须向启动层返回失败状态，不删除或重建既有数据库；本场景的 migration 测试本身不替代账务跨行平衡、退款或更正专项验收，相关证据记录在系统验收文档。
- 验收证据：iPhone 17 Pro（iOS 26.5 Simulator）与数据库基础直接相关的测试持续通过，当前项目全套 Swift Testing 为 87 项通过、0 失败、0 跳过，连同 16 项 XCUITest 共 103/103 通过，最新结果包为 `/tmp/then-p0-navigation-copy-full.xcresult`。其中新增保护测试通过仍委托真实文件系统的线程安全记录器证明：数据库目录创建与每次打开修复、SQLite 主文件/WAL/SHM 均收到 `completeUntilFirstUserAuthentication`；结构化导出随机目录和最终 JSON 分别在创建与写盘后收到 `complete`。数据库与导出专项共 14 项通过，结果包为 `/tmp/then-file-protection-targeted.V0PjaX/Result-3.xcresult`。Simulator 不可靠返回 `.protectionKey`，上述证据只证明生产路径完整发出保护操作，不宣称已证明系统锁屏语义；实际属性、首次解锁和锁屏读写仍由最低 iOS 18 真机验收。migration 测试已同时断言 `v1_create_local_ledger`、`v2_create_calendar_cache`、`v3_create_trip_planning`、`v4_create_journey_recording`、`v5_create_life_links`、`v6_relax_manual_location_coordinates`、`v7_add_journey_expense_review_state`、`v8_add_trip_plan_revision_review`、WAL 和外键；真实 v7 历史库夹具证明计划和关系数据不丢失，标题来源安全回填为用户值，计划版本、revision 解决时间及状态约束正确追加，并在第二次启动时保持幂等。历史 v5 夹具继续证明地点、计划、路线、提醒、账务与 Journey 无损升级，历史 v6 夹具证明有关系 Journey 回填为 `has_expense`、无关系 Journey 回填为 `pending` 且既有关系与账务不变。每个 XCUITest 通过仅 Debug 可用的 UUID 选择独立文件目录，仍执行同一 `AppDatabase`、migration 和 GRDB Repository；无效 UUID 在真实 App 启动中闭合失败到“无法打开本地数据”，且不显示 Tab Bar 或写入入口；Release 二进制不含测试存储、无障碍目的地或日历变化夹具入口。首次启动阶段的既有沙盒数据库检查为 `profile_count=1`、`account_count=4`、`currency_state=CNY:suggested`、`journal_mode=wal`、`integrity_check=ok`；完成合成首笔支出走查后为 `currency_state=CNY:confirmed`、1 笔 posted 交易、两条各 1250 CNY 的借/贷分录且 `integrity_check=ok`。
- 结果：passed

### 场景：系统能力通过真机 POC

- 前置条件：日历、定位、通知、导航和 OCR adapter 已实现。
- 操作步骤：按实施计划分别执行权限同意/拒绝/撤回、锁屏、后台、断网、Apple 地图打开失败与 OCR 低置信度场景。
- 期望结果：每项都有可恢复降级；不会把第三方导航调起误报为行程同步；OCR 不直接生成已确认账目。
- 边界情况：模拟器结果不能替代真机；APNs 不能作为唯一准点提醒；P0 不请求全天 Always 定位。
- 验收证据：脱敏录屏、系统日志、耗电与字段准确率报告。
- 结果：pending

## 已知限制

- 当前没有 Go `main.go` 或 CI；阶段 4 生活关联与 Journey 消费复盘 schema 已完成。iOS 账务、日历缓存、出行计划和 Journey 本地切片已通过自动化，但所有系统能力真机 POC 仍未完成。
- 账号与多设备同步、国内云和分析平台尚未获得业务输入；国内路线供应商、云 OCR 与穿搭推荐不进入当前实现。
- 单一 PostgreSQL schema 策略只适合当前 P0 约束；复杂生产数据演进需要重新评审。

## 最终结论

技术基线静态验收与 iOS 工程基线 passed。Go 服务与真机 POC 场景保持 pending，直到对应实施里程碑交付；这不代表本地数据库或业务功能已经完成。
