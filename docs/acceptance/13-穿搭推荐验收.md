## 验收环境与证据规则

- 使用固定 seed 的合成衣橱与场景 fixture，覆盖完整路径、缺少类别、未知属性、状态冲突、大衣橱和零历史反馈；不得使用真实用户穿着记录或生产数据。
- 覆盖飞行模式、日历/照片/位置拒绝、天气缓存过期、最低支持真机、进程取消和视觉增强完全关闭。
- 最低系统为 iOS 26；按用户决定先在模拟器开发与验证可执行路径，物理性能/保护和人工辅助功能另留发布证据，不以缺真机阻断独立编码，不用模拟器结果代替真机验收。
- 需求验证以纯领域属性测试和确定性快照为主，辅以 ViewModel、GRDB、XCUITest、性能和可访问性证据。
- 每份证据记录场景 ID、需求 ID、策略版本、seed/fixture 版本、commit/build、设备与系统、步骤、结果、时间与复核人，并保存到 CI artifact、版本化报告或发布记录；不得使用短期 `/tmp` 路径。
- 证据和遥测不得包含真实衣物名称、稳定衣物 ID、方案正文、精确上下文、人物照片或可还原生活规律的数据。

## 验收场景

### RECOMMEND-ACC-001 真实可用衣物与硬约束优先

- 覆盖需求：`RECOMMEND-REQ-001`、`RECOMMEND-REQ-002`、`RECOMMEND-REQ-003`。
- 设计依据：Design 06 `REC-01`、`REC-02`、`REC-03`。
- 适用层级：本地核心，首发必选。
- 前置条件：当前用户衣橱含可穿、待洗、借出、归档和已打包衣物，并准备防雨、正式度和必须穿单品等硬约束。
- 操作步骤：在普通、旅行匹配和硬约束场景生成候选，并检查全部候选与替换列表。
- 期望结果：所有衣物都可追溯到当前用户的稳定业务 ID；待洗、借出和归档不出现；已打包仅在明确匹配场景可用；先执行硬约束再排序，高分不能抵消失败；缺少完整路径时不虚构衣物。
- 边界情况：跨账号 ID、已删除衣物、状态在读取中变化、重复请求和衣橱只有部分角色时均安全关闭或给出明确不足，不生成未拥有商品。
- 数据前置：归档与现实状态分离、packed 上下文匹配有可验证事实。确认属性、未知与建议来源必须区分；不能用衣物名称、照片颜色或服装模板元数据冒充用户确认的正式度/防雨等属性。类别路径通过只证明类别子集，不能抵扣全部硬约束。
- 验收证据：领域属性测试、固定 seed 候选快照、owner/状态查询断言和端到端 UI 录屏。
- 结果：`pending`。

### RECOMMEND-ACC-002 锁定冲突、局部换件与撤销

- 覆盖需求：`RECOMMEND-REQ-004`、`RECOMMEND-REQ-010`。
- 设计依据：Design 06 `REC-04`、`REC-09`。
- 适用层级：本地核心。
- 前置条件：已有候选；用户锁定上装；另准备锁定休闲鞋与正式 dress code 冲突的场景。
- 操作步骤：依次执行更暖、换鞋、更正式和手工替换；撤销一步；触发锁定项与硬约束冲突。
- 期望结果：锁定角色始终保持；只重算未锁定角色，替换项仍满足全部硬约束；撤销恢复上一稳定版本；冲突具体可见，不自动解锁或忽略规则，只有用户明确修改后才继续。
- 边界情况：快速连续操作、取消旧计算和结果乱序时，旧结果不能覆盖新会话，锁定与上下文不丢失。
- 验收证据：状态机/取消属性测试、ViewModel 测试、候选版本快照和 XCUITest。
- 结果：`pending`。

### RECOMMEND-ACC-003 未知信息与可追溯解释

- 覆盖需求：`RECOMMEND-REQ-005`、`RECOMMEND-REQ-007`。
- 设计依据：Design 06 `REC-05`、`REC-11`。
- 适用层级：本地核心。
- 前置条件：候选衣物保暖属性未知，天气缓存已过期，且模型存在未确认建议。
- 操作步骤：生成天气优先候选，展开理由与不确定性，再用未确认建议重复生成。
- 期望结果：未知不会被默认值补齐或作为硬过滤事实；天气更新时间和属性不确定性可见；每条理由只能引用用户输入、已确认衣物事实、批准上下文、当前状态或明确反馈，不显示虚假总分或空泛“AI 认为适合”。
- 边界情况：证据来源被删除、语言切换、规则版本变化和理由字段缺失时，不能编造解释；应降级为可理解的有限说明。
- 验收证据：理由来源审计、领域测试、字符串/公平性扫描、本地化快照和 VoiceOver 输出。
- 结果：`pending`。

### RECOMMEND-ACC-004 最多三套、真实差异与无解说明

- 覆盖需求：`RECOMMEND-REQ-006`。
- 设计依据：Design 06 `REC-02`、`REC-09`。
- 适用层级：本地核心。
- 前置条件：分别准备可形成五套、只能形成两套和无可行组合的衣橱。
- 操作步骤：生成默认候选，比较方案身份、角色、方向和冲突；在无解时只修改一个约束后重算。
- 期望结果：最多三套且方向有实质差异；不足时显示真实数量，不复制方案；无解时指出缺少类别、不可用状态或具体约束冲突，并一次只提供一个明确放宽选项。
- 边界情况：大衣橱、相同分数、只有外观差异和随机 seed 变化时，都不能通过重复组合凑数或混入商品。
- 验收证据：组合多样性属性测试、稳定 seed 快照、冲突结构断言和 UI 比较录屏。
- 结果：`pending`。

### RECOMMEND-ACC-005 人物与视觉生成不参与基础推荐

- 覆盖需求：`RECOMMEND-REQ-008`、`RECOMMEND-REQ-009`。
- 设计依据：Design 06 `REC-07`、`REC-11`、`REC-13`。
- 适用层级：本地核心及所有视觉条件能力的隔离门禁。
- 前置条件：同一结构化衣橱分别配置无形象、模板、人物照片、静态试穿成功/失败和动态预览关闭状态。
- 操作步骤：使用相同 seed 和上下文生成推荐并比较输入、过滤、排序、理由和保存结果。
- 期望结果：照片是否存在、外貌、身体、年龄、肤色、性别、消费能力、品牌价格和视觉结果均不进入资格或排序；视觉任务未启动、失败或关闭时，结构化方案、理由、调整和保存完全可用且一致。
- 边界情况：缓存残留、推荐遥测、模型特征和历史预览不得暗中携带人物或生成质量信号。
- 验收证据：输入特征审计、固定 seed 差分测试、网络/任务 spy 和数据流评审记录。
- 结果：`pending`。

### RECOMMEND-ACC-006 保存前状态与版本复核

- 覆盖需求：`RECOMMEND-REQ-011`。
- 设计依据：Design 06 `REC-06`、`REC-08`。
- 适用层级：本地核心。
- 前置条件：候选生成后，将其中一件衣物标记待洗，或改变来源场景/天气摘要。

### RECOMMEND-ACC-010 计划、实际穿着与媒体行为边界

- 操作步骤：保存推荐和手工方案；仅浏览或收藏；主动确认某日期并选择“实际穿了”；依次操作各类媒体动作；检查计划、实际事件、偏好、转化指标和可用入口。

- 边界情况：重复提交、离线重试、媒体回调、分享扩展和历史复用不得重复创建计划/实际记录或偷偷产生偏好；生成成功和用户保留仍不等于实际穿着。
- 验收证据：领域事件映射测试、GRDB 记录计数、偏好/分析 payload 审计、入口静态扫描和端到端 UI 录屏。
- 结果：`pending`。
