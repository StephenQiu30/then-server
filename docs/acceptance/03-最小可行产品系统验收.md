## 验收环境

- 最低支持 iOS 18 真机至少一台，另选当前主流系统与设备。
- 测试系统日历包含普通、重复、全天、跨时区、已取消和移动日历事件。
- MapKit 场景覆盖正常返回、无路线、离线和 Apple 地图交接失败；不设置城市或交通方式覆盖率门槛。
- 轨迹场景覆盖前台、后台、锁屏、低精度、断网和系统终止。
- 账务使用合成数据，覆盖现金、银行卡、信用卡、退款和转账。
- P1 账号与同步验收使用至少两个设备和 PostgreSQL 18.4 测试容器；不纳入 P0 发布环境。
- 证据不得包含真实用户金额、日历标题、地址、坐标或票据。

- 前置条件：全新安装，所有相关权限未请求，无网络。
- 操作步骤：启动 App，选择本地开始；进入今天；接受或修改系统建议的本币；使用默认现金账户和内置分类新增并保存一笔手动支出。
- 期望结果：首次启动不请求日历、通知、定位、相机或相册；本机已原子初始化唯一 LocalProfile、系统账户、默认现金账户与内置分类；用户确认本币后支出保存成功并在账本显示；账号不是前置条件。

## 场景：退款、冲销与更正

- 前置条件：已有正式支出。
- 操作步骤：执行部分退款、剩余退款、整笔冲销和一次金额/分类更正；查看历史、余额和报表。
- 期望结果：累计有效退款不超过当前有效支出且被冲销的退款释放额度；完整冲销原子创建相反交易；更正在同一数据库事务中创建旧交易的相反影响与替代交易并更新唯一 root head revision；账本始终统计全部正式分录，原交易与相反交易相互抵消，净影响等于替代交易且历史可追溯。
- 边界情况：陈旧 expected root revision、重复退款、超额并发退款、重复完整冲销、对已冲销或已被替代交易再次操作和并发更正只允许一个 canonical 结果；存在有效退款时直接冲销当前支出失败，更正金额低于有效退款合计失败；同命令标识不同内容稳定拒绝；任意故障注入后不得出现只创建相反交易、只创建替代交易或只更新 root revision 的半完成结果。
- 验收证据：领域/数据库测试和交易历史截图。阶段性证据：88 项 Swift Testing 全部通过，其中仓储定向测试覆盖部分退款、累计额度、退款撤销释放额度、陈旧 root revision、超额退款、带有效退款的更正下限与整笔撤销阻止、完整撤销净额归零、命令幂等回读，以及在替代分录写入时强制失败后 root revision、交易与分录全部回滚；详情 ViewModel 测试另覆盖操作入口随 root 状态刷新和中文全角小数点输入。第一条真实 XCUITest 在刚创建的 12.34 支出详情记录 2.34 部分退款，并断言“有效退款 2.34 人民币”“仍可退款 10.00 人民币”的可读无障碍名称，再进入账本确认退款后的月报与 canonical root 流水。第二条真实 XCUITest 新建 20.00 支出，将金额和说明更正为 18.00 与“更正后商户”，随后对当前版本执行完整撤销；详情明确显示“更正后的版本”“更正冲销”“当前版本，已撤销”，且退款、更正和撤销入口全部关闭。共享 Scheme 104/104 结果包为 `/tmp/then-p0-diagnostics-full.29ghCZ/Result.xcresult`；人工复核截图 `/tmp/then-p0-journey-expense-full-attachments.EuMqSi/7D947838-FFD9-4CDD-B6B1-602C437FA9EA.png` 可见 18.00 当前版本、20.00 原始版本及相应冲销历史。最低 iOS 18 真机证据仍未完成，因此场景继续保持 `pending`。

## 最终结论规则

- 只有所有 P0 非条件场景为 `passed`，且高风险真机证据完整时，才可称本地 MVP 通过。
- P1 账号与同步发布时，该条件场景必须为 `passed`，但不阻塞本地 P0。
- OCR 可因基准不足通过 feature flag 关闭，但手动记账和相关权限降级必须通过。
- 任何账务不平衡、静默覆盖确认数据、未主动定位、敏感日志或删除后数据复活均为发布阻断问题。
