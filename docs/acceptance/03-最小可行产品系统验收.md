## 验收环境

- 最低支持 iOS 18 真机至少一台，另选当前主流系统与设备。
- 测试系统日历包含普通、重复、全天、跨时区、已取消和移动日历事件。
- MapKit 场景覆盖正常返回、无路线、离线和 Apple 地图交接失败；不设置城市或交通方式覆盖率门槛。
- 轨迹场景覆盖前台、后台、锁屏、低精度、断网和系统终止。
- 账务使用合成数据，覆盖现金、银行卡、信用卡、退款和转账。
- P1 账号与同步验收使用至少两个设备和 PostgreSQL 18.4 测试容器；不纳入 P0 发布环境。
- 证据不得包含真实用户金额、日历标题、地址、坐标或票据。

## 场景：无登录、无权限开始使用

- 前置条件：全新安装，所有相关权限未请求，无网络。
- 操作步骤：启动 App，选择本地开始；进入今天；接受或修改系统建议的本币；使用默认现金账户和内置分类新增并保存一笔手动支出。
- 期望结果：首次启动不请求日历、通知、定位、相机或相册；本机已原子初始化唯一 LocalProfile、系统账户、默认现金账户与内置分类；用户确认本币后支出保存成功并在账本显示；账号不是前置条件。
- 边界情况：今天无事件时有明确空态和“记一笔/创建计划”入口，不出现不可用云功能。
- 验收证据：首次启动录屏、本地数据库断言、无网络请求记录。
- 结果：pending

## 场景：支出、收入、转账与信用卡还款

- 前置条件：存在现金、银行和信用卡账户以及收入/支出分类。
- 操作步骤：分别创建支出、收入、同币种转账、信用卡消费和信用卡还款；查看余额与月报。
- 期望结果：每笔正式交易至少两条分录且按币种平衡；转账/还款不计收入支出；余额和报表可从分录重建一致。
- 边界情况：零/负金额、来源和目标相同、币种不同、重复点击均被正确阻止或提示。
- 验收证据：领域测试、SQLite 查询和 UI 录屏。
- 结果：pending

## 场景：退款、冲销与更正

- 前置条件：已有正式支出。
- 操作步骤：执行部分退款、剩余退款、整笔冲销和一次金额/分类更正；查看历史、余额和报表。
- 期望结果：累计退款不超过可退余额；完整冲销原子创建相反交易；更正在同一数据库事务中创建旧交易的相反影响与替代交易并更新根版本；账本始终统计全部正式分录，原交易与相反交易相互抵消，净影响等于替代交易且历史可追溯。
- 边界情况：重复退款、超额并发退款、重复完整冲销、对已冲销交易再次冲销和并发更正只允许一个 canonical 结果；任意故障注入后不得出现只创建相反交易、只创建替代交易或只更新原状态的半完成结果。
- 验收证据：领域/数据库测试和交易历史截图。
- 结果：pending

## 场景：离线与数据库异常

- 前置条件：关闭网络，准备低存储或可注入数据库写入失败环境。
- 操作步骤：离线创建、编辑和查询账务；开始并结束 Journey；模拟保存失败后恢复。
- 期望结果：网络不阻止本地操作；本地成功与同步状态分开；写入失败保留用户输入且不产生半笔交易或半个 Journey。
- 边界情况：App 在 SQLite 事务中断、migration 失败或磁盘空间不足时不静默重建用户数据库。
- 验收证据：故障注入日志（脱敏）、事务断言和恢复录屏。
- 结果：pending

## 场景：OCR 只生成待确认候选

- 前置条件：准备脱敏/合成清晰、模糊、缺字段和重复票据图片。
- 操作步骤：分别拍摄/选择图片，检查识别结果，修改低置信度字段并确认或取消。
- 期望结果：确认前余额和报表不变化；低置信度可见；重复只提示；确认后一次创建平衡交易；确认、取消和会话异常结束后均删除临时图片，不生成附件记录。
- 边界情况：相机/相册拒绝、设备不支持、识别失败时可以手动记账。
- 验收证据：样本报告、数据库断言、权限录屏和临时文件检查。
- 结果：pending

## 场景：日历授权、选择与完整扫描

- 前置条件：系统日历存在多来源和测试事件。
- 操作步骤：首次进入日程，跳过后手动建计划；再次进入并授权，选择部分日历，完成扫描；随后撤回权限。
- 期望结果：授权前解释 Full Access 与读取策略；跳过不阻塞；只缓存已选来源；撤回后停止扫描且不把事件批量判定删除。
- 边界情况：扫描中断、查询失败和 App 被杀均不提交错误的 `missing`/`source_deleted`；权限或账户不可用只把 CalendarSource access state 设为 `unavailable`，不批量改写 occurrence。
- 验收证据：真机录屏、扫描事务和事件状态断言。
- 结果：pending

## 场景：重复、全天、跨时区与来源变化

- 前置条件：准备重复系列、单次例外、全天、跨时区、移动日历和已删除事件。
- 操作步骤：扫描后修改单次实例、系列、时间和地点；移动/删除事件；切换设备时区。
- 期望结果：单次修改不影响其他 occurrence；全天日期不漂移；每个继承字段保留来源 revision、value source 和覆盖时间；来源变化不覆盖用户 TripPlan；只有确认 `source_deleted` 才取消仍跟随来源的未来提醒，并保留 Journey 和交易。
- 边界情况：事件移出窗口时 occurrence 进入 `out_of_window`；来源取消选择和权限不可用只更新 CalendarSource 的 `unselected`/`unavailable` access state，都不能冒充删除；标识匹配非唯一时进入 `ambiguous`，不自动合并。
- 验收证据：EventKit 真机数据、状态差异截图和数据库断言。
- 结果：pending

## 场景：事件创建出行计划和提醒

- 前置条件：已授权日历；事件分别包含有效、模糊和空地点；通知未请求。
- 操作步骤：确认地点、起点、交通方式和缓冲；生成路线；调整出发时间；启用提醒；再修改事件时间。
- 期望结果：路线显示 MapKit 来源、计算时间、耗时和有效性；出发时间组成可解释；启用时才请求通知；事件变化后需要重新确认/调度，不静默覆盖用户值。
- 边界情况：无路线、离线、通知拒绝或全天事件时仍可保存手动计划，并明确“未安排提醒”。
- 验收证据：真机录屏、通知 request 和 TripPlan/RouteEstimate 断言。
- 结果：pending

## 场景：外部导航是单向交接

- 前置条件：只使用 Apple 地图；准备可成功调起和打开失败的设备状态。
- 操作步骤：从出发卡片分别选择只打开 Apple 地图和开始记录并导航；模拟 URI 失败并返回 App。
- 期望结果：打开地图只记录 handoff，不自动标记出发/到达；记录模式先可靠创建 Journey；失败可复制地址并返回计划。
- 边界情况：地图返回无统一回调时，App 仍要求用户手动结束，不宣称读取导航历史。
- 验收证据：真机录屏、Journey 状态和 handoff 记录。
- 结果：pending

## 场景：实际行程在后台可靠记录和恢复

- 前置条件：真机允许 When In Use 定位；准备真实移动路线。
- 操作步骤：主动开始，前后台切换、锁屏、降低精度、断网、撤回权限和终止 App；重新打开并恢复/结束。
- 期望结果：记录状态始终明显；每个原始采样先带序号和质量标记落盘再异步筛选；中断保留 partial；每设备最多一个 active Journey；异常退出后提示恢复，不自动推断到达；摘要计算后进入 reviewing，用户确认时原子保存摘要、删除全部 TrackPoint/TrackSegment，再进入 completed。
- 边界情况：`finalizing` 失败原地幂等重试，不回到伪 recording；继续采集必须创建新 segment；无轨迹也能保存时间摘要；存储不足停止新增点并说明完整性；原始点清理失败停留在 reviewing，重启后可继续清理，不提供保留、导出或上传选项。
- 验收证据：脱敏轨迹统计、状态录屏、确认前后数据库对比、耗电和恢复报告。
- 结果：pending

## 场景：行程与消费闭环

- 前置条件：存在完成 Journey、来源事件和已有/新交易。
- 操作步骤：从总结新建消费、关联已有交易、标记无消费；解除关系；删除 Journey。
- 期望结果：新交易金额为空，不采用路线估价；关系双向可见；解除或删除 Journey 不删除交易；汇总只含 confirmed + posted 关系。
- 边界情况：一笔交易关联多个对象、来源事件删除、候选被拒绝后不重复提示。
- 验收证据：端到端 UI 测试、关系表和账务不变量断言。
- 结果：pending

## 场景：权限中心、导出与分层删除

- 前置条件：存在账务、日历缓存、Journey、临时轨迹和可选账号数据。
- 操作步骤：查看权限和数据位置；结束/丢弃 OCR 与行程会话；清理日历缓存；导出数据；删除本地数据，账号启用时请求账号删除。
- 期望结果：每个删除入口说明保留项；导出不含 token、内部同步数据、票据图片或原始轨迹；临时文件清理；删除 Journey 不删除交易；账号删除撤销期可通过受限会话或重新认证查询/取消，进入 deleting 后撤销全部会话且不提前宣称完成。
- 边界情况：低存储、临时清理失败、网络中断和备份尚未到期均有明确状态；云端删除范围覆盖 mutation receipt、change log、冲突、建议和死信。
- 验收证据：文件/数据库清单前后对比、录屏和删除任务记录。
- 结果：pending

## 场景：敏感信息不泄漏

- 前置条件：使用带合成敏感字段的完整主流程。
- 操作步骤：检查 App/Go 日志、trace、crash、通知、APNs、诊断包、Swagger 错误及 P1 数据库样本；验证同机资料隔离。
- 期望结果：日志和运维表面不存在 token、金额明细、商户、标题、地址、坐标、轨迹或 OCR 原文；上云高敏感字段为按用户/数据域 DEK 信封加密的密文；P0 搜索和报表只在本地执行；票据图片与原始轨迹未出现在网络、OpenAPI 或服务端；不同本地资料不能互相打开数据。
- 边界情况：错误、超时、重试、契约校验失败和调试构建同样满足。
- 验收证据：自动扫描结果与人工抽查记录。
- 结果：pending

## 场景：无障碍和系统适配

- 前置条件：开启最大 Dynamic Type、VoiceOver、减少动态效果和深色/浅色系统外观。
- 操作步骤：完成快速记账、事件到计划、开始/结束 Journey 和行程关联。
- 期望结果：主操作可达；金额/状态不只靠颜色；地图有等价文字；动态内容不持续抢焦点；点击区域符合系统建议。
- 边界情况：长标题、长地址、大金额和空态不截断关键动作。
- 验收证据：无障碍录屏和检查清单。
- 结果：pending

## P1 条件场景：账号与多设备同步

- 前置条件：P0 发布后产品单独批准 P1 账号方案；两台设备登录同一测试账号。
- 操作步骤：离线并发修改账务和 TripPlan；让本地 dirty 正式交易遇到远端新版本；重复发送 mutation；制造两个服务端事务交错分配 change；分页 pull/snapshot 中断；删除后让长期离线设备恢复；撤销设备和删除账号。
- 期望结果：重复不产生重复业务数据；确定性冲突/拒绝可重复返回首次脱敏回执；远端版本进入 conflict staging 而不覆盖本地 effective 投影；每用户 cursor 分配持锁至提交且不跳页；snapshot 以固定 token/cursor 稳定分页，完成后只拉取更大 cursor；tombstone 不复活；越权访问失败；账号删除覆盖主数据和派生数据；图片与原始轨迹从未进入同步。
- 边界情况：同 mutation ID 不同 payload、依赖 mutation 未确认、refresh 并发、cursor 过期和服务重启。
- 验收证据：Go/PG 集成测试、OpenAPI contract test 和双设备录屏。
- 结果：pending（P1 尚未批准）

## 场景：不实施能力不存在

- 前置条件：安装候选发布构建，检查全部页面、设置、本地 schema、OpenAPI、服务端 schema 与依赖清单。
- 操作步骤：搜索预算、结转、票据保存/附件、轨迹历史/导出/云备份、国内地图选择、Time Sensitive、订阅、付费、免费容量和权益入口；完成一次 OCR 与 Journey 后复查文件和网络。
- 期望结果：上述能力没有入口、空态、隐藏开关、表、字段、接口、SDK 或付费占位；Apple 地图无路线时走手动降级；OCR 会话结束后无票据图，Journey 摘要确认后无原始轨迹。
- 边界情况：调试构建、feature flag、深层链接和旧草稿也不能进入这些未实施能力。
- 验收证据：全局字符串/依赖扫描、schema 与 OpenAPI diff、UI 录屏、文件系统及网络检查。
- 结果：pending

## 最终结论规则

- 只有所有 P0 非条件场景为 `passed`，且高风险真机证据完整时，才可称本地 MVP 通过。
- P1 账号与同步发布时，该条件场景必须为 `passed`，但不阻塞本地 P0。
- OCR 可因基准不足通过 feature flag 关闭，但手动记账和相关权限降级必须通过。
- 任何账务不平衡、静默覆盖确认数据、未主动定位、敏感日志或删除后数据复活均为发布阻断问题。
