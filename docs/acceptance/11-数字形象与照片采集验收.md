## AVATAR-ACC-025 Three.js 灵动反馈

- 覆盖：`AVATAR-REQ-032`～`035`；执行：[11-04](../plan/11-04-Threejs角色灵动反馈执行计划.md)。
- 正常路径：角色就绪后可观察轻微起伏和重心摆动；左右拖动产生短暂方向倾斜并回正；实际换装变化产生一次短确认反馈，角度切换和重复相同配置不冒充换装动作。
- Reduce Motion：开启后角色保持稳定姿态，不自动起伏、不倾斜、不弹性确认；直接拖动、角度按钮、换装和静态回退仍可操作。
- 生命周期：进入后台后无持续动画帧；回到前台恢复当前人物、服装和 yaw，不补算后台时长；WebContent 终止可重建，退出释放资源。
- 边界：当前工程 GLB 缺少已验收眼睑 morph、面部骨架和 clips，本场景不要求也不得宣称眨眼、表情、挥手或行走；微动通过不能抵扣正式人物资产、穿模或最低真机性能。
- 当前结果：生命周期实现已通过 iPhone 17 / iOS 26.5 模拟器的覆盖页、后台 30 秒和 WebContent 终止重建；系统 Reduce Motion 开启后的 2 秒双帧角色区域无像素变化，关闭后可观察到待机帧差。拖动中取消、换装动态录屏和最低支持真机性能仍未完成，因此本验收保持 `in_progress`。
- 证据：相关自动测试 xcresult、正常/Reduce Motion 模拟器录屏，以及最低支持真机 Instruments/录屏。
- 当前证据：iPhone 17 / iOS 26.5 的 Debug 构建及 `AvatarStudioModelTests` 4 项通过，Woo 首页→衣橱→换装 UI 回归 1 项通过，均 0 失败/跳过。上一轮 13.638 秒模拟器录屏现持久化为私有 `assets/acceptance/avatar-motion-v1/idle-simulator.mov`（仅本机持有，不随公开仓库交付），来源与 hash 见 `assets/acceptance/avatar-motion-v1/README.md`（仅本机持有，不随公开仓库交付）。本轮发现原 contact sheet 链接缺失，已改为真实存在的原始录屏；未重新执行或扩大动态验收结论。
- 结果：`in_progress`。默认待机模拟器子集通过；Reduce Motion、拖动/换装动态、前后台恢复和最低真机仍待验收。

### AVATAR-ACC-011 编辑事务与恢复

- 前置条件：已保存角色配置，准备合法边界/非法参数及乱序渲染回调夹具。

- 期望结果：取消不改旧配置，保存重启恢复完整新配置；旧回调不覆盖新状态；越界拒绝且不改体型或已存数据。

- 期望结果：静态替代能完成操作，过期图不冒充当前组合；角色和私有派生缓存删除，真实衣橱/实际记录保留，内置共用资产不被误删。
- 验收证据：VoiceOver/Reduce Motion/减少透明度真机记录、文件与数据生命周期测试。

### AVATAR-ACC-013 渲染失败与配置保存独立

- 覆盖需求：AVATAR-REQ-020。
- 前置条件：配置校验与 Repository/renderer 可分别注入失败，存在已保存角色。
- 操作步骤：合法草稿等待显示时保存；仅使 renderer/缩略图失败后保存；分别输入非法参数、未知版本、冲突服装；让事务失败并重试/取消；投递旧画面回调。
- 期望结果：有效结构化配置可保存，加载/预览失败状态如实保留；未校验通过的草稿不生成新有效配置；事务失败保留草稿与原持久配置；旧图不关联新 revision，渲染回调不触发业务保存。
- 证据：用例/事务/乱序测试，重启读取与原生 UI 录屏。
- 结果：`pending`。规则已确定，生产实现和测试未执行。
