## 14-01 Provider-neutral observation worker

2026-09-24 在同一后端补齐未启用的 `application/generation.ObservationWorker`。观察 worker 只能领取已经持久化 `external_task_id` 且 `submission_state=accepted` 的任务，队列中的任务不会被误推进到 `running`；Provider 返回的外部 ID、状态和失败原因会先做身份与稳定代码校验。`running`/`validating` 只更新任务状态并释放 fencing lease，`succeeded` 只推进到 `validating`，必须等待后续下载、输出校验和原子发布；`failed`/`canceled`/`expired` 通过无输出结算释放额度并清理租约。查询超时、错误或畸形观察不会推进任务，并在释放租约后返回可重试错误。

`go test -race ./internal/application/generation -count=1` 覆盖成功停在 validating、终态失败结算、队列任务拒绝观察、查询失败和畸形失败原因；隔离 PostgreSQL integration 继续验证 accepted observation lease 不会改变任务血缘。该 worker 未接入 bootstrap、Kafka、真实 Provider、fetch/object-store 或产物发布，因此本 slice 仍不产生供应商请求或费用，完整 `14-01-WORKER-01` 保持 in_progress。

## 14-01 Provider-neutral cancellation reconciliation

2026-09-24 补齐已受理任务的取消业务边界。观察 worker 先读取当前外部状态；仅当任务已有 `cancel_requested_at` 且外部状态仍为 queued/running/validating 时调用注入的 `Provider.Cancel`，随后再次查询并按同一状态机收敛。取消调用或二次查询不可信时只释放租约、保留取消请求和 running 状态，返回可重试的 `ErrGenerationCancellationUnknown`；Provider 已返回 canceled/failed/expired 时直接走无输出结算，success 只停在 validating。外部 queued 观察映射为本地 running，不会被误判为非法状态。

结果 worker 在抓取前检查取消请求；validating 任务会在同一 fencing lease 下原子结算为 canceled、释放额度并清除租约，不调用 `ResultFetcher`，因此迟到图片/GLB 不会发布或消费额度。单测覆盖取消成功、取消失败保留请求、queued 观察和 validating 取消；真实 PostgreSQL generation integration 覆盖受理后进入 validating、取消及无输出结算。Provider、MinIO、Kafka、bootstrap 仍未接入，本 slice 不产生外部请求或费用。

## 14-01 Provider-neutral durable worker claims

2026-09-24 为提交、观察和结果三个 worker 增加可选的 `RunNext` 入口及 PostgreSQL 持久领取边界。`ClaimNextSubmissionLease` 从未撤销、已到 `next_attempt_at` 的 queued/running `not_started` 任务，以及 lease 已过期的 queued/running `in_flight` 任务中按创建顺序用 `FOR UPDATE SKIP LOCKED` 领取；`ClaimNextObservationLease` 只领取 running 且已有 accepted external identity 的任务；`ClaimNextResultLease` 只领取 validating 且已有 accepted identity 的任务。每次领取都递增状态 revision、fencing token 和 lease attempt，过期租约可由下一 worker 重新领取，旧 worker 仍不能写入。

`RunNext` 在没有任务时返回 `found=false`，不改变数据库；有任务时复用原有 submit/query/fetch 编排，Provider 仍只存在于注入端口之后。生成单测覆盖三个 `RunNext` 成功路径，隔离 PostgreSQL integration 覆盖提交/观察/结果队列领取、状态门禁和 fencing 递增。该 slice 没有接入 Kafka、bootstrap、真实 Provider、MinIO 或 Codex 生图，不产生外部请求或费用。

## 14-01 崩溃后恢复 `in_flight` 提交
