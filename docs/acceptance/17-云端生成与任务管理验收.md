## 验收环境

- 隔离的 PostgreSQL 18、RabbitMQ quorum queue、Redis、私有 S3-compatible 存储和授权 Provider 沙箱。
- 同一镜像分别以 `APP_ROLE=api|worker|all` 运行；生产形态的 API/worker 独立进程必测。
- 两名隔离测试用户、失效凭据、重复幂等键、乱序消息和迟到回调夹具。
- 不使用 SQLite/内存 fake 代替真实 PostgreSQL/RabbitMQ 作为唯一证据。

## 验收场景

### CLOUD-ACC-001 本地核心独立

- 覆盖需求：`CLOUD-REQ-001`、`CLOUD-REQ-006`。
- 前置条件：用户未登录，云功能开关关闭，所有云依赖不可用。
- 操作步骤：完成无图衣橱、基础推荐、计划、实际穿着与反馈。
- 期望结果：本地成果可用并可重启恢复；云端入口被正确隐藏或解释；不会因云故障自动上传或丢失数据。
- 边界情况：在已接纳任务存在时关闭新流量，需按批准策略恢复旧任务，不影响本地核心。
- 验收证据：端到端录屏、网络抓包和开关回滚记录。
- 结果：`pending`

### CLOUD-ACC-002 认证、所有权与上传资格

- 覆盖需求：`CLOUD-REQ-002`、`CLOUD-REQ-004`。
- 前置条件：两名用户各有合成人物和衣物资产。
- 操作步骤：验证正常/失效登录、成年本人声明、逐次同意、上传准备/确认，并替换 owner 和资产 ID。
- 期望结果：owner 只来自认证上下文；认证不被当作年龄证明；未同意或不合格资产不获签名上传权限；跨用户访问统一拒绝且不泄漏存在性。
- 边界情况：过期 URL、错误 content type、超大载荷、重复 finalize 和上传后撤回同意安全失败。
- 2026-09-08 补充：上传后改变同一对象 key 的内容，再 finalize/读取；只有绑定并校验的具体版本可用，不能出现“先校验再覆盖”。URL 过期或数据库撤回不被误报为已完成所有物理清理。
- 验收证据：契约/授权测试、对象 ACL 报告和网络抓包。
- 结果：`pending`

### CLOUD-ACC-003 OpenAPI、幂等创建与输入快照

- 覆盖需求：`CLOUD-REQ-002`、`CLOUD-REQ-003`。
- 前置条件：`backend/openapi.yaml` 是唯一契约，iOS Client 由其生成。
- 操作步骤：校验契约，使用同/不同幂等键创建静态和动态任务，然后修改源衣物或穿搭。
- 期望结果：响应 schema/错误码与契约一致；同键同请求返回稳定 job，同键不同请求冲突；job 保留已接纳的版本化输入快照。
- 边界情况：空值、枚举、大小、游标和幂等过期边界可预期失败。
- 2026-09-08 补充：撤回授权或删除后用旧 key 重放，不返回旧媒体/签名 URL；额度已耗尽后重放已接纳命令，不重复占额。取消/删除/状态查询不被生成额度阻断。CI 同时验证授权先于回放及 OpenAPI `/v1` 前缀仅出现一次。
- 验收证据：OpenAPI 语法/风格/破坏性检查、iOS Client build 和 Go 契约测试。
- 结果：`pending`

### CLOUD-ACC-004 前进状态机与 App 恢复

- 覆盖需求：`CLOUD-REQ-002`、`CLOUD-REQ-003`。
- 前置条件：已接纳任务，可注入断网、杀 App 和服务器重启。
- 操作步骤：在上传、排队、处理和结果审核阶段离开/重启，从任务入口恢复。
- 期望结果：状态只合法前进；网络断开不丢任务；结果可从稳定 job ID 重新发现；展示建议轮询间隔与真实状态。
- 边界情况：旧/乱序状态不让已终态 job 回退，未找到任务时不生成虚假成功。
- 验收证据：状态机属性测试、重启录屏和跨端 trace。
- 结果：`pending`

### CLOUD-ACC-005 取消、删除与迟到结果

- 覆盖需求：`CLOUD-REQ-003`、`CLOUD-REQ-004`。
- 前置条件：任务分别处于未调用 Provider、Provider 运行中和结果已返回三个窗口。
- 操作步骤：执行取消，再执行结果/源资产删除，注入迟到回调。
- 期望结果：“已请求取消”不伪装 Provider 已停止；取消不代替删除；tombstone 阻止迟到结果可见化或重新计费。
- 边界情况：取消/完成/删除竞态不产生相互矛盾的终态。
- 验收证据：竞态测试、Provider 回调记录和删除查询。
- 结果：`pending`

### CLOUD-ACC-006 Outbox/Inbox 与故障恢复

- 覆盖需求：`CLOUD-REQ-002`、`CLOUD-REQ-003`。
- 前置条件：真实容器依赖可分别终止。
- 操作步骤：在事务提交、Outbox 发布、Provider 请求、对象写入和结果提交窗口杀进程，重复/乱序投递，清空 Redis 后恢复。
- 期望结果：已提交事实最终恢复；未提交事实不出现；Inbox、租约和 fencing token 阻止重复业务效果；Redis 丢失不改写任务真相。
- 边界情况：broker 长时间不可用时 API 执行回压，不无限接纳；DLQ 可追踪且不含敏感正文。
- 验收证据：Testcontainers 报告、数据库/队列快照、trace 和告警。
- 结果：`pending`

### CLOUD-ACC-007 结果质量审核后发布

- 覆盖需求：`CLOUD-REQ-003`。
- 前置条件：Provider 返回合格、低质量和不安全三类合成结果。
- 操作步骤：处理三类结果，再读取用户可见状态和对象存储访问。
- 期望结果：只有通过内容安全、输入一致性和质量门的结果可发布；其他结果不对用户暴露，并有可恢复安全错误。
- 边界情况：审核服务未知/超时时默认不发布，不以随机成功充数。
- 验收证据：授权样本报告、安全测试和结果 ACL 查询。
- 结果：`pending`

### CLOUD-ACC-008 配额占用、结算与释放

- 覆盖需求：`CLOUD-REQ-002`。
- 前置条件：产品、财务和容量负责人已批准可用次数、占用/结算时点、取消返还、恢复窗口和最大等待值。
- 操作步骤：分别创建成功、用户取消、系统失败、重复、超时和容量暂停任务。
- 期望结果：用户可在提交前看见影响；同一业务效果最多结算一次；失败/取消按批准规则释放；配额真相在 PostgreSQL，不依赖 Redis。
- 边界情况：上游数值未批准时本场景结果必须是 `blocked`，不得以假值通过生产验收。
- 验收证据：批准记录、配额事务/并发测试和 UI 录屏。
- 结果：`blocked`

### CLOUD-ACC-009 资产、任务、账号与备份删除

- 覆盖需求：`CLOUD-REQ-004`。
- 前置条件：账号拥有上传资产、运行任务、结果、缓存、Provider 副本和备份状态。
- 操作步骤：分别删除单个结果、源资产、全部 OOTD 云数据和账号，在中途杀 worker 并注入迟到回调。
- 期望结果：读权立即撤销；血缘删除覆盖所有已批准副本；部分失败如实展示；恢复和备份过期不复活。
- 边界情况：日志、回执和通知不含资产 URL、对象 key 或个人内容。
- 验收证据：删除 manifest、对象/数据库查询、Provider 回执和备份恢复演练。
- 结果：`pending`

### CLOUD-ACC-010 旧账号与历史数据兼容

- 覆盖需求：`CLOUD-REQ-005`。
- 前置条件：历史发布事实和数据处置策略已批准，只使用合成历史夹具。
- 操作步骤：以旧账号/数据启动新版本，进入云任务入口，执行保留、只读、导出或明确删除的获批分支。
- 期望结果：旧生活数据不自动变成 OOTD 事实；未批准的账号合并、上传或删除不发生；新云任务不改写历史记录。
- 边界情况：发布事实未知时本场景保持 `blocked` 并采用默认保留。
- 验收证据：历史夹具报告、迁移查询和产品批准记录。
- 结果：`blocked`

### CLOUD-ACC-011 运行角色、灰度、熔断与回滚

- 覆盖需求：`CLOUD-REQ-006`。
- 前置条件：具有独立 API/worker 部署和隔离流量。
- 操作步骤：扩缩 worker，分别关闭静态/动态接纳，注入 Provider 与队列容量超限，执行上一版本回滚。
- 期望结果：API 不被媒体 worker 阻塞；开关可按能力/地域停止新任务；已接纳任务按批准承诺恢复；回滚不破坏已发布 schema 和任务。
- 边界情况：缺失最大等待、停止条件、负责人或已接纳任务承诺时，禁止生产灰度。
- 验收证据：容量/故障注入报告、开关快照、回滚演练和 SLO 仪表盘。
- 结果：`blocked`
