## 后端健康与启动

当前 API 提供 live/ready 和优雅停止；PostgreSQL 或 Redis 初始化失败均不监听，任一依赖断连使 ready 返回 503，但不影响 live，恢复后回到 200。实际进程与隔离容器验证覆盖启动失败、依赖断连恢复、SIGTERM 和未支持角色拒绝；可执行合同见 [17-01](../plan/17-01-后端服务启动与健康契约执行计划.md) 与 [17-17](../plan/17-17-账号认证Redis限流执行计划.md)。

2026-09-15 审核发现 NoMethod 处理器把 Gin 已按路由算出的 `Allow` 固定覆盖为 `GET`，导致例如 `GET /v1/auth/registrations` 的 405 错误宣称允许 GET。Red 测试复现 `Allow="GET" expected="POST"`；移除覆盖后健康路由与注册路由分别返回真实 GET/POST。全量 unit、race、vet、格式和模块校验通过；本机四服务测试 13.816 秒、隔离 actual-binary 集成 13.490 秒通过；镜像 `sha256:4cf4e85417475ec50be7d7050c70722ffb4c5d4e338712cabf7cbaa78bf953f8` 的受限容器测试 6.235 秒通过。运行时 readiness 描述也已同步为实际探测 PostgreSQL 与认证 Redis。

## 验收场景

### CLOUD-ACC-001 本地核心独立

- 覆盖需求：`CLOUD-REQ-001`、`CLOUD-REQ-006`。
- 前置条件：用户未登录，云功能开关关闭，所有云依赖不可用。
- 操作步骤：完成无图衣橱、基础推荐、计划、实际穿着与反馈。
